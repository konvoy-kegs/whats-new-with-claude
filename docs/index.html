What matters this morning is v2.1.302, not v2.1.303. Two default-behaviour changes for anyone running Claude Code headless: claude -p and Agent SDK sessions with no permission mode now start in default mode on third-party providers (Bedrock, Vertex, gateways), with telemetry off, or on a fresh install — pass --permission-mode auto explicitly if a pipeline relied on auto. And fork subagents are now on by default in claude -p, the Agent SDK, the desktop app and VS Code (CLAUDE_CODE_FORK_SUBAGENT=0 turns them off); the desktop app and VS Code also always run subagents in the background now. Also: CLAUDE_CODE_AUTO_MODE_MODEL picks the client-side auto-mode classifier model; the Read tool refuses image sources over 128 MB instead of loading them whole into memory; a prompt-cache miss after ToolSearch/compaction is closed; claude plugin no longer exits before a queued settings write lands; and standalone Claude Design (claude.ai/design) closes 14 December 2026. Cloud sessions: a scheduled routine that failed partway is no longer re-run from the start an hour later (which could post the same report twice).

v2.1.302 — headless permission default, fork subagents on by default, auto-mode model, cloud-session fixes Sat 17 Oct AEDT · 63 bullets

behaviour changes for automation Changed claude -p and Agent SDK sessions with no permission mode to start in default mode on third-party providers, with telemetry off or on a fresh install; --permission-mode auto keeps auto. A CI job on Bedrock or Vertex that never set a mode will now stop at its first permission prompt rather than proceed — set the mode explicitly. Changed fork subagents (subagent_type: "fork") to be on by default in claude -p, the Agent SDK, the desktop app and VS Code, as they already were in the terminal; CLAUDE_CODE_FORK_SUBAGENT=0 turns them off. Changed the desktop app and VS Code to always run the main conversation's subagents in the background, as the terminal does, rather than let Claude choose. Changed prompt and agent hooks so that at most 12 of one event run at a time; the rest wait their turn.
auto mode, config & models Added CLAUDE_CODE_AUTO_MODE_MODEL to choose the model the client-side auto-mode classifier uses; it does not change the model for server-side auto mode. Improved auto mode with the server-side classifier: a conversation too long for the safety check is now compacted, instead of every checked tool call being denied. Added an Idle compaction row to /config for turning idle compaction off or back on. Fixed requests failing with "diagnostics: Extra inputs are not permitted" after switching to Vertex or Bedrock mid-session. Fixed /autocompact and /effort saving to the wrong model when a gateway names Opus 4 or 4.1 with a prefix such as anthropic/claude-opus-4-1. Fixed prompt suggestions spending usage credits on models your plan pays for only with credits. Added a notice to /design-sync and /design-login that standalone Claude Design (claude.ai/design) closes by December 14, 2026.
resource limits, MCP & plugins Fixed the Read tool loading an image file of any size, or a pipe or device named like an image, entirely into memory; image sources over 128 MB are now refused. Fixed MCP servers showing no tools, or every tool call failing, when the server negotiates protocol version 2026-07-28 but omits resultType, ttlMs or cacheScope. Fixed claude plugin and other subcommands sometimes exiting before a queued settings or config write finished, which could lose the change or leave a .tmp file behind. Fixed plugin marketplaces re-cloning on every refresh, and git plugins showing version "unknown", when git defaults to the reftable ref format. Fixed worktree isolation refusing to create or resume worktrees under git 2.56+ when a stray .git file points at a missing directory. Fixed the PowerShell tool not finding commands in a plugin's bin/ folder. Windows: fixed every file write being refused or asked about for projects on exFAT or FAT32 drives. Improved startup time with many plugins enabled, most of all on Windows.
cost & telemetry Fixed a prompt cache miss when a tool added mid-session was loaded again through ToolSearch or after compaction. Fixed a cloud session's cost and usage restarting from zero after the session resumed in a new process. Fixed classifier_category missing from OpenTelemetry tool_decision events for most auto-mode classifier blocks, and new tool_decision attributes pushing out tool_use_id, tool_source and tool_parameters. Fixed a "Prompt is too long" error when stopping a turn mid-compaction. Changed where the Claude in Chrome instructions sit in the system prompt so new conversations read them from the shared prompt cache. Self-hosted runner: fixed git fetches failing with "bad object refs/heads" in sessions that reuse a reftable-format checkout.
cloud sessions & Claude Tag Cloud sessions: added a banner on a routine's page saying why its last run didn't start (e.g. the org's concurrent-session limit); fixed a scheduled routine run that failed partway being run again from the start an hour or more later, which could repeat work such as posting the same report twice; fixed routine runs showing Completed after their session stopped unexpectedly; fixed "Rewind to here" failing on every message except the newest (self-hosted runners need v2.1.246+); fixed the diff view breaking after a repo rename; fixed the PR status bar flipping a conflicted PR back to ready. Claude Tag (Slack): admin settings reorganised into four tabs (Bundles, Connectors, Skills and plugins, Channels); HEIC/SVG/TIFF/BMP attachments now reach Claude as files; the channel-manager role now grants Claude Tag in Slack; DMs on Enterprise Grid run under the last-opened workspace; fixed "DMs are temporarily unavailable" drops (now retries); fixed links absorbing trailing bold/italic marks; repo search now covers up to 100 connected GitHub accounts. Code Review: setup now resumes at the repository picker after connecting GitHub.

v2.1.301 — Fable alias fallback, retry-watchdog cap, classifier telemetry, cost fixes Fri 16 Oct AEDT · 51 bullets

models & unattended runs The fable (and best) alias now retries once on the previous Fable model when the newest isn't available to your org, instead of erroring. Added CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS so unattended retry mode ends a request at a usage limit that resets too far away instead of waiting. Switching to a model with a smaller context window now summarises the conversation on the previous model first, and no longer spends credits on that summary without asking. Fixed conversations being compacted over and over behind an LLM gateway whose responses name a different model than requested. Added classifier_verdict and permission_mode to OpenTelemetry tool_decision events; classifier_category names the rule a classifier block matched with OTEL_LOG_TOOL_DETAILS=1.
permissions, auth & hooks Fixed sign-in refresh timeouts and unexpected sign-outs after a short command such as claude auth status exited mid-refresh. Fixed the permission prompt for a plugin or skill hook's ask decision not showing which plugin or skill it comes from. Fixed quitting removing a hook-created worktree without asking when it may hold unpushed commits. Fixed Grep and Glob reporting no matches when the search program crashed; they now return an error. Self-hosted runner: sessions started from Slack can again attach a repository when managed settings restrict MCP servers (use deniedMcpServers). VS Code: LaTeX math rendering; "Get more usage" link on the usage-limit banner.

v2.1.300 — /advisor on AWS, OTel GenAI spans, hook input validation, gzip Thu 15 Oct AEDT · 88 bullets

Claude Platform on AWS & observability Added /advisor on Claude Platform on AWS (opt-in per session; CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 turns it off). Added OpenTelemetry GenAI semantic-convention attributes to trace spans and cache_creation_5m_tokens/cache_creation_1h_tokens on api_request. Large requests to api.anthropic.com now use gzip even with telemetry off. Local session transcripts now record each API request's system prompt, tools and parameters — mind what you share.
hooks, auth & permissions updatedInput from PreToolUse and PermissionRequest hooks is now validated like Claude's own input; unknown keys are dropped, and input the tool rejects denies the call. Agent hooks no longer ignore their model. CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST sessions ignore CA-bundle, tool-proxy, git TLS and git config variables in settings. Removed --sandbox/--no-sandbox from claude remote-control; set sandbox.enabled in settings.

v2.1.299 and earlier 14 Oct UTC and before

2.1.299 Sandbox and gateway hardening: a sandboxed command could write into a --plugin-dir folder; macOS sandbox symlink bypasses; gateway API key (ANTHROPIC_BASE_URL) leaking to Anthropic background endpoints. mcp__a now matches only the server named a — write mcp__<server>__*. Plugin hooks fail closed. Idle compaction in the terminal ("idleCompaction": false to disable). 190 bullets; bundled in Desktop v2.42304.0.
2.1.296 / 2.1.295 / 2.1.294 Managed-settings PreToolUse hooks denying with "continue": false end the turn; onFailure: "block" for command and HTTP hooks; Bedrock token counts via AWS CountTokens (grant bedrock:CountTokens); instruction-style hooks could allow what they should block; Sonnet 5.5 cache-read pricing corrected to $0.10/Mtok.

Security & evals

v2.1.303 CLI (undocumented) · v2.1.302 defaults changed · Desktop v2.42304.0

Today's actionable items

  • headless permission mode Since 2.1.302, claude -p and Agent SDK sessions with no permission mode start in default mode on third-party providers (Bedrock, Vertex, LLM gateways), with telemetry off, or on a fresh install. Any GitHub Actions job, self-hosted runner or SDK script that assumed auto mode will now block on its first permission prompt. Audit pipelines and pass --permission-mode auto (or the mode you actually want) explicitly. This is the right default for security, but it will surface as hung jobs if nobody tells the pipeline.
  • fork subagents now default-on 2.1.302 turns fork subagents on by default in claude -p, the Agent SDK, the desktop app and VS Code. A fork inherits the parent's context, so it sees everything the parent saw. If your threat model or token budget assumed only explicit subagents, set CLAUDE_CODE_FORK_SUBAGENT=0 in managed settings env. The desktop app and VS Code now also always run subagents in the background.
  • upgrade Fleet CLI target moves to 2.1.303 — but note it has no changelog beyond "Bug fixes and reliability improvements", so there is nothing to cite for change control other than "it is 2.1.302 plus unspecified fixes". 2.1.302 itself adds the Read-tool 128 MB image cap (a memory-exhaustion guard) and the hook concurrency cap of 12 per event. Run claude update on every machine on latest.
  • scheduled routines 2.1.302 fixed a cloud-session routine that failed partway being re-run from the start an hour or more later. Before this, a routine that posted to Slack and then failed could post again. If you saw duplicate routine output last week, this is why; it should stop now.
  • MCP protocol 2026-07-28 2.1.302 fixes MCP servers that negotiate protocol version 2026-07-28 but omit resultType, ttlMs or cacheScope showing no tools or failing every call. If an internal MCP server "lost" its tools last week, upgrade before changing the server.
  • Claude Design standalone closing claude.ai/design closes by 14 December 2026; Claude Design continues inside conversations (chat, Code, Artifacts tab). Anyone using /design-sync or /design-login should plan to move design systems before then.
  • Desktop v2.42304.0 (carry-over) Windows signing certificate for the bundled claude.exe changed — Defender certificate indicators and AppLocker/WDAC publisher rules need the renewed certificate added beside the old one. Managed import now installs MCP servers, plugins and tool-granting skills without per-item confirmation; automatic3pImport reinstalls optional plugins across org moves; mcpPersistentAlwaysAllowEnabled now also governs Code sessions; chat's file-analysis sandbox reaches coworkEgressAllowedHosts; app-run Git operations skip repository hooks; session export covers everything by default. Desktop still bundles 2.1.299 — the Code tab lacks 2.1.300's updatedInput validation and 2.1.302's permission-mode default.
  • MCP permission rules (carry-over) Since 2.1.299, mcp__a matches only the server named a. Audit permissions.allow/deny and agent tools: lists for servers with double underscores and rewrite them as mcp__<whole name>__*.
  • gateway users (carry-over) If you run Claude Code through an ANTHROPIC_BASE_URL gateway with its own API key, that key was sent to Anthropic's background endpoints before 2.1.299. Upgrade first; consider rotating the gateway key.
  • stable dist-tag Still v2.1.292; nine releases behind. Anyone pinned to stable has none of the sandbox, gateway-key, hook or MCP-rule fixes from 2.1.294 onward, and none of the 2.1.302 defaults.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

An undocumented release at the top of the stack. v2.1.303 is the first release in this run whose changelog says nothing. It is on latest and next, so every claude update installs it blind. For change control, pin what you can cite (2.1.302) or accept 2.1.303 as "2.1.302 plus fixes". Watch whether the entry gets filled in.
Defaults are tightening for headless, loosening for parallelism. 2.1.302 moves unattended sessions on third-party providers to default permissions (safer) in the same release that turns fork subagents on everywhere (more context sharing, more tokens). Both are the kind of change that shows up as "it worked on Friday" tickets. Set permission mode and CLAUDE_CODE_FORK_SUBAGENT explicitly in managed settings so the defaults stop mattering.
Telemetry for auto mode is now usable. 2.1.300 added GenAI span attributes; 2.1.301 added classifier_verdict, permission_mode and classifier_category; 2.1.302 fixes classifier_category being missing on most blocks and the new attributes pushing out tool_use_id. A Grafana panel separating "classifier blocked it" from "a rule blocked it" is now reliable — wire it before widening auto mode.
Desktop trails the CLI by four releases. v2.42304.0 (15 Oct) bundles 2.1.299; the CLI is on 2.1.303. No new Desktop build over the weekend. Expect the next bump to jump to 2.1.302 or later and bring the permission-mode and fork-subagent defaults with it.

Claude Cowork

GA · macOS, Windows & Linux · web & mobile · cloud by default on Pro/Max

What's new

cloud sessions & routines · Claude Code 2.1.302 A scheduled routine that fails partway is no longer re-run from the start an hour or more later — the bug could repeat work such as posting the same report twice.
