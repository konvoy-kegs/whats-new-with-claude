Claude Code

CLI · v2.1.273 on latest and next
All sources aligned on v2.1.273. The newest build on npm, the latest dist-tag, the next dist-tag, the changelog top entry and the newest GitHub release all say v2.1.273, published 2026-09-15 18:06 UTC (Wed 16 Sep 04:06 local). claude update installs it. Six releases have shipped since this page last refreshed on Thu 10 Sep (v2.1.268 through v2.1.273); two of them (v2.1.270 and v2.1.272) are one-line reliability releases. This is the version to roll out.
v2.1.273 is a 64-entry release with two items this team should read first. (1) Managed MCP controls were being silently ignored: allowManagedMcpServersOnly, deniedMcpServers and disableClaudeAiConnectors set via MDM or managed-settings.json did nothing whenever server-managed settings were also present. Fixed. (2) Two more permission gaps closed: Bash commands the checker cannot fully analyse were skipping the prompt under permissions.blockReadsOutsideWorkingDirectories, and a subshell could hide a dangerous rm in bypass mode. Also: auto mode on Bedrock, Vertex and Foundry now uses the local safety classifier by default (CLAUDE_CODE_AUTO_MODE_SERVER=1 restores the server-side one), and the v2.1.268 “deny on eval/env -C” change was reverted after it broke commands like time -p make build.
v2.1.271 (Tue 15 Sep, 96 entries) is the release with the new controls. Per-command allowed_domains for Bash, PowerShell and Monitor in auto mode with sandboxing; omitClaudeMd for subagents; --accept-command <sha256> on claude plugin install; a modelPricing multiplier up to 10× for internal chargeback; and a fail-closed fix for an unreadable enterprise managed-mcp.json (it now keeps exclusive MCP control and warns, instead of being ignored). v2.1.269 (Sat 12 Sep, 98 entries) added claude plugin eval, OTEL_METRICS_INCLUDE_REPOSITORY and a tee-destination deny-rule fix. v2.1.268 (Fri 11 Sep) fixed deny rules on symlinked system directories and a regression that broke every request on third-party ANTHROPIC_BASE_URL endpoints since v2.1.265.

v2.1.273 — managed MCP controls actually enforced, two permission gaps closed, local classifier on Bedrock newest documented

Fixed allowManagedMcpServersOnly, deniedMcpServers and disableClaudeAiConnectors set via MDM or managed-settings.json being ignored when server-managed settings are also present. If we set any of these three in a device-managed file and the organisation also pushes server-managed settings, the device-side MCP restrictions were not applied at all. Verify on a real machine after upgrade that a denied MCP server really fails to load. Related, same release: skills synced from claude.ai stayed available after the organisation turned Skills off — they now move to the recoverable trash.
Fixed Bash commands the permission checker cannot fully analyse skipping the prompt under permissions.blockReadsOutsideWorkingDirectories, and a subshell hiding a dangerous rm in bypass mode. Third consecutive release with a blockReadsOutsideWorkingDirectories bypass fix (v2.1.271 covered cd chains and subshells; v2.1.273 covers the unanalysable case). Also fixed: a memory directory chosen by a repository's settings is no longer loaded, recalled or indexed when that setting is on — a cloned repo could previously point the memory system at an arbitrary path.
Reverted the v2.1.268 change that checked Read and Edit deny rules on Bash lines the checker can't analyse (eval, env -C). That change made commands like time -p make build hard-deny; they prompt again now. If anyone reported “Claude refuses to run make” on v2.1.268–272, this is why. The underlying question — what to do with a deny rule when the command can't be parsed — is now “ask”, which is the right middle ground.
Changed auto mode on Bedrock, Vertex and Foundry to use the local classifier by default for now; set CLAUDE_CODE_AUTO_MODE_SERVER=1 to use the platform's server-side classifier. For our Bedrock fleet this means auto-mode approvals are decided on the developer's machine rather than by the Anthropic-hosted classifier. Expect slightly different approve/ask behaviour; if we want server-side parity across Bedrock and first-party, set the variable in managed settings.
Added gateway hint headers for LLM gateways — x-claude-code-request-class, x-claude-code-agent-type, x-claude-code-prev-tool-durations, x-claude-code-compaction and x-claude-code-context-compacted, opt-in with CLAUDE_CODE_GATEWAY_HINT_HEADERS=1. Useful for routing and rate-limiting at the proxy by request class (main turn vs subagent vs compaction). Also: OTEL_LOG_TOOL_DETAILS=1 now puts real agent, skill, plugin and MCP server names on cost and token metrics, so per-plugin spend attribution in the collector becomes possible.
Fixed 401/403 errors on Bedrock, Vertex, Foundry and Claude apps gateway 403s telling you to run /login. The message now names the credential to refresh or points at the gateway administrator. Paired with last week's immediate re-auth error for expired AWS SSO credentials, the Bedrock sign-in failure path is finally legible. Also: /login, /upgrade and /extra-usage no longer discard earlier thinking and force a full prompt-cache rewrite on the next request.
Fixed the context meter and auto-compact counting advisor-tool turns at roughly twice their real size, which made auto-compact fire at about half the real window. Sessions that use advisor tools heavily were compacting far too early. Also: sub-agents and background agents were reported as failed, with their result never delivered, when the final streamed reply omitted token usage or carried no model id; SDK and stream-json output dropped a subagent's remaining messages after it was backgrounded mid-run.
Added forking a session started with claude --remote-control or /remote-control from the Claude app; the fork runs as a background session on your computer. Also: a notification when an MCP server disconnects mid-session and automatic reconnection gives up, pointing at /mcp; and a clearer error when an MCP server's sign-in expires mid-session. Fixed saved scheduled tasks running in the wrong session after .claude/scheduled_tasks.json was copied into another folder such as a new worktree.
Privacy and reporting. Sign-in with a Claude account now also requests access to your claude.ai plugins (expect a changed consent screen on next login). /bug and /feedback reports now include only model-behaviour params (model, system prompt, tools) from the last request, omitting request metadata and CLAUDE_CODE_EXTRA_BODY — relevant if we inject gateway or tenant fields there. In-session SSL and proxy errors now name the error code and the fix (e.g. NODE_EXTRA_CA_CERTS for a corporate CA); /web-setup explains a refused GitHub token.
[Claude Tag] AWS and scheduled-task fixes. AWS connections were refusing region-less endpoints such as Budgets, Savings Plans, WAF Classic and Import/Export; Global Accelerator requests now sign correctly, and an unsignable request now explains why. Scheduled tasks set up in an organisation-shared private Slack channel were silently never posting — they now run in the thread they were created in. Also: Claude now watches related public channels on its own (e.g. an incident channel a conversation depends on); replying in an older thread mid-task no longer restarts the work from scratch. [Claude Code on the web] the admin “Share cloud sessions” setting moved under Data and privacy; routines regain access to a connector an admin removed and re-added. [Code Review] /ultrareview --post posts exactly once on retry; base-branch merges get the lighter follow-up review; REVIEW.md no longer ignored because of an @-mention.

v2.1.271, v2.1.269 and v2.1.268 — the other releases since last refresh this week

v2.1.271 (Tue 15 Sep, 96 entries): per-command allowed_domains for Bash, PowerShell and Monitor in auto mode with sandboxing — the hosts a command needs are reviewed with it and opened for it alone; omitClaudeMd in agent frontmatter so custom and plugin subagents run without user, project and local CLAUDE.md (managed policy files still load); --accept-command <sha256> on claude plugin install/update to accept exactly the command a prior --json run displayed; modelPricing multiplier up to 10 for marked-up chargeback; fast mode in Remote sessions where the org allows it. Fail-closed: an unreadable enterprise managed-mcp.json now keeps exclusive MCP control and warns instead of being ignored. Permission checker: files after unrecognised options (fmt, column), wildcards inside a pattern or option value (grep -v dir/* file), and shell variable declaration flags misrepresenting the command — all fixed. A cached org policy was reused after switching accounts or API keys; /resume and /teleport kept the previous conversation's file-read tracking so Claude could edit files it had never read. Auto mode: a skill's inline ! shell commands follow default-mode permission rules instead of the classifier; a subagent hands back via a dedicated classifier-reviewed call; Monitor watches always have a deadline (30 min max). Gateway, Bedrock, Vertex and Foundry sessions no longer refresh a leftover claude.ai login. Claude Code on the web: Custom network access option in the Cloud environments admin editor. Windows: PowerShell “Exit code 1” when the temp path hit 260 characters.
v2.1.269 (Sat 12 Sep, 98 entries): claude plugin eval runs a plugin's eval suite and produces scored JSON + HTML reports; /output-style [name]; bashEditDiffEnabled shows a diff of files a Bash command changed; OTEL_METRICS_INCLUDE_REPOSITORY tags metrics with vcs.* attributes; CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS; CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS (1–256). Security: a deny/ask rule starting with ! applied beyond the settings source that wrote it; Edit() deny rules and the write-path check did not apply to the file a Bash tee writes, and Bash(tee:*) allow no longer covers destinations outside the working directories; plugin archives extracted for a session were readable by other local users and kept world-writable bits; permission_denials in stream-json omitted path-scoped Read/Edit/Write denials. Organisation plugins enabled through managed settings were not loading in headless sessions or on Claude Desktop — fixed. /insights works on Bedrock/Vertex/gateway accounts that can't reach Opus. Skills synced from claude.ai in cloud sessions are now named anthropic-skills:<name>, matching Desktop. Claude Tag: declines a switch to a model the org hasn't enabled instead of quietly using a fallback; routine runs can reply in an existing thread.
v2.1.268 (Fri 11 Sep, 96 entries): Claude apps gateway pricing: in gateway.yaml is now pushed to signed-in clients through managed settings so /cost and telemetry match the spend meter; startup warning when access_control.allow_cidrs is empty and a one-time warning on the first request from a public address; gatewayInternalNetworks allows /login to the gateway from the org's own public IPv4 block; --json on every claude plugin subcommand. Regression fixed: every turn failed with HTTP 400 on third-party Anthropic-compatible endpoints (ANTHROPIC_BASE_URL) since v2.1.265 because of a regex in the Artifact tool's schema. Security: deny and ask rules on symlinked directories (/etc, /tmp, /var on macOS; /bin on Linux) did not apply when the path was given by its real location; a Read/Edit deny rule did not apply when env -C/eval was on the same line (later reverted in v2.1.273, see above); plugin and marketplace errors showed a token from a git source URL; /mcp, /plugin and claude mcp list showed secrets resolved from ${VAR} placeholders; a respawned teammate could pick up tools from a same-named agent file in an untrusted folder. Workload identity federation via a profile failed with 401 … jti reused; Claude in Slack sessions lost their Slack tools when managed settings set an MCP allowlist; PermissionRequest hooks didn't fire in --print; WebFetch now fails after 300 s (CLAUDE_CODE_WEBFETCH_DEADLINE_MS).

This week's actionable items

  • roll out Standardise on v2.1.273. All sources aligned, documented (64 entries), on latest and next, released on GitHub. claude update gives you v2.1.273. Skip v2.1.268–v2.1.272 as intermediate targets: 268 hard-denied eval/env -C lines, 269 made read-only git commands prompt, and both are fixed by 273.
  • verify Device-managed MCP restrictions were being ignored (fixed v2.1.273). If allowManagedMcpServersOnly, deniedMcpServers or disableClaudeAiConnectors live in MDM or managed-settings.json and the org also pushes server-managed settings, they had no effect until today. After upgrade, confirm on a laptop that a denied server does not appear in /mcp.
  • decide Auto mode on Bedrock now uses the local classifier by default (v2.1.273). Set CLAUDE_CODE_AUTO_MODE_SERVER=1 in managed settings if we want the server-side classifier for the Bedrock fleet. Decide once, apply everywhere — mixed behaviour will generate confusing “it asked me on my machine but not yours” reports.
  • enable Per-command allowed_domains in auto mode with sandboxing (v2.1.271). Network egress for a Bash command is now reviewed with the command and opened only for it. This is the sandboxing control we were missing for package installs and API calls from within a session.
  • audit Symlinked system directories in deny rules (v2.1.268). Rules on /etc, /tmp, /var (macOS) and /bin (Linux) did not apply when a path was given by its real location. Any deny rule written on a symlinked spelling was bypassable by using the resolved path. Now fixed; re-test the rules we rely on.
  • audit tee destinations and !-prefixed rules (v2.1.269). Edit() deny rules did not cover the file a tee writes, and Bash(tee:*) allow covered destinations outside the working directories. A deny/ask rule starting with ! applied beyond its own settings source. If we have ! negations in project settings, check they still mean what we intended.
  • fail-closed Unreadable enterprise managed-mcp.json now keeps exclusive MCP control and warns (v2.1.271). Previously a parse error meant user, project and plugin MCP servers all loaded as if the file didn't exist. Lint the file before rolling out — a malformed one now blocks every non-managed server.
  • secrets Secrets no longer leak into error output (v2.1.268). Plugin and marketplace errors showed a token from a git source URL; /mcp, /plugin, claude mcp list and MCP login errors showed values resolved from ${VAR}. If any session transcripts or bug reports from before 11 Sep were shared externally, check them for MCP header values.
  • plugins Plugin archives were world-readable and kept world-writable bits (v2.1.269) on shared machines. Fixed. Pair with --accept-command <sha256> (v2.1.271) for plugin install in CI: pin the exact install command rather than -y.
  • gateway access_control.allow_cidrs empty now warns at startup and on the first request from a public address (v2.1.268). If our gateway has an empty allow list, expect the warning; set gatewayInternalNetworks for our public block so /login to the gateway works from the office.
  • memory A repository's settings could choose the memory directory under blockReadsOutsideWorkingDirectories (fixed v2.1.273). A cloned repo could point memory extraction at an arbitrary path. Now excluded from the prompt, recall and indexing.
  • unpin stable moved to v2.1.267 — 31 releases forward from v2.1.236 in one step. Still 6 behind latest and missing every item above. Prefer latest with a one-day lag rule.

Patterns worth tracking

blockReadsOutsideWorkingDirectories has been patched in three consecutive documented releases. v2.1.271: cd chains, subshells, cd+git. v2.1.273: commands the checker can't analyse, plus a subshell-hidden rm in bypass mode, plus repo-chosen memory directories. The setting is converging on sound, but every one of these was a bypass in a control we might have believed was in force. Verify on a real machine.
Fail-open continues to be hunted down, now on the MCP side. Last week: three managed allowlists admitted everything when unreadable. This week: managed-mcp.json ignored when unreadable (v2.1.271), and three device-managed MCP keys ignored when server-managed settings also exist (v2.1.273). The lesson repeats: a managed control is only a control once you've watched it deny something.
The deny-on-unanalysable experiment lasted five days. v2.1.268 hard-denied Bash lines containing eval or env -C when a Read/Edit deny rule existed; v2.1.273 reverted it to “ask” after it broke time -p make build. Reasonable outcome, but it's a reminder that permission-checker semantics can change under us between patch versions. Reason to keep a one-day lag and read the changelog before promoting.
Cost attribution is becoming real. OTEL_LOG_TOOL_DETAILS=1 now carries real agent, skill, plugin and MCP server names on cost and token metrics (v2.1.273); OTEL_METRICS_INCLUDE_REPOSITORY adds vcs.* attributes (v2.1.269); gateway pricing reaches clients (v2.1.268); a chargeback multiplier exists (v2.1.271). Per-repo, per-plugin spend dashboards are now possible from the collector alone.

Claude Desktop

macOS · Windows · Linux (beta)

What's new

Salesforce in Claude (beta) — 15 Sep. A plugin that brings a seller's accounts, opportunities and pipeline into Claude with 37 pre-built sales skills: prep a call, review a deal, build a pipeline dashboard, send a forecast. Available in beta on all paid plans for organisations Salesforce approves through its beta sign-up. The newest support-centre release-note entry and the first vertical plugin since the Financial Services set.
Smart reports (beta) — 10 Sep, Enterprise plans. Analyses how a team uses Claude and reports on the work getting done, what it costs, where sessions run into friction, and which repeated patterns are worth packaging as shared skills. For us this is the first product-side view of “what should be a skill”, complementing /skill-doctor on the CLI side.
From the CLI Desktop bundles — organisation plugins enabled through managed settings were not loading on Claude Desktop (fixed v2.1.269, effective once Desktop ships that CLI). Also: Desktop sessions on Bedrock, Vertex or a gateway now get the “what Claude needs” turn-end notification text (v2.1.269); entitled users were told a model is restricted in the Desktop Code tab when a cached model-access denial was stale (v2.1.268); Remote Control clients attached to a Desktop, VS Code or JetBrains session were refused when asking for context-window usage (v2.1.273).
Sign-in with a Claude account now also requests access to your claude.ai plugins (v2.1.273). Expect a changed consent screen the next time developers sign in from Desktop or the CLI. Related: skills synced from claude.ai now go to the recoverable trash when the organisation turns Skills off (v2.1.273) or after sign-out (v2.1.271), rather than staying on disk indefinitely.
Standing context — Fable 5.1, model entitlements, memory, Customize. Fable 5.1 (1 Sep) is the default Fable model in the picker where the organisation is entitled to it. Enterprise admins control which models and effort levels users see under Manage model access (beta since 1 Jul); maxEffortLevel in managed settings gives the CLI-side equivalent. Memory (25 Aug) works across chat and Cowork; off by default for Team and Enterprise. The Customize section groups skills, plugins and connectors; monthly recap at Settings > Reflect.

Claude Cowork

GA · macOS & Windows · Linux beta

What's new

Salesforce in Claude (beta, 15 Sep) is a Cowork plugin — 37 skills covering call prep, deal review, pipeline dashboards and forecast submission, on all paid plans once Salesforce approves the org for the beta. It follows the Financial Services and Legal plugin sets and is the clearest signal yet that vertical plugins are the distribution model for Cowork.
Smart reports (beta, 10 Sep) tells Enterprise admins which repeated Cowork and chat patterns are worth packaging as shared skills, alongside cost and friction. Combine with claude plugin eval (v2.1.269) — scored, reproducible eval suites for plugins with JSON and HTML reports — and there is now a loop: find the pattern, package it, measure it.
From v2.1.273 — saved scheduled tasks were running in the wrong session after .claude/scheduled_tasks.json was copied into another folder, such as a new worktree. Fixed. Also: a notification when an MCP connector disconnects mid-session and reconnection gives up; a clearer error when a connector's sign-in expires (/mcp). Claude Tag scheduled tasks set up in an organisation-shared private Slack channel were silently never posting — fixed, they now keep running in the thread they were created in. If a Slack routine in a private channel went quiet, that was why.
From v2.1.271 — artifacts and plugins. Markdown files published as artifacts now render as styled document pages; a session can watch up to 10 published artifacts for republishes (up from 5); background sessions watch the artifacts they publish. --accept-command <sha256> on claude plugin install/update pins the exact install command for scripted plugin rollouts. Cross-session messages held by the receiving session's permission-mode policy now leave a delivery notice instead of vanishing.
From v2.1.269 — organisation plugins enabled through managed settings were not loading in headless sessions (fixed); skills synced from claude.ai are named anthropic-skills:<name> in cloud sessions to match Desktop; artifact database reads into the session scratchpad no longer stop for working-folder approval; /goal runs retry with backoff or pause and say why instead of stalling silently; one-off cloud routines no longer occasionally run twice after a transient server error.
Standing context — plugins, skills, artifacts and scheduled tasks. Plugins bundle skills, connectors and sub-agents into one installable package; hooks and sub-agents run only in Cowork. /skill-doctor (v2.1.261) shows which installed skills never fire. Artifacts created on or after 19 Aug are shareable, connected, versioned and openable from the web. Cowork sessions run remotely in the cloud (beta) so scheduled tasks fire with no device online. Enterprise plans can turn on skill and plugin security scanning (6 Aug) — still worth enabling given this week's plugin archive permission fix.
