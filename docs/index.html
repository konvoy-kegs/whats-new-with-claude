v2.1.309 — sandbox and permission-check hardening, sed -i and ultrareview behaviour changes Fri 23 Oct AEDT · 79 bullets · newest on npm

sandbox Fixed sandboxed Bash commands on macOS and Linux running the shell's startup files outside the sandbox before each command. Anything in ~/.zshrc, ~/.bashrc or a profile sourced at startup was executing unsandboxed on every sandboxed command; a startup file edited earlier in a session (by Claude or by an injected instruction) would have had full access on the next command. Fixed macOS sandbox denyWrite glob patterns not applying at a path's real location when the pattern's folder is reached through a symlink. Fixed sandboxed commands and auto-accepted edits being able to modify the MCP config file passed with --mcp-config — a sandboxed session could add or change an MCP server for its own later turns or for the next run of a headless pipeline. Fixed profile store write protection not applying when the config directory is reached through a symlink. Linux: fixed sandbox write denies lifting when a background command outlived the session. Changed commands the settings exclude from the sandbox to ask before writing to its write-list paths while the sandbox is enabled but cannot run; the unsandboxed fallback is refused there.
permission checks Fixed the Bash permission check trusting a variable set by a command whose redirect can fail to open. Fixed Bash permission checks not prompting for some compound commands that change directory before running git when the cd is wrapped or prefixed, as they do for a plain cd. Fixed an Edit(path) deny rule not blocking a Bash redirect to that path in some commands that also held a subshell. Windows: fixed PowerShell permission checks auto-approving some Set-Location or cd commands that target the current directory and carry extra arguments; these now prompt. Fixed hooks that run in PowerShell not blocking when the hook's program exits with code 2, and on Windows PreToolUse and PermissionRequest hooks with "shell": "powershell" failing open when Git for Windows isn't installed. Fixed split-pane agent teammates not inheriting the tool deny and --tools rules given on the leader's command line. Fixed a disabled MCP server being reconnected by a later permission prompt in print and SDK sessions.
worktrees & isolation Fixed worktree-isolated sessions accepting some locale-prefixed commands the isolation guard should refuse, and on zsh accepting some arithmetic commands it should refuse. Fixed worktrees and branch checkouts that Claude Code creates so they ignore git replace refs, as its other git operations already do. Changed worktree creation and reuse so git no longer fetches objects on demand, in ordinary clones and in partial clones with a Bash sandbox configured; such a partial clone fetches them first.
behaviour changes Changed sed -i to get the standard Bash prompt and run as written, not a simulated file-edit preview; like other Bash edits, it is no longer restored by /rewind. Changed claude ultrareview to require workspace trust: it asks on a terminal, else refuses; scripts pass --trust-workspace (takes no value; put a PR number or base branch before it) or set CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1. Changed the dangerous rm/rmdir prompt in bypass-permissions mode in the Desktop app and VS Code to deny the command at once with a rewrite hint, so unattended sessions keep going. Changed the /claude-api skill to build Managed Agents subagent teams on multiagent_20261001 with dynamic workflows on by default, instead of coordinator. Fixed Claude notifying unrelated GitHub users by writing role names and placeholders as @-mentions in PRs, issues and comments.
providers, gateways & sessions Fixed fine-grained tool streaming staying off on Amazon Bedrock when ANTHROPIC_BEDROCK_BASE_URL is set to the default bedrock-runtime.<region>.amazonaws.com endpoint. Fixed the "Waiting for API response" hint flickering behind gateways that send only keepalive pings: routes off Anthropic's backend now wait 45 seconds. Fixed sessions compacting repeatedly after reading files under a very large nested CLAUDE.md; an oversized nested CLAUDE.md now loads only its start. Fixed /rewind showing "No code changes" for a turn that changed checkpointed files through /code-review --fix, a subagent or a shell command. Fixed long tool output previews being cut through an emoji, leaving transcripts jq could not parse. Fixed Read reporting "File does not exist" for PDF page ranges in Linux sandboxes that share the parent's /proc. Improved disk-full handling and the speed of many git commands on Windows (errors from them now show in English regardless of git's language). Self-hosted runner: --startup-timeout-min no longer stops a session whose first prompt is still working in a subagent; sessions that move to a new runner now see the interrupted tool call marked as outcome unknown.
Desktop, Cowork & artifacts Fixed messages from a Claude Desktop-hosted session sometimes being lost when its connection refreshed. Fixed features missing from Claude Code sessions in the Desktop app when the terminal on the same computer was signed in to a different account or organization. Fixed plugins and skills synced from claude.ai being removed, sometimes mid-session, after a disk read error. Fixed artifact publishes and updates being refused for some ordinary pages (certain minified scripts, or artifacts Claude could not read first), and Claude asking for permission on each artifact update for the rest of a turn after a compaction. Fixed ctrl+o not showing messages from other agents and sessions still waiting to be delivered. Fixed a skill in an --add-dir folder being unreachable when another skill held its name; it is now offered as <folder>:<name>. Fixed /verify and /code-review not finding a nested package's own skill when its files were changed from the shell. Updated the bundled dataviz skill to accept APCA as a text-contrast measure alongside WCAG 2.
VS Code, cloud sessions, Claude Tag & Code Review VS Code: a log warning says what to do when dictation or the extension's requests fail certificate verification behind a TLS-inspecting proxy; the Claude panel recovers from a cached incomplete copy of its files; session history no longer fills with empty "Untitled" sessions; long /goal-style prompts fold behind Show more; Edit/Write in the chat panel wait 0.75 s for new problems (down from 1–1.5 s). Cloud sessions: the environment editor no longer shuffles environment variables or adds backslashes to values with both kinds of quote; the Changes pane says when it lists only pushed commits or only Claude's edits. Claude Tag: an approved channel draft is no longer posted into your DM by mistake; Allow/Deny on approval cards restart a stopped session; Claude no longer ignores untagged channel messages after a workspace moves to a different Claude organization. Code Review: a finished review now adds a completed check even when earlier tries to create it failed; a push queued behind a running review no longer starts a review after @claude review stop.

Security & evals

v2.1.309 CLI: 11 sandbox / permission-check fixes · Desktop v3.6556.1: GitHub connector write tools now prompt every call, per-host permission modes

Today's actionable items

  • upgrade Fleet CLI target moves to v2.1.309 — do not wait for stable on this one. stable sits on v2.1.308, which has none of the sandbox or permission fixes. For machines where the sandbox is part of the control story (shared runners, auto mode, headless pipelines), pin latest or an explicit 2.1.309 until stable catches up.
  • sandbox: startup files ran unsandboxed Before v2.1.309, every sandboxed Bash command on macOS and Linux first ran the shell's startup files outside the sandbox. Anything that landed in ~/.zshrc, ~/.bashrc, ~/.zshenv or ~/.profile during a session (an edit Claude made, or one an injected instruction asked for) had unrestricted access on the next command. Diff startup files on shared dev boxes and runner images against their known-good versions, and treat the sandbox's file protections as having been bypassable for anything that could write to the home directory.
  • sandbox: --mcp-config was writable Sandboxed commands and auto-accepted edits could modify the MCP config file passed with --mcp-config. In a headless or CI pipeline that reuses one config file, a session could add an MCP server that the next run connects to. Check pipeline-owned MCP config files into source control and verify them on each run (or regenerate them per run) — and audit any that have been sitting on a runner.
  • sandbox: symlinks macOS denyWrite globs did not apply at a path's real location when reached through a symlink, and profile store write protection did not apply when the config directory was reached through one. Any denyWrite rule guarding a folder that is also reachable via a symlinked parent (Homebrew, ~/Library shortcuts, dotfile managers) was not enforced.
  • permission-check bypasses closed Variable trusted from a command whose redirect can fail; wrapped or prefixed cd before git not prompting; Edit(path) deny not blocking a Bash redirect in commands with a subshell; worktree isolation guard accepting locale-prefixed and zsh arithmetic commands; PowerShell Set-Location/cd to the current directory with extra arguments auto-approved. Each is a way a deny rule or the isolation boundary could be stepped around by a specific command shape. Nothing to configure — upgrade.
  • Windows: PowerShell hooks failed open Hooks running in PowerShell did not block on exit code 2, and PreToolUse / PermissionRequest hooks with "shell": "powershell" failed open when Git for Windows was not installed. Any Windows managed-settings hook that was meant to deny was not denying before v2.1.309. Re-test the deny path on a Windows machine after upgrading.
  • bypass mode: rm now denied, not prompted In bypass-permissions mode in the Desktop app and VS Code, dangerous rm/rmdir are denied at once with a rewrite hint. Unattended sessions no longer hang on the prompt; they also can no longer be approved through it. Check any scheduled task that cleans up directories.
  • sed -i and ultrareview sed -i gets the standard Bash prompt and runs as written, and is no longer restored by /rewind. claude ultrareview refuses to run outside a terminal unless --trust-workspace is passed; CI scripts that call it need the flag (put the PR number or base branch before it) or CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1.
  • Desktop v3.6556.1: GitHub connector write tools prompt every call The built-in GitHub connector now asks before every call of issue_write, sub_issue_write, pull_request_review_write, add_reply_to_pull_request_comment and five write tools that toolsets can enable; actions_run_trigger asks regardless of toolPolicy. An exact toolPolicy key or "*" can still allow them. Scheduled Cowork tasks that write to GitHub through the built-in connector will stall on the prompt unless the policy allows the tool — this digest's own GitHub push uses git over HTTPS, not the connector, so it is unaffected. The Microsoft 365 read tool also asks once more after this update where "Always allow" had been chosen.
  • Desktop v3.6556.1: permission mode per host, Bypass reset A folder's permission mode is now saved separately for this computer, each SSH host and each WSL distribution. Folders set to Bypass permissions start in their default mode until you pick it again and confirm; on SSH and WSL, earlier picks more permissive than the default no longer apply. Engineers with bypass-mode folders will see prompts return after the update.
  • Desktop v3.6556.1: SSH workspace folders stricter allowedWorkspaceFolders entries on SSH hosts allow nothing unless they are a full path for that host with no ..; a symlink listed inside another listed folder is left out (list its target). Read-only entries with an unset %VAR% turn the enclosing folder read-only. Review managed allowedWorkspaceFolders for relative paths and symlinks before devices update.
  • Desktop v3.6556.1: 3P / managed settings New installedUpdateEnforcementEnabled / installedUpdateEnforcementHours (with disableAutoUpdates, restart into an installed update after 1–72 h); quickEntryScreenshotsEnabled / quickEntryFileSharingEnabled on macOS; headersHelperArgs / envHelperArgs on managedMcpServers. The approval prompt for a bootstrap-delivered remote connector with a helper script now shows where the helper's output goes and re-asks when that address changes — people who approved one are asked again. The Setup window's firewall allowlist now lists hcaptcha.com and *.hcaptcha.com plus the hosts of bootstrap-delivered MCP servers and marketplaces: export it again. Update checks use releases.claude.com when bootstrapUrl is on config.claude.com.
  • Desktop v3.1623.4: managed MCP and plugin permissions Plugins the app loads now ask before using their pre-approved tools when managed settings set allowManagedPermissionRulesOnly. A local MCP server in managed-mcp.json that uses ${VAR} only in its env values now runs even when isLocalDevMcpEnabled is false or allowedPluginMcpServers is set (one with a variable in its command or arguments is still stopped). Audit managed-mcp.json for servers that were being kept off by that rule.
  • GitHub mentions Claude was notifying unrelated GitHub users by writing role names and placeholders (@reviewer, @owner) as mentions in PRs, issues and comments. Fixed in v2.1.309; worth a one-line note to anyone who got a stray notification from a Konvoy repo.
  • carry-over (v2.1.307) HTTP MCP tool calls could be sent twice on a dropped connection before v2.1.307; only read-only or idempotent tools are retried now. claude_code.safety_event OTel event per blocked, prompted or returned tool call. 30-minute checkout-hook cap on self-hosted runners.
  • carry-over (v2.1.302, v2.1.299) claude -p and Agent SDK sessions with no permission mode start in default mode on third-party providers or with telemetry off (CI needs --permission-mode auto). mcp__a permission rules match only the server named a.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks).

Patterns worth tracking

A sandbox audit landed in one release. Eleven sandbox and permission-check fixes in v2.1.309, several of them full bypasses (startup files outside the sandbox, a writable --mcp-config, symlinked denyWrite). This reads like the output of an internal review rather than individual bug reports; expect follow-ups over the next few releases and keep fleets close to latest while it runs.
The one-liner-then-big-release rhythm held. v2.1.308 (Thu 15:19 AEDT, "Bug fixes and reliability improvements") preceded v2.1.309 (Fri 07:34 AEDT, 79 bullets) by 16 hours, exactly as v2.1.303 preceded v2.1.304. The one-liner is what Desktop bundles and what stable points at, so both are a release behind the hardening.

Both bundle Claude Code 2.1.308, so the Code tab went from three CLI releases behind to one in a day. The v3.6556.1 changes to permission-mode storage and GitHub connector prompts will be visible to every engineer who opens the app this morning.
Scheduled tasks are getting safer and stricter at once. Desktop v3.6556.1 fixes plugins and skills not being found in scheduled tasks and makes MCP tools that need a person ask only on the in-app card (scheduled runs skip them). Claude Code v2.1.309 makes bypass-mode rm a hard deny. Automations that relied on a human eventually clicking Allow will now either continue without the call or fail cleanly; review the ones that write.

Fixed tasks started from a plugin's setup card, a connector's suggested prompts or an onboarding suggestion being silently dropped after the workspace failed to start, and the failed-start notice sometimes not appearing. Fixed earlier tasks missing from the list on some Windows computers after an older version started blank and signed out. The live list of steps now follows whichever steps Claude is working on, not only replies that began with steps. Fixed empty session, project and scheduled-task lists when the app starts while the bootstrap server is unreachable; scheduled tasks now wait until the connection is restored.
connectors in scheduled runs · Desktop v3.6556.1 The built-in GitHub connector now prompts before every write tool call and actions_run_trigger always prompts; the Microsoft 365 read tool re-asks once. Combined with the "ask only on the in-app card" change, an unattended Cowork task that writes to GitHub through the connector will skip the write rather than hang. Tasks that must write need the tool allowed by an exact toolPolicy key, or should use a non-interactive path (git over HTTPS, a webhook).
plugins, skills & artifacts · Claude Code v2.1.309 Fixed plugins and skills synced from claude.ai being removed, sometimes mid-session, after a disk read error. Fixed artifact publishes and updates being refused for some ordinary pages (certain minified scripts, or artifacts Claude could not read first), and Claude asking for permission on every artifact update for the rest of a turn after a compaction. A skill in an --add-dir folder that shares a name with another is now offered as <folder>:<name>. Fixed messages from a Desktop-hosted session being lost when its connection refreshed. Plugins installed from a marketplace folder on this computer now have a Settings tab in Customize (Desktop v3.6556.1), so Code tab sessions run them with the values they ask for; values entered earlier in a terminal must be entered again there.
v3.6556.1 · other Screen readers now name the apps and access a computer-use request asks for, not just "Claude wants to use:". Storage cleanup covers inactive Cowork tasks and opens with /storage. Renaming an open artifact no longer reloads it and clears your typing.

Pro and Max, waitlist, shared usage limits. It overlaps with Cowork's scheduled tasks and Dispatch; expect questions about which to use. Details on the Desktop tab.

"Hand off to Claude Code" under a design's name opens Claude Code with a prompt to build the design in your codebase.
