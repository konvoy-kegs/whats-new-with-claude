Claude Code

CLI · v2.1.267 on latest and next
All sources aligned on v2.1.267. The newest build on npm, the latest dist-tag, the next dist-tag, the changelog top entry and the newest GitHub release all say v2.1.267, published 2026-09-09 18:25 UTC (Thu 10 Sep 04:25 local). claude update installs it. Yesterday's undocumented v2.1.266 turned out to be a single-line regression fix (details below) and has been superseded within a day, as expected. This is the version to roll out.
v2.1.267 is a 53-entry release with three things for this team: a hard cap on effort, fail-closed managed settings, and a large prompt-cache cleanup. maxEffortLevel caps the effort level on every provider including Bedrock, Vertex and Foundry — the first org-wide spend lever on effort. Managed allowedHttpHookUrls, httpHookAllowedEnvVars and allowedChannelPlugins now admit nothing rather than everything when unreadable. And roughly a dozen fixes stop resumed sessions, MCP reconnects and /model switches from rewriting the tool list and missing the prompt cache. Plus another backslash containment bypass, this time in fetched marketplaces.
v2.1.266 (Wed 09 Sep 09:32 local) was a regression fix for LLM-gateway and proxy setups. The undocumented CLAUDE_CODE_USE_GATEWAY variable began forcing Cloud-gateway sign-in on its own in v2.1.265, so configurations setting it alongside an API key, apiKeyHelper or custom auth headers failed every request with “Not signed in to the Cloud gateway”. The variable on its own is ignored again; no configuration change needed. If anyone on v2.1.265 behind our proxy hit that error yesterday, this is why.

v2.1.267 — effort cap, fail-closed managed settings, and a prompt-cache cleanup newest documented

Added maxEffortLevel setting (top-level or per model under modelSettings): caps the effort level on every provider, including Bedrock, Vertex and Foundry; users can still pick a lower level. This is the first org-wide ceiling on effort, and it works through managed settings on Bedrock. Combine with CLAUDE_CODE_SUBAGENT_MODEL_FORCE (v2.1.257) and you have a hard cap on both axes of spend. Paired: effort: frontmatter on custom commands, skills and subagents was being ignored on models whose default effort is still pinned (Opus 4.7, Opus 4.8, Fable 5) — fixed, so per-skill effort declarations now actually apply on those models.
Fixed managed allowedHttpHookUrls, httpHookAllowedEnvVars and allowedChannelPlugins to admit nothing, not everything, when unreadable. Until now a malformed or unreadable managed allowlist for HTTP hook destinations, the env vars hooks may forward, or channel plugins was treated as no restriction. A typo in managed settings was a silent full open. Now it is a silent full close, which is the correct failure mode — but expect “my hook stopped working” tickets if any of these three keys is currently malformed. Validate them before rolling out.
Fixed a case where a marketplace entry path containing a backslash could bypass the containment check for fetched marketplaces on macOS and Linux. Same shape as Wednesday's plugin-path fix in v2.1.265, one layer up: the marketplace manifest's entry paths rather than the installed plugin's. Second backslash containment bypass this week; the pattern is that every path check that assumed / as the only separator is being re-audited. If we host a marketplace, check no entry path contains \.
Roughly a dozen prompt-cache fixes, all in the “tool list rewritten mid-session” family. A tool disappearing from a disconnected MCP server no longer rewrites the tool list and discards earlier thinking; an MCP server re-sending a tool the model already loaded no longer drops earlier reasoning; mid-session MCP and plugin tools are delivered as deferred definitions on supported models instead of being spliced into the tool list; /model no longer re-sends every tool definition on a switch (commit and PR attribution text now arrives as a conversation note instead); a background worker forked from a conversation no longer adds EnterWorktree to the parent's tool block; resumed sessions replay recorded tool descriptions and MCP announcements instead of re-rendering them; a -p conversation resumed interactively keeps the same system prompt prefix; subagents and sessions started with --system-prompt or --append-system-prompt record the prompt once. Taken with v2.1.260 (/cost diagnosis) and v2.1.265 (three prefix fixes), this is the release that should make long agent-team and MCP-heavy sessions stop paying uncached input on every turn.
Fixed expired AWS or Google Cloud credentials under a host app such as Claude Desktop retrying ten times with a generic “request failed” before the re-authenticate error appeared. Anyone running Desktop-hosted sessions against Bedrock with SSO credentials has seen this: the session hangs through ten retries before telling you to log in again. Now the re-auth error surfaces immediately. Also: claude remote-control no longer exits and drops every attached session when its server credential expires (about 30 days after start) — the host re-registers and keeps going. If a long-lived Remote Control host died on you around the one-month mark, that was the cause.
Fixed Workflow agent() calls with large output schemas being refused in auto mode instead of being checked by the safety classifier. Large structured-output schemas were hitting a hard refusal path rather than the classifier. Also: resuming a large session (transcript over 5 MB) no longer drops parallel tool calls and their hook output; -p --resume after a /compact no longer inserts a spurious “Continue from where you left off.” turn; --resume first-render is faster for sessions with many Bash calls.
Added --system-prompt-snapshot off to render the system prompt fresh on every request instead of reusing the conversation's recorded prompt. This is the opposite of the cache work above and is meant for iterating on prompt text: turn it on while editing a system prompt, turn it off in production. Also: Fixed Cowork scheduled tasks in the cloud failing at startup for organizations whose managed settings require sandboxing — see the Cowork section, this affected exactly the configuration we run.
Artifact publishing hardened at the edges. Publishes cut off by a dropped connection mid-upload now retry once when Claude Code can tell the upload never completed, instead of reporting an unknown outcome; a page file that is not valid UTF-8 or contains U+FFFD now gets an error naming the line and column; a refused publish now says why and what to do. Together with v2.1.265's untrusted-content read and unknown-connector-tool refusal, artifacts have had a full week of hardening.
Gateway and self-hosted runner. Gateway: forward_user_identity upstreams now return a 429 as-is to a developer whose email was forwarded, instead of failing over to the next upstream, so the proxy's per-user limits hold. Self-hosted runner: --use-anthropic-git-proxy is reported to the server at registration and prints a warning for each session that still clones through the legacy git proxy. Also: /login on machines whose managed settings require gateway sign-in — Esc now closes the dialog; the usage-limit warning no longer flickers when requests for different models report different limit windows.
[VSCode] Fixed the extension host hanging at 100% CPU when forking, editing an earlier message, or rewinding in a conversation whose saved transcript contains a cyclic parent link. Also: accepting an edit on a CRLF file no longer fails with “String not found in file”; @-mentions keep files whose paths contain spaces; the sessions list loads over Remote-SSH when the workspace exists only on the remote host; runaway ripgrep processes in large or symlink-heavy workspaces are fixed; diff blocks follow the active theme. [Claude Code on the web] GitHub Enterprise Server tokens refresh automatically; gh and API calls work in orgs without the Claude GitHub App via your connected account. [Claude Tag] “Use a custom connector” link in admin preset forms; out-of-credits replies now say so; Connect on Tool access requests no longer fails with “Authorization failed”.
Also worth knowing: Remote Control clients joining a Claude Desktop or VS Code session no longer show a stale permission mode; /context output no longer renders blank on mobile; the Bash tool's guidance now has Claude describe a command in plain words instead of echoing it; sandbox guidance suggests /copy when pbcopy fails; the /diff panel no longer flashes “0 files changed”; shift+enter and option+backspace work again after reconnecting to tmux or ssh inside an agent view; claude agents @ menu lists repositories created after the session started.

Patterns worth tracking

The npm-first, changelog-later gap closed in under a day again. v2.1.266 hit npm on next Wednesday morning with no changelog; by Thursday it was documented, released and superseded by v2.1.267 with everything aligned. Two for two on the “wait a day” rule this week. The operational rule holds: the version to roll out is the one that is documented and promoted, and today that is also the newest number.
Fail-open is being hunted down. v2.1.260: permission rules with parentheses were silently dropped (fail-open). v2.1.265: plugin paths with backslashes skipped containment (fail-open). v2.1.267: three managed allowlists admitted everything when unreadable (fail-open) and are now fail-closed. Each of these was a control we could have set correctly and still had no protection from. The recurring lesson is to verify controls on a real machine, not just in the settings file.
Prompt-cache work has become the largest single category of fixes. Four in v2.1.260, three in v2.1.265, roughly a dozen in v2.1.267, all attacking the same root cause: something changing the tool list or system prompt prefix mid-session. MCP-heavy Cowork sessions and long agent teams are the beneficiaries; watch the cached-input ratio in the collector after upgrade.
Spend controls are consolidating into managed settings. Subagent model force (v2.1.257), Bedrock CountTokens (v2.1.260), per-user 429 passthrough at the gateway and maxEffortLevel on every provider (v2.1.267). Over two weeks the gateway plus managed settings have become a real policy point for cost, not just for auth and telemetry.

From v2.1.267 — expired AWS or Google Cloud credentials under Claude Desktop no longer retry ten times with a generic “request failed” before the re-authenticate error appears. This is the Desktop change of the day for anyone running Desktop against Bedrock with SSO. The hang-then-fail pattern becomes an immediate, actionable prompt to log in again.
From v2.1.267 — Remote Control clients that join a Claude Desktop or VS Code session no longer show a stale permission mode until it is changed again. Paired with Saturday's fix for the same symptom when a phone or browser attaches to a terminal session, permission mode is now consistent across every surface that can attach to a session. Also: /context and other local command output no longer render blank on mobile clients.
From v2.1.265, still landing — Claude Desktop and Cowork send user.email and user.groups in telemetry through the Claude apps gateway, and gateway sessions export OpenTelemetry directly to the collector named in managed settings. Fable 5.1 — 1M context, $10/$50 per Mtok — is the default Fable model in the picker where the organisation is entitled to it. Claude Cowork

GA · macOS & Windows · Linux beta

What's new

From v2.1.267 — Cowork scheduled tasks in the cloud were failing at startup for organizations whose managed settings require sandboxing. Fixed. This is exactly our configuration — cloud-run scheduled tasks under managed settings that mandate sandboxing. If any scheduled task (including this digest) reported a startup failure or silently did not run over the past week, this is the likely cause; re-check tomorrow's runs after the upgrade.
From v2.1.267 — artifact publishing is more reliable and better at explaining itself. A publish cut off by a dropped connection mid-upload now retries once when Claude Code can tell the upload never completed; a page file that is not valid UTF-8 (or contains U+FFFD) gets an error naming the line and column; a refused publish now says why and what to do. For a scheduled task that mirrors an artifact — as this one does — the retry alone removes the most common “unknown outcome” case.
From v2.1.267 — Workflow agent() calls with large output schemas were being refused outright in auto mode instead of being checked by the safety classifier. Fixed. If a Cowork workflow with a big structured-output schema was mysteriously refused under auto mode, it should now go through the classifier like everything else. Also: the Bash tool's guidance has Claude describe what a command does in plain words rather than echoing it — a readability win for the Cowork activity log.
From v2.1.267 — MCP connectors that reconnect, re-send or disappear mid-session no longer rewrite the tool list and drop earlier reasoning. Cowork sessions are the most connector-heavy sessions we run, so they were the most exposed to this class of prompt-cache miss. Resumed sessions also replay recorded tool descriptions instead of re-rendering them, and claude.ai connector tool changes between a session and its resume no longer break the cache.
From v2.1.267 — Claude Tag (Claude in Slack): a “Use a custom connector” link in the preset connection forms in admin settings; an out-of-credits organisation now gets a reply that says so and explains how to add more, instead of “The API rejected the request as invalid”; thread requests to edit or delete a top-level message Claude posted now reach the session that posted it; Connect on Tool access requests under Admin settings > Review requests no longer fails with “Authorization failed”.
From v2.1.265, still landing — artifact publish refuses connector tool names the connector does not expose; reading someone else's artifact treats it as untrusted and flags embedded instructions; Cowork gateway telemetry carries user.email and user.groups; remote sessions no longer keep their sandbox container alive while a connector approval waits; --plugin-dir accepts a folder of plugins. Support-centre Cowork release notes: no new entry since 25 Aug (memory in Cowork), re-checked this morning.
Standing context — plugins, skills, artifacts and scheduled tasks. Plugins bundle skills, connectors and sub-agents into one installable package; hooks and sub-agents run only in Cowork. /skill-doctor (v2.1.261) shows which installed skills never fire. Artifacts created on or after 19 Aug are shareable, connected, versioned and openable from the web. Cowork sessions run remotely in the cloud (beta) so scheduled tasks fire with no device online. Enterprise plans can turn on skill and plugin security scanning (6 Aug) — still worth enabling given two path-containment fixes in the CLI this week alone.
