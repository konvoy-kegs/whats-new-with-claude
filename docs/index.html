v2.1.312 — gateway user_id_claim, Bedrock behaviour changes for custom model names, managed-settings fix, hook concurrency cap, safety_event withdrawn Wed 28 Oct AEDT · 39 bullets · newest on npm

Claude apps gateway · identity Added oidc.user_id_claim to the Claude apps gateway, to identify people by an id_token claim other than sub, such as Microsoft Entra ID's oid. Until now the gateway keyed its per-user identity (the x-claude-gateway-user-id header, and user-scoped spend limits) on sub; Entra tenants that already track people by oid elsewhere can line the two up. The gateway configuration reference checked this morning still documents only email_claim and groups_claim under oidc, so treat the changelog line as the spec until the docs catch up — and note that changing the claim changes the user ID that existing spend-limit rules match on.
Bedrock, Vertex, Foundry & Mantle · custom model names Changed Bedrock, Vertex, Foundry and Mantle to use the shorter system prompt for model names Claude Code doesn't recognise, such as custom deployment names and inference profile ARNs, even when they front Sonnet or Haiku; set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 to keep the full prompt. Any Bedrock session that points at an inference profile ARN or an application inference profile rather than a bare model ID now runs on the shorter prompt, so outputs can drift from yesterday without any config change on our side. Changed automatic model switches after a flagged message to also cover model names Claude Code doesn't recognise, such as custom deployment names; set CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 to turn them off. Until now an ARN-addressed session stayed on its model after a refusal; it can now switch models mid-session, which matters wherever the ARN was chosen for region, cost or compliance reasons. "Mantle" appears for the second day running as a fourth provider name with no docs page yet.
managed settings & policy files Fixed managed settings and organization policy not being fetched for the rest of the session after signing in from the VS Code extension. A developer who signed in through the VS Code panel ran that session without the organisation's managed settings — permission rules, hooks policy, allowed MCP servers — until the next launch. Fixed Claude overwriting a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start; Write now asks Claude to read it all or edit in place. This is the data-loss cousin of the v2.1.311 stale-CLAUDE.md fix: a long rules file edited by Claude could have been truncated to the part it had read. Fixed per-directory and paths: skills not being found after a Bash cd deeper into a git repository — a skill scoped to infra/ silently disappeared once Claude cd-ed into it. Fixed a command with an invalid name stopping all commands from loading, which could leave claude -p with no output.
hooks & OpenTelemetry Changed prompt and agent hooks to run at most 24 at a time per session, sub-agents included, plus at most 12 that have waited longer than their event's timeout; a timeout under 1 second now counts as 1 second. Hooks that fan out per subagent (an audit-log hook on every tool call across a 20-agent team, say) will now queue rather than spawn unbounded; hooks with sub-second timeouts get a full second. Changed Claude Code to stop sending the claude_code.safety_event OpenTelemetry event — it was added in v2.1.307 on 21 Oct and is withdrawn six days later; the tool_decision event with its classifier fields (v2.1.300/301) remains the signal for blocked and prompted tool calls. Changed OpenTelemetry mcp_server.name to report the real name of fixed-URL remote MCP servers declared by plugins from the official Anthropic marketplace, instead of custom — dashboards grouping by that attribute will see new series appear and the custom bucket shrink. Fixed the spinner, OTel effort values and transcripts naming a newly picked effort level before the model applied it; they now show the level in force. Changed a subagent's autoCompactWindow to lower the window set by CLAUDE_CODE_AUTO_COMPACT_WINDOW, where it had no effect before; it still never raises it.
sessions, resume & UI Fixed a rare case where the first reply after resuming a session in the terminal could be missing the next time the session was resumed. Fixed the Read tool sometimes failing on PDF pages with "pdftoppm failed" when old-session clean-up ran at the same time. Fixed some sessions showing as waiting on you when the last message only mentioned items waiting on you mid-sentence. Added click to send: in fullscreen, clicking the "to send now" hint under a queued message sends it right away. Changed usage-limit messages to call the 5-hour window the "5-hour limit" instead of the "session limit"; VS Code shows the reset as a clock time. Changed cloud sessions started from the CLI to get their names and branch names from the server. Improved WebFetch errors in cloud sessions: a host that does not resolve is now explained as possibly outside the allowed network domains, so Claude names the host to allow. Fixed /verify showing its long model-facing description in /help; vim-mode d/c/y with an oversized gj/gk count now only moves the cursor; agent view no longer restores input cleared with Ctrl+C or reopens in shell mode after Ctrl+D.
VS Code, cloud sessions, Claude Tag & Code Review [VSCode] Sessions no longer end on a bare exit code when the organisation's settings couldn't be loaded or were refused at startup; the tab says why and offers Retry or Sign in again. [Cloud sessions] Added an effort level to the model picker when you create or edit a routine that runs in the cloud; added a Bash editor with colours, line numbers and Copy to the setup-script box in cloud environment settings; the step shown when Claude adds a repository now shows a short table instead of raw JSON; fixed resending an unchanged message after a failed send sometimes running it twice; fixed a failed environment creation showing its error only as a toast. [Remote Control] An unarchived session no longer shows as working until a computer reconnects. [Claude Tag] The retry notice in Slack names the model in use or says rate limits were hit; a channel's on/off switch and agent settings no longer fall back to workspace defaults when an older private channel goes public and gets a new ID; Claude now replies in channels whose environment has network access set to None; files no longer land in the wrong thread. [Code Review] Fixed Code Review reviewing an outdated commit, or none at all, when GitHub delivered a push event late; it now reviews the pull request's current commit.

Security & evals

v2.1.312 CLI: managed settings skipped after VS Code sign-in, large CLAUDE.md truncation, refusal fallback on ARN-addressed Bedrock models, safety_event withdrawn, hook concurrency cap · stable four behind

Today's actionable items

  • upgrade Fleet CLI target moves to v2.1.312. stable is now four releases behind on v2.1.308 and has none of the v2.1.309 sandbox fixes, the v2.1.310 Windows hooks fix, the v2.1.311 hook, subagent and retry fixes, or today's managed-settings and CLAUDE.md fixes. For runners, auto-mode pipelines and headless claude -p jobs, pin latest or an explicit 2.1.312 rather than waiting for stable.
  • managed settings not applied after VS Code sign-in Until v2.1.312, signing in from the VS Code extension left managed settings and organisation policy unfetched for the rest of that session. Every policy that lives in managed settings — permission deny rules, allowedMcpServers, hooks policy, allowManagedPermissionRulesOnly — was absent for developers who authenticated through the panel rather than the terminal. There is no audit signal for "ran without managed settings", so the practical move is to get VS Code users onto v2.1.312 first; the new "Retry or Sign in again" tab (also v2.1.312) replaces the old bare exit when org settings can't be loaded, so a session now fails visibly rather than running unpolicied.
  • refusal fallback now covers ARN-addressed Bedrock models Automatic model switches after a flagged message now also apply to model names Claude Code doesn't recognise (custom deployment names, inference profile ARNs). A Bedrock session pinned to a regional inference profile for data-residency or cost reasons can now switch to another model mid-session after a refusal. If the ARN was chosen deliberately, set CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 in managed settings; if not, at least know that the model in the transcript can differ from the one in the config.
  • shorter system prompt for unrecognised model names Bedrock, Vertex, Foundry and Mantle sessions on custom deployment names or inference profile ARNs now use the shorter system prompt, even when the ARN fronts Sonnet or Haiku. That is a behaviour change with no config change on our side; eval baselines captured against ARN-addressed models before today are against the full prompt. CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 keeps the full prompt. Worth a one-line note in the runner image's env until the fleet has decided which prompt it wants.
  • claude_code.safety_event withdrawn Claude Code no longer sends the claude_code.safety_event OpenTelemetry event introduced in v2.1.307 on 21 Oct. Any dashboard, alert or audit export built on it in the last week goes silent at v2.1.312 without an error. The durable signal for blocked, prompted and sent-back tool calls is still the tool_decision event with its classifier_verdict, permission_mode and classifier_category fields (v2.1.300/301). Separately, mcp_server.name now reports real names for fixed-URL remote MCP servers from official-marketplace plugins instead of custom, so per-server groupings shift.
  • hook concurrency cap Prompt and agent hooks run at most 24 at a time per session, sub-agents included, plus at most 12 that have waited longer than their event's timeout; a timeout under 1 second now counts as 1 second. A policy hook that was relying on a 500 ms timeout to fail fast now waits a full second; an audit hook fanned out across a large agent team will queue past 24 in flight. Neither breaks a deny, but both change latency, and a hook that was being killed at 500 ms and treated as "no decision" may now return one.
  • large CLAUDE.md / rules file truncation Claude could overwrite a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start; Write now asks Claude to read it all or edit in place. Check git history on any long rules file Claude has touched in the last few weeks for a commit that shortened it dramatically. Pairs with v2.1.311's stale-CLAUDE.md-after-compaction fix and v2.1.309's nested-CLAUDE.md-over-size-limit change: three releases in a row have touched how big policy files are read.
  • scoped skills vanished after cd Per-directory and paths: skills were not found after a Bash cd deeper into a git repository. A skill that encodes "how we deploy from infra/k8s/" was silently absent exactly when Claude was working in that folder. Fixed in v2.1.312; until then, keep load-bearing skills at repo root. Related: a command with an invalid name stopped all commands from loading, which could leave claude -p with no output and no error.
  • Claude apps gateway: oidc.user_id_claim New option to identify people by an id_token claim other than sub (Entra ID's oid, say). Changing it changes the identity that user-scoped spend limits and the x-claude-gateway-user-id header carry, so set it before rolling out spend limits rather than after. Not yet in the gateway configuration reference.
  • Code Review on late push events Code Review could review an outdated commit, or none at all, when GitHub delivered a push event late; it now reviews the PR's current commit. If a review check passed on a PR whose last push arrived after the review started, the check may not have covered the final diff.

Patterns worth tracking

stable is four releases behind and counting. It has sat on the one-line v2.1.308 since Thursday while v2.1.309 (79 bullets), v2.1.310 (26), v2.1.311 (92) and v2.1.312 (39) shipped on latest. Yesterday's note stands: if stable hasn't moved by Thursday, switch the fleet policy to an explicitly pinned latest version that this digest tracks, because stable is currently a snapshot of the week's least-documented build.
OpenTelemetry surfaces are churning week to week. claude_code.safety_event arrived in v2.1.307 and is gone in v2.1.312; mcp_server.name changed meaning; effort values now report the level in force rather than the level picked; v2.1.310 added agent_id/parent_agent_id/request_id. A sensible rule: don't alert on a Claude Code OTel event until it has survived two weeks of releases, and keep the tool_decision event as the one load-bearing safety signal.
Third-party providers keep getting their own behaviour. v2.1.310 brought the Monitor tool to Bedrock, Vertex and Foundry; v2.1.311 added the signed model catalog from downloads.claude.ai; v2.1.312 changes the system prompt and the refusal fallback for custom model names on the same four providers. Each change is reasonable, but a Bedrock session addressed by inference profile ARN now behaves differently from one addressed by model ID in three separate ways, none of which is in the docs yet. Keep the ARN-vs-model-ID decision written down per runner image.
Hooks are the recurring reliability theme, now with limits. v2.1.309 and v2.1.310 fixed hooks failing open on Windows and PowerShell; v2.1.311 fixed SubagentStop over-firing; v2.1.312 caps concurrency at 24 (+12 overdue) and rounds sub-second timeouts up. Hook semantics under subagents are being pinned down release by release, so any hook that is load-bearing for policy or audit deserves a regression test per release.
Policy files are being read more carefully. v2.1.309 capped oversized nested CLAUDE.md files to their start, v2.1.311 fixed stale content after compaction, v2.1.312 stops Claude truncating a large one on write and finds scoped skills after cd. Taken together: keep CLAUDE.md short and put the long material in skills, which is what Anthropic's own guidance says, and which these fixes make safer to rely on.
Desktop is now four CLI releases behind. v3.6556.2 (22 Oct) is still the newest Desktop build and bundles Claude Code 2.1.308, so the Code tab and local Cowork sessions are missing the v2.1.309 hardening, the v2.1.310 Windows hooks fix, the v2.1.311 unattended-session fixes and today's managed-settings fix. Desktop bumps have landed roughly weekly; the next one is the one to watch.
