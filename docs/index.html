Claude Fable 5

model · access restored

Access restored after export controls lifted headline

Source: Redeploying Claude Fable 5 · anthropic.com · posted 30 Jun, restored 1 Jul 2026

Fable 5 and Mythos 5 are back. On 30 Jun the US government lifted the export controls that had suspended both models since 12 Jun. Fable 5 returned on 1 Jul to users globally on the Claude Platform, Claude.ai, Claude Code, and Claude Cowork. Anthropic is re-enabling access on AWS, Google Cloud, and Microsoft Foundry “as quickly as possible” — those cloud paths may not be live yet. Mythos 5 has been restored for a set of US organisations (government approval on 26 Jun), with Glasswing access expanding from there. Access to all other models — Opus 4.8, Sonnet 5, Haiku — was never affected.
What this means for us: workflows pinned to claude-fable-5 on Claude Code and the API should work again. But Bedrock/AWS access is still being re-enabled — keep CI agents and Bedrock calls on claude-opus-4-8 until Fable 5 is confirmed live on AWS. Also note the new safety classifier (below) blocks more borderline requests during routine coding/debugging; any blocked request to Fable 5 is auto-routed to Opus 4.8, so callers should expect an occasional silent model switch on security-adjacent prompts.
  • status Export controls lifted 30 Jun; Fable 5 available again globally from 1 Jul across Claude Platform, Claude.ai, Claude Code, and Cowork. Cloud provider (AWS / Google Cloud / Microsoft Foundry) re-enablement is in progress, not confirmed complete.
  • safeguards Anthropic shipped an improved cybersecurity classifier that blocks the specific Amazon-reported bypass in >99% of cases; blocked requests are flagged and re-routed to Opus 4.8. It flags benign requests more often during routine coding/debugging — expect more false positives. US Commerce CAISI tested both the prior and new safeguards and rated them extraordinarily strong.
  • access & pricing The included Fable 5 allowance for Pro, Max, Team, and select (premium) Enterprise plans (up to 50% of weekly usage limits) ran through 7 Jul; that window has now closed, so continued access is via usage credits. Standard Enterprise seats have no included allowance — access is credits-only.
  • industry Anthropic, with Amazon, Microsoft, Google and other Glasswing partners, is drafting a consensus framework for scoring AI jailbreak severity, and has opened a HackerOne program for cyber-jailbreak submissions against Fable 5.
  • background Fable 5 launched 9 Jun as a Mythos-class model made safe for general use; Mythos 5 is the same model with fewer safeguards, restricted to Project Glasswing partners for defensive cybersecurity.

v2.1.214 — permission-security sweep, EndConversation tool, scheduled-task fix security

Published 18 Jul 2026 at 00:13 UTC · CHANGELOG · the biggest release since Friday: seven distinct permission-check fixes, a new safety tool, and a wide reliability sweep

Seven Bash/permission security fixes in one release — upgrade unattended and CI agents promptly. Fixed: a permission-check bypass in Windows PowerShell 5.1 sessions; single-segment dir/** allow rules like Edit(src/**) auto-approving writes to nested dir/ directories anywhere in the tree (now only <cwd>/dir); Bash permission checks now fail closed on file-descriptor redirect forms the analyzer parsed differently than bash; commands over 10,000 characters always prompt instead of running automatically; zsh variable subscripts in [[ ]] comparisons now prompt; certain help/man invocations that could run unsafe options or command substitutions are no longer auto-approved; and remote-session permission prompts can no longer proceed before the local confirmation dialog.
New EndConversation tool. Claude can now end sessions with highly abusive users or jailbreak attempts, as on claude.ai since 2025 — see Anthropic’s research post. Also new: permission prompts for docker/Podman commands carrying daemon-redirect flags (--url, --connection, --identity, remote mode) that previously ran without one.
Scheduled-task fix relevant to this digest: scheduled tasks no longer refuse their own configured prompt as untrusted input — the fired prompt is now delivered as the session’s assigned task. Plus a heartbeat for long-running tool calls that previously went silent.
  • observability Added message.uuid, client_request_id, and tool_source attributes to OpenTelemetry log events; CLAUDE_CODE_OTEL_CONTENT_MAX_LENGTH configures the 60 KB truncation limit; reasoning effort now included in the subagentStatusLine payload.
  • behaviour change Single-segment dir/** hook if: conditions now match only <cwd>/dir — write **/dir/** for any-depth matching (deny/ask rules keep any-depth match); file -m/-f now requires permission instead of being auto-allowed as read-only.
  • reliability Fixed streaming turns failing with “Socket is closed” behind corporate proxies on Windows; stream-json output no longer truncates at exit for slow-reading SDK consumers; unbounded memory growth from oversized --settings files fixed (>2 MiB now errors at startup); pkill -f patterns matching the CLI’s own process no longer kill the session (Linux).
  • windows PowerShell tool: commands no longer hang when a child process waits on stdin; Python UnicodeDecodeError/UnicodeEncodeError fixes; >/>> redirects on PowerShell 5.1 no longer write UTF-16LE files other tools can’t read.
  • background Background daemon shutdown no longer deletes its successor’s control socket; idle parked sessions no longer keep the daemon alive indefinitely; completed background sessions can be removed again via claude rm; sessions from non-git folders can be deleted from the agents view.
  • fix Plugins enabled via --settings load again (regression since v2.1.181); feature flags no longer go stale after OAuth token rotation; hooks with exit code 2 now block as documented even when stdout JSON fails schema validation; session cost/token telemetry no longer double-counts on cumulative message_delta frames.

v2.1.212 — /fork background sessions, runaway-loop caps, MCP auto-background now documented

Published 16 Jul 2026 at 19:20 UTC · CHANGELOG · Friday’s “undocumented” npm release now has its notes: workflow features, two safety caps, and a plan-mode security fix

/fork now copies your conversation into a new background session (its own row in claude agents) while you keep working; the in-session subagent it used to launch is now /subtask. Typing /resume in the agent view opens a picker of past sessions — including deleted ones — and resumes your pick as a background session.
Runaway-loop caps. Session-wide limits on WebSearch calls (default 200, CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION) and subagent spawns (default 200, CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION) stop runaway loops; /clear resets the budget. MCP tool calls running longer than 2 minutes now move to the background automatically (CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS to tune or disable).
  • security Fixed plan mode auto-running file-modifying Bash commands (e.g. touch, rm) without a permission prompt or SDK canUseTool callback; fixed worktree creation following a repository-committed symlink at .claude/worktrees, which could create files outside the repository.
  • feat claude auto-mode reset restores the default auto-mode configuration (with confirmation, --yes to skip).
  • reliability SIGTERM during a running Bash tool no longer orphans the command’s process tree in print/SDK mode; web search/fetch retry 529s and rate limits with bounded backoff instead of returning “API Error” text as results; prompt caching’s mid-conversation system block now works behind LLM gateways and custom base URLs (Bedrock, Vertex, 1P).
  • fix Conversations with many images no longer fail incorrectly with “Request too large”; /background on Windows works when Group Policy blocks PowerShell 5.1 (daemon prefers PowerShell 7); OTLP HTTP exports no longer rejected by Azure Monitor endpoints that refuse chunked transfer encoding.
  • behaviour change The Task tool’s mode parameter is deprecated (now ignored) — subagents inherit the parent session’s permission mode; Enterprise forceLoginMethod now enforced for VS Code, SDK, setup-token, and install-github-app logins, not just the terminal.

v2.1.211 — Bedrock/Vertex prompt-caching billing fix, permission-preview hardening

Published 15 Jul 2026 at 19:24 UTC · CHANGELOG · featured in Friday’s digest

Prompt-caching regression fixed on Bedrock, Vertex, Mantle, and Foundry. A regression was billing the trailing system context block as fresh input tokens on every request. Directly relevant to our Bedrock agents’ token spend — update CI/agent images and watch input-token costs drop.
  • security Permission previews relayed to chat channels now neutralize bidirectional-override, zero-width, and look-alike quote characters; in auto mode a PreToolUse hook’s ask decision now floors unsandboxed Bash at a prompt; file-upload validation hardened.
  • feat --forward-subagent-text flag / CLAUDE_CODE_FORWARD_SUBAGENT_TEXT env var includes subagent text and thinking in stream-json output; “always allow” rules now save at the repository root so worktree approvals persist.
  • aws Fixed Claude Code on Vertex and Bedrock attempting the default Opus model at startup when a model is explicitly configured; parallel sessions no longer all log out after wake-from-sleep on a shared credential store.
