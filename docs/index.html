Claude Code

CLI · v2.1.247 on next, v2.1.246 on latest
Sources do not agree this morning, and the difference is a release channel rather than a lag. The newest package on npm is v2.1.247, published 04:02 local today, and it already has a changelog entry (33 items) and a GitHub release tag (09:06 local). But it sits on the next dist-tag, not latest — latest is still v2.1.246. That means a plain claude update installs v2.1.246 right now; v2.1.247 is being trialled on the canary channel. This is the opposite of the usual pattern, where npm runs ahead of the changelog. Here the documentation landed first and the promotion has not happened yet.
v2.1.247 is a hardening release — the security items are about content Claude Code renders, not commands it runs. Two of them close terminal-injection paths: marketplace-supplied text in /plugin output is now escape-safe, and markdown hyperlinks pointing at network or automounter paths now render as plain text instead of clickable links. There is also a sandbox-cleanup bug that deleted dotfile-managed ~/.claude/settings.json symlinks (nix/home-manager, stow), and an availability fix for hooks that flood the conversation. For anyone on Bedrock, the notable line is that Claude is finally told when an MCP server fails to connect instead of silently concluding the tools do not exist.

v2.1.247 — terminal-injection hardening, a dotfile-eating sandbox cleanup, and MCP failures finally surfaced today's headline

33 entries · published Thu 27 Aug 04:02 local · currently on next only · source: CHANGELOG.md

Supply chain — marketplace-supplied text can no longer inject terminal escapes. “Improved plugin marketplace hardening: names containing control or invisible characters are rejected, and marketplace-supplied text in /plugin and claude plugin output is escape-safe.” A plugin marketplace is third-party content that Claude Code prints straight into your terminal, and a terminal will act on control sequences embedded in text it is asked to display. Names carrying control or invisible characters could also be used to make one plugin visually impersonate another. This matters directly to us: admins can point Cowork at a private marketplace backed by a GitHub repository, so the trust boundary is whoever can push to that repo. Action: take next if we run any marketplace we do not exclusively control, and review who has write access to the ones we do.
Rendered links — markdown hyperlinks pointing at network paths are now inert. “Changed terminal hyperlinks in rendered markdown: link targets that point at a network or automounter path, contain a control character, or lead with an invisible character now render as plain text.” Claude renders model output and file contents as markdown, and a terminal hyperlink is a clickable target the user does not see before clicking. A UNC or automounter path in that position means one click reaches out to a host of the author's choosing — the classic credential-leak shape on Windows, and an unwanted mount elsewhere. These now degrade to plain text. Read this together with the marketplace item: both are the same class of defect — untrusted content reaching the terminal with more authority than text should have.
Config integrity — the Bash sandbox cleanup was deleting dotfile-managed settings.json symlinks. “Fixed the Bash sandbox's after-command cleanup deleting a dotfile-managed ~/.claude/settings.json symlink (nix/home-manager, stow) when it is repointed outside the sandbox's writable area.” If anyone here manages dotfiles with home-manager, stow or chezmoi — and on this team that is likely — the sandbox could remove the symlink that supplies their Claude Code settings. The practical consequence is a developer silently dropping to default settings, including permission defaults, without an error to explain it. Worth asking the team directly whether anyone has had settings “reset themselves” this week.
AWS — Claude is now told when an MCP server fails to connect on Bedrock, Vertex and Foundry. “Improved Bedrock, Vertex, and Foundry sessions (and any with telemetry disabled): Claude is now told when a configured MCP server failed to connect, instead of concluding its tools don't exist.” This is the most consequential non-security line in the release for us. Previously a connection failure was indistinguishable from a tool that was never configured, so the model would quietly route around the missing capability and produce a plausible answer built without it. A silent capability gap is worse than an error, because the output still looks correct. Anywhere we run Claude Code against Bedrock with MCP servers attached, prior results that depended on a flaky server are suspect.
Availability — a noisy hook could wedge the session permanently. “Fixed a hook or background agent that printed megabytes of error output being able to overflow the conversation and wedge the session on ‘Prompt is too long’.” A misbehaving hook is normally a local annoyance; here it could render a session unrecoverable. Paired with a second fix for unbounded memory growth when a hook's or background task's output file could not be written — the file now records where the output was lost rather than accumulating it. Both matter for CI runners and long-lived automation, where nobody is watching the output.
Policy — organization sign-in enforcement now fails closed. “Changed organization sign-in enforcement to exit at start when the administrator's managed settings cannot be read, even if host-supplied or per-user Windows registry settings exist.” Previously an unreadable managed-settings file could let a session start under host or per-user settings instead — which is precisely the fallback an enforcement mechanism must not have. Related in the same release: analytics now stay off from startup rather than only after login when managed settings force gateway sign-in or a custom OAuth deployment, closing a window where telemetry left the machine before policy applied.
Context — Sonnet 5 now auto-compacts against its full 1M window. “Changed Sonnet 5's default auto-compact window to its full 1M context, so sessions on the 1M window now auto-compact at about 967K tokens instead of about 934K.” A free ~33K tokens of headroom before compaction on every long Sonnet 5 session, and one fewer compaction on work that was previously landing just over the old threshold.
Cost — /claude-api cost-optimize, plus Admin API coverage in the bundled skill. A new workflow that profiles an existing project's Claude API spend and works through cost levers — caching, token hygiene, batch, effort, model choice — one measured change at a time, which is the right shape for this: cost work fails when several levers move at once and nothing is attributable. The /claude-api skill also gained Admin API coverage: organization members, invites, workspaces, API keys, rate limit reports, workload identity federation and CMEK. Between this and v2.1.243's modelPricing, the tooling for answering “what is this costing us and why” is now actually present.
Reliability — sub-agents no longer die on a first-call model 404. They now fall back through the session's model chain, and the error returned to the parent includes the error type, status, request id and model. A subagent dying on an unavailable model was previously an opaque failure mid-workflow; now it degrades and reports something you can act on. Relevant anywhere we pin subagents to a specific model id, especially Bedrock and Vertex spellings.
  • feat SendFeedback tool — when something goes wrong in a session, Claude can draft a feedback report for you to review and send from /feedback. Turn off with the feedbackDrafts setting.
  • feat spinnerTipsOverride gains structure — {id, text, cooldownSessions, priority} entries, a tipsFile, and a label, so an organization can rotate its own tips alongside the built-in ones. A low-effort channel for internal conventions.
  • feat Bash permission prompts now point at auto mode with a one-keystroke “Yes, and switch to auto mode” option.
  • fix Cloud sessions no longer go silent when the container restarts mid-turn while a background agent, shell or monitor is running — the resumed session now reports the lost work.
  • fix /compact and “Summarize from here” in --agent sessions were summarizing under the default system prompt instead of the conversation's own.
  • fix A version-less marketplace plugin's live cache directory was deleted and recreated on a second-scope install, which could disrupt a session already using it.
  • fix /terminal-setup was overwriting an entire Zed keymap.json instead of merging in its keybinding.
  • fix First-run setup exited with “Unable to connect to Anthropic services” when managed settings configure gateway sign-in and Anthropic's own endpoints are unreachable — a misleading error in exactly the network posture an enterprise deployment has.
  • fix Ctrl shortcuts under non-Latin keyboard layouts (e.g. Cyrillic) in kitty-protocol terminals, and stray <35;150;7M mouse-report text appearing in the prompt.

Still worth actioning from yesterday carry forward

v2.1.246 — rotate any LLM gateway API key. Telemetry and metrics requests to Anthropic were carrying the API key configured for a third-party gateway via ANTHROPIC_BASE_URL. A credential minted for our gateway was being sent to a host that is not our gateway — that is a disclosure, and the response to a disclosed credential is rotation, not just an upgrade. This is on latest today, so there is no reason to still be exposed.
v2.1.246 — audit Bash allow rules with a wildcard before the subcommand. A rule like Bash(git * main) also matches options inserted before the subcommand (git -c ..., git --exec-path=...), which changes what the command does. v2.1.246 adds a startup warning but does not narrow the rules for you. Same release also made malformed commands with a dangling && or || fail closed.
v2.1.246 — the background retention sweep was deleting git worktrees you created yourself under .claude/worktrees/ when a stale background-session record pointed at them. Treat that directory as unsafe for anything unpushed until everyone has upgraded.
v2.1.245 — startup crash on glibc 2.44 (Arch, CachyOS, Fedora Rawhide). Only relevant if a developer image or CI runner is built on a rolling-release base.
v2.1.243 — modelPricing, and a 4.5× smaller Linux binary. Contracted per-model rates now drive /cost, the status line and telemetry instead of list price. Separately, zstd compression takes the Linux x64 binary from ~340 MB to ~75 MB with 40–70 MB less memory per session — which changes the economics of baking Claude Code into container images and CI runners.

Security & evals

three new items today

This week's actionable items

1. New — review write access to any plugin marketplace we run. v2.1.247. Marketplace-supplied text in /plugin and claude plugin output is now escape-safe, and plugin names containing control or invisible characters are rejected. Before this, a marketplace could put terminal control sequences into a developer's terminal, and could name a plugin so it visually impersonated another. The trust boundary for a GitHub-backed private marketplace is whoever can push to that repo. Action: enumerate the marketplaces configured across the team, confirm branch protection and write access on the repos behind them, and take @next on any machine that consumes a marketplace we do not exclusively control.
2. New — terminal hyperlinks to network paths are now inert. v2.1.247. Rendered markdown link targets that point at a network or automounter path, contain a control character, or lead with an invisible character now render as plain text. A terminal hyperlink hides its target; a UNC path in that position turns one click into an outbound connection to a host chosen by whoever authored the text — and on Windows that is the standard credential-leak shape. Since Claude renders both model output and file contents, the author is not necessarily anyone we trust. Same class as item 1: untrusted content reaching the terminal with more authority than text should have.
3. New — organization sign-in enforcement now fails closed. v2.1.247. When the administrator's managed settings cannot be read, Claude Code exits at start rather than continuing under host-supplied or per-user Windows registry settings. An enforcement mechanism with a fallback to less-privileged-source settings is not an enforcement mechanism. Alongside it, analytics now stay off from startup rather than only after login when managed settings force gateway sign-in or custom OAuth — closing a startup window where telemetry left the machine before policy applied. Both matter only if we rely on managed settings for policy; if we do, they matter a lot.
4. Carried — rotate every LLM gateway API key. v2.1.246, on latest. Telemetry to Anthropic was carrying the key configured for a third-party gateway via ANTHROPIC_BASE_URL. Upgrade is not sufficient; the credential was disclosed and needs rotating. Second credential-scoping fix in four days after v2.1.243's ANTHROPIC_AUTH_TOKEN attribution fix, so audit the whole gateway configuration rather than this one path.
5. Carried — one careful pass over Bash allow rules and hook conditions. v2.1.243 and v2.1.246. Three defects in a week in Bash-pattern matching inside gating mechanisms: wildcards before a subcommand matching injected options, malformed commands not failing closed, and hook if conditions firing on unrelated commands containing $() or backticks. Review the rule set once, properly, rather than three times reactively.
6. Carried — data loss under .claude/worktrees/. v2.1.246. The background retention sweep removed git worktrees created by the user when a stale background-session record pointed at them. Integrity and availability rather than confidentiality, but the failure mode is unexplained missing work.

Sandboxing and isolation notes

New — the sandbox's after-command cleanup was deleting dotfile-managed settings.json symlinks (v2.1.247). Where ~/.claude/settings.json is a symlink managed by nix/home-manager or stow and repointed outside the sandbox's writable area, cleanup removed it. The developer silently drops to default settings — including permission defaults — with no error explaining why. Ask the team whether anyone has had settings apparently reset themselves this week.
New — hook and background-task output can no longer wedge or balloon a session (v2.1.247). Megabytes of error output from a hook or background agent could overflow the conversation and lock the session on “Prompt is too long”; separately, memory grew without bound when a hook's output file could not be written. Both are unattended-automation failure modes — CI runners and scheduled tasks, where nobody sees the output.
Carried — sandbox filesystem config was ignoring --setting-sources (v2.1.246). Where we use that flag to make a specific settings set authoritative — typically CI and managed environments deliberately excluding user or project settings — the sandbox's filesystem rules were not derived from the same set.

Claude Desktop

macOS · Windows · Linux (beta)

What's new

Sources: support.claude.com release notes (newest entry 25 Aug — unchanged since yesterday), platform release notes, Claude Desktop help. Checked Thu 27 Aug 2026.

New today — the desktop app was being told a session was ready before it was. v2.1.247: “Fixed self-hosted runner sessions reporting running before Claude Code had started, which could trigger a premature ‘Claude is waiting for your input’ notification from the Claude desktop app.” A notification that fires before there is anything to respond to trains people to ignore the notification — worth having if anyone here runs self-hosted runners alongside the desktop app.
Memory now spans chat and Cowork, and the default differs by plan (25 Aug). Everything Claude remembers is listed under Topics in Settings > Memory, where any item can be edited or deleted. Memory is on by default for Free, Pro and Max, and off by default for Team and Enterprise organizations. On a Team or Enterprise plan nothing is retained unless somebody turned it on — so this is a decision to make deliberately, not a change that has already happened to us. See Use Claude's chat search and memory.
Sensitive topics are excluded unless explicitly opted in. Categories such as health and beliefs stay out of memory unless Include sensitive topics in memory is turned on. It is a per-user toggle — worth knowing it exists before anyone asks what memory is allowed to hold.
Carried forward — MCP sign-in from the desktop app was failing on a whole class of server. v2.1.243 fixed “Invalid redirect URI” on servers supporting client ID metadata documents, with Linear named as an example. If anyone tried to connect an MCP server from Desktop recently and hit that, retry after updating.
Standing context — the Customize panel, plugin governance and Cowork GA. Claude Cowork is generally available on macOS and Windows through the Claude Desktop app, with Linux in beta, on all paid plans, and available on web and mobile since 7 Jul. A Customize section groups skills, plugins and connectors in one place. Also live: the monthly recap at Settings > Reflect, break reminders and quiet hours at Settings > Time and focus, and a managed marker in /mcp and /plugins showing which connector credentials are the organization's rather than the user's.

Claude Cowork

Generally available · cloud sessions in beta

What's new

Sources: Release notes — 25 Aug entry, Use Claude Cowork on web, desktop, and mobile, Get started with Claude Cowork, Use Claude Cowork safely. Checked Thu 27 Aug 2026.

New today — a cloud session whose container restarts mid-turn no longer goes silent (v2.1.247). “Fixed cloud sessions going silent when the session's container restarts between turns while a background agent, shell, or monitor is still running — the resumed session now reports the lost work.” This is the single most relevant line in today's release for scheduled tasks. A container restart during a long unattended run previously produced a session that simply stopped, with the work it had in flight unaccounted for. Now the resumption tells you what was lost, which is the difference between a run you can trust and one you have to re-do blind. Related: a background session that showed “opening…” forever in claude agents after its terminal host died now fails within seconds with a reason.
New today — MCP failures no longer look like missing tools. On Bedrock, Vertex, Foundry and any session with telemetry disabled, Claude is now told when a configured MCP server failed to connect rather than concluding its tools do not exist. For a scheduled Cowork task this is the difference between a run that fails and a run that quietly produces a worse answer. A task that depends on a connector which was briefly unreachable would previously have completed, without the connector, looking entirely normal.
New today — a marketplace plugin's live cache can no longer be pulled out from under a running session. A version-less marketplace plugin's live cache directory was deleted and recreated on a second-scope install, which could disrupt a session already using it. Relevant if we install the same plugin at both user and project scope, which is easy to do accidentally.
Memory now works across chat and Cowork in the cloud (25 Aug). Memory was previously a chat-side concept; it now spans both surfaces for cloud sessions. The governance-relevant detail: off by default for Team and Enterprise, on by default for Free, Pro and Max. Cowork sessions touch files, connectors and internal systems, so a memory store spanning them is a materially different proposition to one spanning chat alone — worth an explicit decision rather than leaving it to individual toggles. Everything retained is inspectable and deletable under Settings > Memory > Topics.
The operational rule that keeps catching people: scheduled tasks run with no device online. They execute on Anthropic's servers rather than a laptop, so they no longer need the machine awake or the app open. The corollary is the trap: a scheduled task cannot reach local files unless the desktop app happens to be open on that machine. Anything that must touch local state needs to be designed around that, not assumed.
Carried forward — two v2.1.246 fixes aimed squarely at unattended runs. Non-interactive sessions now automatically continue a response cut off mid-stream by a server error, connection loss or stall; and MCP tool calls interrupted in headless/remote sessions are reported as interrupted rather than “completed with no output”. Together with today's container-restart fix, three of the four ways a scheduled task could silently degrade have now been closed in two releases.
Standing context — plugin and skill governance for Team and Enterprise. (1) Org-wide skill management — a skill uploaded through organization settings appears for everyone under Customize > Skills. (2) Admins can create private plugin marketplaces, including from a GitHub repository — see today's marketplace hardening item; that repo's write access is the trust boundary. (3) Enterprise skill and plugin security scanning (6 Aug, beta) checks third-party skills and plugins for malicious content on upload or edit. (4) Plugin OpenTelemetry now distinguishes admin-install, so “what did we push versus what did people add themselves” is answerable from telemetry.
