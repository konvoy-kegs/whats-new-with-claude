All sources aligned on v2.1.319. The newest version on npm is v2.1.319, published 2026-11-06 00:58 UTC (Fri 06 Nov 11:58 AEDT); latest and next both point at it, the changelog's top entry is v2.1.319 (146 bullets), the GitHub release is v2.1.319 (2026-11-06 17:04 UTC, Sat 07 Nov 04:04 AEDT) and code.claude.com serves it. claude update on the default channel pulls 2.1.319. It shipped about two hours after Friday's digest went out, so this is the first morning it appears here; nothing has been published to npm in the roughly 70 hours since (the weekend). stable is still v2.1.311.
What matters this morning. (1) Move the pin to 2.1.319. It is the biggest release since v2.1.299 and the most security-relevant in three weeks: a Bash permission bypass where a crafted environment prefix could hide part of a command from permission checks, a sandbox escape when creating a worktree, a sed command that could skip the permission check in accept-edits and auto mode, /rewind restoring or deleting files through a directory symlink, and Bash deny/ask rules missing commands written with quoted words. Every one of those is a reason not to leave runners or claude -p jobs on 2.1.318. (2) Auto mode changes behaviour behind LLM gateways and with telemetry or feature flags off. Calls the server cannot check are now asked about or denied, with no fallback to the built-in classifier; CLAUDE_CODE_AUTO_MODE_SERVER=0 keeps the old behaviour, and =1 turns the server-side check on even with CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS set. Bedrock, Vertex and Foundry are unchanged. A headless job in auto mode that gets no safety check now exits 1 instead of 0. (3) Two new switches for unattended runs: permissions.denyInsteadOfPrompting (a tool call that would wait on a prompt is denied and the turn continues — terminal, subagents and teammates) and MCP tasks moving to the background the moment a server runs a tool call as a task. (4) Desktop is now two releases behind. v4.23118.0 still bundles 2.1.317, so the Code tab and local Cowork sessions have neither Wednesday's --continue fix nor Friday's security fixes; the connector-name rule fix for Desktop (mcp__claude_ai_Slack entries in deny lists being ignored) is in 2.1.319 and takes effect only once a Desktop build ships it. (5) Dates this week: the Plugins page is GA today; Unified Claude switches on tomorrow for any Desktop policy with no desktopHome (the gateway now warns about exactly that at start-up); the 6 Nov release note adds Enterprise project tags for cost-code spend reporting.

v2.1.319 — permission bypass and sandbox-escape fixes, auto mode without the classifier fallback, denyInsteadOfPrompting, MCP tasks in the terminal, gateway spend and log controls Fri 06 Nov AEDT · 146 bullets · latest · 18 Added, 90 Fixed, 16 Improved, 19 Changed, 2 Removed, 1 Updated

security fixes Fixed a Bash permission bypass where a crafted environment prefix could hide part of a command from permission checks. Fixed a sandbox escape when creating a worktree. Fixed a case where a sed command could skip the permission check in accept-edits and auto mode. Fixed a case where /rewind could restore or delete a file through a directory symlink. Fixed a case where Bash deny and ask rules missed commands written with quoted words. Fixed self-hosted runners: --trust-workspace false now also stops hooks in the repository's settings files and skills from running. Fixed a request that kept failing with a 401 refreshing your login on every retry and causing 401s in your other sessions. Fixed cloud sessions losing session-scoped deny and ask rules (such as those a PermissionRequest hook adds) when the session moves to a new worker; cloud sessions now drop session-scoped allow rules at a worker move when deny and ask rules can't all be kept, so you may be asked again. Fixed deny and ask rules, hook matchers and disallowedTools entries written with a claude.ai connector's terminal name (mcp__claude_ai_Slack) being ignored in Claude Desktop — takes effect once Claude Desktop includes this version, which v4.23118.0 does not.
auto mode Changed auto mode with telemetry or feature flags off, including behind LLM gateways: calls the server can't check are asked about or denied, with no fallback to the built-in classifier. Set CLAUDE_CODE_AUTO_MODE_SERVER=0 to keep using the built-in classifier; Bedrock, Vertex and Foundry are unchanged. Behind an LLM gateway, CLAUDE_CODE_AUTO_MODE_SERVER=1 turns on the server-side check even with CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS set; if managed settings set the latter, they must set the 1 too. Fixed the case where =1 in managed settings was ignored behind a gateway whose URL is set only there. A project's settings files or a plugin can no longer switch the server-side check back on once you have switched it off outside the project. Fixed claude -p exiting 0 in auto mode when its actions were refused because no safety check was available: text and JSON output now exit 1. Fixed /status showing "Auto mode server: Enabled" when the review isn't reaching the session. Fixed auto mode refusing actions without saying why when permission rules or autoMode settings are very large: it now explains and, unless autoMode deny rules are set, asks in the terminal. Fixed a case where auto mode was wrongly refused when a client sent a model change and an auto-mode request back to back.
permissions and unattended runs Added permissions.denyInsteadOfPrompting: a tool call that would wait on a permission prompt is denied and the turn continues, in terminal sessions, subagents and teammates. Changed Monitor's WebSocket watch to follow a rule on every Bash command: a deny refuses it, and under an ask rule an allow on Monitor, bypass mode or auto mode no longer skips the prompt. Changed the Bash tool to ask before running which with flags outside a lookup/display set. Changed a session's exact Bash or PowerShell ask rule to be refused, not asked about, when a broader deny rule covers the command. Changed --add-dir directories to register plugin marketplaces only once that directory's own trust dialog has been accepted. Changed nested skill loading: with the Bash sandbox on, skills in .claude/skills folders below the starting folder load only if you start Claude Code there or /cd there. Changed CLAUDE_CODE_PROXY_RESOLVES_HOSTS so settings files can no longer set it where the host manages the network. Fixed needless prompts for read-only commands wrapped in a plain timeout DURATION. Changed PostToolUse hooks to run, with up to 10 seconds to finish, on tool calls that finish after a new message interrupts the turn.
MCP tasks, feature flags and the terminal Added support for MCP tasks in the terminal: when an MCP server runs a tool call as a task, Claude Code moves it to the background right away and tells Claude the result when it finishes — works without feature-flag fetching (Bedrock, Vertex, Foundry, LLM gateways, DISABLE_TELEMETRY); CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND makes Claude Code wait inside the tool call instead, CLAUDE_CODE_DISABLE_MCP_TASKS=1 turns them off. Added CLAUDE_CODE_DISABLE_FEATURE_FLAGS, which stops feature-flag fetching without turning off telemetry; every flag then uses its built-in default. Fixed MCP servers on the older handshake failing to connect, or returning empty results, because Claude Code declared an extension it only uses with newer servers. Fixed a long-running MCP tool call on a claude.ai connector sometimes never reporting its result after --resume. Fixed claude -p --resume with a prompt losing a deferred tool call when its MCP server is missing: the run now exits 1. Added an "Earlier in this session" row to /tasks listing finished subagents, so you can reopen one and message it. Added /claude-api latency-optimize. The /model picker groups older models under a "More models" row; /context keeps the table Claude reads short and no longer re-sends its visual grid every turn.
Claude apps gateway Added spend for today, this week and this month to /usage for developers behind a Claude apps gateway who have no spend limit, when the gateway runs this version or later. Added admin.pooled_conflict_rule and admin.pooled_priority_order, to set which pooled group budget pays first for a developer in several groups. Added an optional login_notice setting shown on the gateway's browser verification page and on Claude Code's sign-in screen. Added CLAUDE_GATEWAY_LOG_FORMAT=json: operational log lines become JSON with severity, time and message. Added boot warnings for: another policy's availableModels allowing a custom model id one policy lists by name; policies with no desktopHome that rely on coworkTabEnabled: false or chatSessionRetentionDays, ahead of Claude Desktop's November 10 change; upstreams that mix AWS GovCloud with other upstreams; base URL variables in the gateway's environment; managed settings naming an Amazon Bedrock guardrail in a header the gateway doesn't forward. The spend limit error now reads "spend limit reached · resets Dec 1", then admin.blocked_message. Fixed Claude Desktop offering a web search tool that always failed when every upstream is Amazon Bedrock. Fixed a terminal whose gateway sign-in had expired sending telemetry and managed-settings requests the gateway logged as invalid_token.
sign-in, config files and TLS Added a warning when your claude.ai login ends and Claude Code continues on the sign-in from ant auth login, which bills usage to your Claude Console organization, and a line at startup naming the organization billed. Fixed edits to a settings file being ignored when made within a few seconds of Claude Code writing that file. Fixed a config file left at the legacy name hiding your setup with no warning: Claude Code now says on stderr when a home holds two config files, and which is in use. Fixed ~/.claude.json, settings and edited files ending up empty or cut off when the disk fills during a save in a read-only folder or to a bind-mounted file; on Windows, config saves wait longer for a file another program has open. Fixed a case where Claude Code listed every project file at start on Linux for projects on NFS, SMB or Lustre. Changed the automatic certificate repair behind a TLS-inspecting proxy: it no longer runs when ALL_PROXY is the only proxy variable set — set HTTPS_PROXY to the proxy's http:// URL instead. With CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC set, Claude Code now makes a TLS handshake with the configured API host after a certificate failure (no API request) so certificate errors don't persist. Fixed Monitor's WebSocket watch failing with "could not resolve" behind a proxy when CLAUDE_CODE_PROXY_RESOLVES_HOSTS is set. Fixed detailed beta tracing not presenting CLAUDE_CODE_CLIENT_CERT to collectors that require a client certificate.
runners, cloud sessions, loops and background work Self-hosted runner: CLAUDE_RUNNER_CHECKOUT_PATH now gives each repository in a session its own folder (-2, -3, … on a name clash); removed the end-of-session upload of a session's debug log — a failed session's log stays on the runner host unless --remove-session-state is set; a runner started with --use-anthropic-git-proxy or --configure-git no longer registers before a failed startup check exits it; a runner whose model-access renewal keeps being refused now retries sooner and posts a warning in the session. [Cloud sessions] Fixed scheduled tasks silently dropping a connector named memory: runs now keep it, mounted under that name plus a short suffix. [Cloud sessions] Fixed "Send now" on a waiting message ending running background agents. Fixed /permissions in cloud sessions replying only that it isn't available; it now says where the rules live. Changed self-paced /loop to end when a turn finishes without rescheduling instead of scheduling a fallback wakeup (CLAUDE_CODE_LOOP_KEEPALIVE=1 for the old behaviour); /loop confirmations in cloud sessions now note that a timer stops with its container. Fixed /clear killing running commands of background agents, teammates and workflows. Fixed background Bash commands that finish almost instantly losing their output. Fixed the OTel claude_code.session.count metric counting Agent SDK prewarm() processes that were never claimed. Fixed claude remote-control exiting silently with status 0 when a first-run question gets no answer; it now says why and exits 1. Fixed CLAUDE_CODE_RESUME_INTERRUPTED_TURN re-running a plan-mode turn when the session resumes in another permission mode.
everyday terminal fixes, Chrome, IDE, Claude Tag Fixed /diff showing "Diff unavailable" (and a session's diff failing to load on claude.ai and mobile) when the repository has a file or folder named HEAD; fixed the /diff pane opening blank after 64 or more editing turns. Fixed slash commands typed after a leading space, tab or newline being sent as plain text. Fixed Write ending the turn as a refusal when it couldn't read the file to overwrite. Fixed a mistyped model name such as opus-5-5 telling you to update Claude Code instead of suggesting the model you meant. Claude in Chrome: removed shortcuts_list and shortcuts_execute from the built-in tools; waits up to 6 seconds for the session's own browser to return after a disconnect; javascript_tool results up to 60,000 characters stay in the conversation; checks the page before repeating an action that may have run after a mid-action disconnect. [VSCode] Fixed Claude carrying out an unapproved plan after a window reload; prompts over 50,000 characters now stay in the box with a notice instead of being cut silently; the plugin-marketplace removal confirmation checks which plugins are installed. [Claude Tag] Admins can launch without picking a channel when the channel list couldn't load; saving auto mode allow rules no longer overwrites another admin's changes; a Claude Tag row on the Models admin page for Enterprise orgs. [Code Review] Unlinking a GitHub organization also turns off its All repositories setting, and it stays off after relinking.

Current lineup and what changed

  • Haiku 5.5 claude-haiku-5-5 — default Haiku on the Anthropic API since 2.1.293 (7 Oct); 1M context.
  • Sonnet 5.5 claude-sonnet-5-5 — default Sonnet in Claude Code (28 Sep).
  • Opus 5.5 claude-opus-5-5 — default Opus (22 Sep). Also the model behind Claude Duet, and the named migration target for Opus 4.8 fast mode.
  • Fable 5.1 claude-fable-5-1 — top tier (1 Sep); 1M context in Claude Code. fable/best aliases retry once on the previous Fable model when the newest isn't enabled for your org (since 2.1.301).
  • Opus 4.8 fast mode · deprecated (v2.1.316, Desktop v4.16336.0) Deprecated as of 30 October 2026; removed 30 November 2026. After removal, fast-mode requests on Opus 4.8 return an error and do not fall back to standard Opus 4.8. The Desktop changelog carries the same line, so Code-tab and Cowork sessions are covered by the same date. Opus 4.8 itself (28 May) is not being removed. 21 days.
  • model picker and names (v2.1.319) The /model picker groups older models under a "More models" row instead of listing them after the current ones. A mistyped model name such as opus-5-5 now suggests the model you meant instead of telling you to update Claude Code. The gateway warns at boot when another policy's availableModels also allows a custom model id that one policy lists by name.
  • spend visibility (v2.1.319 / 6 Nov release note) /usage shows spend for today, this week and this month for developers behind a Claude apps gateway with no spend limit (gateway on 2.1.319 or later). admin.pooled_conflict_rule and admin.pooled_priority_order decide which pooled group budget pays first. Separately, on claude.ai: Enterprise organisations can now tag projects with the cost codes they already use (WBS code, charge code, client-matter number) and see most spend in those projects by tag (beta, 6 Nov). Covers chat, unified Chat/Cowork and local Cowork tasks in a project (Desktop 3.6556.1+), and Claude Code once the project is set (2.1.305+). Does not cover Claude Code on the web, Claude Code through Bedrock, Vertex, a gateway or an API key, the API/Console, Chrome, Design or Slack/Teams. Not available to HIPAA, CMEK, ZDR or non-US-storage orgs, or to orgs that route Desktop through their own provider.
  • subagents and model switching (v2.1.318) Subagents stop instead of switching models when "Switch models when a message is flagged" is set to "Ask each time". Background subagents move a shell command to the background after 3 minutes on all providers so the prompt cache doesn't expire; on Bedrock, Vertex, Foundry, or with telemetry off, a progress summary on a cold cache can wait up to 5 minutes.
  • telemetry by plan and provider (v2.1.317) anthropic.plan, anthropic.seat_type, anthropic.provider and anthropic.custom_base_url on OTel metrics, events and spans. The gateway's GET /v1/organizations/analytics/cost report gives the same split per developer, per day and per IdP group from the server side.
  • subagent effort (v2.1.316 / v2.1.317 / v2.1.318) CLAUDE_CODE_SUBAGENT_EFFORT sets the effort subagents run at when nothing else names one; subagents and teammates on a different model use that model's saved effort level; a mod's $.model.fork takes an effort option. CLAUDE_CODE_DISABLE_ULTRATHINK turns the keyword off.
  • per-session cost and gateway spend in Desktop (v4.16336.0 / v4.23118.0) With inferenceModelPricingEnabled on, each session's estimated cost shows above the message box in Cowork, Chat and Code. v4.23118.0 adds "Apps gateway admin" to the user menu, where a gateway's spend admins set spend limits and pooled budgets, see spend, and export it.
  • prompt caching on [1m] spellings (v2.1.317) DISABLE_PROMPT_CACHING_OPUS and DISABLE_PROMPT_CACHING_SONNET had no effect on [1m], other-region and undated spellings of the default model. Fixed.
  • model names behind gateways (v2.1.314) Model IDs spelled with a dot behind an LLM gateway, such as claude-opus-4.8, were treated as an older model with the wrong context window, output limit, effort, thinking mode and cost. Fixed.
  • cloud-provider aliases (v2.1.316) sonnet, opus and haiku on Vertex AI and Amazon Bedrock switch to an older model mid-session instead of erroring when the newest isn't yet available to the account or region; the gateway checks every model a request names against the allow- and deny-lists.
  • ultrathink = xhigh effort (v2.1.311) In the terminal and VS Code, ultrathink runs the turn at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 through Anthropic's API. The stable build.
  • signed model catalog on cloud providers (v2.1.311) Claude Code on Bedrock, Mantle, Vertex and Foundry loads model settings from a signed file on downloads.claude.ai; CLAUDE_CODE_MODEL_CATALOG=off disables it.
  • API version 2026-10-21 (v2.1.307) /claude-api api-version moves your code to it. Check the Claude API release notes before switching production services.
  • Claude Duet (21 Oct) Research preview of a proactive-agent app built around Opus 5.5, Pro and Max, waitlist. Third-newest entry on the Claude apps release notes, after the 5 Nov Enterprise security update and the 6 Nov project-tags entry.
  • plans Max and Team plans include monthly API credits for the Claude Platform (7 Oct).
  • Claude Platform · message threads (2 Nov) New in the Messages API: send the conversation once and the API receives only what's new on every turn, aimed at long-running agents. Make long-running agents faster with message threads.

It closes a Bash permission bypass (a crafted environment prefix could hide part of a command from permission checks), a sandbox escape when creating a worktree, a sed command skipping the permission check in accept-edits and auto mode, /rewind restoring or deleting a file through a directory symlink, and Bash deny and ask rules missing commands written with quoted words. The first three are the kind of thing that matters most in exactly the unattended contexts where the pin lives. It keeps everything from 2.1.318 (--continue, spawn ENOENT, shared-home fixes).
  • v2.1.319 · auto mode behind gateways and with telemetry off Calls the server can't check are now asked about or denied; there is no fallback to the built-in classifier. That covers LLM gateways, DISABLE_TELEMETRY and feature flags off; Bedrock, Vertex and Foundry are unchanged. Anything that ran auto mode through a gateway last week was quietly using the local classifier; this week it prompts (interactive) or denies (headless) unless CLAUDE_CODE_AUTO_MODE_SERVER=0 is set, or =1 is set to use the server-side check even with CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS. Managed settings that set the latter must set the 1 too. A project's settings or a plugin can no longer turn the server check back on once you've turned it off outside the project. claude -p in auto mode now exits 1, not 0, when actions were refused because no safety check was available — a CI job that silently "succeeded" with nothing done last week will fail honestly this week. /status no longer claims "Auto mode server: Enabled" when the review isn't reaching the session.
  • v2.1.319 · permissions.denyInsteadOfPrompting A tool call that would wait on a permission prompt is denied and the turn continues, in terminal sessions, subagents and teammates. For unattended jobs this is the missing piece between "hang on a prompt forever" and "bypass everything": set it alongside an allow list and the job completes what it is allowed to do and reports the rest as refused. Pair it with blockWritesOutsideWorkingDirectories (v2.1.314) for runners.
  • v2.1.319 · rule evaluation tightened Monitor's WebSocket watch now follows a rule on every Bash command (a deny refuses it; under an ask rule, an allow on Monitor, bypass mode or auto mode no longer skips the prompt). A session's exact Bash or PowerShell ask rule is refused, not asked about, when a broader deny covers the command. which with flags outside a lookup/display set asks first. --add-dir directories register plugin marketplaces only once their own trust dialog is accepted. With the Bash sandbox on, nested .claude/skills folders below the starting folder load only when you start or /cd there. CLAUDE_CODE_PROXY_RESOLVES_HOSTS can no longer be set from settings files where the host manages the network. Self-hosted runners with --trust-workspace false now also stop hooks in the repository's settings files and skills from running — previously only part of the repository's configuration was held back.

The other side of it: session-scoped allow rules are now dropped at a worker move when deny and ask rules can't all be kept, so a long cloud session may ask again for something it was already allowed. /permissions in cloud sessions now says where the session's rules live instead of "not available".

Patterns worth tracking

The release that arrived after the digest. v2.1.319 was published at 11:58 AEDT on Friday, two hours after that morning's run reported a quiet CLI, and its GitHub release followed sixteen hours later (Saturday 04:04 AEDT). It fits the pattern from the last fortnight — a build that gets its release and changelog within a day is a real latest; one still notes-less at the next morning's check is a v2.1.315 — but it also means a Friday-morning digest can be stale by lunchtime. The weekend was quiet: about 70 hours without an npm publish, the longest gap since the 26 Oct to 30 Oct stretch.
Three permission-boundary fixes in one release, after a fortnight of edge corrections. 2.1.309 had eleven sandbox and permission fixes; 2.1.318 fixed stray keystrokes approving prompts and widened URL deny lists; 2.1.319 fixes a command-hiding environment prefix, a worktree sandbox escape, sed skipping the check, /rewind through symlinks and quoted-word rule misses. The direction is consistent: the shell-parsing layer between "what Claude asked to run" and "what the rule engine saw" keeps being tightened. The practical reading for runners: stay within a release or two of latest, because stable (2.1.311) predates all of it.
Auto mode is converging on the server-side check. 2.1.314 made a hook's allow count as no answer in Cowork cloud sessions; 2.1.316 stopped autoMode.allow lists from dropping the built-in scheduled-task rule; 2.1.319 removes the local-classifier fallback behind gateways and with telemetry off, stops projects and plugins re-enabling the server check, and makes headless auto mode exit non-zero when there was no check at all. For a fleet behind a gateway, auto mode now needs an explicit decision (CLAUDE_CODE_AUTO_MODE_SERVER 0 or 1) in managed settings rather than inheriting whatever the environment happened to allow.
Unattended-run controls are filling in. denyInsteadOfPrompting (2.1.319), blockWritesOutsideWorkingDirectories (2.1.314), onFailure: "block" for SDK hooks (2.1.317), credential_expires_at in -p output (2.1.318), honest exit codes for refused auto-mode runs and lost deferred tool calls (2.1.319), MCP tasks that background themselves (2.1.319). A headless job can now be configured to never hang, never write outside its tree, fail closed on a broken hook, warn before its login expires and exit non-zero when it did nothing. Worth a one-page internal standard for how runners are configured.
Desktop's CLI lag is now two releases and both matter. Thursday's v4.23118.0 bundles 2.1.317; since then the CLI has shipped the --continue fix and five security fixes, plus a Desktop-specific fix (connector-name deny rules) that is inert until Desktop ships 2.1.319. Two Desktop builds in three days last week suggests another is near; until it lands, treat the Code tab and local Cowork as a 2.1.317 environment when reasoning about what rules apply.
Spend is being sliced three ways at once. Gateway: /usage spend for developers with no limit, pooled budgets with conflict rules and priority order, a cost report API, OTel plan and seat attributes. Desktop: per-session cost above the message box and an Apps gateway admin page. Claude.ai: project tags for cost codes (Enterprise beta), which explicitly exclude the gateway and API-key paths. An organisation that uses both a gateway and claude.ai seats gets two non-overlapping spend views; the join is the developer's IdP identity on one side and the project on the other.
Dates: two this week, one next, three on 30 Nov. Plugins page GA (today), Unified Claude for unset desktopHome (tomorrow, 12:00 PM PT), Enterprise unified default (16 Nov), Desktop key deprecation warnings (17 Nov), the 30 Nov trio (Skills-off blocks plugins, Enterprise Plugins page, Opus 4.8 fast mode), and 17 Dec for the deprecated keys. The gateway's new desktopHome warning turns tomorrow's change from a guess into a list.
