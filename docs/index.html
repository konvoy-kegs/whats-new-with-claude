CLI · v2.1.266 on next, v2.1.265 on latest
Sources diverge this morning: two releases overnight. The newest build on npm is v2.1.266, published 2026-09-08 23:32 UTC (Wed 09 Sep 09:32 local), shortly before this digest ran. It carries only the next dist-tag. The latest dist-tag, the changelog top entry and the newest GitHub release all say v2.1.265 (published Wed 09 Sep 05:05 local, GitHub release tagged 06:37 local). v2.1.266 has no changelog entry and no GitHub release yet. We do not know what is in it. This is the usual pattern — the patch lands on npm first, the dist-tag and changelog follow within hours — but until they do, treat v2.1.266 as undocumented.
What claude update gives you depends on the channel. claude update follows the latest dist-tag by default, so this morning it installs v2.1.265. Anyone on the next channel gets v2.1.266. Standardise on v2.1.265 — it is documented (50 entries, below), promoted, and released on GitHub. There is no v2.1.264 on npm; the number was skipped, as v2.1.262 was on Saturday.
v2.1.265 is the first substantive release since Friday, and it is heavy on containment and telemetry. Two plugin-path containment bypasses fixed (a backslash in a plugin path skipped the symlink containment check on macOS and Linux), artifact publishing now refuses connector tool names the connector does not expose, reading someone else's artifact now treats the page as untrusted and flags embedded instructions, remote MCP servers no longer get an OAuth client registered until you actually sign in, and Claude Desktop and Cowork now send user.email and user.groups in telemetry through the Claude apps gateway, matching terminal sessions. Details below and under Security.

v2.1.265 — plugin containment, gateway telemetry, and a folder of plugins newest documented

Added user.email and user.groups to the telemetry Claude Desktop and Cowork send through a Claude apps gateway, matching terminal sessions. Until now Desktop- and Cowork-hosted sessions arrived at the collector without a user identity while terminal sessions had one. If our OTel dashboards show Desktop usage as anonymous or unattributed, this is the release that fixes it. Paired: gateway sessions now export OpenTelemetry directly to a collector the gateway's managed settings name in OTEL_EXPORTER_OTLP_ENDPOINT instead of through the gateway's relay (sessions without a named collector still use the relay), and the relay no longer pauses all forwarding for 30 seconds after rejecting a few malformed or oversized payloads. Check the collector's ingress allows direct client traffic before rolling this out.
Fixed a plugin path containing a backslash bypassing the symlink containment check on macOS and Linux. A plugin whose path carried a literal \ was not being checked against the plugin root at all. Also fixed: plugin directories whose names begin with two dots being wrongly refused as outside the plugin root (the check was too eager in the other direction), and a plugin's default component folder that the OS cannot check — a symlink loop, say — being silently skipped rather than reported in /plugin. Seventh consecutive week with a plugin path or marketplace containment fix.
Added support for pointing --plugin-dir at a folder of plugins. Each child folder with a manifest loads, and children added or removed while running are picked up live. Useful for a local plugin dev tree or a mounted org plugin bundle. It also means a writable plugin folder is now a live code-injection surface for a running session — keep it read-only in shared or CI contexts.
Fixed artifact publish accepting connector tool names the connector does not expose. Publishing is now refused when none of the declared tools exist, and warned when only some do. Also: the Artifact tool's read of an artifact someone else wrote now treats the page as untrusted content and flags embedded instructions rather than relaying them. This is a prompt-injection mitigation for shared artifacts — relevant now that artifacts created since 19 Aug are shareable across the org.
Improved remote MCP servers that need sign-in: Claude Code no longer registers an OAuth client with them until you actually authenticate. Previously every configured remote MCP server got a dynamic client registration on connect whether or not anyone signed in — noise in the IdP and orphaned clients. Also fixed: MCP servers configured as http that only speak the legacy HTTP+SSE transport never connecting (now falls back to SSE per spec), and some claude.ai connectors in cloud sessions showing as needing authentication although connected (servers answering an unsupported request with 401).
Changed machines with forceLoginGatewayUrl in managed settings to be Claude apps gateway sessions from startup, like forceLoginMethod: "gateway"; a leftover claude.ai login or API key is not used. Closes the gap left by Saturday's v2.1.261 change, which only covered forceLoginMethod. Also fixed: /login showing “no gateway URL is configured” when re-run in a session signed in to a gateway set by managed settings; /add-dir <subdirectory> refusing a subdirectory's agents when managed settings lock only skills to plugins.
Fixed VS Code and SDK sessions occasionally requiring re-login when a session was closed while refreshing its token. If anyone reported random sign-outs in the VS Code extension over the past fortnight, this is the cause. Also fixed: background (--bg) sessions retired mid-turn when a message arrived just before the idle timeout; remote sessions keeping their sandbox container alive while a connector approval or sign-in link waits for you; non-interactive sessions (-p, Agent SDK, cloud) resetting the shell working directory on each new user message — a cd now persists across turns.
Three prompt-cache fixes. Resuming a foreground-spawned subagent no longer changes its tool list and system prompt prefix; agent teammates and resumed subagents no longer move SubagentStart hook context and preloaded skills out of the prompt prefix on later turns; the advisor tool decision is now made once per conversation rather than re-decided per request. All three were silent cache-miss generators on long agent-team sessions — the kind /cost started diagnosing in v2.1.260.
Added a 1 GB cap on tool results saved to disk; the in-conversation preview says when a saved file was truncated. Also: Windows — Read, Write and Edit refusing every file (“symlink resolution changed after permission was checked”) when running inside an AppContainer or restricted-token sandbox is fixed; Claude Code's own git status and diff probes no longer run clean filters configured by a nested repository inside the working tree; --worktree startup on large repos now checks out in parallel (git 2.32+); image processing uses the runtime's built-in support, so the CLI no longer extracts a native image module to the temp directory (one fewer thing for endpoint protection to flag).
Also worth knowing: /model opusplan[1m] no longer rejected; /model now says when a default could not be saved and why; two-key shortcuts wait 3 seconds inside tmux; slash commands typed mid-prompt show a list; resuming a workflow run after its container restarted with a missing run journal now fails clearly instead of rerunning every agent; the claude-api skill's error-code reference is corrected (model access failures are 404, unavailable beta headers 400). [VSCode] sessions inactive for 14 days are now auto-archived (new “Archive inactive sessions” setting); the sidebar chat no longer comes back blank after Reload Window.

v2.1.261 and v2.1.260 — still the releases to read for permission changes last week

v2.1.261 (Sat 05 Sep): /skill-doctor shows which loaded skills go unused and what they cost in context; bashOutputMaxChars and taskOutputMaxChars raise inline output up to 128K characters; the Bedrock setup wizard times out instead of hanging when AWS never responds and works behind a TLS-inspecting proxy; forceLoginMethod: "gateway" now rejects leftover API keys and claude.ai logins; auto mode treats a diagram-renderer URL that carries content as an upload; the dangerous-rm prompt catches rm -rf on positional parameters and inside sh -c strings.
v2.1.260 (Fri 04 Sep): the /diff panel; a likely cause for prompt-cache misses in /cost; Edit/Write/Read rules with parentheses in the path were being silently dropped, leaving “read-only” folders writable; the v2.1.259 Read()-on-Bash-arguments change was reverted; zsh REPORTTIME/REPORTMEMORY/DIRSTACKSIZE command-substitution bypass in auto mode closed; Bedrock calls honour the OS certificate store; the gateway on Bedrock uses bedrock:CountTokens for aborted requests; Fable 5.1 appears in the /model picker and its prompt caching covers context attached after tool results.

Security & evals

This week's actionable items

  • roll out Standardise on v2.1.265, not v2.1.266. v2.1.265 is documented, on latest, and released on GitHub. v2.1.266 landed on next this morning with no changelog and no release; re-check tomorrow. claude update gives you v2.1.265.
  • audit Plugin paths with backslashes, and any --plugin-dir now pointing at a folder. v2.1.265: a \ in a plugin path skipped the symlink containment check on macOS and Linux. And --plugin-dir on a folder hot-loads every child with a manifest — a writable plugin folder is a live code path into a running session. Keep it read-only in shared and CI contexts.
  • collector Gateway sessions now export OTel directly to the collector named in OTEL_EXPORTER_OTLP_ENDPOINT rather than via the gateway relay (v2.1.265). If the collector's ingress only allows the gateway's egress IP, Desktop and terminal telemetry will start failing on upgrade. Open it, or leave the collector unnamed to keep the relay.
  • attribution Desktop and Cowork telemetry through the gateway now carries user.email and user.groups (v2.1.265). Good for attribution; check the collector's retention and access policy now that it holds per-user identity for non-terminal sessions too.
  • close the gap forceLoginGatewayUrl alone now forces a gateway session from startup (v2.1.265), joining forceLoginMethod: "gateway" (v2.1.261). Leftover API keys and claude.ai logins are ignored under either. Expect a second small wave of “asked to log in again” tickets.
  • IdP hygiene Remote MCP servers no longer get a dynamic OAuth client registered until someone signs in (v2.1.265). If your IdP audit shows a pile of orphaned Claude Code clients from servers nobody used, that is why, and it stops now.
  • shared artifacts Reading an artifact someone else wrote now treats it as untrusted and flags embedded instructions (v2.1.265). Artifact publish also refuses connector tool names the connector does not expose. Both are prompt-injection controls on the org-shareable artifacts introduced 19 Aug — another reason to be on v2.1.265 before widening artifact sharing.
  • audit Every file permission rule with parentheses or brackets in its path (v2.1.260, still in force). Rules with (/) were silently dropped; an unclosed [ broke every edit. On Windows, \( reads as an escape.
  • re-read The Read()-on-Bash coverage from v2.1.259 is reverted in v2.1.260. Deny rules do not cover --file=.env or cd DIR && cat. Sandboxing and permissions.blockReadsOutsideWorkingDirectories remain the controls that hold.
  • IAM Grant bedrock:CountTokens to the Claude apps gateway role (v2.1.260). Aborted requests are counted with the free API; without the permission the count fails.
  • check first allowedMcpServers no longer filters managed MCP servers (v2.1.259). Move any suppressed managed-mcp.json server to deniedMcpServers before rollout.
  • unpin Move anything pinned to the stable dist-tag. stable is v2.1.236 from 20 Aug — twenty-two releases and every fix on this list behind.

Patterns worth tracking

The npm-first, changelog-later gap is back. v2.1.266 hit npm on next at 09:32 local with nothing to say what is in it. Friday's next/latest split closed in under a day; expect the same here. The operational rule holds: the version to roll out is the one that is documented and promoted, not the newest number.
Containment fixes are moving from permission rules to plugin paths and shared content. Last week it was parenthesised paths and zsh substitutions. This week it is backslashes in plugin paths, symlink loops going unreported, and shared artifacts carrying instructions. Every input that can reach a session — rule, plugin, artifact, MCP server — is getting the same “the check you assumed was running was not” treatment. Keep “we set it” and “we verified it on a real machine” as separate tickets.
Telemetry is being consolidated around the gateway. v2.1.259 added identity attributes to cloud sessions; v2.1.261 fixed Desktop's protobuf/JSON mismatch; v2.1.265 adds user identity to Desktop and Cowork and sends everything straight to the named collector. Over three releases the gateway went from a relay to a policy point that hands each client a collector address. Worth a short review of who can set OTEL_EXPORTER_OTLP_ENDPOINT in managed settings.
Prompt-cache hygiene is now a recurring changelog category. Three separate cache-prefix fixes in v2.1.265, four Fable 5.1 caching fixes in v2.1.260, and /cost now explaining misses. If spend on long agent-team sessions drops after this upgrade, do not credit the team — credit the prefix staying put.

What's new

From v2.1.265 — Claude Desktop and Cowork now send user.email and user.groups in telemetry through the Claude apps gateway, matching terminal sessions. This is the Desktop change of the day. Combined with Saturday's fix for Desktop being told to export JSON while collectors expected protobuf, Desktop-hosted sessions should now appear in the collector with a user attached. Expect a step change in attributed Desktop usage after the upgrade lands, and check the collector's access policy now that it holds identity for Desktop sessions.
From v2.1.265 — gateway sessions export OpenTelemetry directly to the collector named in the gateway's managed settings rather than through the gateway relay; sessions without a named collector still relay. Also: machines with forceLoginGatewayUrl in managed settings are gateway sessions from startup, ignoring leftover claude.ai logins or API keys — the Desktop-side counterpart to Saturday's forceLoginMethod change.
From v2.1.265 — VS Code and SDK sessions occasionally required re-login when a session was closed while refreshing its token. Fixed. Also: image processing now uses the runtime's built-in support instead of extracting a native module to the temp directory — one fewer unsigned binary appearing on Desktop-managed endpoints; a 1 GB cap on tool results saved to disk. [VSCode] sessions inactive for 14 days are auto-archived (configurable), and the sidebar chat no longer reloads blank after Reload Window.
Support-centre release notes: no new entry since 1 Sep (Fable 5.1 and Mythos 5.1), re-checked this morning. Fable 5.1 — 1M context, $10/$50 per Mtok — is the default Fable model in the picker where the organisation is entitled to it. Claude Cowork

GA · macOS & Windows · Linux beta

What's new

No new Cowork release-note entry since 25 Aug (memory in Cowork), re-checked this morning. Everything below is from the v2.1.265 CLI changelog, which is where Cowork's runtime fixes land — and today there is a lot of it.
From v2.1.265 — artifact publish now refuses connector tool names the connector does not expose (refused when none exist, warned when only some do), and reading an artifact someone else wrote treats the page as untrusted content and flags embedded instructions rather than relaying them. These are the first prompt-injection controls specifically for org-shared artifacts since sharing arrived on 19 Aug. If a scheduled task reads a shared artifact — as this one's mirror does — it now gets a warning rather than following whatever is in it.
From v2.1.265 — Cowork telemetry through the Claude apps gateway now carries user.email and user.groups. Cowork usage was the least attributable slice of our Claude spend; after this upgrade it is attributed like a terminal session. Also: remote sessions no longer keep their sandbox container alive while a connector approval or sign-in link waits for you — a quiet cost fix for scheduled tasks that stall on a permission.
From v2.1.265 — some claude.ai connectors in cloud sessions showed as needing authentication even though they were connected (servers that answer an unsupported request with 401). Fixed. Also fixed: MCP servers configured as http that only speak the legacy HTTP+SSE transport never connecting; remote MCP servers no longer get an OAuth client registered until you actually sign in. If a connector in a cloud Cowork session kept asking you to reconnect, upgrade before re-authorising anything.
From v2.1.265 — --plugin-dir can point at a folder of plugins, with children added or removed while running picked up live. Handy for developing an org plugin against a running Cowork session. Also: Windows — Read, Write and Edit refusing every file inside an AppContainer or restricted-token sandbox is fixed, which affected Cowork's local file tools on locked-down Windows builds; a plugin's default component folder that cannot be checked (symlink loop) is now reported in /plugin instead of skipped.
From v2.1.265 — non-interactive sessions (-p, Agent SDK, cloud) no longer reset the shell working directory on each new user message. A cd now persists across turns. Also: resuming a workflow run after its container restarted with a missing run journal fails with a clear error instead of rerunning every agent; /workflows agent detail shows tool calls as running, failed or done with the subagent's task list.
Standing context — plugins, skills, artifacts and scheduled tasks. Plugins bundle skills, connectors and sub-agents into one installable package; hooks and sub-agents run only in Cowork. /skill-doctor (v2.1.261) shows which installed skills never fire. Artifacts created on or after 19 Aug are shareable, connected, versioned and openable from the web. Cowork sessions run remotely in the cloud (beta) so scheduled tasks fire with no device online. Enterprise plans can turn on skill and plugin security scanning (6 Aug) — still worth enabling given seven consecutive weeks of plugin path fixes in the CLI.
