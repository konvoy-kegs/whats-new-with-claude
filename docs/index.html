v2.1.286 — retries, fallbacks, scripting and plugin hardening newest · aligned

reliability One retry budget per model call. Failed API requests now share a single limit across the whole call, so with default settings a failing call sends at most 14 requests. Predictable load on gateways and Bedrock/Vertex quotas during outages.
models Same-tier fallback on refusal. If the Anthropic API refuses the model your default or alias resolves to, Claude Code retries once on the previous model of the same tier instead of failing every turn. The fallback notice now says when context dropped from 1M to 200K.
automation --bare is now truly bare. Connects only the MCP servers named on the command line, sends no system reminders, starts no background tasks, and stops (rather than backgrounds) shell commands that hit their timeout. Worth adopting in CI/headless runs.
plugins Stricter plugin sources. Plugin installs now refuse npm sources that are git repos or folders, and install dependencies only from registry packages. Check any internal plugins that point npm at a git URL.
fleet Fixes worth knowing. Multiple processes/IDE extensions no longer each open a login browser when gcpAuthRefresh / awsAuthRefresh credentials expire; --resume / --continue no longer lose turns after parallel tool calls in a crashed session; Claude apps gateway spend meter now prices 1-hour cache writes correctly; permission prompts show "2 of 5" when requests stack.

v2.1.285 — provider lockdown, Desktop handoff, headless plugins Wed 30 Sep · now stable

allowedProviders managed setting pins which API providers a machine may use; claude --desktop hands a session to the Desktop app; claude plugin configure / install --config for scripted plugin setup; ANTHROPIC_AUTH_TOKEN sessions now load org policy.

v2.1.284 — Sonnet 5.5 lands, auto mode everywhere Tue 29 Sep

Claude Sonnet 5.5 (claude-sonnet-5-5) default Sonnet on the Anthropic API ($2 / $10 per Mtok, 1M context); auto mode default on every plan and provider; /mcp reconnect all; marketplace/npm plugins can no longer pre-approve their own tools under allowManagedPermissionRulesOnly.

Security & evals

credential leak fix · plugin source hardening

Today's actionable items

  • credentials MCP error messages could show a credential's value when "Bearer" or "Basic" came before its key name (fixed in 2.1.286). If you ship MCP error logs anywhere central, consider rotating tokens that may have appeared.
  • plugins Plugin installs now refuse npm sources that are git repositories or folders; dependencies come only from registry packages. Supply-chain win — check internal plugins still install.
  • policy Remote Control sessions (incl. claude remote-control) now disconnect when org policy turns Remote Control off; previously they stayed connected.
  • cloud Clearing an org environment's setup script in admin settings no longer leaves new cloud sessions running the old script.
  • pin stable moved to v2.1.285 (includes allowedProviders and the ANTHROPIC_AUTH_TOKEN policy-loading fix). Suggested canary: v2.1.286.
  • deadline Enterprise skill/plugin scanning defaults to "Requires review" tomorrow, Fri 2 Oct, if no setting is chosen.
  • deadline Cowork on Pro/Max goes cloud-by-default on Tue 6 Oct.

Patterns worth tracking

Fleet governance keeps expanding. 283 (deniedModels) → 285 (allowedProviders) → 286 (policy now actively kills Remote Control sessions). Admin intent is enforced on live sessions, not just new ones.
Bounded failure. 286 caps retries per call and adds deterministic model fallback — outages now degrade predictably instead of hammering providers.
