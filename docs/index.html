v2.1.296 — managed-hook enforcement, gateway code policy, subagent controls newest · aligned

hooks & permissions Fixed managed-settings PreToolUse hooks denying with "continue": false, and managed prompt hooks that block, refusing the call but not ending the turn. Fixed managed PostToolUse hooks not applying updatedMCPToolOutput in some sessions. Fixed Bash permission checks auto-approving commands that assign and then use BASH_ARGV0 (now prompt). Fixed Esc during a UserPromptSubmit hook letting the unchecked prompt through. Fixed cloud sessions skipping auto mode's checks on Claude in Chrome actions. Windows: rm -rf /c/Users/<name> in Git Bash now asks even in bypass mode.
secrets & MCP Fixed secret redaction in shared transcripts and debug logs missing some values (including JSON inside a shell string). Fixed headless sessions starting a folder's .mcp.json or plugin MCP server that was switched off for that folder, after changing directory or reloading plugins. Fixed hook output being altered when it contained text resembling a plugin hint tag. Fixed a plugin secret named constructor/prototype being deleted on save.
Claude apps gateway & Desktop Added a code key to managed.policies[]: the same settings as cli, also applied in Claude Desktop's Code tab; beside desktop, it turns on Desktop's gateway mode. Code tab now shows the reason as a reply when a gateway session can't start. Fixed a gateway serving allowedProviders with "gateway" locking out laptops that name it in user settings, and a saved gateway sign-in being ignored under forceLoginMethod: gateway with no URL (regression in 2.1.295).
new settings autoCompactWindow in subagent frontmatter and --agents, so a subagent compacts earlier than the main conversation. CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL pins every workflow agent to one model. CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS caps 529 backoff. Read tool allow_large option for whole large files. MCP tool descriptions and server instructions sent up front now capped at 4,096 chars (was 2,048). /cost and --max-budget-usd now price Sonnet 5.5 cache reads at $0.10/Mtok (was $0.20).
Windows, runners & reliability PowerShell commands up to 32 KB now honour allow rules and read-only detection (was ~1 KB). Stdio MCP servers get a graceful stdin close before kill at shutdown. claude plugin install retries GitHub sources over HTTPS when there's no SSH key. Edit/NotebookEdit now refuse non-UTF-8 files rather than mangling non-ASCII characters. Self-hosted runners: clearer registration errors, git fetch/push fix with --capacity above 1, per-session queue positions. VS Code: Claude in Chrome now asks before browser actions in every session. Claude Tag: admins can manage workspace/channel memory files.

v2.1.295 — fail-closed hooks, gateway controls, MCP reliability Thu 8 Oct UTC · bundled in Desktop

hooks & guards Added onFailure: "block" for command and HTTP hooks (fail closed instead of open). Fixed --tools/--restricted not applying to late-registered built-in tools. Gateway: per-upstream models lists, timeouts.upstream_ttfb_ms for Bedrock/Vertex/Foundry, upstream_request_id in audit events. On Amazon Bedrock, token counts use AWS CountTokens — grant bedrock:CountTokens. claude.ai connectors negotiate MCP protocol 2026-07-28 by default. Program Status Protocol (OSC 7501) lets supporting terminals show whether Claude is working, waiting or done.

v2.1.294 — hook judgement fixes Thu 8 Oct UTC

hooks Fixed prompt and agent hooks written as instructions (such as "Block commands that...") allowing what they should block. Improved judging of instruction-style Stop/SubagentStop prompt hooks.

v2.1.293 — Claude Haiku 5.5 Wed 7 Oct UTC

model Added Claude Haiku 5.5 (claude-haiku-5-5), now the default Haiku on the Anthropic API — 1M context, $0.10/$0.50 per Mtok ($0.50/$2.50 over 100K). agentType added to the subagentStatusLine payload. Reverted the 2.1.281 auto-mode denial wording change.

Security & evals

no new CLI release · Desktop lags one build

Today's actionable items

  • fleet Target remains 2.1.296. It carries the 2.1.292–2.1.295 hardening plus the managed-hook, BASH_ARGV0 and Windows bypass-mode fixes.
  • Desktop Code tab Desktop v2.31226.1 bundles 2.1.295, not 2.1.296 — so the Code tab still lacks the managed-hook enforcement fix. Run /status in a local Code-tab session to see which CLI it's on; terminal claude and the Code tab update independently.
  • managed hooks If you deny tools via managed PreToolUse hooks with "continue": false, or rewrite MCP output with updatedMCPToolOutput, retest on 2.1.296 — earlier versions didn't end the turn or apply the rewrite reliably.
  • Desktop skills Desktop v2.31226.0 fixes a skill switched off in Customize still being offered to Claude and running when asked for by name, and a deleted skill still being offered in an already-running Code session. If you rely on disabling skills as a control, update Desktop.
  • Desktop worktrees Same build fixes Claude's file edits in a worktree session sometimes landing in the main checkout or another session's worktree. Worth knowing if anyone saw unexplained diffs in main.
  • gateway Using the Claude apps gateway with Desktop? Add a code entry to managed.policies[] to apply CLI settings to the Code tab. Carry-over: grant bedrock:CountTokens and add onFailure: "block" to guard hooks.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

Five releases of guardrail hardening, now paused. 2.1.292 through 2.1.296 all closed gaps where hooks, auto mode, tool lists or Bash parsing could be bypassed. Nothing new since Friday. Treat hooks as part of your security boundary and test them on each upgrade.
Desktop bundles trail the CLI by a release or two. Desktop v2.26454.x shipped 2.1.289 then 2.1.293; v2.31226.0 shipped 2.1.293; v2.31226.1 shipped 2.1.295. Expect 2.1.296 on the next Desktop bump.
stable still lags. v2.1.287, nine releases behind latest, missing all five hardening releases. Pin to latest-track versions on managed machines.

Claude Desktop

v2.31226.1 · 9 Oct · two builds since Friday

What's new

v2.31226.1 · 9 Oct Bundles Claude Code 2.1.295. No user-facing General/Code/Cowork changes. Third-party deployments: MSIX installs on Windows now end programs started through Git Bash when the app updates; fixed every request failing on a 1M-context model when the inference gateway or cloud provider refuses the 1M capability (the request is now resent without it).
v2.31226.0 · 8 Oct · General Settings > Import now brings skills and local MCP servers across when importing this computer's third-party history: saved skills upload to your own skills automatically, and local MCP servers can be added and started after you confirm. Fixed chats showing "Page not found" on server/connection problems (now offers retry). Fixed dictation continuing to record after releasing the mic button. Fixed messages being sent under a different organization after an org switch. Fixed session-started programs (MCP servers and helpers) staying alive on Linux after a crash or force-quit.
v2.31226.0 · Code tab Environment variables now live on saved environments: "This computer" starts clean, existing machine-wide variables are copied into the environments created for you, and the session's Environment card shows which saved environment you started from. SSH sessions no longer auto-continue an interrupted task (select it in the sidebar to resume; a stopped task shows Try again). The Files pane now prompts before discarding unsaved edits with Auto save off. Fixed group delete of sessions with uncommitted worktree changes, and a raft of SSH connection fixes (idle drops, large file loads, hosts that print a banner, stuck at "Setting up plugins…").
v2.31226.0 · Third-party / enterprise desktopHome for Unified Claude (beta): standard turns on the combined Chat + Cowork experience, off turns both off (Code unaffected). otlpAttrMaxChars caps captured content in the OpenTelemetry export (default 61,440). allowedWorkspaceFolders ro is now enforced in SSH sessions. claudeAiImport.automatic3pImport now carries Cowork artifacts, projects, memory, global instructions, scheduled tasks, plugins and skills. Fixed OAuth-authenticated managedMcpServers failing until the next token refresh when the server rejected the token early.
carry-over v2.26454.0 (6 Oct) and v2.19675.1 (5 Oct) brought the Linux attachment fix, Microsoft 365 connector account controls (microsoftAuthDefaultAccount, "Use a different account"), and the fix for a long skill description wiping every local skill. Full detail on the Claude Desktop changelog.
plans Monthly API credits (7 Oct). Max and Team plans get monthly Claude Platform credits, claimed in Settings > Billing (Max) or Organization settings > Billing (Team).

Claude Cowork

GA · macOS, Windows & Linux · web & mobile · cloud by default on Pro/Max

What's new

scheduled tasks · Desktop v2.31226.0 (8 Oct) Four scheduled-task reliability fixes. A task created while the task list was still loading no longer overwrites the prompt of an existing task with the same name. Claude no longer asks for access to a folder the session already had (which left scheduled runs waiting on an approval nobody was there to give). A tool that an organization's approval policy marks "ask" now shows the prompt and waits instead of being skipped, and a newer run retires an earlier run's unanswered prompt. The "Scheduled task failed" notification now appears when a task's sandbox can't start. Relevant to anyone running digests like this one.
computer use & plugins · v2.31226.0 Computer use on macOS no longer saves into hidden folders or types into an app that isn't responding; menu commands aren't reported as disabled after an app was briefly busy; screenshots land under the right step. Plugin installs, updates and marketplace refreshes no longer fail or drop a plugin from the list when started back-to-back, and a removed marketplace no longer blocks re-adding one with the same name. Fixed a skill switched off in Customize still being offered and run.
cloud sessions · Claude Code 2.1.296 New status filter on the Sessions and Runners lists in admin settings; each session waiting on a self-hosted runner shows its own queue position; a message sent mid-reply no longer jumps above the reply. Fixed auto mode occasionally refusing an update to your own artifact. Fixed skills synced from claude.ai never finishing install when sessions share a config directory.
Unified Claude (beta) · admin switch Enterprise/third-party deployments can now set desktopHome to opt the org into (or out of) the combined Chat + Cowork experience that's rolling out to Pro and Max since 16 Sep. Two matching switches appear in the Setup window's Allowed surfaces section.
carry-over Cloud by default (since 6 Oct) on Pro and Max. New tasks run in the cloud; "Only on your computer" was removed. Local folder access still needs the desktop app open. See Use Claude Cowork on web, desktop, and mobile and Claude Cowork and chat are one Claude.
