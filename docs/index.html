v2.1.282 — admin policy that actually sticks newest · aligned · hours old

Managed settings no longer fail open. A mistyped value for boolean lock keys such as disableClaudeAiConnectors or allowManagedPermissionRulesOnly used to be ignored — the lock now applies and startup names the key. Managed permissions, autoMode, worktree and attribution blocks were ignored entirely if one nested value was invalid; the rest now still applies. On Windows/WSL, an admin policy that is present but invalid (HKLM or managed-settings.json) now stops user-writable HKCU and WSL /etc/claude-code from applying.
Telemetry can't be switched on by a repo. Project and local settings now ignore OpenTelemetry variables that enable export, set the endpoint or capture content (CLAUDE_CODE_ENABLE_TELEMETRY, OTEL_LOG_*). A startup notice plus /status and claude doctor entries list any such variables that were ignored or that turned telemetry off.
Skills and sandbox tightened. Repo, user and --add-dir skills could pre-approve their own tools via allowed-tools under allowManagedPermissionRulesOnly (fixed). sandbox.excludedCommands now ignores project/local entries when managed settings set allowUnsandboxedCommands: false or allowManagedDomainsOnly: true. Bash rules with a mid-pattern :* now match from settings files, not just --allowedTools.
Reserved skill namespaces. Skill(anthropic-skills:*) and Skill(claude-ai:*) allow rules now cover only skills synced from claude.ai. Local skill folders or commands in those namespaces no longer load, and an MCP server named anthropic-skills or claude-ai lists no skills or prompts (tools still work) — rename it if you rely on that.
Session reliability. Fixes for every request 400-ing when history holds undecryptable web search results (e.g. turns answered through a third-party gateway), redacted_thinking errors on every turn, extended thinking dropped on resume or mid-turn slash commands, compaction failing on a refused summary (now retries on a fallback model), and a stale login-refresh lock stalling requests for up to a minute.
Worth announcing. maxProseWidth caps prose width in wide terminals. allowClaudeInChromeWithManagedMcp lets claude --chrome run alongside an exclusive managed-mcp.json. Gateway store.readiness_grace_seconds keeps /readyz ready through a short Postgres failover. Auto mode now uses the server-side classifier by default on direct API when telemetry is off (CLAUDE_CODE_AUTO_MODE_SERVER=0 opts out). Cloud sessions show Claude GitHub App status under Settings › Connectors › GitHub.

Security & evals

managed-settings fixes

Today's actionable items

  • pin Suggested: canary v2.1.282 and skip v2.1.281 for the fleet. v2.1.282 carries all of 2.1.281's fixes plus managed-settings enforcement fixes that matter for a managed fleet. Before rollout, run claude doctor on a canary to see which managed keys or OTel variables it now flags.
  • policy Managed settings could fail open — mistyped boolean locks ignored; one invalid nested value voided whole permissions/autoMode blocks (fixed in v2.1.282). Validate managed-settings files; startup now names bad keys.
  • exfil Repo settings could turn on OpenTelemetry export and point it at any endpoint, including content capture (OTEL_LOG_*). Project/local settings now ignore these (v2.1.282). Set telemetry only in managed or user settings.
  • skills Repo skills could pre-approve their own tools via allowed-tools under allowManagedPermissionRulesOnly (fixed in v2.1.282).
  • sandbox Project/local sandbox.excludedCommands now ignored when managed allowUnsandboxedCommands: false or allowManagedDomainsOnly: true.
  • Windows An invalid HKLM policy no longer lets HKCU or WSL /etc/claude-code settings take over.
  • GitHub /install-github-app said "cancelled" but still pushed the branch and saved the API key secret (fixed in v2.1.282). Check repos where someone backed out of the install.
  • naming Any internal plugin, skill folder or MCP server named anthropic-skills or claude-ai will stop listing skills — rename.
  • carried Command-substitution rm and NUL-byte rule fixes (v2.1.281); gateway safeguards pass-through (v2.1.278); Enterprise skill/plugin scanning defaults to "Requires review" on 2 Oct if no setting is chosen.

Patterns worth tracking

Fail-closed is the theme this week. Three consecutive builds (280–282) each close a path where permissions or policy silently didn't apply.
Repo-controlled config is being demoted. Project settings lose telemetry, sandbox exclusions and skill self-approval power when managed policy exists.
The gateway keeps growing. Readiness grace for Postgres failover (282) follows Bedrock IAM roles and guardrails (281).
