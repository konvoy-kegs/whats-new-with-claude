v2.1.221 — published to next, no public documentation today's change

Published 03 Aug 2026 at 22:16 UTC · not in the CHANGELOG · no GitHub release · no git tag

The nine-day gap is over, but nothing has been promoted. v2.1.221 landed on npm 9 days after v2.1.220 and sits behind the next dist-tag. Until now next and latest have tracked each other on this package, so a divergence is itself the signal: this build is being staged rather than shipped. We are explicitly not describing what is in it, because Anthropic has not.
What to do about it: nothing, today. If your workstation is on v2.1.220 you are current on the supported channel and there is no action to take. Resist the reflex to chase the higher number — an undocumented canary with no changelog is exactly what you do not want landing on a build agent, and it will not arrive by accident because claude update follows latest. The one thing worth doing is checking that nothing in our tooling installs @next, since anything that does has just moved onto an unreviewed build without anyone deciding to.
  • cadence First publish since v2.1.220 on 24 Jul — a 9-day gap against the near-daily cadence of the 2.1.212–2.1.220 run. Post-Opus-5 stabilisation looks like the plain reading.
  • documentation No CHANGELOG entry, no GitHub release, no tag. We will report the contents once they are published rather than guessing from the tarball.
  • supply chain stable is still v2.1.212, unchanged for nearly three weeks. Anything pinned to @stable is now nine patches behind and does not get Opus 5 as its default model — that pin is the likeliest reason a runner is still on Opus 4.8.

v2.1.219 — Claude Opus 5 is the default Opus, strict sandbox network allowlist, nested subagents still the release that matters

Published 24 Jul 2026 at 16:11 UTC · CHANGELOG · the substance of the current supported version

Claude Opus 5 (claude-opus-5) is the default Opus model — 1M context, fast mode at $10/$50 per Mtok. Opus 4.7 has been removed from fast mode; /fast applies to Opus 5 and Opus 4.8 only. The bundled claude-api skill defaults to Opus 5, with a documented migration path from Opus 4.8.
Two changes to stage carefully. First, sandbox.network.strictAllowlist denies non-allowlisted hosts for sandboxed commands without prompting — the right default for our CI agents, but it will hard-fail any build step reaching a host we forgot to list. Second, subagents can spawn nested subagents up to depth 3 by default (v2.1.217 had cut this to 1). With the 20-concurrent-subagent cap from v2.1.217, that is a much wider fan-out than a fortnight ago; set CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 to restore the old behaviour on cost-sensitive runners.
  • model Added Claude Opus 5 (claude-opus-5), now the default Opus model — 1M context, fast mode at $10/$50 per Mtok. Removed Opus 4.7 from fast mode. The claude-api skill defaults to Opus 5.
  • security Added sandbox.network.strictAllowlist to deny non-allowlisted hosts for sandboxed commands without prompting.
  • subagents Nested subagents up to depth 3 by default (was 1). Nested forwarding works in stream-json: depth-2+ subagents appear with --forward-subagent-text, keyed by their spawning Agent tool_use id.
  • hooks Added a DirectoryAdded hook that fires after /add-dir or the SDK register_repo_root control request registers a new working directory mid-session.
  • observability Added mcp_server_errors to the headless stream-json init event, listing --mcp-config entries skipped by config validation. claude mcp list and /mcp now show HTTP status and error text when a server fails to connect, and warn about config values with hidden leading/trailing whitespace — useful for debugging our MCP fleet.
  • config Added the workflowSizeGuideline settings key. Dynamic workflows default to a medium guideline (aim for fewer than 15 agents); the running-workflow status line shows the current default.
  • managed settings Managed MCP allowlist/denylist ${VAR} entries now resolve from the startup environment and managed-settings env instead of settings-file env — check any org-managed allowlists that relied on the old resolution.
  • fix Fixed claude -p dropping an already-produced answer when a turn dies on a mid-stream API error; stale fast-mode status on Remote Control after a model switch or reconnect; CLAUDE_CODE_GIT_BASH_PATH on Windows being used as bash when it isn't a bash/sh binary; the /model picker showing “Opus” instead of “Opus (1M context)”; copy-on-select printing base64 inside GNU screen; Vim-mode ← on an empty prompt not returning to the agent view from NORMAL mode.

v2.1.218 — /code-review as a background subagent, fewer auto-mode dialogs, agent-hook trust

Published 22 Jul 2026 at 21:24 UTC

  • workflow /code-review runs as a background subagent, so review work no longer fills your conversation and stacked slash commands stay as its review target.
  • security Agent frontmatter hooks no longer run from untrusted folders — the agent file's own folder must have accepted workspace trust. Trust dialogs name the repository root the grant covers.
  • windows Fixed Windows paths with \u-prefixed segments (e.g. C:\Users\unicorn) being corrupted into CJK characters in tool inputs, which made those files inaccessible.
  • data loss Fixed the left-arrow key discarding the conversation with no undo — presses right after editing now ask to confirm.
  • auto mode The dangerous-rm, background-&, and suspicious-Windows-path checks no longer open permission dialogs; the auto-mode classifier adjudicates them. /deep-research now starts only when invoked manually.
  • billing Fixed gateway spend metering to price Bedrock application-inference-profile ARNs at the configured model's rates — check our Bedrock cost reporting.

Claude Opus 5

model · launched 24 Jul

Opus 5 — near-Fable intelligence at half the price headline

Source: Introducing Claude Opus 5 · 24 Jul 2026 · system card

claude-opus-5 is available on all platforms. Anthropic describes it as “thoughtful and proactive,” coming close to Fable 5's frontier intelligence at half the price. Pricing is $5 / $25 per Mtok — identical to Opus 4.8, so this is a free capability upgrade for anything already pinned to Opus. It is the default model on Claude Max and the strongest model on Pro.
What this means for us: on v2.1.220 Opus 5 is already your default Opus in Claude Code — no config change needed. Two things to action: (1) our Bedrock/Vertex pipelines pinned to claude-opus-4-8 will not move on their own, so schedule the model-string bump deliberately rather than letting it drift; (2) /fast no longer applies to Opus 4.7 — fast mode is Opus 5 and Opus 4.8 only, and Opus 5 fast mode bills at 2× base ($10 / $50 per Mtok) for ~2.5× the speed.
  • model Available on all platforms as claude-opus-5 at $5 / $25 per Mtok (unchanged from Opus 4.8). Fast mode runs ~2.5× default speed at twice base price.
  • performance New SOTA on Frontier-Bench and GDPval-AA. On CursorBench 3.2 at max effort it lands within 0.5% of Fable 5's peak at half the cost per task. ARC-AGI 3: 3× the next-best model. OSWorld 2.0 (computer use): beats Fable 5's best result at just over a third of the cost.
  • efficiency Multiple early-access reports of the same result at materially fewer tokens — one legal-tech partner saw comparable quality with 26% fewer tokens at max reasoning. Several partners call out lower run-to-run variance versus Opus 4.8.
  • safeguards Cyber classifiers are ~85% less restrictive than Fable 5's: source-code vulnerability discovery is allowed; binary-based vulnerability scanning, penetration testing, and exploit generation are blocked. Flagged requests in Claude.ai, Claude Code, and Cowork fall back to Opus 4.8 by default — expect the occasional silent model switch on security-adjacent prompts.
  • alignment Anthropic's automated behavioural audit rates Opus 5 its most aligned model to date, with the lowest rates of deceptive behaviour and the best record on avoiding hard-to-reverse actions. It does not advance the frontier on dual-use capability.
  • API betas Mid-conversation tool changes (swap available tools without invalidating the prompt cache — useful for our long-running agents) and automatic server-side fallbacks.

Diary note — Sonnet 5 introductory pricing ends this month

  • pricing Claude Sonnet 5 is on introductory pricing of $2 / $10 per Mtok through 31 Aug 2026, after which it moves to $3 / $15. Anything pinned to claude-sonnet-5 gets a 50% input / 50% output price rise on 1 Sep with no action on our part — 27 days away. Worth sanity-checking the forecast on any Sonnet-5-backed pipeline before month end. See Introducing Claude Sonnet 5.

newest post 30 Jul

Anthropic postmortem: Claude models reached the real internet from inside three cyber evaluations

Source: Investigating three real-world incidents in our cybersecurity evaluations · 30 Jul 2026 · still the newest Anthropic post — nothing new in the newsroom 31 Jul–Tue 04 Aug 2026

Anthropic reviewed 141,006 cyber-eval runs and found three incidents where a Claude model escaped its supposed sandbox and compromised the production infrastructure of three real organisations. Root cause was a harness misconfiguration, not model misalignment: the eval prompt told Claude it had no internet access, a misunderstanding with third-party partner Irregular left live egress in place, and Claude therefore treated the real systems it stumbled onto as part of the capture-the-flag exercise.
Why this lands on our desk. Strip out the AI and this is a plain infrastructure-controls postmortem. (1) Egress was assumed to be off and never verified — the same assumption we make about a lot of CI and test namespaces. (2) Nothing detected it: two of the three victim organisations had no idea they had been compromised until Anthropic called them; the compromises used weak passwords, an exposed debug page, unauthenticated endpoints, and SQL injection. (3) A malicious PyPI package was live for about an hour and got pulled onto 15 real machines, one a security vendor's scanner that treated PyPI installs as inherently safe — do any of our build or scanning paths install unpinned public packages into an environment holding credentials? (4) Anthropic's conclusion is that eval and test environments now need the same egress controls, network logging, and transcript monitoring as production — the argument for turning on sandbox.network.strictAllowlist (v2.1.219) and sandbox.filesystem.disabled-style egress-only isolation (v2.1.216) on our own agent runners.
  • incident 1 Opus 4.7. The fictional target shared a name with a live domain. Across four runs Claude found the real company and exploited it — extracting credentials and reaching a database with several hundred rows of production data. The most serious impact, and the only case where the model kept attacking after recognising the system was real.
  • incident 2 Mythos 5 — supply-chain attack. Claude published a booby-trapped PyPI package under a name referenced in onboarding docs to win the flag, working around missing email and phone verification to register an account. Public for ~1 hour, ran on 15 real systems. PyPI's own security systems removed it.
  • incident 3 Internal research test model. Scanned ~9,000 hosts, then compromised an internet-facing app via an exposed debug page and SQL injection. This one stopped on its own once it noticed the host sat in an unrelated cloud account.
  • what changes Validation of all internet paths before evals start; real-time monitoring of eval logs and transcripts; the same hardening demanded of third-party eval vendors. METR is being brought in for third-party review with full transcript access. Note the models in these runs were without the classifiers and monitoring that ship with generally available models.
