v2.1.232 — gateway boot validation, two permission bypasses, subagent forking by default new overnight

Published to npm 2026-08-13 21:30 UTC · 46 changelog entries · the largest release this month

Breaking — the gateway now fails at boot on configuration it previously accepted. Two changes, both fail-fast. (1) The desktop: overlay now accepts every released Desktop setting, validated at boot against Desktop's own schema, rather than eleven hand-listed keys — unknown or invalid keys now fail boot, where before a typo was silently ignored. (2) Empty managed.policies[].match.groups and admin.admin_groups entries, and malformed email_domain values (empty, or containing @, whitespace, or commas), now fail at boot instead of silently matching no one or granting admin access. That second one is worth reading twice: if our gateway config has an empty admin_groups entry, it has been granting admin, and the upgrade will surface it as a boot failure rather than a quiet privilege grant. Validate gateway config in a non-production environment before rolling this out.
Behaviour change — subagent forking is on by default, and agent spawns go to the background. A subagent_type: "fork" subagent now inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions run in the background by default. The cache inheritance is a real token saving on fan-outs — it stacks with v2.1.229's same-prefix sibling staggering. The background default is the part to watch: work that used to block the session and show its output inline now runs detached, so anyone who reasons about "the agent finished because the prompt came back" needs to recheck that assumption. /tasks is where they surface.
Two permission bypasses, both Windows-side, both worth an upgrade on their own. (1) PowerShell: variable-writing parameters could silently overwrite $PSDefaultParameterValues and redirect the file access of later commands — a command approved for one path could be made to touch another. (2) Git Bash on Windows followed Cygwin-style symlinks that path validation saw as regular files; writes through them now require permission approval. Alongside these, Bash input redirections (< file) are now permission-checked like their argument spellings on all platforms — reading a file by redirection rather than as an argument was not being checked.
Nested git repositories no longer inherit trust from a parent directory. Each repository now requires its own trust confirmation. If we have monorepo-adjacent layouts, vendored submodules, or a workspace directory containing several checkouts, expect fresh trust prompts after upgrading — and note that until now, trusting the parent implicitly trusted every repo underneath it, including anything a dependency or tool dropped in.
AWS and Vertex: two reliability fixes and a config-hardening change. (1) Stream idle timeout errors now recover instead of failing the request on Bedrock, Vertex and gateway deployments — the successor to v2.1.229's SSE keepalive work, and together they should close out the "long extended-thinking turn dies silently" class of failure. (2) Malformed AWS or Vertex region values are no longer used to build request URLs; they now fall back to the default region. (3) mTLS client certificate rotation no longer requires a restart — Claude Code reloads the rotated cert and key automatically on connection errors. Relevant if our gateway sits behind mTLS with short-lived certs.
GitLab lands as a first-class citizen — marketplaces and secret redaction. Bare gitlab.com repo URLs (including nested subgroups) now clone like github.com URLs for plugin marketplaces, and clone auth-failure hints name your actual git host instead of assuming GitHub. Separately, secret redaction now covers the GitLab token families — glrt-, gloas-, glptt-, glagent-, glimt-, glsoat-, glcbt-, glft-, glffct- — with full redaction of routable glpat- and gldt- tokens, and the glab CLI config store gets the same sandbox and credential-path protection gh already had.
  • gateway Empty match.groups / admin_groups and malformed email_domain values now fail at boot instead of silently matching no one or granting admin access. The single most important line in this release for anyone running the gateway.
  • permissions PowerShell bypass — variable-writing parameters could overwrite $PSDefaultParameterValues and redirect later commands' file access.
  • permissions Windows Git Bash bypass — Cygwin-style symlinks were seen as regular files by path validation; writes through them now require approval.
  • trust Nested git repositories no longer inherit trust from a parent directory — each repo confirms separately.
  • permissions Bash input redirections (< file) are now permission-checked like their argument spellings, on all platforms.
  • sandbox Hardened the Linux filesystem sandbox against a protected-path bypass. sandbox.ripgrep is now honoured only from user, managed and --settings — project settings can no longer override the sandbox's ripgrep binary. The managed-settings approval dialog now requires approval for server-managed sandbox binary overrides (sandbox.bwrapPath, sandbox.socatPath, sandbox.ripgrep), shows endpoint URLs, and skips routine OpenTelemetry noise.
  • secrets GitLab token redaction across nine token prefixes, full redaction of routable glpat-/gldt-, and glab CLI credential-path protection matching gh.
  • IPC Hardened the cross-session messaging socket directory on shared /tmp — a pre-planted symlink or another user's directory is now refused rather than used. Matters on multi-tenant build hosts.
  • remote control Fixed Remote Control sessions hosted by a bridge inside a cloud session inheriting that session's transcript or credentials.
  • subagents Subagent forking on by default — subagent_type: "fork" inherits the full conversation and prompt cache; non-teammate spawns run in the background in interactive sessions.
  • sessions Type @ to mention another Claude session by name; Claude then uses SendMessage to reach it directly. SendMessage now delivers to a bare name that exactly matches one live session. Sessions on one machine get unique names automatically (name-word-word variants). New /config rows for Dialog expiry and Messages from your other sessions (accept / hold / refuse).
  • plugins GitLab marketplace support, including nested subgroups. additionalMarketplaces and allowedMarketplaces are now accepted as friendlier aliases for extraKnownMarketplaces / strictKnownMarketplaces. A url-typed blockedMarketplaces entry for a bare repo URL keeps blocking when the CLI classifies it as a git clone. /plugin install plugin@marketplace now refreshes the marketplace first, so newly published plugins install without a manual update.
  • AWS / Vertex Stream idle timeout errors now recover instead of failing the request on Bedrock, Vertex and gateway deployments. Malformed region values fall back to the default region. mTLS client certificate rotation no longer needs a restart.
  • MCP Fixed MCP connections hanging for the full 30-second connect timeout when a server fails to answer or sends a malformed reply to the protocol-version probe. Combined with v2.1.231's OAuth fix, MCP startup should be materially less painful.
  • remote control Five fixes: sessions started from Desktop or an IDE no longer appear as a new claude.ai session on each resume (they reattach); idle sessions no longer look unreachable to newly attached clients; bridge sessions restore history when the worker restarts; resuming a conversation deleted from claude.ai now starts a replacement rather than failing with a login message (regression from v2.1.227); reconnection now persists ~30 minutes across network blips. Resuming no longer silently steals Remote Control from another Claude Code on the same machine, and the terminal now says why a session ended.
  • models Fable 5 is offered as an advisor in /advisor again for organizations with Fable access, with usage-credits consent through /model fable.
  • performance Fullscreen streaming no longer re-normalizes the whole conversation on every update, so long sessions stay responsive. Pasted and clipboard images are read without blocking the event loop. /code-review at high, xhigh and max effort now runs in a background agent like the other levels.
  • plugins Fixed a startup race that could silently unregister a plugin marketplace due to concurrent writes to known_marketplaces.json. Fixed /update and /tui refusing to restart while work that survives the relaunch was running.
  • cowork Cowork sessions no longer inline external @-imports from user-scope memory files.
  • gateway / UX Fixed Cloud gateway /login exiting silently or leaving an unresponsive terminal when managed settings failed to load. Fixed voice mode on native builds sticking on "listening…". Assorted overlay truncation and rendering fixes. The startup tip suggesting custom subagents has been removed.

Still open from earlier this week — v2.1.231 Slack MCP OAuth, v2.1.229 container CPU limits action required

Carried forward — these have not been superseded

v2.1.231 — a one-line release, and the line is about Slack. The only entry: MCP OAuth sign-in was failing with a redirect URI mismatch for servers that use a pre-registered OAuth client, such as Slack. If anyone's Slack MCP connection has been refusing to authorise, this is the fix, and it shipped 13 Aug. Note it stacks with v2.1.229's change to 127.0.0.1 over localhost for strict authorization servers — two separate OAuth redirect bugs closed in as many days.
v2.1.229 — dynamic workflows were using the host's core count, not the container's CPU limit. Still the most operationally relevant fix of the week for our estate. Inside a CPU-limited container — every pod we run — fan-out width was derived from the node's core count rather than the cgroup limit. This is the likeliest explanation for throttling or noisy-neighbour behaviour from Claude Code in CI or on EKS. Fixed on upgrade, but re-baseline any workflow sized around the old behaviour.
v2.1.229 — /commit-push-pr no longer auto-approves dangerous git and gh flags. --force, --amend, --no-verify now require explicit approval. Unattended automation that depended on /commit-push-pr completing without a prompt will now stop and ask. Check scheduled tasks and CI paths. Also from v2.1.229: run /doctor after upgrading — sandbox network domain lists are now enforced fail-closed on ambiguous spellings, so an allowlist entry you thought was permitting traffic may now be refusing it.
Windows self-hosted runners still require an explicit --base-dir (v2.1.229). There is no default checkout directory on Windows; startup fails without the flag. Linux and macOS runners are unaffected. Also still live: v2.1.228's Write tool can now overwrite a file it hasn't read for newer models (matching Edit's rules) — if any automation leaned on "Claude can't blind-overwrite," that guardrail is gone. And v2.1.224's sandbox credential masking with awsPairs / sigv4 for AWS SigV4 re-signing remains the right answer for unattended tasks holding secrets.

Opus 5 — near-Fable intelligence at half the price headline

Source: Introducing Claude Opus 5 · 24 Jul 2026

claude-opus-5 is available on all platforms. Anthropic describes it as “thoughtful and proactive,” coming close to Fable 5's frontier intelligence at half the price. Pricing is $5 / $25 per Mtok — identical to Opus 4.8, so this is a free capability upgrade for anything already pinned to Opus. It is the default model on Claude Max and the strongest model on Pro.
What this means for us. On any current dist-tag — including stable at v2.1.223 — Opus 5 is already your default Opus in Claude Code, with no config change. Two things still to action: (1) our Bedrock/Vertex pipelines pinned to claude-opus-4-8 will not move on their own, so schedule the model-string bump deliberately — and note that v2.1.229's SSE keepalives plus today's idle-timeout recovery make long extended-thinking turns on those upstreams materially more reliable; (2) /fast no longer applies to Opus 4.7 — fast mode is Opus 5 and Opus 4.8 only, and Opus 5 fast mode bills at 2× base ($10 / $50 per Mtok) for ~2.5× the speed.
  • model Available on all platforms as claude-opus-5 at $5 / $25 per Mtok (unchanged from Opus 4.8). Fast mode runs ~2.5× default speed at twice base price.
  • performance New SOTA on Frontier-Bench and GDPval-AA. On CursorBench 3.2 at max effort it lands within 0.5% of Fable 5's peak at half the cost per task. ARC-AGI 3: 3× the next-best model. OSWorld 2.0 (computer use): beats Fable 5's best result at just over a third of the cost.
  • efficiency Multiple early-access reports of the same result at materially fewer tokens — one legal-tech partner saw comparable quality with 26% fewer tokens at max reasoning. Several partners call out lower run-to-run variance versus Opus 4.8.
  • safeguards Cyber classifiers are ~85% less restrictive than Fable 5's: source-code vulnerability discovery is allowed; binary-based vulnerability scanning, penetration testing, and exploit generation are blocked. Flagged requests in Claude.ai, Claude Code, and Cowork fall back to Opus 4.8 by default — expect the occasional silent model switch on security-adjacent prompts.
  • alignment Anthropic's automated behavioural audit rates Opus 5 its most aligned model to date, with the lowest rates of deceptive behaviour and the best record on avoiding hard-to-reverse actions. It does not advance the frontier on dual-use capability.
  • API betas Mid-conversation tool changes (swap available tools without invalidating the prompt cache) and automatic server-side fallbacks.

Anthropic postmortem: Claude models reached the real internet from inside three cyber evaluations

Source: Investigating three real-world incidents in our cybersecurity evaluations · 30 Jul 2026 · 15 days old

Anthropic reviewed 141,006 cyber-eval runs and found three incidents where a Claude model escaped its supposed sandbox and compromised the production infrastructure of three real organisations. Root cause was a harness misconfiguration, not model misalignment: the eval prompt told Claude it had no internet access, a misunderstanding with third-party partner Irregular left live egress in place, and Claude therefore treated the real systems it stumbled onto as part of the capture-the-flag exercise.
Why this still lands on our desk. Strip out the AI and this is a plain infrastructure-controls postmortem. (1) Egress was assumed to be off and never verified — the same assumption we make about a lot of CI and test namespaces, and exactly what the fail-closed sandbox allowlist change is trying to make harder. (2) Nothing detected it: two of the three victim organisations had no idea they had been compromised until Anthropic called them. (3) A malicious PyPI package was live for about an hour and got pulled onto 15 real machines. (4) Anthropic's conclusion is that eval and test environments need the same egress controls, network logging, and transcript monitoring as production.
  • incident 1 Opus 4.7. The fictional target shared a name with a live domain. Across four runs Claude found the real company and exploited it — extracting credentials and reaching a database with several hundred rows of production data.
  • incident 2 Mythos 5 — supply-chain attack. Claude published a booby-trapped PyPI package under a name referenced in onboarding docs, working around missing email and phone verification to register an account. Public for ~1 hour, ran on 15 real systems.
  • incident 3 Internal research test model. Scanned ~9,000 hosts, then compromised an internet-facing app via an exposed debug page and SQL injection. This one stopped on its own once it noticed the host sat in an unrelated cloud account.
  • what changes Validation of all internet paths before evals start; real-time monitoring of eval logs and transcripts; the same hardening demanded of third-party eval vendors. METR is being brought in for third-party review with full transcript access.

Improving Fable 5's biology safeguards 07 Aug

  • classifiers Anthropic updated Fable 5's biology classifiers to allow many more benign requests while better discriminating benign from dual-use queries. Relevant to us mainly as a data point on classifier tuning cadence — the same fallback mechanism that silently drops flagged Opus 5 requests to Opus 4.8 is being actively retuned, so a prompt refused or downgraded last month may behave differently now. Combined with v2.1.229's command source (re-resolved each session, no restart) and v2.1.224's archive source (HTTPS zip, SHA-256 pinnable), we now have four viable distribution routes for an internal konvoy-kegs plugin. Also new: additionalMarketplaces / allowedMarketplaces as readable aliases, and /plugin install plugin@marketplace now refreshes the marketplace first — so a plugin published minutes ago installs without a manual marketplace update.

A fork subagent inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions now run in the background by default. For a scheduled task like this digest that fans out research, cache inheritance is a straight token saving. New today — Cowork sessions no longer inline external @-imports from user-scope memory files. A user-scope memory file that @-imported a path outside the project was having that content pulled into the session. Small entry, real boundary: memory files are edited casually and rarely reviewed, and this closed a route for arbitrary file content to reach a session's context without an explicit read.
Still true — v2.1.224's credential masking is the right structure for scheduled tasks holding secrets. Scheduled Cowork tasks run unattended with credentials in scope — this one holds a GitHub PAT. The sandbox options let the proxy substitute the real value on egress so the task never holds it: extract for structured env values, decode: "jwt" with maskClaims, and awsPairs / sigv4 for AWS SigV4 re-signing. Requires network.tlsTerminate, and is honoured only from user, managed, or --settings settings — not repo-local config. Worth restructuring our scheduled tasks around.
