v2.1.305 — gateway regression fix, MCP allowlist change, nested user namespaces, worktree & runner fixes Wed 21 Oct AEDT · 38 bullets · newest on npm

sandbox Added sandbox.allowNestedUserNamespaces so sandboxed commands on Linux can create user namespaces (Chromium, rootless podman). The changelog is explicit: this lets them get around the sandbox's file protections. Off by default; treat turning it on as equivalent to loosening the sandbox for that project, and keep it out of managed settings unless a team needs Chromium or podman inside sandboxed Bash.
managed MCP & allowlists Changed allowedMcpServers to stop filtering managed-mcp.json stdio servers that use ${VAR} only in env. A server your allowlist left out now loads on upgrade; use deniedMcpServers to keep it off. If you rely on allowedMcpServers as the sole gate for managed stdio servers, audit managed-mcp.json before rolling v2.1.305 out. Also: plugins that Claude Desktop mounts by path no longer keep their allowed-tools when the organization's managed settings set allowManagedPermissionRulesOnly.
Bedrock, Vertex & gateways (v2.1.304 regression) Fixed every request failing on Vertex, Bedrock and other providers when the endpoint or a gateway rejects tool search, and behind gateways with ToolSearch disallowed or left out of --tools. v2.1.304 turned tool search on by default behind a custom ANTHROPIC_BASE_URL; this is the fallback that should have shipped with it. Also fixed: /effort and /autocompact not applying when the model name differed from a modelOverrides value by letter case or a [1m] tag; an MCP server passed by a cloud session or the SDK's setMcpServers being replaced later by a same-named server from your own settings; Claude naming the wrong model after a subagent fell back.
worktrees, disks & workflows New worktrees in a bare repository sometimes started from local HEAD instead of the default branch, and unchanged subagent worktrees were sometimes not cleaned up — both fixed. Bash on a full disk now says the disk is full and that nothing ran, instead of a raw ENOSPC path. Workflow resume no longer re-runs already-completed pipeline() and parallel() agents; they are served from the run's journal. Scheduled Cowork cloud sessions: more cases fixed of waiting five minutes per subagent whose WebFetch needed a URL approval nobody was there to give.
unattended runs, self-hosted runner & /usage CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS lets retry mode notice a usage limit that was lifted before its reset. Self-hosted runner: repository access failing since v2.1.296 when a git credential helper or askpass program reads its settings through GIT_CONFIG is fixed, as is a start script failing with Resource temporarily unavailable when TERM is set (v2.1.300 regression). /usage warnings are now one-line fixes naming their source and f applies them (same fixes in VS Code and /doctor). Startup warnings go to the debug log instead of printing above the logo.
Code Review, Claude Tag & cloud sessions Code Review: re-reviews no longer open with LGTM while earlier blocking findings are still open, and the newest commit is reviewed when several pushes land mid-review. Claude Tag: routines set up in a Slack thread keep posting after another routine restarts the conversation, and no longer report success without posting after a conversation ended; admins can add public channels Claude hasn't joined from the Add place search. Cloud sessions: the environments admin page no longer wrongly refuses to save an existing environment with an "installs packages" error. Remote Control no longer leaves empty "(session)" entries in /resume.

v2.1.304 — auto-mode setup everywhere, Managed Agents security check, settings ceilings, Code Review levels Tue 20 Oct AEDT · 76 bullets · now stable and bundled in Desktop

auto mode & Managed Agents /auto-mode-setup: a guided setup that reads your project and recent sessions to teach auto mode about your environment, now also on Bedrock, Vertex, Foundry and the Claude apps gateway. /claude-api managed-agents-secure compares a Managed Agents agent's settings with Anthropic's published security guide without changing anything. Pro/Max: a warning when resuming an inactive conversation would use a noticeable share of the 5-hour usage limit.
policy, sandbox & headless Mods' settings.read hooks receive each settings layer and rewrite the merged settings, so a managed mod can make an organization's setting a ceiling. Organization policy now refreshes right after approving an ANTHROPIC_API_KEY at startup. Sandboxed commands no longer fail to start on Linux when a denyRead glob has non-class brackets ([user-id]). rm -r of a mounted drive or top-level folder (/Volumes, /media, WSL /mnt/c) now gets the safety prompt. A plugin can no longer keep a headless run going past --max-turns by spawning subagents. claude --worktree no longer removes the worktree and branch without asking when HEAD was detached.
Code Review & gateways Review levels (Quick / Standard / Deep) per org and per repo, and an option to review every repository in a GitHub organization including ones added later. Tool search on by default behind a custom ANTHROPIC_BASE_URL (see the v2.1.305 regression fix above). context_management: Extra inputs are not permitted behind LLM gateways is retried without the field. CLAUDE_CODE_AUTO_COMPACT_WINDOW now accepts k/M suffixes.

v2.1.302 and v2.1.301 Fri 16 – Sat 17 Oct AEDT · 114 bullets

2.1.302 · behaviour changes for automation claude -p and Agent SDK sessions with no permission mode start in default mode on third-party providers, with telemetry off, or on a fresh install (--permission-mode auto keeps auto). Fork subagents on by default in claude -p, the SDK, desktop and VS Code (CLAUDE_CODE_FORK_SUBAGENT=0 turns them off). Desktop and VS Code always run the main conversation's subagents in the background. CLAUDE_CODE_AUTO_MODE_MODEL picks the client-side auto-mode classifier model. Standalone Claude Design (claude.ai/design) closes 14 December 2026.
2.1.301 · models & observability The fable and best aliases retry once on the previous Fable model when the newest isn't available to your organization. OTel tool_decision events gain classifier_verdict, permission_mode and classifier_category. CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS ends a request at a usage limit that resets too far away.

Security & evals

v2.1.305 CLI (documented) · Desktop v3.1623.0 with 10 breaking managed-settings changes

Today's actionable items

  • upgrade Fleet CLI target moves to v2.1.305. It is a fix release over v2.1.304 and closes the v2.1.304 gateway/Bedrock regression. Anyone on v2.1.304 behind a gateway that rejects tool search should move today; everyone else can take it on the normal cadence. stable still points at v2.1.304.
  • MCP allowlist drift v2.1.305 stops allowedMcpServers from filtering managed-mcp.json stdio servers that use ${VAR} only in env. A server that the allowlist previously excluded will load after the upgrade. Audit managed-mcp.json and add any you don't want to deniedMcpServers before rollout.
  • nested user namespaces sandbox.allowNestedUserNamespaces is new and off by default. Turning it on lets sandboxed Linux commands create user namespaces and, per the changelog, get around the sandbox's file protections. Consider denying it in managed settings until a team asks for Chromium or rootless podman in sandboxed Bash.
  • Desktop v3.1623.0: managed settings now bite harder Ten (breaking) changes in the Code tab where claude.ai admin settings apply: a Claude Code managed-settings file that fails to load now blocks Code sessions from starting or resuming on that computer; disableDesktopLocalSessions and disableSshSavedPasswords in the computer's own managed settings now apply (and the string "true" counts); sshHostAllowlist must also list ProxyJump / ProxyCommand jump hosts by HostName, hosts missing from the local list are refused whatever admin settings allow, and an empty or malformed list turns SSH off. Validate every managed-settings file before this build reaches engineers.
  • Desktop v3.1623.0: SSH & MCP SSH sessions no longer start desktop-configured MCP servers on a remote host whose admin uses managed-mcp.json to allow only their own servers; sessions won't start when a host can't report the real location of a folder (symlinks); the Browser pane in SSH sessions keeps sign-ins per session, opens localhost/private addresses only when typed, and won't open intranet sites at public-looking names. "Download file" is removed for .js/.bat/.ps1 shown as text in remote sessions.
  • Desktop v3.1623.0: 3P / device management isLocalDevMcpEnabled: false now also stops local MCP servers from plugins (org marketplaces included), from managed-mcp.json entries using ${VAR}, and from Claude Code's own config in the Code tab. builtinToolPolicy accepts every built-in tool name (entries for CronCreate or LSP are no longer dropped). releaseChannel: staggered lets devices skip intermediate releases. "Open external link" confirmation removed for most links on consumer builds; third-party deployments keep it.
  • Desktop plugins & allowed-tools (v2.1.305) Plugins that Claude Desktop mounts by path no longer keep their allowed-tools when managed settings set allowManagedPermissionRulesOnly — the managed rules now win, as intended.
  • self-hosted runner (v2.1.305) Repository access via a git credential helper or askpass reading GIT_CONFIG has been broken since v2.1.296 and is now fixed. If runners were patched around that, the workaround can be removed.
  • Code Review (GitHub) Re-reviews no longer open with LGTM while earlier blocking findings remain; the newest commit is reviewed when several pushes land mid-review (v2.1.305). Review levels and org-wide enrolment arrived in v2.1.304.
  • headless permission mode (carry-over, 2.1.302) claude -p and Agent SDK sessions with no permission mode start in default mode on third-party providers or with telemetry off. CI pipelines that assumed auto mode need --permission-mode auto.
  • MCP permission rules (carry-over, 2.1.299) mcp__a matches only the server named a. Audit prefix-style rules.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks).

Patterns worth tracking

Big release, next-day fix. v2.1.304 (76 bullets) turned tool search on by default behind gateways; v2.1.305 arrived within 24 hours to stop that from breaking Bedrock and Vertex. Expect the same cadence after large releases and hold gateway fleets a day behind latest.
Desktop crossed a major version and caught up on the CLI. v2.42304.2 (19 Oct, no changes, CLI 2.1.299) became v3.1623.0 (20 Oct, CLI 2.1.304). The jump is mostly about enforcement: managed settings that used to be advisory on a device now stop sessions outright, and SSH allowlists cover jump hosts.
Enforcement keeps moving into managed settings and mods. 2.1.299–2.1.296 hardened hooks; v2.1.304 let managed mods set ceilings; v2.1.305 takes allowed-tools away from path-mounted plugins under allowManagedPermissionRulesOnly, but also loosens allowedMcpServers filtering. Read each release's "Changed" bullets, not just "Fixed".
stable now trails by one. After the 17-day park on v2.1.292 and the overnight jump to v2.1.304, stable did not follow v2.1.305 on day one. Watch whether it settles into a one-release lag.

Claude Desktop

v3.1623.0 · 20 Oct · bundles Claude Code 2.1.304 · Windows 10 2004+ now required

What's new

v3.1623.0 · 20 Oct · General Storage in Settings: shows the disk space Claude uses and frees space by removing inactive Cowork tasks and Code sessions; a low-disk warning opens it, as does /storage in Cowork and Code (not yet on third-party deployments). Minimum Windows is now 10 version 2004 (build 19041); older PCs keep their current version and the Microsoft Store build is unchanged. The "Open external link" confirmation is gone for most links. Fixes: unsent or still-uploading messages no longer lost after a reload; pop-out windows (Projects, Code sessions, side panes) reopen after sign-in or reload; saving a skill no longer fails on Windows when the skills folder path is 260+ characters; macOS freeze when an app's icon was missing from a permission prompt.
v3.1623.0 · Code tab (breaking) Ten breaking changes for managed devices (see Security): managed-settings file load failures block sessions; local-session and saved-password bans from the computer's own managed settings apply; sshHostAllowlist covers jump hosts and an empty/malformed list turns SSH off; SSH sessions won't start desktop MCP servers on hosts governed by managed-mcp.json; Browser pane isolation in SSH sessions; relative or odd folder paths dropped from WSL/SSH sessions. Fixes: an app update or restart no longer ends work on an SSH host (Windows carries on with the running task; macOS/Linux no longer drops tasks or permission prompts older than three days); queued messages come back after a quit, update or crash; removing an inactive session's worktree no longer deletes an archived session's nested worktree; SSH hosts with MaxSessions 1 now connect.
v3.1623.0 · 3P / device management New for third-party deployments: the Code tab (New session page with saved environments, session rail, sidebar grouping by environment, plan and next-step box, /btw side chats); quickEntryDefaultShortcut; releaseChannel: staggered; an optional base64 icon on managedMcpServers entries; "Sign in with Claude Console" keeps your sign-in instead of creating an API key; builtinToolPolicy accepts every built-in tool name; isLocalDevMcpEnabled: false also stops plugin and managed-config local MCP servers; subagents in Code tab sessions always run in the background and keep running after Stop. Fixes for blocked-claude.ai sign-in loops, read-only allowedWorkspaceFolders, duplicate imports, and keychain-reset breakage.
carry-over v2.42304.2 (19 Oct) was a no-change rebuild on Claude Code 2.1.299. v2.42304.0 (15 Oct) introduced the session rail and Code-tab layout that v3.1623.0 now ships to third-party deployments. Claude Code v2.1.305 is not yet bundled; when Desktop next bumps it brings the gateway regression fix and the allowedMcpServers change.

Claude Cowork

What's new

Desktop v3.1623.0 · 20 Oct "Hand off to Claude Code" in the menu under a design's name: opens Claude Code with a prompt to build the design in your codebase, or gives you the prompt to paste. Import from Claude (third-party builds, where device management turned it on) now keeps an attached home, Documents or ~/Claude folder on a copied task or project (folders above home and system folders such as ~/Library or AppData are still left out). /storage works in Cowork too. Fixes: global instructions reverting to an earlier version after an older task was archived, deleted or continued; recently opened tasks being removed by automatic local cleanup after a restart (HIPAA configuration); the folder picker showing "Couldn't load" until reload; Claude being told to save into a read-only allowedWorkspaceFolders entry.

An MCP server passed by a cloud session no longer gets replaced mid-session by a same-named server from your own settings. Cloud sessions and teammates now tell Claude when compaction had to drop the oldest messages. The Cloud environments admin page no longer refuses to save an existing environment with an "installs packages" error.
Claude Tag (Slack) · v2.1.305 Routines set up in a Slack DM thread keep posting after another routine in that thread restarts the conversation; routines whose conversation ended are skipped and the creator is told, instead of reporting success without posting. Admins can add public channels Claude hasn't joined from the Add place search; access bundles can re-add a repository that moved GitHub accounts; admin pages in large orgs work while the channel list is still loading.
carry-over · v2.1.304 A claude.ai Directory plugin's skills now run as commands from the "/" menu in Cowork cloud sessions. Artifacts with several views: Claude writes out each view's link when asked. Nothing new on the Claude apps release-notes page since 7 Oct (Haiku 5.5, monthly API credits).
