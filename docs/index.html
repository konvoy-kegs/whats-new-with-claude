v2.1.310 — Monitor on every provider, gateway retries, Windows hooks fail-open, Enterprise roles for cloud sessions Sat 24 Oct AEDT · 26 bullets · newest on npm

Monitor tool · providers Added the Monitor tool and plugin monitors on Bedrock, Vertex and Foundry, and when telemetry or nonessential traffic is disabled; long foreground sleeps are now blocked there too. Until now the Monitor tool (and plugins that declare monitors that start automatically while the plugin is active) only worked on the Anthropic API with feature-flag fetching on. The tools reference now lists v2.1.310 as the minimum on those platforms and with DISABLE_TELEMETRY or CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC set. On Windows the tool still needs Git Bash. Related in the settings reference: the managed hooks policy option "Monitors from other plugins are blocked" (a plugin's monitors don't start unless the plugin is force-enabled) also requires v2.1.310.
gateways & compaction Fixed requests failing behind some gateways and compatible servers that reject the effort-2025-11-24 beta value or mid-conversation system messages; Claude Code now retries without them. Note what that means for a gateway fleet: if your gateway strips or rejects the effort beta, /effort settings are silently not applied on the retried request — add the beta to the gateway's allowlist rather than relying on the fallback. Fixed compaction after a "Prompt is too long" error keeping too much of a conversation with dense text, such as base64 or SVG, so the next request could fail again. Improved memory use of non-interactive sessions (-p, Agent SDK) during compaction when the transcript file is very large. Changed the error for an MCP tool call that times out in a non-interactive session while the server's elicitation is unanswered: it now tells Claude that no answer came and not to repeat the call.
permissions & hooks Windows: Fixed PreToolUse and PermissionRequest hooks letting a tool call through when Git Bash is missing and the hook's command is only quoted strings, such as a quoted path. This is the second Windows fail-open fix in two releases (v2.1.309 covered PowerShell hooks on exit code 2 and "shell": "powershell" hooks without Git for Windows). Fixed file read permission prompts not showing where a symbolic link leads — before this, approving a Read of ./config could be approving a read of wherever that link resolved. Improved auto mode's prompt before the first read outside the working directories: it now says when blocking those reads makes shell commands ask for permission.
files, sessions & terminals Fixed background cleanup deleting some recent files, such as pasted images, when cleanupPeriodDays is set to a very large value. Anyone who set a huge retention value "to keep everything" was getting the opposite for recent pasted content. Fixed a question's auto-continue timeout firing the moment the external editor closed after a long edit. Improved a mod's Image to draw inside tmux with allow-passthrough and focus-events on, in kitty, Ghostty and iTerm2 3.5+ with fullscreen rendering, where it showed only its alt text. Linux: improved /sandbox and the sandbox startup warning to name Ubuntu's AppArmor restriction on user namespaces, and how to lift it, when it keeps bubblewrap from starting the sandbox — the usual cause of "sandbox cannot run" on Ubuntu 24.04 runner images.
cloud sessions & Enterprise admin Added Claude Code cloud sessions and Remote Control permissions to Enterprise custom roles, so Owners can control access to each by role. Changed turning on Cloud sessions or Remote Control in admin settings to ask for confirmation and list the custom roles that have that permission. Added a Choose file button to load a cloud environment's setup script from a file. The cloud environment dialog now opens network access, setup script and environment variables from rows instead of listing every editor at once. The session start checklist shows a cloud environment's setup script output in a scrolling box. Failed saves and archives in the cloud environment edit dialog, and failed routine API token actions, now show their error inside the dialog instead of a toast only.
VS Code, Claude Tag & Code Review VS Code: pressing Enter on the plan review card's "Send feedback and keep planning" button no longer approves the plan instead of sending your comments back; the panel no longer shows "Something went wrong" after "Switch branch & continue" on a cloud session opened from Session history's Web tab. Claude Tag: !restart and !help are no longer treated as ordinary messages when sent in bold, italic or strikethrough; admin channel and workspace pages are no longer replaced by a load error when a background bundle refresh fails; the spend limits page no longer reports that no channels match a filter while names are still loading. Code Review: the admin section no longer hides its repositories and switches after a failed refresh, retries the first load, and shows one Try again banner when it still fails.
docs gated to v2.1.310 · OpenTelemetry The monitoring docs now gate three fields to v2.1.310: agent_id (the subagent's identifier on its tool and API events, same value as the span's agent_id), parent_agent_id (the agent that spawned or last resumed the subagent; absent for the main session) and request_id on tool_result and tool_decision events (the request_id of the API response that contained the tool call, so a tool decision can be joined to that response's API events). Together with v2.1.307's claude_code.safety_event, this is enough to build a per-subagent audit trail of which model turn asked for which tool and what the permission system did with it.

v2.1.309 — sandbox and permission-check hardening, sed -i and ultrareview behaviour changes Fri 23 Oct AEDT · 79 bullets · not on stable

sandbox & permission checks Fixed sandboxed Bash commands on macOS and Linux running the shell's startup files outside the sandbox before each command. Fixed macOS sandbox denyWrite globs not applying at a path's real location when reached through a symlink. Fixed sandboxed commands and auto-accepted edits being able to modify the MCP config file passed with --mcp-config. Fixed profile store write protection not applying through a symlinked config directory. Fixed the Bash permission check trusting a variable set by a command whose redirect can fail to open; wrapped or prefixed cd before git not prompting; an Edit(path) deny rule not blocking a Bash redirect in commands with a subshell; worktree isolation accepting locale-prefixed and zsh arithmetic commands; PowerShell Set-Location/cd with extra arguments auto-approved; PowerShell hooks not blocking on exit code 2 and failing open without Git for Windows. Fixed split-pane agent teammates not inheriting the leader's tool deny and --tools rules.
behaviour changes sed -i now gets the standard Bash prompt and runs as written; like other Bash edits it is no longer restored by /rewind. claude ultrareview requires workspace trust: scripts pass --trust-workspace (no value; put a PR number or base branch before it) or set CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1. In bypass-permissions mode in the Desktop app and VS Code, dangerous rm/rmdir are denied at once with a rewrite hint, so unattended sessions keep going. Fixed Claude notifying unrelated GitHub users by writing role names and placeholders as @-mentions in PRs, issues and comments. Fine-grained tool streaming now turns on for the default bedrock-runtime.<region>.amazonaws.com endpoint. The /claude-api skill builds Managed Agents subagent teams on multiagent_20261001 with dynamic workflows by default.
Desktop, Cowork, VS Code & cloud Fixed messages from a Claude Desktop-hosted session sometimes being lost when its connection refreshed, and features missing when the terminal on the same computer was signed in to a different account or organization. Fixed plugins and skills synced from claude.ai being removed, sometimes mid-session, after a disk read error. Fixed artifact publishes being refused for some ordinary pages and Claude re-asking permission on every artifact update after a compaction. Fixed sessions compacting repeatedly under a very large nested CLAUDE.md. VS Code: TLS-inspecting proxy warning for dictation, no more empty "Untitled" sessions in history, long /goal prompts fold behind Show more, Edit/Write wait 0.75 s for new problems. Cloud sessions: the environment editor no longer shuffles environment variables or adds backslashes to values with both kinds of quote.

Security & evals

v2.1.310 CLI: Windows hooks fail-open (second fix in two releases), symlink targets in read prompts, Enterprise custom roles for cloud sessions · v2.1.309 hardening still not on stable

Today's actionable items

  • upgrade Fleet CLI target moves to v2.1.310. stable is now two releases behind on v2.1.308 and has none of Friday's sandbox or permission fixes, nor today's Windows hooks fix. For machines where the sandbox or hooks are part of the control story (shared runners, auto mode, headless pipelines, Windows laptops with managed hooks), pin latest or an explicit 2.1.310 rather than waiting for stable.
  • Windows: hooks failed open, round two v2.1.310 fixes PreToolUse and PermissionRequest hooks letting a tool call through when Git Bash is missing and the hook's command is only quoted strings, such as a quoted path. v2.1.309 fixed the PowerShell variants. Any Windows managed-settings hook written as "command": "\"C:\\\\tools\\\\deny.exe\"" on a machine without Git Bash was not denying before today. Re-test the deny path on a Windows machine on v2.1.310, and treat "Git Bash installed" as a prerequisite in the Windows baseline image.
  • read prompts now show symlink targets File read permission prompts did not show where a symbolic link leads. A Read of an innocuous-looking path inside the project that was actually a link to ~/.aws, ~/.kube or /etc would have been approved as the project path. Fixed in v2.1.310; worth a look at any repo that vendors dotfiles via symlinks.
  • gateways: effort beta silently dropped Behind a gateway that rejects the effort-2025-11-24 beta value or mid-conversation system messages, v2.1.310 retries without them instead of failing. That is the right default for availability, but a gateway that strips the beta now produces sessions that quietly ignore /effort and any managed effort setting. Add effort-2025-11-24 to the gateway's allowed beta list if effort limits are part of the cost controls.
  • cleanupPeriodDays: recent files were being deleted Background cleanup deleted some recent files, such as pasted images, when cleanupPeriodDays was set to a very large value. If a managed settings file sets a large retention value to keep transcripts, check whether anyone reported pasted screenshots disappearing from sessions; fixed in v2.1.310.
  • Enterprise: cloud sessions & Remote Control per role Claude Code cloud sessions and Remote Control permissions are now on Enterprise custom roles, and turning either on in admin settings asks for confirmation and lists the custom roles that have the permission. Review which roles should be able to start cloud sessions (they run code against your repos from Anthropic's or a self-hosted runner) and which should be able to Remote Control a desktop session.
  • managed hooks policy: block monitors from other plugins The settings reference adds a managed hooks policy option that blocks a plugin's monitors unless the plugin is force-enabled (v2.1.310+). With the Monitor tool now live on Bedrock/Vertex/Foundry, a plugin from an allowed marketplace can start long-running monitors by itself; this option is how to keep that to plugins the organization force-enables.
  • OTel: join tool decisions to API responses request_id on tool_result and tool_decision events, plus agent_id / parent_agent_id on subagent events, are gated to v2.1.310 in the monitoring docs. Together with claude_code.safety_event (v2.1.307) and the classifier fields (v2.1.302), the Grafana/Loki pipeline can now attribute a blocked or prompted tool call to the exact model response and subagent that produced it. Worth a dashboard panel once fleets are on 2.1.310.
  • MCP elicitation in unattended sessions An MCP tool call that times out in a non-interactive session while the server's elicitation is unanswered now tells Claude that no answer came and not to repeat the call. Scheduled Cowork tasks and claude -p pipelines that hit an elicitation will fail that call cleanly once instead of looping on it.
  • carry-over (v2.1.309) Sandboxed Bash ran the shell's startup files outside the sandbox before each command; --mcp-config was writable from sandboxed commands and auto-accepted edits; macOS denyWrite globs and profile store protection did not apply through symlinks; five permission-check bypasses closed (redirect-variable trust, wrapped cd before git, Edit(path) deny vs Bash redirect in subshells, locale-prefixed and zsh arithmetic commands in worktree isolation, PowerShell cd with extra arguments); PowerShell hooks failed open; bypass-mode rm/rmdir now a hard deny; sed -i no longer restored by /rewind; claude ultrareview needs --trust-workspace in scripts; stray GitHub @-mentions fixed. Diff startup files on shared dev boxes and runner images; audit pipeline-owned MCP config files.
  • carry-over (Desktop v3.6556.1) The built-in GitHub connector prompts before every write call (issue_write, sub_issue_write, pull_request_review_write, add_reply_to_pull_request_comment and five toolset-enabled write tools); actions_run_trigger always prompts. A folder's permission mode is saved per host (this computer, each SSH host, each WSL distribution) and Bypass-permissions folders reset to default until re-picked. allowedWorkspaceFolders on SSH hosts must be full paths with no ..; symlinks inside listed folders are left out. New 3P keys: installedUpdateEnforcementEnabled/Hours, quickEntryScreenshotsEnabled, quickEntryFileSharingEnabled, headersHelperArgs, envHelperArgs. Firewall allowlist adds hcaptcha.com and bootstrap-delivered MCP/marketplace hosts — export it again. This digest's own GitHub push uses git over HTTPS, not the connector, so it is unaffected.
  • carry-over (v2.1.307, v2.1.302, v2.1.299) HTTP MCP tool calls could be sent twice on a dropped connection before v2.1.307; only read-only or idempotent tools are retried now. claude -p and Agent SDK sessions with no permission mode start in default mode on third-party providers or with telemetry off (CI needs --permission-mode auto). mcp__a permission rules match only the server named a.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks).

Patterns worth tracking

Windows hooks have now failed open in two consecutive releases. v2.1.309 fixed PowerShell hooks (exit code 2 ignored; "shell": "powershell" hooks failing open without Git for Windows) and v2.1.310 fixes Git-Bash-missing with quoted-string commands. The common thread is a hook command that cannot be launched being treated as "allow". If the Windows laptops carry managed deny hooks, a regression test that removes Git Bash and checks the hook still denies is cheap and now clearly worth having.
stable is not a safe harbour this week. It has sat on the one-line v2.1.308 since Thursday while v2.1.309 (79 bullets, eleven sandbox/permission fixes) and v2.1.310 (26 bullets, Windows hooks) shipped on latest. Whatever promotion cadence Anthropic uses for stable, it is currently lagging the security fixes by two releases; fleets that pin stable for predictability are trading away the fixes that matter most.
Third-party-provider parity is a steady drip. /auto-mode-setup and mod drawing reached Bedrock, Vertex and Foundry in v2.1.304; Monitor and plugin monitors in v2.1.310. Each lands a few releases after the Anthropic API version, which is the pattern to expect for the Bedrock-backed sessions: features seen in a demo on the Anthropic API will usually show up on Bedrock within one to two weeks, gated by a minimum version in the docs.
Desktop is two CLI releases behind and had a silent rebuild. v3.6556.2 (22 Oct) lists no user-facing changes in any section and still bundles Claude Code 2.1.308, so the Code tab is missing both the v2.1.309 hardening and today's fixes. A no-change build the same day as a large one usually means a packaging or crash fix; nothing to do, but the next Desktop bump is the one to watch.

from Claude Code v2.1.310 · scheduled runs & files Fixed background cleanup deleting some recent files, such as pasted images, when cleanupPeriodDays is set to a very large value — the likely explanation if a screenshot pasted into a task vanished before the task finished. An MCP tool call that times out in a non-interactive session while the server's elicitation is unanswered now tells Claude that no answer came and not to repeat the call; unattended runs that hit an elicitation fail that call once instead of looping. Improved memory use of non-interactive sessions during compaction when the transcript is very large. These reach Cowork in the app once Desktop bundles 2.1.310 (currently 2.1.308).
scheduled tasks · Desktop v3.6556.1 · 22 Oct Fixed Claude not finding your plugins and skills in scheduled tasks and other tasks not open on screen (except in third-party deployments) — the likeliest cause of a scheduled task that worked when run by hand but ignored a plugin's skill overnight. MCP tools that their server marks as needing a person now ask only on the in-app card: their notifications have no Allow button, and scheduled tasks go on without those calls instead of waiting. /schedule is gone from the slash menu; typing it fills in a request to schedule the task, like the Schedule button. Fixed tasks started from a plugin's setup card, a connector's suggested prompts or an onboarding suggestion being silently dropped after the workspace failed to start. Fixed earlier tasks missing from the list on some Windows computers after an older version started blank and signed out.
connectors in scheduled runs · Desktop v3.6556.1 The built-in GitHub connector now prompts before every write tool call and actions_run_trigger always prompts; the Microsoft 365 read tool re-asks once. Combined with the "ask only on the in-app card" change, an unattended Cowork task that writes to GitHub through the connector will skip the write rather than hang. Tasks that must write need the tool allowed by an exact toolPolicy key, or should use a non-interactive path (git over HTTPS, a webhook) — which is how this digest pushes its own site.
