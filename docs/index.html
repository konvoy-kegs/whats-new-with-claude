v2.1.238 — MCP credential inheritance and trust gating, a memory leak in long sessions, authenticated plugin marketplaces new overnight

41 entries · published Fri 21 Aug 04:01 local · the largest release since v2.1.234

MCP — a headersHelper in a repo you cloned has been running with your credentials in its environment, before you trusted the folder. Two entries, and they only make sense read together. (1) “MCP headersHelper from a project .mcp.json, plugin, or agent file now runs without inherited credential env vars; user, managed and claude.ai-scope helpers now run from the Claude config dir.” (2) “MCP headersHelper in a project .mcp.json, and inline MCP servers in project or --add-dir agent files, now require that folder's trust dialog to have been accepted (also under claude -p).” A headersHelper is a command the repo specifies, that Claude Code executes to mint auth headers. Until today, a project-scoped one inherited whatever credentials were in your environment and, on the evidence of the second fix, could run before the trust dialog was answered. The claude -p clause is the sharp end: in headless and CI invocations there is no dialog to answer, so the gate was effectively absent. If we run claude -p over repos we do not fully control, this is today's upgrade justification on its own.
Memory — long interactive sessions grew without bound because subagent results were never released. “Fixed unbounded memory growth in long interactive sessions: subagent tool results are now released once they leave the recent display window.” Every subagent tool result stayed resident for the life of the session. The sessions that suffer most are the ones that fan out to many subagents and run for hours — which is exactly the shape of our long-running Cowork and CI work. Combined with v2.1.235's grep memory-exhaustion fix and v2.1.233's CLAUDE_CODE_TOOL_MEMORY_LIMIT cgroup cap, the runaway-memory surface is now meaningfully smaller than it was a week ago. If we have raised container memory limits for Claude Code recently, re-baseline them after upgrading rather than leaving the headroom in place.
Plugin marketplaces — headersHelper is the piece the internal konvoy-kegs marketplace was missing. “headersHelper on a url marketplace or a catalog entry runs a command that mints HTTP headers (e.g. a short-lived token) for catalog and same-origin archive fetches.” That is authenticated plugin distribution without a static token sitting in config — mint a short-lived credential per fetch instead. The guard rails shipped with it: a catalog entry's helper runs only when you install or update that plugin, after its command is shown, and claude plugin install/update now prompt [y/N] (pass -y to skip). So the command is displayed before it runs and you approve it explicitly. Note the same release tightens where a project-scoped helper can run — the marketplace feature and the credential-isolation fix are two sides of one change.
Self-hosted runners — two changes that matter if we run Claude Code on our own infrastructure. (1) --defer-shutdown-max-min <minutes>: on SIGTERM, keep serving attached sessions, park whatever is left after that many minutes, then exit. This is the graceful-drain flag a Kubernetes rollout needs — without it, a deploy terminates live sessions at the pod's terminationGracePeriodSeconds. (2) --proxy-authorization-command / --proxy-authorization-file for egress proxies that require a freshly issued Proxy-Authorization header on every connection. And a fix in the same area: runners were occasionally removed by the server after a single slow or lost poll, handing their healthy session to another runner — a plausible explanation for sessions that appeared to migrate for no reason on a busy or lossy network.
Behaviour change — the double-press /clear shortcut is gone. “Changed Ctrl+L and Cmd+K in fullscreen to always just repaint — the double-press /clear shortcut was removed, and 1-row nvim terminals no longer trigger automatic /clear loops.” If anyone has built the muscle memory of double-tapping Ctrl+L to clear the conversation, it now only repaints. The nvim clause explains why: a 1-row terminal was triggering /clear in a loop on its own. Also changed: claude mcp list and claude mcp get now show disabled servers as ⊘ Disabled instead of connecting to them for a health check — faster, and it stops a disabled server being woken by an inventory command.
  • permissions Improved Bash tool permission checking for zsh-specific syntax in shell conditionals. No detail on what was mis-parsed, but it is the same family as the < file redirection gap still outstanding from v2.1.233 — shell syntax the permission checker reads differently than the shell does.
  • permissions Fixed MCP elicitation dialogs showing nothing for URLs longer than 4,096 characters, and permission prompts dropping the “don't ask again” option when the project path didn't fit the terminal width. A dialog that renders empty is a dialog you approve blind; a narrow terminal silently changing which options a prompt offers is the kind of thing that makes approvals inconsistent between machines.
  • output styles Fixed custom, project, and plugin output styles drifting back to the default voice mid-session. If we ship a project output style and people report Claude “stops sounding right” after a while, that was this.
  • ergonomics New keybindingFlavor setting — set it to "readline" to make Ctrl+W in the prompt delete back to the previous whitespace, as in Bash. Default ("classic") is unchanged.
  • hygiene Fixed leftover /tmp/claude-*-cwd files when a Bash command is killed, times out, or is interrupted. Small, but these accumulate on long-lived runners and CI hosts.
  • proxies A proxy's refusal of a connection is now reported as a proxy refusal, naming the proxy, instead of a generic network error. Anyone who has spent an afternoon on a “network problem” that was a corporate proxy will appreciate this one.
  • sessions Cross-session messaging now tells the sender the truth. Sending to a session that refuses inbound messages (e.g. crossSessionInbound: "refuse") now reports “refused” instead of a silent success, and a session whose inbox drops messages (rate limit or full queue) now says so instead of the messages vanishing. Third consecutive release closing a silent-drop path in SendMessage.
  • agents ListAgents/SendMessage reported “Remote Control is not connected” in sessions run by claude remote-control (server mode) or Desktop/IDE hosts — they now list and reach Remote Control peers. Separately, ListAgents no longer exposes the idle worker pre-warmed for your next background session; it appears only once a task claims it.
  • remote control Eleven Remote Control fixes in one release. The notable ones: messages sent from web or Desktop mid-turn no longer disappear from the transcript after the turn finishes; a crashed session can be reused when you next message it instead of requiring a restart; a brief network hiccup during sign-in renewal no longer disconnects with “login expired”; model picks made on a phone now update the model shown in the terminal; sessions no longer inherit session-scoped environment variables from the launching shell.
  • resilience Remote Control now tolerates brief HTTP 403 refusals from a network edge, VPN, or proxy for up to 3 minutes, naming the refusing party when a block persists. Paired with the proxy-naming fix above, this release is unusually good at telling you when the network, rather than Claude, is the problem.
  • startup Bare claude starts sooner on macOS, and the automatic update check now runs about 10 seconds after launch instead of competing with startup for CPU.
  • skills Updated the bundled claude-api skill for the Managed Agents 19 Aug release — web search/fetch domain settings and memory stores on self-hosted sandboxes.

v2.1.237 — a prompt-cache fix for gateway users, and a “Concise” output style

2 entries · published Thu 20 Aug 09:57 local

Prompt caching was broken for sessions using an LLM gateway or custom base URL. One line in the changelog, real money behind it. Every request through a gateway or custom ANTHROPIC_BASE_URL was missing cache and re-billing full context at uncached rates. If we route Claude Code through a gateway, this is a direct cost regression that has now been fixed — and it is the second cache bug in three releases, after v2.1.235's whole-prompt-cache invalidation on language-server reconnect. Worth a look at the gateway's spend line before and after upgrading.
  • output styles New built-in “Concise” output style — Claude leads with results and skips preamble and narration while doing the work just as thoroughly. Select it under Output style in /config. Note v2.1.238 fixes custom and project output styles drifting back to the default mid-session, so the two releases go together.

Still open — reverted Bash checks, gateway boot validation, MCP secret exposure, container limits action required

v2.1.233's reverts still stand — < file redirection is not permission-checked. Five releases on. v2.1.233 reverted v2.1.232's Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (< file), promising a narrower version later. v2.1.234 through v2.1.238 all pass without bringing it back. Today's release does improve Bash permission checking for zsh-specific conditional syntax, which shows the area is being worked — but reading a file by < file is still not checked the way the argument spelling is, on any platform. Any deny rule written on the strength of that change still does not do what it looks like it does.
v2.1.234 — MCP diagnostic output may already have leaked live secrets, and nothing since has addressed what was already pasted. The code fix landed: MCP scope-conflict warnings show the configured ${VAR} form rather than resolved values, and connection-failure details show only the server origin. The historical exposure is untouched. Today's headersHelper credential-isolation change makes this more pressing, not less — it confirms that MCP configuration has been running closer to our live credentials than the config implied. Search #cloud-engineers and Jira for pasted MCP diagnostics and rotate anything that appears. Still the only item on the board with a possible past exposure rather than a future one.
v2.1.232 — the gateway still fails at boot on configuration it previously accepted. Unchanged by v2.1.233 through v2.1.238, and still the biggest upgrade risk. Two fail-fast changes. (1) The desktop: overlay now accepts every released Desktop setting, validated at boot against Desktop's own schema — unknown or invalid keys now fail boot, where a typo used to be silently ignored. (2) Empty managed.policies[].match.groups and admin.admin_groups entries, and malformed email_domain values, now fail at boot instead of silently matching no one or granting admin access. If our gateway config has an empty admin_groups entry today, it has been granting admin. Validate in a non-production environment first.
v2.1.229 / v2.1.233 / v2.1.238 — the memory and CPU picture is now correct in all three dimensions; re-baseline anything sized around the old behaviour. v2.1.229 fixed dynamic workflows using the host's core count rather than the container's CPU limit — the likeliest explanation for throttling or noisy-neighbour behaviour from Claude Code in CI or on EKS. v2.1.233 added CLAUDE_CODE_TOOL_MEMORY_LIMIT to cap Bash commands with a Linux memory cgroup. v2.1.235 fixed the embedded grep exhausting memory on pathological patterns. Today's unbounded-growth fix is the last of the set. Any container memory ceiling we raised to work around a leak can now come back down — but measure before you cut.
Carried forward: v2.1.236's macOS wildcard read-deny bypass — **/.env-style rules lost to overlapping allows, missed directory contents, and could be walked past by renaming. v2.1.235's Shift+Tab permission-grant bypass and v2.1.236's invisible managed-settings approval prompt — two ways a reflex keystroke issued a grant nobody saw. v2.1.234's NT-namespace hardening — Windows hosts that stopped at v2.1.233 are still exposed. v2.1.233's Todo/task tools remain removed on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer (CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to restore). v2.1.234's strictKnownMarketplaces SCP-style host-confusion fix — re-read any allowlist. And v2.1.224's sandbox credential masking with awsPairs / sigv4 is still the right answer for unattended tasks holding secrets.

What's new

Sources: Get started with Claude Cowork, Schedule recurring tasks, Use plugins in Claude. Checked Fri 21 Aug 2026 — no new Cowork-specific release note since 7 Jul (Cowork on web and mobile). The live items are overnight's CLI changes, the 6 Aug plugin-scanning beta, and v2.1.228's skill hardening.

New — the MCP headersHelper change is the one that matters most for scheduled tasks. A scheduled Cowork task runs unattended, non-interactively, in a working directory it did not choose, with credentials in scope — this task holds a GitHub PAT. From v2.1.238, a headersHelper from a project .mcp.json, plugin, or agent file runs without inherited credential environment variables and requires the folder's trust dialog to have been accepted, including under claude -p. Unattended runs are precisely the case where no one is present to answer a trust dialog, so the gate was doing the least work exactly where it was needed most. Every scheduled task that touches a repository should be on v2.1.238 before its next run.
New — long sessions no longer grow without bound, and subagent-heavy tasks are the ones that benefit. “Fixed unbounded memory growth in long interactive sessions: subagent tool results are now released once they leave the recent display window.” A Cowork task that fans out to subagents and runs for hours was holding every subagent result in memory for the life of the session. This is the fourth and last piece of the memory story — after v2.1.229's container CPU-limit fix, v2.1.233's CLAUDE_CODE_TOOL_MEMORY_LIMIT cgroup cap and v2.1.235's grep fix. If a long-running Cowork task has ever been OOM-killed, retry it after upgrading before you go looking for another cause.
New — claude plugin install/update now prompt [y/N], which will block non-interactive automation. The prompt exists so a catalog entry's headersHelper command is shown before it runs — a good change — but anything that calls claude plugin install from a script or a scheduled task will now hang waiting for input unless it passes -y. Worth grepping our automation for plugin installs before rolling v2.1.238 out to unattended runners.
New — authenticated internal marketplaces are now practical. headersHelper on a url marketplace or catalog entry mints HTTP headers — a short-lived token, for instance — for catalog and same-origin archive fetches. For the internal konvoy-kegs marketplace this removes the last awkward part: distributing plugins behind auth without a static token in config. Combined with v2.1.234's strictKnownMarketplaces host-confusion fix and v2.1.233's claude plugin validate checking bare .claude/skills directories, the pieces are now in place.
New — cross-session messaging finally reports failures. Two entries. Sending to a session that refuses inbound messages (crossSessionInbound: "refuse") now reports “refused” instead of a silent success, and a session whose inbox drops messages to a rate limit or a full queue now tells the sender rather than letting them vanish. This is the third consecutive release closing a silent-drop path in SendMessage, after v2.1.235's oversized-message refusal and v2.1.236's burst refusal. Multi-session orchestration in Cowork was reporting success for messages that were never delivered — if a supervising task has ever appeared to hand off work that never happened, this is the likeliest explanation.
Standing — v2.1.224's credential masking is still the right structure for scheduled tasks holding secrets. The sandbox options let the proxy substitute the real value on egress so the task never holds it: extract for structured env values, decode: "jwt" with maskClaims, and awsPairs / sigv4 for AWS SigV4 re-signing. Requires network.tlsTerminate, and is honoured only from user, managed, or --settings settings. Today's headersHelper change is the complement from the other direction: masking governs what leaves, credential isolation governs what a repo-supplied command can see in the first place.
