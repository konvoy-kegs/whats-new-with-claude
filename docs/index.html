Claude Code

CLI · v2.1.300 on latest and next
All sources aligned on v2.1.300. npm newest, the latest and next dist-tags, the changelog top and the newest GitHub release all read v2.1.300. npm publish 2026-10-14 14:27 UTC (Thu 15 Oct 01:27 AEDT); GitHub release 2026-10-14 18:24 UTC. The five-day quiet spell ended with two releases on the same UTC day: v2.1.299 (14 Oct 00:23 UTC) and v2.1.300 fourteen hours later. v2.1.297 and v2.1.298 were never published to npm. Both releases have full changelog entries (190 and 88 bullets). stable moved from v2.1.287 to v2.1.292, still six releases behind latest.
What matters in the pair. v2.1.299 is a security sweep: a sandbox write escape via --plugin-dir, macOS sandbox symlink bypasses, a third-party gateway API key being sent to Anthropic endpoints, MCP permission rules that silently matched the wrong server, fail-closed plugin hooks, and a credential fragment leaking into a teammate's task description. v2.1.300 adds /advisor on Claude Platform on AWS, OpenTelemetry GenAI span attributes, hook updatedInput validation, gzip request bodies, and a fix for the Cowork "Allow for this task" regression from 2.1.292. Desktop v2.37337.1 still bundles 2.1.295, so none of this is in the Code tab yet.

v2.1.300 — /advisor on AWS, OTel GenAI spans, hook input validation, gzip newest · aligned

Claude Platform on AWS Added /advisor on Claude Platform on AWS. No advisor runs until you pick one with /advisor, advisorModel or --advisor; CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 turns it off outright. Changed large requests to api.anthropic.com to use gzip compression even when telemetry is disabled (CLAUDE_CODE_GZIP_REQUEST_BODIES=0 to opt out). Fixed feature flags and staged rollouts staying stale behind a TLS-inspecting proxy whose certificate is trusted only through the OS certificate store.
observability Added OpenTelemetry GenAI semantic-convention attributes to trace spans (gen_ai.provider.name, gen_ai.conversation.id, gen_ai.tool.name, error.type). Added cache_creation_5m_tokens and cache_creation_1h_tokens to the api_request event, splitting cache writes by lifetime. Fixed tool_result events missing git_commit_id after git commit -q in reftable repositories. Changed local session transcripts to also record each API request's system prompt, tools and parameters, so a shared transcript can reproduce a request exactly — mind what you share.
hooks, auth & permissions Changed hooks: updatedInput from PreToolUse and PermissionRequest hooks is now validated like Claude's own input — unknown keys are dropped, and input the tool rejects denies the call. Fixed agent hooks ignoring their model: an unavailable model now falls back to the caller's instead of allowing the action. Fixed a login refused by forceLoginOrgUUID leaving the refused organization's token stored, or live after /login. Changed CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST sessions to ignore CA-bundle, tool-proxy, git TLS and git config variables such as SSL_CERT_FILE in settings (under Claude Desktop, only in project settings). Changed PermissionRequest hooks in Cowork cloud sessions: a setMode update in an allow is now ignored. Removed --sandbox/--no-sandbox from claude remote-control (they never did anything); passing either now exits with an error — set sandbox.enabled in settings instead.
reliability Fixed a conversation failing on every turn with a 400 when the API rejected an MCP tool's input schema; the tool is now sent without parameters for the rest of the conversation. Fixed Claude not being told about an MCP server's tools until its next tool call when the server connected after a compaction. Fixed automatic tool search turning off mid-conversation while MCP servers reconnect. Fixed resumed headless/SDK sessions losing compaction summaries or recent messages after a cut-off or retried reply. Fixed Write, Edit and NotebookEdit in Cowork cloud sessions reporting success for a local path where the file never arrived. Fixed cloud sessions hanging 5 minutes per turn when the organization's policy can't be read. Changed exit to force-kill background commands still running 1.5 s after being asked to stop. Several reftable fixes: --worktree reopen, branch showing as .invalid, conflicted cherry-pick detection in the Desktop diff view. Fixed claude daemon stop reporting "stopped" while a stuck service kept running; it now waits, force-kills, and exits 1 if still there.
mods, Desktop, Slack & VS Code Mods gain virtualText prompt decorations, $.ui.view({ agentId }), a dir prop for RTL text, the prompt.change hook, and agent.spawn can now rewrite a workflow agent's prompt and model. Claude Desktop's Code tab applies managed settings when forceLoginGatewayUrl names an Anthropic-operated gateway serving the session's hostname. Claude Tag: Slack Connect channel support (off by default, Owner/admin opt-in), a private Allow once / Deny card for connector approvals in threads, and Slack voice clips. VS Code: new claudeCode.attachSelection setting; fast mode no longer stays on after credits run out; Shift+drag file paths fixed on Windows and in WSL/SSH/Dev Container windows; Ctrl+Alt+F no longer hijacks Find. Cloud sessions: fixed "Allow for this task" missing from Cowork's approval prompts for connector tools where an org turns off "Always allow" (regression in 2.1.292).

v2.1.299 — sandbox and gateway hardening, MCP rule semantics, idle compaction Wed 14 Oct UTC · 190 bullets

sandbox Fixed a sandboxed shell command being able to write into a --plugin-dir folder, whose code Claude Code reloads and runs outside the sandbox. Fixed sandboxed commands on macOS reading or writing a denied path by its real location when the denied path passes through a symlink. Fixed sandbox denyRead/allowRead globs with braces, parentheses or backslashes in a folder name being read differently by the settings checks than by the sandbox. Fixed allowRead/allowWrite entries not being re-checked when their starting directory is replaced by a symlink. Fixed worktree-isolated sessions accepting some awk programs the isolation guard should refuse. Fixed WSL2 bwrap: Can't mkdir /mnt/c/Program Files/ClaudeCode failures.
gateways & credentials Fixed feature flag, startup, fast mode, profile and feedback requests to Anthropic carrying the API key configured for a third-party gateway (ANTHROPIC_BASE_URL), and the server-managed settings request doing the same when a managed settings file sets ANTHROPIC_BASE_URL. Fixed an agent teammate started without a description keeping part of a credential from its prompt in the task description. Fixed the Claude apps gateway serving models that a policy's availableModelsMatch: exact or deniedModels blocks (now 400 and left out of model lists). Fixed MCP OAuth sign-in, refresh and sign-out not sending configured headers/headersHelper, which broke servers behind an authenticating proxy. Changed requests to claude.ai's connector proxy and Anthropic-hosted MCP servers to no longer follow HTTP redirects. Changed the resume command printed at exit to name the session by ID, not name, so nothing in a session name can run when pasted. Changed the /ultrareview errors to stop suggesting git add . (could stage .env).
permission rules & hooks (behaviour change) Changed MCP allow rules to reach only the server they name: mcp__a no longer allows a server named a__b or a_; write mcp__<server>__* with the whole normalized name. Fixed deny and ask rules for mcp__<server> not applying when the normalized name contains a double underscore. Agent tools: lists now take only the named server's tools. Changed actions a plugin hook can block to be refused, not let through, when the hook cannot be handed them or cannot hand back its answer; a tool that already ran has its result withheld. Fixed plan mode running a write that a PreToolUse hook or a mod's tool.check hook allowed. Fixed mods' hooks being handed values with __proto__ keys silently removed, which could skip a tool.check guard. Windows: PreToolUse and PermissionRequest hooks that set no shell were failing open when Git for Windows isn't installed; a guard that fails now blocks. Changed UserPromptSubmit hooks to run before a skill or slash command expands, so a blocking hook also stops its embedded shell commands. Changed auto mode in Cowork cloud sessions: a PermissionRequest hook can no longer approve shell commands or subagents. Fixed MCP servers added to a running headless/SDK session being connected before policy checks ran, and claude mcp list/get starting a server a policy blocks. Fixed rm prompts on shell -c scripts that don't run rm (CLAUDE_CODE_STRICT_INLINE_SHELL_RM_PROMPT=1 restores the strict behaviour). Skills or commands whose file names contain hidden, direction-changing or blank-like characters, < or > are no longer offered until renamed.
context & cost Added idle compaction in the terminal: a 200K+ token conversation left idle for about 54 minutes is compacted before its one-hour prompt cache expires, so the next message doesn't reprocess it all. CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS changes the floor; "idleCompaction": false in settings.json turns it off (needs v2.1.290+). Added CLAUDE_CODE_DISABLE_FILE_MENTIONS: Claude gets the paths of @ mentions to read with its file tools rather than the files' contents. Added /usage warnings for max effort, workflows, always-on context and large tool results; fixed /usage and the status line sometimes showing more than 100%. Added /effort and /fast in agent view to set what new sessions start with. Fixed sessions on a gateway-specific model name behind a custom ANTHROPIC_BASE_URL ending with "Prompt is too long" near 200K tokens; streams through a custom base URL now wait 300 s (was 180) for first data. Improved PDF @-mentions: bytes no longer kept in the transcript.
gateway, runners & SDK Added CLAUDE_CODE_ATTRIBUTION_HEADER=0 in a Claude apps gateway's code policy env to turn off the attribution block in Desktop's Code tab (and a new field in the block for gateway sessions). Added --shutdown-drain-sec to claude self-hosted-runner orchestrator so SIGTERM drains the in-flight poll and spawn hooks. Added --disallow-tools and a disallowed_tools case field to claude plugin eval; a run that ends on an API error now scores 0 and fails the suite. Added $.session.identity() and $.prompt.media for managed-settings mods. Fixed a 2.1.296 regression where cloud and headless sessions could run an approved tool call twice after a restart. Fixed MCP connections over HTTP hanging 30 s when a server never ends the body of its reply to a notification. Cloud and Remote Control MCP connectors now negotiate protocol 2026-07-28 by default (MCP_PROTOCOL_NEGOTIATION=legacy opts out); first-party MCP descriptions and instructions reach Claude in full rather than cut at 4,096 chars.
Windows, scheduling & files Windows: fixed the process-liveness check leaving orphaned PowerShell processes until memory ran out, and Bash commands failing with "command not found" for a whole session when Git Bash did not report its PATH at startup. Fixed scheduled tasks being announced for the wrong minute (tools now report the actual next run) and firing again after every turn, or early, during the repeated hour when daylight saving ends. Fixed Read garbling UTF-16LE files with a BOM, and Write dropping BOMs or silently converting Windows-1252/Shift-JIS/GBK/UTF-16BE to UTF-8 (now refused). Fixed memory growing without bound under heavy --debug logging or when stderr isn't read. Fixed files of 30–35 MiB sent over Remote Control or to a cloud session not arriving. Fixed Claude in Chrome asking for permission while no browser is connected. Changed Claude in Chrome in Cowork cloud sessions outside auto mode: an approved-site action the safety classifier flags now asks you instead of being refused (unless managed settings apply). Claude Tag can now delete a canvas it created, edits a wrong message in place with an "Edited" note, and joins channels over 100 members quietly.

Security & evals

v2.1.299 · sandbox, gateway-key and permission-rule fixes

Today's actionable items

  • upgrade Fleet CLI target moves to 2.1.300. 2.1.299 closes a sandbox write escape (--plugin-dir), macOS symlink bypasses of denied paths, sandbox glob parsing mismatches, and a third-party gateway API key being sent on Anthropic-bound background requests. 2.1.300 adds updatedInput validation for PreToolUse/PermissionRequest hooks and fixes a refused forceLoginOrgUUID login leaving that org's token live. Run claude update on every machine on latest.
  • gateway users If you run Claude Code through an ANTHROPIC_BASE_URL gateway with its own API key, that key was being sent to Anthropic's feature-flag, startup, fast-mode, profile, feedback and server-managed-settings endpoints before 2.1.299. Upgrade first; consider rotating the gateway key.
  • MCP permission rules (behaviour change) 2.1.299 narrows mcp__a to the server named a only — it no longer matches a__b or a_. Deny/ask rules for servers whose normalized name contains __ now apply where they silently didn't. Audit permissions.allow/deny and agent tools: lists for servers with double underscores and rewrite them as mcp__<whole name>__*.
  • hooks fail closed Plugin hooks that can't be handed an action, or can't return an answer, now refuse it (2.1.299). Windows hooks with no shell now block when Git for Windows is missing instead of failing open. updatedInput that a tool rejects now denies the call (2.1.300). Expect more denials from flaky hooks — that's the point; fix the hook rather than loosening the rule.
  • Cowork cloud auto mode A PermissionRequest hook can no longer approve shell commands or subagents in Cowork cloud auto mode (2.1.299), and a setMode in its allow is ignored (2.1.300). Any automation that relied on hook-granted shell approval in the cloud will now wait or be denied.
  • transcripts Local session transcripts now record each request's system prompt, tools and parameters (2.1.300). Shared transcripts are more reproducible and more revealing; redaction still applies, but review before sharing externally.
  • remote-control scripts claude remote-control --sandbox / --no-sandbox now exit with an error (2.1.300). Grep launch scripts and systemd units; use sandbox.enabled in settings.
  • redirects Requests to claude.ai's connector proxy and Anthropic-hosted MCP servers no longer follow HTTP redirects (2.1.299). A connector fronted by a redirecting proxy will start failing; the connector's own server redirects are unaffected.
  • Desktop Code tab v2.37337.1 still bundles 2.1.295. The Code tab lacks everything from 2.1.296 through 2.1.300, including today's sandbox and gateway-key fixes. Terminal claude and the Code tab update independently; /status shows which CLI a session is on.
  • stable dist-tag Promoted to v2.1.292 overnight (was 2.1.287 for two weeks). Still misses 2.1.293–2.1.300. Anyone pinned to stable has the 2.1.292 UNC-path and sandbox read-deny fixes but none of the hook enforcement or today's sandbox fixes.
  • Desktop (carry-over) v2.37337.1 (13 Oct) removed the former managed-config key names (isDxtEnabled, enduserAttribution, trustBootstrapLocalExec, inferenceGatewayHeaders and friends); renewed the Windows signing certificate; stopped auto-adding inference, gateway and OTLP hosts to coworkEgressAllowedHosts. If you haven't migrated the MDM profile yet, it's still the top Desktop item.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

Seven consecutive hardening releases. 2.1.292 through 2.1.300 (297/298 skipped) each closed a path where hooks, the sandbox, permission rules, auto mode or credential handling could be bypassed. 2.1.299 is the largest single sweep yet: sandbox escapes, gateway-key leakage and permission-rule matching in one release. Treat the hook and sandbox layers as a security boundary that needs retesting on each upgrade.
Permission-rule semantics are tightening, not just bugs being fixed. 2.1.299 changed what mcp__a matches, made plugin hooks fail closed, and stripped shell approval from Cowork cloud hooks. These are deliberate narrowing changes; expect more. Keep a known-good test of your managed settings on a scratch machine.
Gaps in the version sequence are normal. 2.1.297 and 2.1.298 never reached npm, the changelog or GitHub. Don't treat a missing number as a pulled release — the digest reconciles all three sources each morning.
Desktop bundles trail the CLI by a release or more. v2.37337.1 ships 2.1.295; the CLI is five releases ahead. Expect 2.1.296 or later on the next Desktop bump, which usually lands within a week of a big CLI run.

Claude Cowork

GA · macOS, Windows & Linux · web & mobile · cloud by default on Pro/Max

What's new

cloud sessions · Claude Code 2.1.299 / 2.1.300 Permission model tightened in Cowork cloud auto mode: a PermissionRequest hook can no longer approve shell commands or subagents (those prompts wait or are denied), and a setMode update in a hook's allow is ignored. Fixed "Allow for this task" missing from Cowork's approval prompts for connector tools where an org turns off "Always allow" (regression since 2.1.292). Claude in Chrome in cloud sessions outside auto mode: an approved-site action the safety classifier flags now asks instead of being refused. Fixed Cowork cloud sessions running an old version of an account plugin changed or disabled from another device until restart.
scheduled tasks & reliability · 2.1.299 / 2.1.300 Fixed scheduled tasks being announced for the wrong minute, and firing again after every turn (or early) during the repeated hour when daylight saving ends. Fixed Write, Edit and NotebookEdit in Cowork cloud sessions reporting success for a path on your own computer where the file never arrived. WebFetch in cloud sessions now tells Claude a page failed moments ago instead of refetching. Fixed cloud sessions hanging 5 minutes per turn when the org policy can't be read, and running an already-answered message a second time after a restart mid-reply. Fixed files of 30–35 MiB sent to a cloud session not arriving. Fixed a cloud-session memory spike when many existing output files were re-sent at once.
artifacts & admin · 2.1.299 / 2.1.300 Claude now applies a small artifact change and republishes in one call, and makes larger edits and republishes within a single response. A local session can watch up to 25 published artifacts (was 10). Fixed the Artifact tool refusing an unchanged republish of a large page over a spurious one-line diff. Admin: deleting a self-hosted environment now turns off its routines right away with the reason shown; Sessions search in a self-hosted environment's admin details now finds a pasted session ID; the deploy command for a new self-hosted environment shows in full with a copy button.
Desktop v2.37337.1 · 13 Oct (carry-over) Scheduled tasks on your computer that couldn't be edited after their first run now can be; tasks that never started on a computer where the workspace fails to start now start without it after about ten minutes. Chart.js, Grid.js and Mermaid now ship with the app, so artifacts render offline or behind a CDN block. Fixed Cowork tasks on a computer whose admin turned off the local VM trying to start locally instead of in the cloud, and the first message of a new task being lost on reload.
carry-over Cloud by default (since 6 Oct) on Pro and Max. New tasks run in the cloud; "Only on your computer" was removed. Local folder access still needs the desktop app open.
