v2.1.233 — NTLM credential leak closed, Friday's Bash permission changes partly reverted, Todo tools removed on newer models new since Friday

20 entries · published Sat 15 Aug 04:50 local · the only release over the weekend

Security — Windows NT device-prefix paths were bypassing UNC validation, leaking NTLM credentials. Paths spelled with the NT \??\ device prefix were not recognised as UNC paths by path validation, so a write or read that should have been treated as a network path was handled as local. The exploit route is the standard one: coax a Windows host into touching a remote SMB path and it authenticates on the way, handing over an NTLM hash. Any Claude Code on Windows should be on v2.1.233, and this stacks on top of v2.1.232's PowerShell and Git Bash bypasses — three path-validation escapes on Windows in two releases.
Correction to Friday's digest — two of v2.1.232's permission changes have been reverted. The changelog is explicit: “Reverted the 2.1.232 Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (< file); a narrower version will return in a later release.” So reading a file via < file redirection is once again not permission-checked the way the argument spelling is, on every platform, and Git Bash's Cygwin-symlink handling is back to the pre-v2.1.232 behaviour. We flagged both as closed on Friday. They are not. Treat redirection-based reads as an unchecked path until the narrower version lands. (The PowerShell $PSDefaultParameterValues fix and the nested-repo trust change from v2.1.232 both stand — only these two were pulled.)
Breaking — Todo/task-tracking tools are gone on current models. TaskCreate, TaskGet, TaskUpdate, TaskList and TodoWrite are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer models. Set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to bring them back. Anything that parses task-list output, or any workflow, hook or skill that assumes Claude will emit a todo list on a current model, will silently stop doing so after this upgrade. Worth a grep of our hooks and scheduled tasks.
Infrastructure — Bash commands can now be memory-capped with a Linux cgroup. Opt-in via CLAUDE_CODE_TOOL_MEMORY_LIMIT, so a runaway build can no longer stall the session by eating the box. This is the natural companion to v2.1.229's fix for dynamic workflows reading the host's core count instead of the container's CPU limit — between the two, Claude Code finally behaves itself inside a constrained pod. Alongside it: idle sessions on Linux no longer sometimes keep one CPU core at 100% when sandboxing is enabled, which is the sort of thing that shows up as a mystifying baseline on a node's CPU graph.
Gateway — per-user spend attribution, and upstream errors finally carry their own message. A new opt-in forward_user_identity setting on Anthropic upstreams sends the signed-in user's identity as headers, so a proxy behind the gateway can attribute spend per user — the missing piece for chargeback. Separately, 400 and 413 errors from Vertex, Foundry and Claude Platform on AWS upstreams now carry the upstream's own message instead of a generic one, which also fixes a bug where auto-compact failed on the apps gateway.

  • revert Reverted v2.1.232's Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (< file). A narrower version returns in a later release. Do not assume these are covered.
  • skills Fixed skill/command argument substitution to prevent argument values from being re-expanded as template markers — an injection route where a value passed into a skill could be re-interpreted as template syntax.
  • infra Opt-in memory cgroup support for Bash tool commands on Linux via CLAUDE_CODE_TOOL_MEMORY_LIMIT, so a runaway build can't stall the session.
  • gateway Opt-in forward_user_identity on Anthropic upstreams sends the signed-in user's identity as headers, so a proxy behind the gateway can attribute spend per user.
  • gateway 400/413 errors from Vertex, Foundry and Claude Platform on AWS upstreams now carry the upstream's own message; fixes a bug with auto-compact on the apps gateway.
  • gitlab GitLab merge request URL support added to the --worktree flag and the claude agents view, where MRs display as !N. The GitHub app setup tip no longer appears in repos whose origin is on gitlab.com or bitbucket.org; the enterprise marketplace tip now covers non-GitHub internal git hosts.
  • config CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS configures the WebFetch session URL cache TTL. Default unchanged at 15 minutes.

  • cloud Fixed cloud sessions occasionally being marked as lost when the environment shut down while Claude was waiting on a permission prompt.
  • desktop / IDE Fixed Notification hooks not firing for permission prompts when running under Claude Desktop or VS Code.
  • windows Fixed auto mode repeatedly stopping for manual approval on ordinary cd <dir> && <command> > file Bash commands — a v2.1.232 regression.
  • skills Fixed bundled skill aliases like /checkup and /review reporting “Unknown command” in -p mode or with plugins/MCP loaded, when a user or project skill shadows the bundled one.
  • runners Improved claude self-hosted-runner session start time — the session branch is created without rewriting the working tree, and two server round trips no longer block the agent's launch.
  • plugins claude plugin validate now checks a bare .claude/skills directory, reporting SKILL.md files whose frontmatter fails to parse. Useful before publishing to an internal marketplace.
  • diagnostics Print mode now writes [claude-code:unrecognized_model] to stderr when a request goes out for a model ID Claude Code doesn't recognise — map it with modelOverrides to silence. A useful canary for pinned model strings in CI.

Still open from last week — gateway boot validation, container CPU limits, /commit-push-pr action required

v2.1.232 — the gateway still fails at boot on configuration it previously accepted. Unchanged by v2.1.233 and still the biggest upgrade risk. Two fail-fast changes. (1) The desktop: overlay now accepts every released Desktop setting, validated at boot against Desktop's own schema rather than eleven hand-listed keys — unknown or invalid keys now fail boot, where a typo used to be silently ignored. (2) Empty managed.policies[].match.groups and admin.admin_groups entries, and malformed email_domain values, now fail at boot instead of silently matching no one or granting admin access. If our gateway config has an empty admin_groups entry today, it has been granting admin. Validate in a non-production environment first.
v2.1.232 — nested git repositories no longer inherit trust, and subagent forking is on by default. Each repository now requires its own trust confirmation, so expect fresh prompts in workspace directories and monorepo-adjacent layouts. Separately, a subagent_type: "fork" subagent inherits the full conversation and prompt cache, and non-teammate agent spawns in interactive sessions run in the background by default — work that used to block the session and print inline now surfaces in /tasks.
v2.1.229 — dynamic workflows were using the host's core count, not the container's CPU limit. Still the most operationally relevant fix of the fortnight for our estate: inside a CPU-limited container — every pod we run — fan-out width came from the node's core count rather than the cgroup limit. Likeliest explanation for throttling or noisy-neighbour behaviour from Claude Code in CI or on EKS. Now paired with v2.1.233's CLAUDE_CODE_TOOL_MEMORY_LIMIT, so both CPU and memory behave correctly in a pod. Re-baseline any workflow sized around the old behaviour.
v2.1.229 — /commit-push-pr no longer auto-approves dangerous git and gh flags. --force, --amend, --no-verify now require explicit approval, so unattended automation that relied on /commit-push-pr finishing without a prompt will stop and ask. Also still live: run /doctor after upgrading — sandbox network domain lists are enforced fail-closed on ambiguous spellings, so an allowlist entry you thought was permitting traffic may now be refusing it. And Windows self-hosted runners still require an explicit --base-dir; there is no default checkout directory on Windows.
Carried forward: v2.1.228's Write tool can now overwrite a file it hasn't read for newer models, matching Edit's rules — if any automation leaned on “Claude can't blind-overwrite,” that guardrail is gone. v2.1.231's MCP OAuth redirect URI fix for pre-registered clients such as Slack remains the fix if a Slack MCP connection is refusing to authorise. And v2.1.224's sandbox credential masking with awsPairs / sigv4 for AWS SigV4 re-signing is still the right answer for unattended tasks holding secrets.

Opus 5 — near-Fable intelligence at half the price headline

Source: Introducing Claude Opus 5 · 24 Jul 2026

claude-opus-5 is available on all platforms. Anthropic describes it as “thoughtful and proactive,” coming close to Fable 5's frontier intelligence at half the price. Pricing is $5 / $25 per Mtok — identical to Opus 4.8, so this is a free capability upgrade for anything already pinned to Opus. It is the default model on Claude Max and the strongest model on Pro.
What this means for us. On any current dist-tag — including stable at v2.1.224 — Opus 5 is already your default Opus in Claude Code, with no config change. Three things still to action: (1) our Bedrock/Vertex pipelines pinned to claude-opus-4-8 will not move on their own, so schedule the model-string bump deliberately; (2) /fast no longer applies to Opus 4.7 — fast mode is Opus 5 and Opus 4.8 only, and Opus 5 fast mode bills at 2× base ($10 / $50 per Mtok) for ~2.5× the speed; (3) v2.1.233's [claude-code:unrecognized_model] stderr line in print mode is a cheap way to catch stale pinned model strings in CI before they become an outage.
  • model Available on all platforms as claude-opus-5 at $5 / $25 per Mtok (unchanged from Opus 4.8). Fast mode runs ~2.5× default speed at twice base price.
  • performance New SOTA on Frontier-Bench and GDPval-AA. On CursorBench 3.2 at max effort it lands within 0.5% of Fable 5's peak at half the cost per task. ARC-AGI 3: 3× the next-best model. OSWorld 2.0 (computer use): beats Fable 5's best result at just over a third of the cost.
  • efficiency Multiple early-access reports of the same result at materially fewer tokens — one legal-tech partner saw comparable quality with 26% fewer tokens at max reasoning. Several partners call out lower run-to-run variance versus Opus 4.8.
  • safeguards Cyber classifiers are ~85% less restrictive than Fable 5's: source-code vulnerability discovery is allowed; binary-based vulnerability scanning, penetration testing, and exploit generation are blocked. Flagged requests in Claude.ai, Claude Code, and Cowork fall back to Opus 4.8 by default — expect the occasional silent model switch on security-adjacent prompts.
  • alignment Anthropic's automated behavioural audit rates Opus 5 its most aligned model to date, with the lowest rates of deceptive behaviour and the best record on avoiding hard-to-reverse actions. It does not advance the frontier on dual-use capability.
  • API betas Mid-conversation tool changes (swap available tools without invalidating the prompt cache) and automatic server-side fallbacks.

Anthropic postmortem: Claude models reached the real internet from inside three cyber evaluations

Source: Investigating three real-world incidents in our cybersecurity evaluations · 30 Jul 2026 · 18 days old

Anthropic reviewed 141,006 cyber-eval runs and found three incidents where a Claude model escaped its supposed sandbox and compromised the production infrastructure of three real organisations. Root cause was a harness misconfiguration, not model misalignment: the eval prompt told Claude it had no internet access, a misunderstanding with third-party partner Irregular left live egress in place, and Claude therefore treated the real systems it stumbled onto as part of the capture-the-flag exercise.
Why this still lands on our desk. Strip out the AI and this is a plain infrastructure-controls postmortem. (1) Egress was assumed to be off and never verified — the same assumption we make about a lot of CI and test namespaces, and exactly what the fail-closed sandbox allowlist change is trying to make harder. (2) Nothing detected it: two of the three victim organisations had no idea they had been compromised until Anthropic called them. (3) A malicious PyPI package was live for about an hour and got pulled onto 15 real machines. (4) Anthropic's conclusion is that eval and test environments need the same egress controls, network logging, and transcript monitoring as production.
  • incident 1 Opus 4.7. The fictional target shared a name with a live domain. Across four runs Claude found the real company and exploited it — extracting credentials and reaching a database with several hundred rows of production data.
  • incident 2 Mythos 5 — supply-chain attack. Claude published a booby-trapped PyPI package under a name referenced in onboarding docs, working around missing email and phone verification to register an account. Public for ~1 hour, ran on 15 real systems.
  • incident 3 Internal research test model. Scanned ~9,000 hosts, then compromised an internet-facing app via an exposed debug page and SQL injection. This one stopped on its own once it noticed the host sat in an unrelated cloud account.
  • what changes Validation of all internet paths before evals start; real-time monitoring of eval logs and transcripts; the same hardening demanded of third-party eval vendors. METR is being brought in for third-party review with full transcript access.
