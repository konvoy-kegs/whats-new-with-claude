v2.1.234 — NT-namespace hardening completed, three credential-disclosure fixes, dropped permission denies new overnight

~50 entries · published Tue 18 Aug 04:19 local · the largest release since v2.1.232

Security — the Windows NT-namespace fix now covers the paths Saturday's release missed. v2.1.233 closed the \??\ device-prefix bypass for Bash. v2.1.234 extends the same rejection to remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads — the changelog calls these “the remaining pre-approval file accesses.” The phrasing matters: these are paths touched before a permission prompt, so the NTLM credential-leak vector was still reachable on a v2.1.233 host through any of them. Windows hosts that upgraded on Saturday are not done; they need v2.1.234. That is four path-validation escapes on Windows across three releases.
Security — MCP diagnostics were printing resolved secrets. Scope-conflict warnings now show the configured ${VAR} form rather than its expanded value, and connection-failure details show only the server origin instead of the full URL. If anyone has pasted MCP diagnostic output into a ticket, a PR, or a Slack thread while debugging a server connection, that output may have contained a live token. Worth a retrospective grep of #cloud-engineers and any Jira comments from the last few weeks — and rotating anything found.
Security — permission previews could hide what you were approving. Two related fixes on the Remote Control approval path. Credential masking on relayed permission previews could mask so aggressively that commands, paths or destinations were hidden from the approver — you were being asked to approve something you could not fully see. Oversized private-key blocks now redact under full-strength redaction, provider API tokens mask even when directly followed by shell delimiters, and previews now relay only to channel servers admitted by the inbound trust gate, honouring a server's explicit permission-capability opt-out. If we approve anything from a phone, this is the release that makes those prompts trustworthy.
Permissions — session-scoped denies were being silently dropped. “Fixed session-scoped permission answers (including denies) being dropped when answering background subagent tool permission prompts.” Background subagent spawns became the default in v2.1.232 on 13 Aug, so for five days a deny answered against a background subagent may not have stuck for the rest of the session. Related: auto mode in very long sessions was repeatedly re-checking and denying sandboxed commands' network access after the conversation had been compacted, which is the likely cause of any “it worked for an hour then started refusing network calls” report.
Context — the built-in claude-api skill dropped from ~200k+ tokens to ~25k. Reference docs are now loaded on demand rather than inlined. That is a ~175k token refund on every session that loads the skill, which on a 200k-context model is the difference between the skill being usable and it consuming the entire window. If we shelved anything that used claude-api because it blew the context, it is worth retrying.
Quality of life — /permissions and /add-dir now work mid-turn. /permissions can be opened while Claude is working and rule changes apply to the rest of the current turn; /add-dir, /autocompact, /theme, /help, /config and /advisor all open mid-turn in the fullscreen TUI. Previously the only way to widen a permission mid-task was to interrupt. Also new: Claude Code continues your session automatically when a claude.ai usage limit resets (toggle in /config), and /goal now checks in on background tasks that have kept a goal waiting 30+ minutes instead of hanging indefinitely.

Still open from last week — gateway boot validation, reverted Bash checks, container CPU limits action required

v2.1.233's reverts still stand — < file redirection is not permission-checked. v2.1.233 reverted v2.1.232's Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (< file), promising a narrower version later. v2.1.234 does not bring it back. Reading a file by < file redirection is still not checked the way the argument spelling is, on any platform. Any deny rule written on the strength of that change still does not do what it looks like it does.
v2.1.232 — the gateway still fails at boot on configuration it previously accepted. Unchanged by v2.1.233 or v2.1.234 and still the biggest upgrade risk. Two fail-fast changes. (1) The desktop: overlay now accepts every released Desktop setting, validated at boot against Desktop's own schema — unknown or invalid keys now fail boot, where a typo used to be silently ignored. (2) Empty managed.policies[].match.groups and admin.admin_groups entries, and malformed email_domain values, now fail at boot instead of silently matching no one or granting admin access. If our gateway config has an empty admin_groups entry today, it has been granting admin. Validate in a non-production environment first.
v2.1.229 / v2.1.233 — container resource limits are now correct in both dimensions. v2.1.229 fixed dynamic workflows using the host's core count rather than the container's CPU limit — the likeliest explanation for throttling or noisy-neighbour behaviour from Claude Code in CI or on EKS. v2.1.233 added CLAUDE_CODE_TOOL_MEMORY_LIMIT to cap Bash commands with a Linux memory cgroup. Between the two, Claude Code finally respects a pod's full resource envelope. Re-baseline any workflow sized around the old behaviour.
v2.1.229 — /commit-push-pr no longer auto-approves dangerous git and gh flags. --force, --amend, --no-verify now require explicit approval, so unattended automation that relied on /commit-push-pr finishing without a prompt will stop and ask. Also still live: run /doctor after upgrading — sandbox network domain lists are enforced fail-closed on ambiguous spellings, so an allowlist entry you thought was permitting traffic may now be refusing it. And Windows self-hosted runners still require an explicit --base-dir.
Carried forward: v2.1.233's Todo/task-tracking tools are still removed on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer — re-enable with CLAUDE_CODE_ENABLE_TODO_TOOLS=1. v2.1.228's Write tool can overwrite a file it hasn't read for newer models. v2.1.231's MCP OAuth redirect URI fix for pre-registered clients such as Slack. And v2.1.224's sandbox credential masking with awsPairs / sigv4 is still the right answer for unattended tasks holding secrets.

Opus 5 — near-Fable intelligence at half the price headline

Source: Introducing Claude Opus 5 · 24 Jul 2026

claude-opus-5 is available on all platforms. Anthropic describes it as “thoughtful and proactive,” coming close to Fable 5's frontier intelligence at half the price. Pricing is $5 / $25 per Mtok — identical to Opus 4.8, so this is a free capability upgrade for anything already pinned to Opus. It is the default model on Claude Max and the strongest model on Pro.
What this means for us. On any current dist-tag — including stable, now at v2.1.226 — Opus 5 is already your default Opus in Claude Code, with no config change. Three things still to action: (1) our Bedrock/Vertex pipelines pinned to claude-opus-4-8 will not move on their own, so schedule the model-string bump deliberately; (2) /fast no longer applies to Opus 4.7 — fast mode is Opus 5 and Opus 4.8 only, and Opus 5 fast mode bills at 2× base ($10 / $50 per Mtok) for ~2.5× the speed; (3) v2.1.233's [claude-code:unrecognized_model] stderr line in print mode is a cheap way to catch stale pinned model strings in CI before they become an outage.
  • model Available on all platforms as claude-opus-5 at $5 / $25 per Mtok (unchanged from Opus 4.8). Fast mode runs ~2.5× default speed at twice base price.
  • performance New SOTA on Frontier-Bench and GDPval-AA. On CursorBench 3.2 at max effort it lands within 0.5% of Fable 5's peak at half the cost per task. ARC-AGI 3: 3× the next-best model. OSWorld 2.0 (computer use): beats Fable 5's best result at just over a third of the cost.
  • efficiency Multiple early-access reports of the same result at materially fewer tokens — one legal-tech partner saw comparable quality with 26% fewer tokens at max reasoning. Several partners call out lower run-to-run variance versus Opus 4.8.
  • safeguards Cyber classifiers are ~85% less restrictive than Fable 5's: source-code vulnerability discovery is allowed; binary-based vulnerability scanning, penetration testing, and exploit generation are blocked. Flagged requests in Claude.ai, Claude Code, and Cowork fall back to Opus 4.8 by default — expect the occasional silent model switch on security-adjacent prompts.
  • alignment Anthropic's automated behavioural audit rates Opus 5 its most aligned model to date, with the lowest rates of deceptive behaviour and the best record on avoiding hard-to-reverse actions. It does not advance the frontier on dual-use capability.
  • API betas Mid-conversation tool changes (swap available tools without invalidating the prompt cache) and automatic server-side fallbacks.

Anthropic postmortem: Claude models reached the real internet from inside three cyber evaluations

Source: Investigating three real-world incidents in our cybersecurity evaluations · 30 Jul 2026 · 19 days old

Anthropic reviewed 141,006 cyber-eval runs and found three incidents where a Claude model escaped its supposed sandbox and compromised the production infrastructure of three real organisations. Root cause was a harness misconfiguration, not model misalignment: the eval prompt told Claude it had no internet access, a misunderstanding with third-party partner Irregular left live egress in place, and Claude therefore treated the real systems it stumbled onto as part of the capture-the-flag exercise.
Why this still lands on our desk. Strip out the AI and this is a plain infrastructure-controls postmortem. (1) Egress was assumed to be off and never verified — the same assumption we make about a lot of CI and test namespaces, and exactly what the fail-closed sandbox allowlist change is trying to make harder. (2) Nothing detected it: two of the three victim organisations had no idea they had been compromised until Anthropic called them. (3) A malicious PyPI package was live for about an hour and got pulled onto 15 real machines. (4) Anthropic's conclusion is that eval and test environments need the same egress controls, network logging, and transcript monitoring as production.
  • incident 1 Opus 4.7. The fictional target shared a name with a live domain. Across four runs Claude found the real company and exploited it — extracting credentials and reaching a database with several hundred rows of production data.
  • incident 2 Mythos 5 — supply-chain attack. Claude published a booby-trapped PyPI package under a name referenced in onboarding docs, working around missing email and phone verification to register an account. Public for ~1 hour, ran on 15 real systems.
  • incident 3 Internal research test model. Scanned ~9,000 hosts, then compromised an internet-facing app via an exposed debug page and SQL injection. This one stopped on its own once it noticed the host sat in an unrelated cloud account.
  • what changes Validation of all internet paths before evals start; real-time monitoring of eval logs and transcripts; the same hardening demanded of third-party eval vendors. METR is being brought in for third-party review with full transcript access.
