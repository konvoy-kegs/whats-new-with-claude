v2.1.296 — managed-hook enforcement, gateway code policy, subagent controls newest · aligned

hooks & permissions Fixed managed-settings PreToolUse hooks denying with "continue": false, and managed prompt hooks that block, refusing the call but not ending the turn. Fixed managed PostToolUse hooks not applying updatedMCPToolOutput in some sessions. Fixed Bash permission checks auto-approving commands that assign and then use BASH_ARGV0 (now prompt). Fixed Esc during a UserPromptSubmit hook letting the unchecked prompt through. Fixed cloud sessions skipping auto mode's checks on Claude in Chrome actions. Windows: rm -rf /c/Users/<name> in Git Bash now asks even in bypass mode.
secrets & MCP Fixed secret redaction in shared transcripts and debug logs missing some values (including JSON inside a shell string). Fixed headless sessions starting a folder's .mcp.json or plugin MCP server that was switched off for that folder, after changing directory or reloading plugins. Fixed hook output being altered when it contained text resembling a plugin hint tag. Fixed a plugin secret named constructor/prototype being deleted on save.
Claude apps gateway & Desktop Added a code key to managed.policies[]: the same settings as cli, also applied in Claude Desktop's Code tab; beside desktop, it turns on Desktop's gateway mode. Code tab now shows the reason as a reply when a gateway session can't start. Fixed a gateway serving allowedProviders with "gateway" locking out laptops that name it in user settings, and a saved gateway sign-in being ignored under forceLoginMethod: gateway with no URL (regression in 2.1.295).
new settings autoCompactWindow in subagent frontmatter and --agents, so a subagent compacts earlier than the main conversation. CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL pins every workflow agent to one model. CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS caps 529 backoff. Read tool allow_large option for whole large files. MCP tool descriptions and server instructions sent up front now capped at 4,096 chars (was 2,048). /cost and --max-budget-usd now price Sonnet 5.5 cache reads at $0.10/Mtok (was $0.20).
Windows, runners & reliability PowerShell commands up to 32 KB now honour allow rules and read-only detection (was ~1 KB). Stdio MCP servers get a graceful stdin close before kill at shutdown. claude plugin install retries GitHub sources over HTTPS when there's no SSH key. Edit/NotebookEdit now refuse non-UTF-8 files rather than mangling non-ASCII characters. Self-hosted runners: clearer registration errors, git fetch/push fix with --capacity above 1, per-session queue positions. VS Code: Claude in Chrome now asks before browser actions in every session. Claude Tag: admins can manage workspace/channel memory files.

v2.1.295 — fail-closed hooks, gateway controls, MCP reliability Thu 8 Oct UTC

hooks & guards Added onFailure: "block" for command and HTTP hooks (fail closed instead of open). Fixed --tools/--restricted not applying to late-registered built-in tools. Gateway: per-upstream models lists, timeouts.upstream_ttfb_ms for Bedrock/Vertex/Foundry, upstream_request_id in audit events. On Amazon Bedrock, token counts use AWS CountTokens — grant bedrock:CountTokens. claude.ai connectors negotiate MCP protocol 2026-07-28 by default.

v2.1.294 — hook judgement fixes Thu 8 Oct UTC

hooks Fixed prompt and agent hooks written as instructions (such as "Block commands that...") allowing what they should block. Improved judging of instruction-style Stop/SubagentStop prompt hooks.

v2.1.293 — Claude Haiku 5.5 Wed 7 Oct UTC

Security & evals

managed hooks: retest after upgrade

Today's actionable items

  • fleet Move to 2.1.296. It carries the 2.1.292–2.1.295 hardening plus today's managed-hook, BASH_ARGV0 and Windows bypass-mode fixes.
  • managed hooks If you deny tools via managed PreToolUse hooks with "continue": false, or rewrite MCP output with updatedMCPToolOutput, retest on 2.1.296 — earlier versions didn't end the turn or apply the rewrite reliably.
  • CI / headless MCP servers disabled per-folder now stay off after cd or plugin reload in headless runs. Worth confirming in pipelines that rely on that.
  • gateway Using the Claude apps gateway with Desktop? Add a code entry to managed.policies[] to apply CLI settings to the Code tab. Carry-over: grant bedrock:CountTokens and add onFailure: "block" to guard hooks.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

Five releases of guardrail hardening. 2.1.292 through 2.1.296 all close gaps where hooks, auto mode, tool lists or Bash parsing could be bypassed. Treat hooks as part of your security boundary and test them on each upgrade.
stable still lags. It moved to 2.1.287 but remains nine releases behind latest, missing all five hardening releases. Pin to latest-track versions on managed machines.

Claude Cowork

GA · macOS, Windows & Linux · web & mobile · cloud by default on Pro/Max

What's new

Cloud sessions and self-hosted runners (Claude Code 2.1.296). New status filter on the Sessions and Runners lists in admin settings; each session waiting on a self-hosted runner now shows its own queue position; a message sent mid-reply no longer jumps above the reply. Fixed auto mode occasionally refusing an update to your own artifact.
Skills and plugins synced from claude.ai. Fixed synced skills never finishing install (and re-downloading every sync) when sessions share a config directory, and synced plugins being disabled when their marketplace dependency was also synced.
Cloud by default (since 6 Oct) on Pro and Max. New tasks run in the cloud; "Only on your computer" was removed. Local folder access still needs the desktop app open. See Use Claude Cowork on web, desktop, and mobile and Claude Cowork and chat are one Claude.
