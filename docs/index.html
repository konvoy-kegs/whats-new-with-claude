v2.1.239 — still the newest documented release: silent Bedrock double-billing, Windows cross-session messaging, data-residency cost accuracy act on this

59 entries · published Sat 22 Aug 03:18 local · the largest release since v2.1.234 · four versions have shipped since with no readable detail

Billing — Bedrock behind a header-stripping proxy was being billed twice for every turn, silently. “Fixed Bedrock streaming behind proxies that strip the response Content-Type header, which silently doubled billed API calls by re-running every turn non-streaming.” Read the mechanism: Claude Code starts a streaming request, the proxy strips the header that identifies the response as a stream, Claude Code concludes streaming is unsupported, and re-runs the same turn non-streaming. Both calls bill. There is no error, no warning, and no visible symptom other than the invoice. Any Bedrock traffic that traverses a proxy we control is a candidate — corporate egress proxies, service meshes, and anything doing TLS termination and response rewriting are all plausible strippers. Upgrade, then reconcile the Bedrock spend line against turn counts for the affected window.
AWS — Bedrock with an SSO profile and awsAuthRefresh hung at startup behind an HTTPS proxy. “Fixed Claude Code hanging at startup behind an HTTPS proxy when using Bedrock with an SSO profile and awsAuthRefresh — the credential pre-check now honors HTTPS_PROXY.” The credential pre-check was making a direct connection and ignoring the proxy variable the rest of the process respects, so it waited on a connection that could never complete. This is the exact shape of our Bedrock-plus-SSO setup, and a startup hang is the kind of failure people work around locally rather than report.
Cost — /cost, the status line and --max-budget-usd were under-reporting spend on data-residency workspaces. “Cost estimates (/cost, status line, --max-budget-usd) now include the 1.1× US-only-inference premium for data-residency workspaces.” A 10% premium omitted from the estimate matters most for --max-budget-usd, which is a control, not a display: a budget cap computed from pre-premium numbers lets 10% more real spend through than the flag says. If anyone has budget caps wired into CI or scheduled runs on a data-residency workspace, the effective ceiling just became honest.
Windows — cross-session messaging now works, closing the last platform gap. “Windows: cross-session messaging is now available, so Claude Code sessions across your machines can message each other with SendMessage and find each other with ListAgents, as on macOS and Linux.” Multi-session orchestration was macOS/Linux-only; Windows developers can now participate in the same agent topology as everyone else. Paired with the ListAgents fixes below, this is the release where multi-agent workflows stop being platform-conditional.
New workflow — /claude-api upgrade migrates Python projects from anthropic 0.x to 1.x. Added alongside an updated Python reference for 1.x, with the note that timeouts now use anthropic.Timeout, not httpx.Timeout. If we have Python services still on the 0.x SDK, this is a one-command starting point rather than a manual sweep, and the timeout change is the kind of detail that silently stops working rather than failing loudly.

Infrastructure and sandboxing v2.1.239

  • fix The Linux sandbox broke every git command in repos with extensions.worktreeConfig set — it made a nonexistent .git/config.worktree unreadable rather than absent, which git treats as fatal. Anyone using worktree-scoped config inside a sandboxed session was hitting a wall.
  • fix Remote sessions now keep sending keep-alives while a long SessionStart or Setup hook runs, so the container is no longer idle-reaped mid-hook. Directly relevant to any provisioning hook that takes longer than the idle window.
  • fix Hooks failed with posix_spawn ENOENT after the session's working directory was deleted; they now run from the project root or home directory instead.
  • fix Alpine/musl builds now load the native add-ons — image paste, clipboard and audio capture were shipping glibc-built binaries the musl runtime refused. Relevant to anything running Claude Code in an Alpine container image.
  • fix OpenTelemetry trace fragmentation fixed: tool executions deferred by a PreToolUse hook now resume in the original turn's trace instead of opening a new one. If we are shipping Claude Code telemetry anywhere, per-turn traces were being split.
  • fix Persistent retry mode (CLAUDE_CODE_RETRY_WATCHDOG) now fails immediately on organization spend-limit and out-of-credits errors instead of waiting indefinitely for a reset that is not coming. A hung CI job instead of a clear failure is the worst of both.
  • fix .worktreeinclude patterns starting with **/ silently matched nothing when the target lived in a gitignored directory.
  • fix Agents, skills and commands whose .md file starts with a UTF-8 BOM were silently ignored. A file that is present, valid and invisible is a bad failure mode — worth checking any config authored on Windows.
  • fix Marketplace metadata.pluginRoot had no effect; bare plugin source names now resolve under it as documented. Matters for anyone standing up an internal marketplace.
  • fix claudeMdExcludes did not exclude a symlinked .claude/rules file when the pattern named the rules directory or the symlink rather than its target.

Cloud sessions, Remote Control and plugin governance v2.1.239

  • feat Plugins synced from claude.ai now show as name@synced in cloud sessions, work with claude plugin enable/disable <name>@synced, and never override a same-named plugin you installed. The no-override guarantee is the important half — an org-pushed plugin silently shadowing a local one is a debugging nightmare.
  • sec Claude Code on the web: Bash and other tool requests to non-API anthropic.com hosts (www, docs) now go through the session's network proxy, so the environment's allowed-domain policy applies. Previously these bypassed the policy we configured.
  • fix Remote MCP servers stayed failed after a transient 5xx on a mid-session reconnect in cloud sessions or via SDK setMcpServers(). One blip meant a dead server for the rest of the session.
  • fix Cloud sessions resumed out of plan mode after an idle worker restart — a session you deliberately left in plan mode could come back able to act.
  • fix Runaway session-title syncing to Remote Control when two Claude Code processes shared one background job's state (a v2.1.232 regression); title updates are now deduplicated and rate-limited.
  • fix ListAgents now tells a session its own name (the one peers use to reach it), and ListAgents//list-agents now list live teammates — previously a reachable teammate simply looked absent.
  • fix Sessions whose title starts with / were unaddressable by SendMessage and showed as “(untitled)” in ListAgents.
  • fix Custom session titles disappeared from /resume after more than ~64 KB of conversation was written following the rename.
  • fix claude -c/resume picked up sessions from a different directory whose path differed only by characters like _, - or .. Resuming into the wrong repo is a quietly dangerous bug.
  • fix Remote sessions: images uploaded from mobile now include their saved file path, so Claude can copy them into files it creates.

Correctness and data handling v2.1.239

  • sec Masked (password-style) inputs — such as the login code field — let their text be pasted back with Ctrl+Y elsewhere, or saved to prompt history when cleared with double Esc. A field rendered as dots was recoverable in plaintext from the kill ring and from history. Small blast radius, but exactly the class of bug worth patching rather than reasoning about.
  • sec WebFetch retained expired page content in memory for the whole session instead of the intended 15 minutes. A stated retention window that was not enforced.
  • sec A request rejected by an organization policy check was re-sent before the rejection was shown. The policy held, but the retry ordering meant a blocked request went out again before anyone was told it had been blocked.
  • fix A race on Esc with a prompt queued could let the next turn finish early, leaving the session idle while Claude was still working — and a later resubmit could repeat actions. Repeated actions from a queued prompt is the failure mode to care about here.
  • fix Starting Claude Code from a directory that no longer exists produced a raw crash dump; it now prints a clear message.
  • fix Edit and Write calls paused for about 5 seconds in JetBrains IDE terminals when the Claude Code plugin was connected.
  • fix The usage-limit message for an exhausted monthly spend limit now also says when the session or weekly limit resets.
  • feat The fullscreen renderer offer now appears on Bedrock, Vertex, Foundry and other previously excluded setups, and new installs there start in fullscreen.

Interface, keybindings and /goal v2.1.239

  • feat /goal check-ins on long-running background work now back off — 30 minutes, then 1 hour, then every 2 hours — instead of repeating every 30 minutes. Resuming from the claude --resume picker also restores the active goal.
  • feat keybindingFlavor: "readline" now matches Bash for word keys: Alt+F and Ctrl/Option+→ stop at word end, Alt+D deletes to it, Ctrl+Y pastes it back, and punctuation separates words.
  • fix Ctrl+W, Ctrl+U, Ctrl+K, Option+Backspace, Option+D and vim df/dt left a broken [Pasted text #N] placeholder when the cursor was inside it.
  • fix MCP elicitation forms taller than the terminal were clipped in fullscreen; the form now fits the window with Accept/Decline always visible.
  • fix Fullscreen answered a permission prompt when you clicked the terminal window merely to focus it. An accidental approval from a focus click is worth knowing about even now it is fixed.
  • fix Slash-command panels (/config, /model) covered the latest messages in fullscreen; the conversation now stays pinned above the panel.
  • fix The dark-ansi theme rendered expanded tool results with text the same colour as the background in fullscreen.
  • fix The fullscreen renderer prompt reappeared on every launch when it could never be answered; it now stops after three launches.
  • fix Mouse movement in browser-based terminals inserted text like "35;150;7M" into the prompt when a mouse report arrived split across writes.
  • fix /resume and the agents view showed a session as recently changed when only its file was touched or it was merely reopened; and /resume in all-projects mode no longer tells you to cd into a deleted directory.
  • fix Vim mode in the agent view: Escape now switches to NORMAL and keeps your text instead of clearing the prompt.
  • fix Claude in Chrome: /clear now closes the session's Chrome tab group, and empty groups are closed on /resume and exit.
  • fix Also: /insights echoing literal <message> tags; custom theme overrides for the effort/ultracode badge ignored; selection:copy dropping a Shift+Arrow selection; the /voice startup tip persisting after voice was enabled; shell-mode Tab completion dropping ./; Ctrl+Backspace deleting a character instead of a word in search boxes; the /workflows dialog losing its header off-screen; long tool-use paths now truncate mid-string; and [VSCode] the usage-limit banner's “View usage” link sitting inline.

Security & evals

newest documented change 22 Aug

This week's actionable items

1. New this morning — four undocumented releases is a supply-chain hygiene question, not just an annoyance. v2.1.240 through v2.1.243 ship with either one boilerplate line or nothing. We cannot review what we cannot read, and two of the four (v2.1.242, v2.1.243) have no GitHub release tag either, so there is no signed artefact to diff against. This is not an allegation of anything — Anthropic publishes patch builds ahead of promoting them routinely — but if our change-management process requires a documented rationale before a version moves in CI, v2.1.239 is currently the newest version that clears that bar. Pin explicitly; do not track latest or next unattended.
2. Cost integrity — upgrade any Bedrock host that sits behind a proxy. v2.1.239. Streaming behind a proxy that strips the response Content-Type header caused every turn to be re-run non-streaming, doubling billed API calls, with no error surfaced. Not a confidentiality issue, but a silent-doubling billing bug is a security-adjacent control failure: our spend telemetry was wrong and nothing told us. Action: upgrade, then reconcile Bedrock spend against turn volume for the pre-upgrade window.
3. Allowed-domain policy was bypassable from Bash on Claude Code on the web. v2.1.239. “Requests from Bash and other tools to non-API anthropic.com hosts (e.g. www, docs) now go through the session's network proxy, so your environment's allowed domains apply.” The prior behaviour is the finding: a class of egress skipped the proxy, and therefore skipped the allow-list we configured. Narrow in scope — anthropic.com hosts only — but any documented enforcement point with a hole in it deserves the upgrade.
4. Credential hygiene — masked input fields were recoverable in plaintext. v2.1.239. Password-style inputs such as the login code field let their text be pasted back with Ctrl+Y elsewhere, or written to prompt history when cleared with a double Esc. Low blast radius, trivially exploitable by anyone at the keyboard or reading a history file. If anyone has typed a code into a shared or recorded terminal recently, prompt history is worth clearing.
5. Policy-check ordering — a blocked request went out again before the block was shown. v2.1.239. “Fixed a request rejected by an organization policy check being re-sent before the rejection was shown.” The policy decision itself held; the retry path did not respect it in ordering. Worth noting for anyone reading policy-enforcement logs and wondering about duplicate rejected requests.
6. Data retention — WebFetch held expired content for the session, not 15 minutes. v2.1.239. The intended window was 15 minutes; actual behaviour was the full session lifetime. If we have made any retention statement that leans on that window, it was not accurate before this release.
7. Worsening — the stable dist-tag is now twelve releases behind and has not moved since Friday. It sits at v2.1.231 (13 Aug) while npm's newest is v2.1.243. Anything we pin to stable lacks: both NT-namespace fixes, v2.1.234's credential-disclosure fixes, v2.1.235's permission-grant bypass fix, v2.1.236's sandbox read-deny precedence fix, v2.1.238's MCP headersHelper trust gate and credential-inheritance fix, and all of items 2–6 above. Recommendation unchanged and now more urgent: pin to an explicit version we have reviewed, not to stable.
8. Carried forward — MCP headersHelper under claude -p. v2.1.238. A headersHelper is a command specified by the repository that Claude Code executes to mint auth headers. Until v2.1.238 a project-scoped one inherited whatever credentials were in the environment and could run before the trust dialog was answered — and under claude -p there is no dialog, so the gate was effectively absent. Anywhere we run claude -p over code we do not fully control — CI, automated review, scheduled tasks — must be on v2.1.238 or later.

Sandboxing and isolation notes

  • sec Linux sandbox × git worktree config (v2.1.239): the sandbox made a nonexistent .git/config.worktree unreadable rather than absent, which broke every sandboxed git command in repos with extensions.worktreeConfig set. A sandbox that breaks the tool it is meant to contain gets disabled by whoever hits it — that is the real risk here.
  • sec macOS sandbox read-deny precedence (v2.1.236): wildcard deny rules such as **/.env now take precedence inside allowed read regions, cover matched directories' contents, and cannot be bypassed by renaming the denied file. All three clauses describe prior gaps.
  • sec Auto mode classification parity (v2.1.236): severity-scored classification now applies on Bedrock, Vertex AI and Foundry and when telemetry is disabled. Our Bedrock hosts were previously on weaker defaults than the Claude API path.
  • sec Auto mode git status check (v2.1.236): can no longer be fooled by a repo's status.showUntrackedFiles=no setting into reporting a clean tree.
  • feat Enterprise skill and plugin security scanning (6 Aug, still the newest dated support release note) automatically checks third-party skills and plugins for malicious content on upload or edit. Worth enabling before we widen who can publish to an internal marketplace.

What's new

Sources: support.claude.com release notes, platform release notes, Claude Desktop help. Checked Tue 25 Aug 2026 — no new Desktop-specific release note. The newest dated support entry is still skill and plugin security scanning (6 Aug, 19 days old). All recent movement is in v2.1.239, which carries the Desktop-hosted and Remote Control fixes.

The plan-mode fix is still the one to know about. v2.1.239 fixed cloud sessions (web, Desktop and mobile) resuming out of plan mode after an idle worker restart. Plan mode is a safety boundary you set deliberately; a session that silently returns able to act is the wrong default in every direction. If anyone parks Desktop-hosted sessions in plan mode and comes back to them later, this is your upgrade reason.
Remote Control's runaway-sync fix had been burning cycles since v2.1.232. “Fixed runaway session-title syncing to Remote Control when two Claude Code processes shared one background job's state (2.1.232 regression); title updates are now deduplicated and rate-limited.” Two processes sharing background-job state and racing on title updates is a regression that shipped nine releases before its fix and generated traffic the whole time.
Two smaller Desktop-visible fixes. (1) Custom session titles disappeared from /resume after more than ~64 KB of conversation was written following the rename — you named a session and, after enough work, the name was gone. (2) Images uploaded from mobile now include their saved file path, so Claude can copy them into files it creates. Also: clearer messaging and claude doctor wording when Remote Control is not enabled for an account.
Standing context — the Customize panel and Cowork GA. Claude Cowork is generally available on macOS and Windows through the Claude Desktop app, with Linux in beta, on all paid plans. A Customize section groups skills, plugins and connectors in one place, and Cowork supports creating and scheduling both recurring and on-demand tasks. Also live: a monthly recap at Settings > Reflect (beta, requires memory on) and Settings > Time and focus for break reminders and quiet hours.

Claude Cowork

Generally available · cloud sessions in beta

What's new

Sources: Use Claude Cowork on web, desktop, and mobile (marked updated this week), Get started with Claude Cowork, Schedule recurring tasks, Use plugins in Claude. Checked Tue 25 Aug 2026.

Genuinely new — the cross-surface support article was revised this week, and it now spells out what does and does not work off-desktop. Cowork runs on desktop, web, mobile and the Claude in Chrome side panel (side panel: Max and Team, rolling out to Pro, Enterprise where an admin has enabled it). The revised per-surface matrix is the useful part: scheduled tasks, projects, connectors, skills and plugins now work on all three surfaces, while live artifacts remain desktop-only, and local file access, browser use and computer use work from web and mobile only while the desktop app is open on that machine. Cloud sessions on web and mobile are still labelled beta.
The operational consequence worth internalising: scheduled tasks now run with no device online. They execute on Anthropic's servers rather than your laptop, so a scheduled task no longer needs the machine awake or the app open. That also means a scheduled task cannot reach local files unless the desktop app happens to be open — a task that reads a connected folder will silently have nothing to read when the machine is off. Worth checking any scheduled task we have that assumes local file access.
Two v2.1.239 fixes land directly on scheduled tasks. (1) Remote sessions now keep sending keep-alives while a long SessionStart or Setup hook runs, so the container is not idle-reaped mid-hook. A scheduled task with a slow setup step was racing the idle reaper. (2) /goal check-ins on long-running background work now back off — 30 minutes, then 1 hour, then every 2 hours — instead of hammering every 30 minutes.
Worth re-reading in light of scheduled tasks — the v2.1.238 headersHelper change. A scheduled Cowork task runs unattended, non-interactively, in a working directory it did not choose, with credentials in scope. That is precisely the shape the v2.1.238 fix addresses. Anyone running scheduled Cowork tasks over repos we do not fully control should be on v2.1.238 or later.
Standing context — plugin and skill governance for Team and Enterprise. (1) Org-wide skill management — a skill uploaded through organization settings appears for everyone in Customize > Skills, so nobody re-uploads it. (2) Admins can create private plugin marketplaces, with a Knowledge Work marketplace added by default and built-in legal and finance marketplaces available. (3) Enterprise skill and plugin security scanning automatically checks third-party skills and plugins for malicious content on upload or edit. Also shipped: ten financial-services agent templates (pitchbooks, KYC screening, month-end close) as Cowork and Claude Code plugins.
