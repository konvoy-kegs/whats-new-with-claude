v2.1.258 — macOS 12 launch regression and a scheduled-session failure today's headline

Claude Code would not launch at all on macOS 12 (Monterey). “Fixed Claude Code failing to launch on macOS 12 (Monterey), a regression introduced in 2.1.255.” This is a three-release window (2.1.255 through 2.1.257) in which a Monterey machine that ran claude update ended up with a CLI that does not start. Neither 2.1.255 nor 2.1.256 was published to npm, so in practice the exposure is anyone who installed v2.1.257 during the five hours it stood alone. Worth an explicit check with anyone still on an older macOS — the failure mode is a non-starting binary, not a degraded one, so it will look like a broken install rather than a version problem.
Remote and scheduled sessions were failing outright after a re-sent permission approval. “Fixed remote and scheduled sessions failing with ‘user messages must have non-empty content’ after a re-sent permission approval could not be applied.” This is the one that matters for our own automation. Scheduled Cowork tasks and Remote Control sessions are exactly the shape of session that re-sends an approval when a connection blips — and the failure is a hard API error that ends the run, not a retry. If a scheduled task has failed inexplicably in the last few days, this is the likely cause; it is fixed as of this release rather than something to work around.

v2.1.257 — Fable 5.1, Containment Escape, and two more permission bypasses 104 entries

Claude Fable 5.1 is out and is now the default Fable model. claude-fable-5-1 — 1M context, $10/$50 per Mtok, $0.25/Mtok cache reads. One caveat that will catch people behind a gateway: fable and best in Claude apps gateway sessions keep resolving to Fable 5 for now, because gateways not yet configured for 5.1 reject it. To actually use 5.1 through a gateway you have to pick it explicitly in /model. Also in this release: --effort now lifts a new model's default-effort hold for that session only rather than permanently, and gateway-supplied description text can now appear on discovered /model picker entries.
New — a Containment Escape rule in auto mode. “Added a Containment Escape rule to auto mode so cloud metadata-credential fetches, egress evasion, and cross-tenant reach are no longer auto-approved unless your environment marks them expected.” This is the SSRF-to-instance-metadata class written directly into the permission model — a fetch of 169.254.169.254-style metadata credentials from inside an auto-mode session now stops and asks. For us that covers any Claude Code session on an EC2 instance or in a container with an instance profile attached. The default is now fail-closed; if a legitimate workflow needs metadata access, the environment has to declare it expected rather than the session silently allowing it.
New — a one-time prompt before the first file read outside your working directories, and a setting to block them entirely. Auto mode now asks once before reading outside the working directories, with the option to block such reads permanently via permissions.blockReadsOutsideWorkingDirectories. Worth turning on as a managed setting. Reads outside the working directory are how a session picks up ~/.aws/credentials, ~/.ssh, or another repo's .env — the prompt makes it visible and the setting makes it impossible. Paired with it: /add-dir now accepts a directory inside the current working directory (it used to reject them), and --add-dir, /add-dir and additionalDirectories now refuse network paths (UNC shares, /net/<host> automounts) before touching them.
Permission bypass — permissions.ask rules were skipped inside compound commands and subshells. “Fixed a permissions.ask rule being skipped in auto mode when the matching command ran inside a compound command or subshell, letting it run without the confirmation prompt.” This is the fourth correction to the Bash permission matcher in two weeks — after the arithmetic-assignment auto-approval in v2.1.251 and the pre-subcommand wildcard behaviour in v2.1.246. Also fixed here: [[ ]] conditionals that zsh parses differently from bash were being auto-approved, and Read()/Edit() deny rules did not apply to < file redirects or reader commands like tac and egrep. If your ask/deny rules are a control rather than a convenience, re-read them — they have been softer than they look, repeatedly.
Permission bypass — plugins could read outside their own directory through symlinked component paths. “Fixed plugins being able to read files outside their own directory through a declared command, agent, skill, hooks or other component path that is a symlink; such paths are now refused with an error.” This is the direct sequel to last week's marketplace path-traversal fix — same trust boundary, different primitive. Write access to a repo backing a private marketplace was, again, write access to a read primitive on every machine installing from it. Relatedly: claude mcp add/remove now fails fast instead of hanging or exhausting memory when .mcp.json is a FIFO or device-file symlink.
Credential leaks across three gateway providers. Three separate fixes, all the same shape — a credential going somewhere it was not minted for. (1) A doubly-listed custom Authorization header was overriding the configured credential on Bedrock, Mantle, Vertex and WIF, and the Vertex setup wizard was picking up a leftover Anthropic profile from ~/.config/anthropic. (2) The Claude apps gateway was sending stray host Authorization or profile headers to Foundry, Vertex and Bedrock. (3) A leftover Anthropic API key or auth token was being sent alongside your Foundry subscription key in API-key mode. Anyone running Claude Code against Bedrock or Vertex with a custom header set should treat this as a rotation prompt. Also hardened: MCP connection and OAuth debug logs now redact credentials carried in a server's URL or headers, and gateway sign-in and token refresh now verify the gateway's pinned TLS certificate.
Managed-settings and MCP lockdown gaps closed. --disallowedTools and session deny rules were being dropped after the first settings reload when allowManagedPermissionRulesOnly is enabled — so an org control silently stopped applying mid-session. /mcp reconnect and enable were still connecting a settings-file MCP server that a managed allow/deny list or strictPluginOnlyCustomization loaded after startup should have blocked. claude mcp remove was leaving a remote server's stored OAuth credentials behind under strictPluginOnlyCustomization. And defaultMode: "bypassPermissions" in project .claude/settings.json or settings.local.json is now ignored entirely, like "auto" — set it in user or managed settings, or pass --permission-mode. Three of these are cases where a policy appeared to be in force and was not.
New settings and controls worth knowing. timeFormat and timeZone settings (12-hour, 24-hour, 24-hour UTC, or a strftime pattern) for the turn-end clock and transcript timestamps. CLAUDE_CODE_SUBAGENT_MODEL_FORCE to apply the subagent model to every subagent, ignoring per-spawn and agent-definition overrides — this restores the hard cap that v2.1.251 turned into a default. s in /effort for session-only effort changes, matching /model. A /doctor warning for stale sandbox mask files left by a killed session. And /btw history browsing moved from ←/→ to Shift+←/Shift+→ (or [/]).
Background sessions and agent teams — a long list of silent-failure fixes. Background sessions failed to start on macOS npm installs during a self-update, and on Windows when a stale daemon lock pointed at a reused process id. Sessions left running an older Claude Code binary piled up across auto-updates instead of being retired. claude --bg from a just-deleted directory reported “backgrounded” and left a crashed row; it now exits 1 with a reason. Background commands that detach from their shell (under timeout or setsid) survived a task stop or exit. Stopping a background subagent left its monitors running. Subagents stopped when a response was cut off mid-stream by a sleep or dropped connection — they now continue automatically instead of ending incomplete. And claude agents now says when a background session is waiting on you to approve a message from another session, and who sent it.
Prompt-cache and performance work. Several distinct cache-miss fixes: Remote Control connecting mid-session was re-sending the Bash tool definition; sessions with an advisor model set missed the cache on every background request (compaction, /recap, prompt suggestions), re-sending the full conversation uncached each time; long screenshot-heavy sessions missed the cache every turn once images exceeded the per-request size cap; and /fork now keeps the original conversation's prompt cache in the new background session. On rendering: less re-render work per turn in long conversations, streaming no longer slows as the reply grows, background-agent updates no longer re-render the whole screen, and per-keystroke input work is down.
VS Code extension — the session panel got a real overhaul. Collapsible ACCOUNT & USAGE and SESSION MANAGER headers with the account email, usage meter and a details link; a model pill in the input footer that opens the model picker with an Effort row and a “More models” page; output style selection in the command menu; and “Delete session” is now “Archive session”, with archived sessions moving to a collapsible group with an Unarchive action. Also fixed: third-party provider deployments (Bedrock, Vertex) were still showing claude.ai-only features and calling claude.ai with a leftover login.

Still worth actioning from last week carry forward

v2.1.251 — five permission bypasses, all still relevant if you have not upgraded. Symlink TOCTOU in Read/Write/Edit, Read(...) deny rules not applying through symlinked Grep/Glob paths, plugin marketplace path traversal, the Workflow tool's pre-check scriptPath read, and Bash auto-approving arithmetic variable assignments. All fixed in the version you get by upgrading today.
v2.1.248 — rotate credentials that lived in uncommitted *.tfvars or prod.env files. /ultrareview and locally seeded cloud sessions were uploading uncommitted edits to those files, and to editor swap/temp/backup copies of credential files (key.pem.tmp, id_rsa.swo). The fix is forward-looking only — an upload that already happened is not undone by upgrading.
v2.1.248 — --restricted is still the mode to reach for on untrusted code. It removes the tools that run commands or code plus WebFetch, keeps file tools inside the working directory, refuses bypassPermissions, and ignores user, project and local settings files. Today's blockReadsOutsideWorkingDirectories setting narrows normal mode further, but --restricted is still the stronger answer for reviewing a dependency or a read-only CI runner.
v2.1.246 — rotate any third-party LLM gateway API key. Telemetry and metrics requests to Anthropic were carrying the API key configured for a gateway via ANTHROPIC_BASE_URL. A credential minted for our gateway was sent to a host that is not our gateway. On latest for two weeks now; there is no reason to still be exposed.

Sandboxing and isolation notes

The Containment Escape rule is the most consequential security change in this release, and it is a category rather than a bug fix. Cloud metadata-credential fetches, egress evasion and cross-tenant reach now sit outside what auto mode will approve on its own. This is the SSRF-to-IMDS chain written into the permission model instead of left to a network policy. For an infrastructure team it changes the default assumption: a Claude Code session running on an instance with a role attached is no longer one auto-approved curl away from that role's credentials. The environment has to declare metadata access expected; silence is now a refusal.
Three policy-enforcement gaps in one release is the pattern to watch. Managed deny rules dropping after a settings reload, /mcp reconnect still connecting a server a managed list should block, and project defaultMode: "bypassPermissions" being honoured — all three are cases where an administrator had configured a control that appeared to be in force and was not. Configuring a policy and verifying it applies are different activities, and this release is the argument for doing the second one.
Fail-closed keeps replacing silent-permissive. Network paths in --add-dir are refused before being touched. Symlinked plugin component paths error instead of resolving. .mcp.json as a FIFO fails fast instead of exhausting memory. Non-JSONL data piped into claude -p --input-format stream-json fails with a clear error instead of growing memory without bound. Dismissing the Remote Control consent prompt with Esc no longer counts as consent. policyHelper timeouts above the timer maximum are clamped instead of re-running every millisecond. Six weeks into this pattern it is clearly deliberate rather than incidental.

Claude Desktop

macOS · Windows · Linux (beta)

What's new

New — Remote Control sessions started from the Claude app now honour the model you selected. v2.1.257: “Fixed Remote Control (claude remote-control) sessions started from the Claude app ignoring the selected model and running on the machine's default instead.” If you picked Opus in the app and the machine defaulted to Sonnet, you got Sonnet and were not told. Anyone running Remote Control from Desktop should assume recent sessions may not have been on the model they chose.
New — telemetry settings pushed through server-managed settings now apply on warm starts, including desktop-app Code sessions. They were being ignored, so an org's OTEL configuration silently did not apply to sessions the desktop app started warm. Relevant to anyone relying on desktop-launched sessions appearing in a central collector.
Carried forward — Remote Control stalls on a degraded connection are fixed. v2.1.252 fixed Remote Control sessions hosted by Claude Desktop or VS Code stalling for minutes after a tool finished when the connection to claude.ai was degraded. If Desktop-hosted Remote Control has felt unusably slow, that was a real bug and it is fixed.
Carried forward — the 30-day session deletion fix (v2.1.248). The CLI's transcript cleanup was reaping desktop-written sessions the app still considered live. Anything already reaped before that release is gone and upgrading does not recover it. The desktopSessionCleanupPeriodDays setting caps the exemption; org-managed retention policy still takes precedence.
Standing context — memory, the Customize panel, and Cowork GA. Everything Claude remembers is listed under Topics in Settings > Memory and can be edited or deleted. Memory is on by default for Free, Pro and Max, and off by default for Team and Enterprise — on our plan nothing is retained unless somebody turned it on. Also live: Claude Cowork generally available on macOS and Windows; a Customize section grouping skills, plugins and connectors in one place; the monthly recap at Settings > Reflect; break reminders and quiet hours at Settings > Time and focus.

Claude Cowork

GA · macOS & Windows

What's new

New — reading an artifact that is not yours now always asks first, even in auto mode. v2.1.257: “Changed Cowork and claude.ai cloud sessions: reading an artifact that isn't yours now always asks you first, even in auto mode.” This is a deliberate carve-out from auto mode for cross-user data — auto mode no longer implies consent to open somebody else's artifact. Expect an extra prompt in shared workspaces; that is the intended behaviour, not a regression.
New — the scheduled-session failure that broke automated tasks is fixed. v2.1.258 fixed remote and scheduled sessions failing with “user messages must have non-empty content” after a re-sent permission approval could not be applied. This digest is itself a scheduled Cowork task, so it is the exact failure shape. Also fixed in v2.1.257: /schedule routines whose prompt was saved without a message role then ran with nothing to do — a scheduled task that appeared to run and did nothing.
Standing context — plugins, skills and scheduled tasks. Plugins bundle skills, connectors and sub-agents into one installable package, usable in chat on the web, the Chat tab in Desktop, and Cowork. In Cowork, Customize in the upper right opens a new task that walks through tailoring an installed plugin's skills and connectors to how you work. Recurring and on-demand scheduled tasks are available. Enterprise plans can turn on skill and plugin security scanning, which checks third-party skills and plugins for malicious content on upload or edit — worth enabling given four consecutive weeks of marketplace and plugin path fixes in the CLI.
