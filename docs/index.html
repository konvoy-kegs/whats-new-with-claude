v2.1.243 — contracted-rate cost accounting, a 4× smaller binary, and a hook-matching bug worth checking today's headline

60 entries · published Tue 25 Aug 09:10 local · changelog and release tag landed 09:40 local

Cost — modelPricing makes /cost, the status line and telemetry use our contracted rates instead of list price. “Added modelPricing managed setting so an organization's contracted per-model rates and discount multiplier are used for /cost, the status line, and telemetry cost figures instead of list price.” If we are on negotiated pricing, every cost number Claude Code has ever reported to us has been wrong — systematically high by our discount. This is a managed setting, so it is something we configure centrally and once. Pairs directly with v2.1.239's data-residency premium fix: between the two, the cost telemetry is finally reconcilable against an actual invoice.
Cost — promptCacheTtl and subagentPromptCacheTtl give API-key and Bedrock/Vertex users a 1-hour prompt cache. “Added promptCacheTtl and subagentPromptCacheTtl settings so API-key and cloud-provider users can keep a 1-hour prompt cache on the main conversation while subagents stay at 5 minutes.” The split default is the thoughtful part — long-lived main conversation cache where the context is stable, short subagent cache where it churns. For anyone running Claude Code against Bedrock at volume, this is a direct spend lever, not a convenience setting.
Infrastructure — the Linux x64 binary went from about 340 MB to about 75 MB. “Improved native install and auto-update download size: the binary is now zstd-compressed (about 75 MB instead of 340 MB on Linux x64).” A 4.5× reduction changes the economics of baking Claude Code into container images and CI runners — layer size, pull time, registry egress and auto-update bandwidth all drop together. Alongside it: roughly 40–70 MB less memory per session (code is loaded on demand rather than kept resident), earlier garbage collection in long-running sessions, about 2 MB off the binary from more compact bundled skill text, and faster startup (sandbox and MCP bring-up no longer block the first frame).
Containers — cross-session messaging was silently off in rootless containers and user namespaces since v2.1.232. “Fixed cross-session messaging silently turning off inside user namespaces and rootless containers after the 2.1.232 socket-directory hardening.” A security hardening change eleven releases ago broke the feature specifically in the environment we are most likely to run it in. Silently is the operative word: sessions simply could not find each other, with no error to explain why. If anyone tried multi-session orchestration inside a rootless container recently and concluded it did not work, it did not — and now does.
CI — workload identity federation was re-exchanging a single-use token across processes in the same job. “Fixed workload identity federation in CI: processes in one job share the exchanged token instead of re-exchanging the single-use token; a rejected exchange fails fast with the server's message.” Re-exchanging a token that is by definition single-use means the second process fails, and previously it failed slowly and opaquely. Directly relevant to any OIDC-federated CI where more than one Claude Code process runs in a job.
Hooks — if conditions fired on the wrong commands when command substitution was involved. “Fixed hook if conditions like Bash(cat *) firing on unrelated Bash commands when the command contained $() or backtick command substitution followed by more arguments.” This is a matching bug in a gating mechanism, which makes it worth an audit rather than just an upgrade. If we use hook if conditions to gate, log or block particular Bash shapes, a command containing $(...) plus further arguments could match a pattern it should not have — and by symmetry, the intended pattern may not have matched when we assumed it did. Worth re-reading our hook conditions against this behaviour.
Sandbox — network-violation detail was being dropped when the blocked command still exited 0. “Fixed sandbox network-violation details being dropped from the Bash tool result when the blocked command still exited 0 (for example curl printing the proxy's 403 page).” The canonical case: curl is blocked by the proxy, prints the 403 body, and exits 0 because it successfully fetched something. The sandbox denial was real but invisible — to Claude and to whoever read the transcript afterwards. Related: the sandboxed Bash prompt no longer lists allowed network hosts, so Claude attempts requests and surfaces an approval prompt rather than assuming an unlisted host is blocked.

  • fix Auth, model-availability and other client-generated error messages rendered like model output instead of as error lines — errors that look like Claude talking are errors people miss.
  • fix Remote Control: claude remote-control exited and stranded attached sessions when the server dropped its environment mid-session (it now recovers); and sessions served by it could get stuck after a stop/restart for Team and Enterprise members without an admin or owner role.

v2.1.239 — the Bedrock double-billing fix is still the one to action carry forward

59 entries · published Sat 22 Aug 03:18 local

Billing — Bedrock behind a header-stripping proxy was being billed twice for every turn, silently. “Fixed Bedrock streaming behind proxies that strip the response Content-Type header, which silently doubled billed API calls by re-running every turn non-streaming.” Claude Code starts a streaming request, the proxy strips the header that identifies the response as a stream, Claude Code concludes streaming is unsupported, and re-runs the same turn non-streaming. Both calls bill. No error, no warning, no symptom other than the invoice. Any Bedrock traffic traversing a proxy we control is a candidate. Upgrade, then reconcile Bedrock spend against turn counts for the affected window. Read this alongside v2.1.243's modelPricing setting — together they are the difference between cost figures we can reconcile and cost figures we cannot.
AWS — Bedrock with an SSO profile and awsAuthRefresh hung at startup behind an HTTPS proxy. The credential pre-check was making a direct connection and ignoring HTTPS_PROXY, so it waited on a connection that could never complete. This is the exact shape of our Bedrock-plus-SSO setup, and a startup hang is the kind of failure people work around locally rather than report. Note v2.1.243 fixed a second, related proxy-variable bug — no_proxy casing on the IDE connection.
Cost — /cost, the status line and --max-budget-usd were under-reporting spend on data-residency workspaces by omitting the 1.1× US-only-inference premium. That matters most for --max-budget-usd, which is a control, not a display: a cap computed from pre-premium numbers let 10% more real spend through than the flag said.
Windows — cross-session messaging arrived, closing the last platform gap. Sessions across machines can message each other with SendMessage and find each other with ListAgents, as on macOS and Linux. Read with v2.1.243's rootless-container fix: between the two, cross-session messaging now works on Windows and inside rootless containers, which is most of where it was previously unavailable.
Security items from v2.1.239, all still worth the upgrade: Bash on Claude Code on the web bypassed the allowed-domain proxy for non-API anthropic.com hosts; masked password-style inputs were recoverable in plaintext via Ctrl+Y or prompt history; WebFetch retained expired page content for the whole session rather than 15 minutes; and a request rejected by an organization policy check was re-sent before the rejection was shown.

This week's actionable items

1. New — audit hook if conditions that gate on Bash command shapes. v2.1.243. “Fixed hook if conditions like Bash(cat *) firing on unrelated Bash commands when the command contained $() or backtick command substitution followed by more arguments.” This is a correctness bug in a matching mechanism people use as a control. If a hook exists to log, gate or block a class of command, a command containing $(...) plus further arguments matched patterns it should not have — and the converse case, where the intended pattern failed to match, is the one that matters for anything used as a guardrail. Action: upgrade, then re-read our hook if conditions and confirm they gate what we think they gate.
2. New — sandbox network denials were invisible when the blocked command exited 0. v2.1.243. “Fixed sandbox network-violation details being dropped from the Bash tool result when the blocked command still exited 0 (for example curl printing the proxy's 403 page).” The sandbox was enforcing correctly; the enforcement just was not reported. curl fetches the proxy's 403 page, prints it, exits 0 — and the violation detail was dropped. If we have been reading transcripts to confirm sandbox behaviour, we were reading an incomplete record.
3. New — telemetry from ANTHROPIC_AUTH_TOKEN sessions now falls under our data-handling settings. v2.1.243. “Improved attribution of usage telemetry to your organization for sessions that authenticate with ANTHROPIC_AUTH_TOKEN directly against the Anthropic API, so its data-handling settings apply.” The implication is that previously it did not. If any of our automation authenticates that way, its telemetry sat outside the org's configured data handling until this release.
4. New — CI workload identity federation was re-exchanging single-use tokens. v2.1.243. Processes in one job now share the exchanged token instead of each re-exchanging a token that is single-use by definition, and a rejected exchange now fails fast with the server's message. Relevant to any OIDC-federated pipeline running more than one Claude Code process per job.
5. Carried forward — cost integrity on Bedrock behind a proxy. v2.1.239, plus modelPricing in v2.1.243. Streaming behind a proxy that strips the response Content-Type header caused every turn to be re-run non-streaming, doubling billed API calls, with no error surfaced. A silent-doubling billing bug is a control failure: our spend telemetry was wrong and nothing told us. v2.1.243 then fixed the other half — cost figures were computed at list price rather than our contracted rates. 6. Carried forward — three data-handling and policy fixes from v2.1.239. (a) Bash and other tools on Claude Code on the web reached non-API anthropic.com hosts outside the session proxy, bypassing our allow-list. (b) Masked password-style inputs were recoverable in plaintext via Ctrl+Y or prompt history. (c) WebFetch retained expired page content for the whole session rather than the stated 15 minutes. 8. Carried forward — MCP headersHelper under claude -p. v2.1.238. A headersHelper is a command specified by the repository that Claude Code executes to mint auth headers. Until v2.1.238 a project-scoped one inherited whatever credentials were in the environment and could run before the trust dialog was answered — and under claude -p there is no dialog, so the gate was effectively absent. Anywhere we run claude -p over code we do not fully control — CI, automated review, scheduled tasks — must be on v2.1.238 or later.

Claude Cowork

Generally available · cloud sessions in beta

What's new

Sources: Use Claude Cowork on web, desktop, and mobile (marked updated this week), Get started with Claude Cowork, Schedule recurring tasks, Cowork architecture overview. Checked Tue 25 Aug 2026.

Genuinely new — the cross-surface support article was revised this week and now spells out what does and does not work off-desktop. Cowork runs on desktop, web, mobile and the Claude in Chrome side panel (side panel: Max and Team, rolling out to Pro, Enterprise where an admin has enabled it). The revised per-surface matrix is the useful part: scheduled tasks, projects, connectors, skills and plugins work on all three surfaces; live artifacts remain desktop-only; and local file access, browser use and computer use work from web and mobile only while the desktop app is open on that machine. Cloud sessions on web and mobile are still labelled beta.
The operational consequence worth internalising: scheduled tasks run with no device online. They execute on Anthropic's servers rather than a laptop, so they no longer need the machine awake or the app open. The corollary is the trap: a scheduled task cannot reach local files unless the desktop app happens to be open on that machine. A task that reads a connected folder will run on time and silently find nothing when the machine is off. Worth auditing any scheduled task of ours that assumes local file access — the failure is quiet, not loud.
New — v2.1.243 adds per-loop token accounting, which is the missing piece for scheduled work. “Added a Loops breakdown to /usage: per-loop run count, total tokens, tokens per run, and last run, so runaway or chatty /loop tasks are easy to spot.” Unattended recurring work is exactly where token spend drifts without anyone noticing, and until now there was no per-loop attribution to notice it with.
New — two v2.1.243 fixes land on unattended runs. (1) Remote MCP servers in non-interactive (-p) and SDK sessions never recovered after a dropped connection; they now reconnect or report as failed. For a scheduled task, a silently dead MCP server meant a run that completed while doing nothing useful. (2) Sessions went silent for 10+ minutes when the API never started a response — now a ~3 minute timeout, one retry, then a clear error.
Carried forward — two v2.1.239 fixes on scheduled tasks. (1) Remote sessions keep sending keep-alives while a long SessionStart or Setup hook runs, so the container is not idle-reaped mid-hook. (2) /goal check-ins on long-running background work back off — 30 minutes, then 1 hour, then every 2 hours.
Worth re-reading in light of scheduled tasks — the v2.1.238 headersHelper change. A scheduled Cowork task runs unattended, non-interactively, in a working directory it did not choose, with credentials in scope. That is precisely the shape the v2.1.238 fix addresses. Anyone running scheduled Cowork tasks over repos we do not fully control should be on v2.1.238 or later.
Standing context — plugin and skill governance for Team and Enterprise. (1) Org-wide skill management — a skill uploaded through organization settings appears for everyone in Customize > Skills.
