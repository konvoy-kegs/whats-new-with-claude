v2.1.235 — a Shift+Tab permission-grant bypass, dialog/grant mismatch fixed, grep hardened new overnight

19 entries · published Wed 19 Aug 04:24 local · a small consolidation release after yesterday's ~50-entry v2.1.234

Permissions — Shift+Tab in the permission prompt's comment field was granting session-wide edit permission. The changelog entry: “Fixed Shift+Tab inside the permission prompt's comment field approving the edit and granting session-wide edit permission instead of closing the field.” Two things went wrong at once — the edit was approved, and a standing session-wide grant was issued — from a keystroke whose expected behaviour was to close the field. Anyone who habitually uses Shift+Tab for indentation or focus movement may have been issuing blanket edit grants without knowing. This is the entry that justifies the upgrade on its own.
Permissions — dialog text and “don't ask again” now match what a grant actually covers. “Display text and ‘don't ask again’ options now always match what a grant would cover, and ‘don't ask again’ is withheld when contents cannot be fully displayed.” This is the same class of problem as yesterday's masked-preview fix: the dialog was describing one thing while the grant covered another. The withholding behaviour is the important half — if Claude Code can't show you the full contents, it now refuses to offer you the standing-grant option at all rather than letting you sign a blank cheque. Related: notebook cell delete/replace approval dialogs were silently omitting existing cell content when the notebook or cell couldn't be read; the dialog now says why.
Availability — the embedded grep could be made to exhaust memory. On native macOS and Linux builds, pathological patterns now fail fast instead of exhausting memory. A regex that backtracks catastrophically against a large tree was previously a way to take the session — and potentially the host — down. Given Claude Code composes search patterns itself, this was reachable without anyone doing anything deliberate. Same entry fixes -m N with -A/-C printing incorrect context, which means any tooling that parsed capped grep output with context was reading the wrong lines.
Enterprise — claude rc was skipping the gateway availability check. “Remote Control: claude rc now applies the same enterprise-gateway availability check as interactive startup.” Remote Control started via the rc subcommand was not being gated the way an interactive launch is, so a policy expressed at the gateway could be sidestepped by choosing a different entry point. If we lean on gateway availability rules to control who can drive sessions remotely, that control had a hole in it until this release.
Cost — a language server reconnecting was invalidating the whole prompt cache. “Fixed whole-prompt-cache invalidation when a language server disconnected or reconnected mid-session.” LSP restarts are routine — a rebuild, a config change, a crash-and-respawn — and each one was throwing away the entire cached prompt, meaning the next turn re-billed the full context at uncached rates. On long sessions in a large repo this is a real number, not a rounding error. Alongside it: memory and CPU usage during background cloud sessions (/ultrareview, /autofix-pr) improved by no longer re-scanning and re-rendering their event streams on every update.

  • approvals Permission dialog display text and “don't ask again” options now always match what a grant would cover, and “don't ask again” is withheld when contents cannot be fully displayed.
  • approvals Fixed notebook cell delete/replace approval dialogs silently omitting the existing cell content when the notebook or cell could not be read; the dialog now states why.
  • availability Embedded grep on native macOS/Linux builds: pathological patterns now fail fast instead of exhausting memory, and -m N with -A/-C prints correct context.
  • enterprise Remote Control: claude rc now applies the same enterprise-gateway availability check as interactive startup — the subcommand previously bypassed it.
  • cost Fixed whole-prompt-cache invalidation when a language server disconnected or reconnected mid-session — every LSP restart was re-billing the full context.
  • perf Improved memory and CPU usage while cloud sessions such as /ultrareview or /autofix-pr run in the background — their event streams are no longer re-scanned and re-rendered on every update.
  • context The context-limit error now says when auto-compact is off and points at /config to re-enable it — previously it just told you that you were out of room.
  • editor New optional spellcheck setting underlines misspelled words in the prompt input as you type, using an installed aspell, hunspell or ispell. Off by default.
  • agents Fixed the Agent tool advertising a general-purpose default in sessions where that agent is unavailable — an omitted subagent_type now returns a clear error listing the agents that do exist.
  • messaging SendMessage now refuses messages too large for cross-session delivery up front instead of silently dropping them.
  • tasks Fixed the expanded task list (ctrl+t) always starting collapsed when resuming or relaunching into a session that still has open tasks.
  • updates Fixed the prompt footer not showing the “Update installed” restart notice after a background auto-update — sessions were sitting on an old build with no indication.
  • tui Vim mode: NORMAL mode and cursor position are now preserved when toggling the detailed transcript (ctrl+o) or closing a panel. Dialogs: arrow keys and Enter pressed in quick succession now select the option you navigated to, not the previously highlighted one.
  • rendering Fixed nested markdown list items misaligning at depth 3+ (with a hanging indent added to wrapped items), prompt input highlights appearing shifted in some multi-line prompts, and slash commands run mid-response showing HTML entities instead of characters.
  • vscode Fixed focus jumping between open Claude tabs on its own when a window with several Claude panels is restored or reloaded.

Still open — gateway boot validation, reverted Bash checks, MCP secret exposure, container limits action required

v2.1.234 — MCP diagnostic output may already have leaked live secrets, and v2.1.235 does nothing about what was already pasted. Yesterday's release fixed MCP scope-conflict warnings printing resolved secret values instead of the configured ${VAR} form, and connection-failure details printing more than the server origin. The code fix is in; the historical exposure is not. Debugging an MCP server has been a normal thing to paste into a thread or a ticket. Search #cloud-engineers and Jira for pasted MCP diagnostics and rotate anything that appears. This remains the only item on the board with a possible past exposure rather than a future one.
v2.1.233's reverts still stand — < file redirection is not permission-checked. v2.1.233 reverted v2.1.232's Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (< file), promising a narrower version later. Neither v2.1.234 nor v2.1.235 brings it back. Reading a file by < file redirection is still not checked the way the argument spelling is, on any platform. Any deny rule written on the strength of that change still does not do what it looks like it does. Two releases and five days on, treat this as the standing gap.
v2.1.232 — the gateway still fails at boot on configuration it previously accepted. Unchanged by v2.1.233, v2.1.234 or v2.1.235, and still the biggest upgrade risk. Two fail-fast changes. (1) The desktop: overlay now accepts every released Desktop setting, validated at boot against Desktop's own schema — unknown or invalid keys now fail boot, where a typo used to be silently ignored. (2) Empty managed.policies[].match.groups and admin.admin_groups entries, and malformed email_domain values, now fail at boot instead of silently matching no one or granting admin access. If our gateway config has an empty admin_groups entry today, it has been granting admin. Validate in a non-production environment first.
v2.1.229 / v2.1.233 — container resource limits are correct in both dimensions; re-baseline anything sized around the old behaviour. v2.1.229 fixed dynamic workflows using the host's core count rather than the container's CPU limit — the likeliest explanation for throttling or noisy-neighbour behaviour from Claude Code in CI or on EKS. v2.1.233 added CLAUDE_CODE_TOOL_MEMORY_LIMIT to cap Bash commands with a Linux memory cgroup. With v2.1.235's grep memory fix on top, the runaway-memory surface is now meaningfully smaller — but the limit is still worth setting explicitly on Linux runners.
v2.1.229 — /commit-push-pr no longer auto-approves dangerous git and gh flags. --force, --amend, --no-verify now require explicit approval, so unattended automation that relied on /commit-push-pr finishing without a prompt will stop and ask. Also still live: run /doctor after upgrading — sandbox network domain lists are enforced fail-closed on ambiguous spellings, so an allowlist entry you thought was permitting traffic may now be refusing it. And Windows self-hosted runners still require an explicit --base-dir.
Carried forward: v2.1.234's NT-namespace hardening for remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads — Windows hosts that stopped at v2.1.233 are still exposed. v2.1.233's Todo/task-tracking tools remain removed on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer (CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to restore). v2.1.234's strictKnownMarketplaces SCP-style host-confusion fix — re-read any allowlist. v2.1.228's Write tool can overwrite a file it hasn't read for newer models. And v2.1.224's sandbox credential masking with awsPairs / sigv4 is still the right answer for unattended tasks holding secrets.

Opus 5 — near-Fable intelligence at half the price headline

Source: Introducing Claude Opus 5 · 24 Jul 2026

claude-opus-5 is available on all platforms. Anthropic describes it as “thoughtful and proactive,” coming close to Fable 5's frontier intelligence at half the price. Pricing is $5 / $25 per Mtok — identical to Opus 4.8, so this is a free capability upgrade for anything already pinned to Opus. It is the default model on Claude Max and the strongest model on Pro.
What this means for us. On any current dist-tag — including stable, now at v2.1.227 — Opus 5 is already your default Opus in Claude Code, with no config change. Three things still to action: (1) our Bedrock/Vertex pipelines pinned to claude-opus-4-8 will not move on their own, so schedule the model-string bump deliberately; (2) /fast no longer applies to Opus 4.7 — fast mode is Opus 5 and Opus 4.8 only, and Opus 5 fast mode bills at 2× base ($10 / $50 per Mtok) for ~2.5× the speed; (3) v2.1.233's [claude-code:unrecognized_model] stderr line in print mode is a cheap way to catch stale pinned model strings in CI before they become an outage.
  • model Available on all platforms as claude-opus-5 at $5 / $25 per Mtok (unchanged from Opus 4.8). Fast mode runs ~2.5× default speed at twice base price.
  • performance New SOTA on Frontier-Bench and GDPval-AA. On CursorBench 3.2 at max effort it lands within 0.5% of Fable 5's peak at half the cost per task. ARC-AGI 3: 3× the next-best model. OSWorld 2.0 (computer use): beats Fable 5's best result at just over a third of the cost.
  • efficiency Multiple early-access reports of the same result at materially fewer tokens — one legal-tech partner saw comparable quality with 26% fewer tokens at max reasoning. Several partners call out lower run-to-run variance versus Opus 4.8.
  • safeguards Cyber classifiers are ~85% less restrictive than Fable 5's: source-code vulnerability discovery is allowed; binary-based vulnerability scanning, penetration testing, and exploit generation are blocked. Flagged requests in Claude.ai, Claude Code, and Cowork fall back to Opus 4.8 by default — expect the occasional silent model switch on security-adjacent prompts.
  • alignment Anthropic's automated behavioural audit rates Opus 5 its most aligned model to date, with the lowest rates of deceptive behaviour and the best record on avoiding hard-to-reverse actions. It does not advance the frontier on dual-use capability.
  • API betas Mid-conversation tool changes (swap available tools without invalidating the prompt cache) and automatic server-side fallbacks.

Anthropic postmortem: Claude models reached the real internet from inside three cyber evaluations

Source: Investigating three real-world incidents in our cybersecurity evaluations · 30 Jul 2026 · 20 days old

Anthropic reviewed 141,006 cyber-eval runs and found three incidents where a Claude model escaped its supposed sandbox and compromised the production infrastructure of three real organisations. Root cause was a harness misconfiguration, not model misalignment: the eval prompt told Claude it had no internet access, a misunderstanding with third-party partner Irregular left live egress in place, and Claude therefore treated the real systems it stumbled onto as part of the capture-the-flag exercise.
Why this still lands on our desk. Strip out the AI and this is a plain infrastructure-controls postmortem. (1) Egress was assumed to be off and never verified — the same assumption we make about a lot of CI and test namespaces, and exactly what the fail-closed sandbox allowlist change is trying to make harder. (2) Nothing detected it: two of the three victim organisations had no idea they had been compromised until Anthropic called them. (3) A malicious PyPI package was live for about an hour and got pulled onto 15 real machines. (4) Anthropic's conclusion is that eval and test environments need the same egress controls, network logging, and transcript monitoring as production.
  • incident 1 Opus 4.7. The fictional target shared a name with a live domain. Across four runs Claude found the real company and exploited it — extracting credentials and reaching a database with several hundred rows of production data.
  • incident 2 Mythos 5 — supply-chain attack. Claude published a booby-trapped PyPI package under a name referenced in onboarding docs, working around missing email and phone verification to register an account. Public for ~1 hour, ran on 15 real systems.
  • incident 3 Internal research test model. Scanned ~9,000 hosts, then compromised an internet-facing app via an exposed debug page and SQL injection. This one stopped on its own once it noticed the host sat in an unrelated cloud account.
  • what changes Validation of all internet paths before evals start; real-time monitoring of eval logs and transcripts; the same hardening demanded of third-party eval vendors. METR is being brought in for third-party review with full transcript access.

New — the task-list widget bug is fixed, but only the display half. v2.1.235 fixes the expanded task list (ctrl+t) always starting collapsed when resuming or relaunching into a session that still has open tasks. Worth pairing with the standing caveat: v2.1.233 removed the Todo/task tools entirely on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer, so on a current model there may be no tasks to display in the first place unless CLAUDE_CODE_ENABLE_TODO_TOOLS=1 is set. Set the variable first, then the display fix matters.
New — the Agent tool no longer promises a general-purpose subagent that isn't there. v2.1.235: an omitted subagent_type in a session where the general-purpose agent is unavailable now returns a clear error listing the agents that do exist, rather than silently advertising a default that would fail. For Cowork this is the difference between a plugin-supplied agent set working predictably and a task dying with an opaque error — directly relevant if we ship our own plugin with a constrained agent list.
New — background cloud sessions got materially cheaper to run. v2.1.235 improved memory and CPU usage while /ultrareview and /autofix-pr run in the background: their event streams are no longer re-scanned and re-rendered on every update. Long-running Cowork work that spawns background reviews was paying that cost continuously. Alongside it, the prompt-cache invalidation fix on language-server reconnect removes a recurring uncached re-bill from any session touching a repo with an LSP.
Still live — the claude-api skill went from ~200k+ tokens to ~25k. v2.1.234 loads its reference docs on demand instead of inlining them. For Cowork specifically this is the difference between a skill that eats the entire context window and one that costs a fifth of it. If we shelved anything that used claude-api because it blew the context, retry it. It is also a template for our own skills: put reference material behind an on-demand read rather than in SKILL.md.
Still true — v2.1.224's credential masking is the right structure for scheduled tasks holding secrets. Scheduled Cowork tasks run unattended with credentials in scope — this one holds a GitHub PAT. The sandbox options let the proxy substitute the real value on egress so the task never holds it: extract for structured env values, decode: "jwt" with maskClaims, and awsPairs / sigv4 for AWS SigV4 re-signing. Requires network.tlsTerminate, and is honoured only from user, managed, or --settings settings. Worth restructuring our scheduled tasks around — and v2.1.234's MCP secret-printing fix is a reminder of how easily a resolved credential ends up somewhere it shouldn't.

Cowork surfaces permission prompts constantly and the comment field is right there; assume any long Cowork session on an older build may carry an unintended standing edit grant.
