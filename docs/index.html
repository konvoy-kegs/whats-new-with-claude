v2.1.246 — a gateway credential leak, two Bash permission-matching fixes, and a worktree data-loss bug today's headline

61 entries · published Wed 26 Aug 05:17 local · source: CHANGELOG.md

Credentials — telemetry to Anthropic was carrying the API key configured for a third-party gateway. “Fixed telemetry and metrics requests to Anthropic carrying the API key configured for a third-party gateway (ANTHROPIC_BASE_URL); a credential is now only sent to its own host.” This is a credential-disclosure bug and it is the most important line in the release. If we point Claude Code at a gateway or proxy via ANTHROPIC_BASE_URL, the key minted for that host was being attached to telemetry and metrics requests going to Anthropic's host. The fix scopes credentials to their own origin. Action: upgrade, then treat any gateway key used with an affected version as exposed and rotate it. Pairs with v2.1.243's related fix for ANTHROPIC_AUTH_TOKEN telemetry attribution — this area has now been corrected twice in four days, which is itself worth noting.
Permissions — Bash allow rules with a wildcard before the subcommand match more than you think. “Added a startup warning for Bash allow rules with a wildcard before the subcommand (e.g. Bash(git * main)), since they also match options inserted before the subcommand.” A rule like Bash(git * main) was intended to allow a subcommand against main; in practice the wildcard also swallows options placed before the subcommand — things like git -c core.pager=... or git --exec-path=..., which change what git actually does. This is a warning rather than a behaviour change, so upgrading tells you where the problem is but does not fix it for you. Action: upgrade, read the startup warnings, and rewrite any flagged rule to put the wildcard after the subcommand.
Permissions — malformed commands with a dangling && or || now always require approval. “Fixed Bash permission checks to always require approval for malformed commands with a dangling && or || operator.” A command the parser cannot fully decompose is a command whose permission decision cannot be trusted; previously such input could take a path that did not require approval. Fail-closed is the right default here, and this closes a parser-edge-case gap in the permission gate. Second permission-matching fix in the same release, alongside v2.1.243's hook if-condition bug — the Bash rule matcher has had three corrections in a week.
Data loss — the background retention sweep was deleting git worktrees you created yourself. “Fixed the background retention sweep removing git worktrees under .claude/worktrees/ that you created yourself when an old background-session record pointed at them.” A stale background-session record pointing at a path was enough for the cleaner to remove a worktree it did not create. If anyone has lost uncommitted work under .claude/worktrees/ and could not explain it, this is the explanation. Upgrade, and treat that directory as unsafe for anything not pushed until everyone has.
Sandbox — the command sandbox's filesystem configuration was ignoring --setting-sources. The last line of the changelog and easy to miss: the sandbox filesystem config did not respect --setting-sources. Where we use --setting-sources to control which settings files are authoritative — CI, managed environments, anything that deliberately excludes user or project settings — the sandbox's filesystem rules were not being derived from the same set. Related: the Notification hook was not firing while the sandbox's “Network request outside of sandbox” permission prompt was waiting, so an unattended run could sit at a prompt with no notification sent.
New — an Auto mode tab in /permissions for viewing and editing the auto mode classifier rules. Auto mode decides for itself which tool calls are safe to run without asking; until now the rules driving that decision were not directly inspectable. A permissions surface you cannot read is a permissions surface you cannot review — this makes auto mode's behaviour auditable and adjustable in the same place as everything else. Worth a look before widening auto mode use.

v2.1.245 — one line, and it is a startup crash hotfix

1 entry · published Tue 25 Aug 14:45 local

“Fixed a crash on startup on Linux distributions that ship glibc 2.44 (for example Arch Linux, CachyOS and Fedora Rawhide).” A single-entry release published four hours after v2.1.243 got its dist-tag, which is the shape of a hotfix for something that broke on contact with a rolling-release base. Not a concern for Ubuntu/Debian/Amazon Linux hosts, but worth knowing if any developer image or CI runner is built on a rolling distribution.

Still worth actioning from earlier this week carry forward

v2.1.243 — modelPricing makes cost figures reflect our contracted rates. A managed setting so an organization's contracted per-model rates and discount multiplier are used for /cost, the status line and telemetry instead of list price. On negotiated pricing, every cost number Claude Code has reported has been systematically high by our discount. Configure centrally, once.
v2.1.243 — hook if conditions fired on the wrong commands when command substitution was involved. Bash(cat *)-style conditions matched unrelated commands containing $() or backticks followed by more arguments. A matching bug in a gating mechanism. Read alongside today's two Bash permission fixes — if we gate on Bash command shapes anywhere, the whole rule set deserves one careful pass this week rather than three separate ones.
v2.1.243 — a 4.5× smaller Linux binary and 40–70 MB less memory per session. zstd compression takes the Linux x64 binary from about 340 MB to about 75 MB, and code is now loaded on demand rather than kept resident. Changes the economics of baking Claude Code into container images and CI runners.
v2.1.239 — Bedrock behind a header-stripping proxy was being billed twice per turn, silently. The proxy strips the response Content-Type, Claude Code concludes streaming is unsupported and re-runs the turn non-streaming. Both calls bill, with no error surfaced. Any Bedrock traffic traversing a proxy we control is a candidate — upgrade, then reconcile Bedrock spend against turn counts for the affected window.
v2.1.243 — cross-session messaging was silently off in rootless containers and user namespaces since the v2.1.232 socket-directory hardening. If anyone tried multi-session orchestration in a rootless container recently and concluded it did not work, it did not — and now does.

Security & evals

four new items today

This week's actionable items

1. New — rotate any LLM gateway API key. v2.1.246. “Fixed telemetry and metrics requests to Anthropic carrying the API key configured for a third-party gateway (ANTHROPIC_BASE_URL); a credential is now only sent to its own host.” A credential minted for our gateway was being transmitted to a host that is not our gateway. That is a disclosure regardless of how trustworthy the receiving host is, and the correct response to a disclosed credential is rotation, not just an upgrade. Action: upgrade, then rotate every key configured via ANTHROPIC_BASE_URL that was in use before v2.1.246. Note this is the second credential-scoping fix in four days — v2.1.243 addressed ANTHROPIC_AUTH_TOKEN telemetry attribution — so it is worth checking the whole gateway configuration rather than just this one path.
2. New — audit Bash allow rules with a wildcard before the subcommand. v2.1.246. A rule such as Bash(git * main) also matches options inserted before the subcommand, which is a materially wider grant than the author intended — git -c ... and git --exec-path=... change what the command does. v2.1.246 adds a startup warning but does not narrow the rules for you. Action: upgrade, collect the warnings, rewrite the flagged rules. Do this in the same pass as item 3 and v2.1.243's hook if-condition fix — all three are Bash-pattern matching defects in gating mechanisms, and the rule set should be reviewed once, properly.
3. New — malformed Bash commands now fail closed. v2.1.246. “Fixed Bash permission checks to always require approval for malformed commands with a dangling && or || operator.” A command the permission parser cannot decompose previously did not necessarily require approval. Fail-closed on unparseable input is the correct behaviour and this is a genuine gap being closed, not a cosmetic change.
4. New — sandbox filesystem config was ignoring --setting-sources. v2.1.246. Where we use --setting-sources to make a specific settings set authoritative — typically CI and managed environments that deliberately exclude user or project settings — the command sandbox's filesystem rules were not derived from that same set. Anywhere the flag is load-bearing, the sandbox was not honouring it. Related in the same release: the Notification hook now fires while the sandbox network-approval prompt is waiting, so an unattended run no longer stalls at a prompt in silence.
5. New — data loss under .claude/worktrees/. v2.1.246. The background retention sweep removed git worktrees created by the user, not by Claude Code, when a stale background-session record pointed at them. Not a confidentiality issue but an integrity and availability one. If anyone has unexplained missing work in that directory, this is why.
6. Carried forward — hook if conditions matched the wrong commands. v2.1.243. Conditions like Bash(cat *) fired on unrelated Bash commands containing $() or backtick substitution followed by more arguments. By symmetry, the intended pattern may also have failed to match where we assumed it did — so both false positives and false negatives are in scope for the audit.
7. Carried forward — cost integrity on Bedrock behind a proxy. v2.1.239, plus modelPricing in v2.1.243. Streaming behind a proxy that strips the response Content-Type caused every turn to be re-run non-streaming, doubling billed API calls with no error surfaced. Upgrade, then reconcile Bedrock spend against turn counts for the affected window.
8. Worsening — the stable dist-tag is now fourteen releases behind and has not moved in a week. It sits at v2.1.231 (13 Aug) while latest is v2.1.246. Anything pinned to stable lacks: today's gateway credential fix, both Bash permission fixes, the sandbox --setting-sources fix, the worktree data-loss fix, v2.1.243's hook-matching fix and modelPricing, v2.1.239's Bedrock double-billing fix, v2.1.236's sandbox read-deny precedence fix, and v2.1.234/235's credential-disclosure and permission-grant fixes. Pinning to stable is now a materially worse security posture than tracking latest, which is the opposite of the intent.
9. Carried forward — MCP headersHelper under claude -p. v2.1.238. A headersHelper is a command specified by the repository that Claude Code executes to mint auth headers. Until v2.1.238 a project-scoped one inherited whatever credentials were in the environment and could run without an explicit trust gate. Relevant to any unattended run over a repository we do not fully control.

Sandboxing and isolation notes

  • sec Sandbox filesystem config vs --setting-sources (v2.1.246): the sandbox was not deriving its filesystem rules from the settings sources the flag made authoritative.
  • sec Notification hook during sandbox network prompts (v2.1.246): the hook did not fire while the “Network request outside of sandbox” prompt was waiting — an unattended run stalled with nothing notified.
  • sec Sandbox network-violation reporting (v2.1.243): violation details were dropped when the blocked command still exited 0 (curl printing the proxy's 403 page). Enforcement worked; visibility did not.
  • sec Sandboxed Bash prompt no longer lists allowed network hosts (v2.1.243): Claude now attempts requests and surfaces an approval prompt rather than assuming an unlisted host is blocked. A deliberate shift from implicit-deny-by-omission toward an explicit approval path.
  • sec Rootless containers and user namespaces (v2.1.243): the v2.1.232 socket-directory hardening silently disabled cross-session messaging in exactly those environments. A hardening change with an unintended availability cost, now corrected.
  • sec macOS computer use (v2.1.243): clicking the desktop, Dock or a Finder window now requires granting Finder through the access dialog, like any other app. A tightening.
  • sec macOS sandbox read-deny precedence (v2.1.236): wildcard deny rules such as **/.env now take precedence inside allowed read regions, cover matched directories' contents, and cannot be bypassed by renaming the denied file. All three clauses describe prior gaps.
  • feat Enterprise skill and plugin security scanning (6 Aug) automatically checks third-party skills and plugins for malicious content on upload or edit. Worth enabling before we widen who can publish to an internal marketplace.

Claude Cowork

Generally available · cloud sessions in beta

What's new

Sources: Release notes — 25 Aug entry, Use Claude Cowork on web, desktop, and mobile, Get started with Claude Cowork, Use Claude Cowork safely.

New — memory now works across chat and Cowork in the cloud (25 Aug). Previously memory was a chat-side concept; it now spans both surfaces for cloud sessions. The governance-relevant detail: memory is off by default for Team and Enterprise organizations and on by default for Free, Pro and Max. Cowork sessions touch files, connectors and internal systems, so a memory store spanning them is a different proposition to one spanning chat alone — worth an explicit decision and a note in whatever we tell people about acceptable use, rather than leaving it to individual toggles. Everything retained is inspectable and deletable under Settings > Memory > Topics.
The operational rule that keeps catching people: scheduled tasks run with no device online. They execute on Anthropic's servers rather than a laptop, so they no longer need the machine awake or the app open. The corollary is the trap: a scheduled task cannot reach local files unless the desktop app happens to be open on that machine. Anything that must touch local state needs to be designed around that, not assumed.
New — two v2.1.246 fixes land squarely on unattended runs. (1) Non-interactive sessions now automatically continue a response cut off mid-stream by a server error, connection loss or stall, instead of ending with an error — a scheduled task that died to a transient network blip now recovers itself. (2) MCP tool calls interrupted in headless/remote sessions were reported to the model as “completed with no output” rather than as an interruption, so the run continued believing a step had succeeded emptily. Both are exactly the failure shapes that make a scheduled task quietly produce a worse result rather than fail loudly.
New — the Notification hook now fires while a sandbox network-approval prompt is waiting (v2.1.246). An unattended Cowork run that hit an unapproved host previously sat at a prompt with nothing notified. If we rely on Notification hooks to know a scheduled run needs attention, this was a blind spot.
Carried forward — per-loop token accounting (v2.1.243). The Loops breakdown in /usage gives per-loop run count, total tokens, tokens per run and last run. Unattended recurring work is exactly where token spend goes unnoticed, so per-loop attribution is the missing piece for anyone running scheduled tasks. Pairs with v2.1.246's cap of three /goal check-ins per idle period.
Carried forward — the v2.1.238 headersHelper change is worth re-reading in this context. A scheduled Cowork task runs unattended, non-interactively, in a working directory it did not choose, with credentials in scope. That is precisely the shape the fix addresses. Anyone running scheduled tasks over repositories we do not fully control should read it as applying to them.
Standing context — plugin and skill governance for Team and Enterprise. (1) Org-wide skill management — a skill uploaded through organization settings appears for everyone under Customize > Skills. (2) Admins can create private plugin marketplaces, including from a GitHub repository. (3) Enterprise skill and plugin security scanning checks third-party skills and plugins for malicious content on upload or edit. (4) v2.1.246 makes plugin OpenTelemetry usable for governance: enabled_via is now admin-install for admin-installed plugins, so “what did we push versus what did people add themselves” is answerable from telemetry.
