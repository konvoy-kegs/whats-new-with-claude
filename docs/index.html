v2.1.292 — security sweep, plugin install shortcut, MCP protocol bump newest · aligned

permissions PreToolUse hook approvals and auto mode could bypass the permission prompt for file reads from network (UNC) paths — fixed. Also fixed: sandboxed commands could read staged /ultrareview uploads under ~/.claude/seed-admin; a managed sandbox read-deny path that appears or re-points mid-session wasn't dropping project grants inside it or ending credential injection from files it covers; a notebook or PDF read on macOS/Windows could return a file outside what was approved via a link swapped mid-read; rm -rf on the 8.3 short name (or another alternate Windows spelling) of the home folder or a drive wasn't treated as removing it.
managed policy A tampered on-disk cache of server-managed settings could switch off or unseat the built-in policy plugin while the settings fetch failed — fixed. claude plugin marketplace add/install no longer run before an organization's managed settings have loaded on first run. A user-installed mod that returns a $ name clashing with an org plugin is now the one unloaded, not the org plugin. Subagents with permissionMode: auto no longer enter auto mode when it's disabled by settings or the circuit breaker.
workflow claude plugin install --marketplace <source> adds the marketplace (under the same policy checks as marketplace add) and installs in one step. The Agent tool takes an effort parameter so sub-agents run at the level you ask for. CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS sets a longer base backoff for 529s. NO_PROXY is now honoured for Claude Code's own API requests when HTTPS_PROXY is set. Agent names capped at 256 chars.
MCP & plugins Local (stdio) MCP servers negotiate protocol version 2026-07-28 by default on every install, including Bedrock, Vertex and Foundry; MCP_PROTOCOL_NEGOTIATION=legacy opts out. Servers that ignore the newer check are remembered for 7 days and connected the older way without the wait. An MCP tool with a name over 128 chars no longer fails every request. claude -p/SDK first turn no longer waits on HTTP/SSE servers' resources/list. Mods gain prompt.autocomplete, prompt caching in $.model.complete, and workflow agents in agent.spawn; claude plugin test now fails on a failed expect inside a registered hook.
reliability One-shot claude -p and Agent SDK runs no longer stop a background command 5 s after the final result or drop a scheduled wakeup. Plan mode is restored on --resume//resume. Saved scheduled tasks created after /resume, /branch or /clear now fire; /loop survives a process restart. Grep/Glob retry once on unreadable paths instead of reporting no matches. @-mentioned files over 256 KB are reported by size rather than silently dropped. Hook output <system-reminder> tags are escaped before reaching Claude.
cloud · Claude Tag · Code Review Scheduled and Run-now routine runs publish a private artifact without an approval prompt (connector/access requests still ask). Routine runs no longer sit "running" for hours after finishing; "Always allow" is no longer offered for connector tools an org set to require approval. Claude Tag: Enterprise admins get an Edit button on a channel's Allowed domains card; !status says when Claude stopped reading untagged messages and why. Code Review: PRs-reviewed chart gains period totals and a per-repo breakdown; reviews use the base branch's CLAUDE.md when the PR edits it.

v2.1.291 — two regression fixes Mon 6 Oct UTC

regressions Cloud sessions could drop answers to permission prompts (introduced in 2.1.290); the last messages of a session could be lost when quitting (introduced in 2.1.288). Nothing else in this release.

v2.1.290 — permission & policy hardening Mon 5 Oct UTC

permissions Bash checks no longer auto-approve "read-only" commands (rg, git grep) whose args the shell expands as wildcards, or commands whose variable names zsh reads differently from bash; permission rules apply after a PreToolUse hook rewrites a tool's input; background workers no longer honour --allow-dangerously-skip-permissions without the disclaimer; symlinked CLAUDE.md/AGENTS.md respect blockReadsOutsideWorkingDirectories. pyright and more ps forms now prompt.
workflow claude attach <name> / claude logs <name> accept part of a session name; /claude-api managed-agents-onboard scaffolds Managed Agents; new /status/doctor warnings when managed settings ignore user sandbox paths or a managed settings file is a symlink outside the managed folder; interactive WebSearch budget refills at 100 calls/hour instead of ending at 200; Claude in Chrome can no longer be enabled by a project's settings files.

v2.1.289 — deny/ask rules hold in more places Sat 3 Oct UTC

Bash deny/ask rules no longer slip under sandbox auto-allow with env-var prefixes (e.g. TZ="$HOME" rm -rf build); Read deny rules apply through IDE symlinks; user plugins can't rewrite org-managed MCP sign-in tool descriptions; agent.spawn for teammates in plugin hooks; VS Code claude auth status sign-out regression reverted.

Security & evals

fourth consecutive permission-hardening release

Today's actionable items

  • Windows fleet Move to 2.1.292: closes PreToolUse/auto-mode approvals bypassing the prompt for UNC-path file reads, and rm -rf on the 8.3 short name of the home folder or a drive not being treated as destructive.
  • managed settings A tampered local cache of server-managed settings could unseat the built-in policy plugin while the settings fetch failed. Upgrade managed machines; 2.1.292 also makes claude plugin commands wait for managed settings on first run.
  • sandbox Managed read-deny paths that appear mid-session now drop project grants and stop credential injection from covered files; sandboxed commands can no longer read staged /ultrareview uploads.
  • MCP protocol stdio MCP servers now negotiate 2026-07-28 by default (incl. Bedrock/Vertex/Foundry). Smoke-test internal stdio servers after upgrading; MCP_PROTOCOL_NEGOTIATION=legacy is the escape hatch.
  • Desktop admin · deadline today inferenceGatewayAuthScheme: "sso" stops being accepted on 7 Oct 2026 in Desktop releases before v2.26454.0. If you use it, upgrade to v2.26454.0 (which keeps reading it as inferenceCredentialKind: "interactive") or set inferenceCredentialKind explicitly.
  • Microsoft 365 connector Teams chat search now needs ChannelMessage.Read.All; grant Entra admin consent, add it to the connector's Access scope, and have users reconnect.
  • Cowork computer use Desktop v2.26454.0: computer use on macOS no longer edits or saves hidden files/folders in home (~/.aws, ~/.vimrc).

Patterns worth tracking

Permission edges keep closing. 2.1.288, 2.1.289, 2.1.290 and now 2.1.292 each fix cases where deny/ask rules or approval gates were skipped. Treat older clients as having weaker guardrails and keep the fleet current; stable is now seven releases behind latest.
Regression cadence. 2.1.291 shipped within hours of 2.1.290 to fix cloud sessions dropping permission answers. If you pin, pin 2.1.292, not 2.1.290.
Org-vs-user precedence for mods. 2.1.289, 2.1.290 and 2.1.292 all tighten how user-installed mods interact with organization plugins and guards.

Claude Desktop

v2.26454.0 · 6 Oct · bundles Claude Code 2.1.289

What's new

v2.26454.0 (6 Oct) — stability release. A reply or tool step that fails to draw no longer takes the whole chat down. Attachments load again on Ubuntu 22.04/Debian 12. Installed plugins no longer vanish after an upload; the app no longer crashes at launch with very many Cowork tasks, or closes when a crashed built-in-browser tab is resized. Code: Quit now respects the "Claude is still working" prompt; SSH sessions resume after Claude Code restarts on the remote host; a new session no longer silently switches to Local when the picked Remote Control computer or cloud environment goes away; typed messages and attachments survive a failed send.
v2.26454.0 — 3P / admin. New claudeAiImport.allowedOrganizationUuids restricts chat-history import to listed Claude.ai orgs (file import off). microsoftAuthDefaultAccount signs the Microsoft 365 connector in with the Windows work account, no picker; a "Use a different account" button shows the signed-in account. Connector sign-ins are now per-person on shared computer logins. New OTLP events: SSH host not running the configured sandbox, and desktop_claude_ai_import. Skills with a description over 1,024 chars are refused instead of wiping every local skill.
Earlier this week. v2.19675.1 (5 Oct): read-only Chat access to project folders, .zip/.skill uploads keep all files. v2.19675.0 (1 Oct): line comments in the Files pane, Retry on failed sends, computer use requires macOS 14+.

Claude Cowork

GA · macOS & Windows · Linux beta · web & mobile · cloud by default on Pro/Max

What's new

Desktop v2.26454.0 (6 Oct) — Cowork fixes. Computer use on macOS no longer edits or saves hidden files and folders in your home folder (~/.vimrc, ~/.aws). A scheduled task moved to the cloud no longer reappears as a separate paused local task that could run twice. Claude can use document menu commands (New Slide, Undo in Keynote) and click-drag on canvases while the app is in the background. Tasks start in a second copy of the app on the same Windows account; no more freeze when a second message hits a task that's still starting.
Cloud by default since yesterday (6 Oct) on Pro and Max. New tasks run in the cloud on every surface; "Only on your computer" was removed from Settings > General; tasks started locally before 6 Oct stay there until finished. See Use Claude Cowork on web, desktop, and mobile.
Cloud sessions (Claude Code 2.1.292). Scheduled and Run-now routines publish a private artifact without an approval prompt; routine runs no longer stay listed as running for hours; SVG/HEIC/TIFF attach as regular files; "Always allow" is no longer offered for connector tools an org requires approval on; sessions no longer blame a proxy for blocked artifacts when org settings couldn't be confirmed; Claude is told which stopped background agents it can resume after a restart.
Plugins. claude plugin install --marketplace <source> (2.1.292) adds and installs in one step under org policy checks. Plugin developer portal for the Claude directory open since 25 Sep.
