v2.1.285 — provider lockdown, Desktop handoff, headless plugins newest · aligned

governance allowedProviders managed setting limits which API providers a machine may use — Anthropic API, custom endpoint, Bedrock, Mantle, Vertex AI, Foundry, Claude Platform on AWS, or a Cloud gateway. Pairs with 283's deniedModels for full model/provider control.
workflow claude --desktop opens the Claude desktop app on the current directory, or on a session with --continue / --resume <id>.
plugins Scriptable plugin setup. claude plugin configure <plugin> shows unset options and accepts values via --values-stdin; claude plugin install --config <server>.<key>=<value> configures bundled .mcpb MCP servers at install time. Useful for fleet bootstrap scripts.
env CLAUDE_CODE_DISABLE_WEB_FETCH turns off the WebFetch tool; CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES caps re-sends of timed-out non-streaming fallbacks.
reliability Fleet-relevant fixes. Plugin/marketplace installs over SSH now honour GIT_SSH / core.sshCommand; Bedrock and Vertex sessions fall back to an older same-tier model when an admin removes the default; setModel mid-session now picks up the new model's token limits.

Security & evals

provider lockdown · policy loading fixes

Today's actionable items

  • policy Sessions authenticating with ANTHROPIC_AUTH_TOKEN against the Anthropic API never loaded the organisation's policy (fixed in 2.1.285). If your fleet uses that auth path, update.
  • providers New allowedProviders managed setting — consider pinning machines to your approved provider(s) (e.g. Bedrock only).
  • managed settings Behaviour change: if the OS denies reading the managed settings file, Claude Code now warns and starts without those policies; other read errors and unparseable files still stop every session. Check file permissions on managed-settings deployments.
  • plugins Installs whose ids differ only in ., -, @ or letter case could land in another plugin's cache/data folder — now refused.
  • credentials /ultrareview uploads could include uncommitted credential files with a colon before the extension (e.g. server:8443.key) — fixed.
  • terminal claude mcp list/get printed terminal escape sequences from MCP server names and values — now sanitised.
  • permissions Fork subagents now inherit plan mode / dontAsk and cannot exit plan mode; auto mode classifier no longer skipped for some Artifact tool reads/uploads.
  • pin stable moved to v2.1.280. Suggested canary: v2.1.285.
  • deadline Enterprise skill/plugin scanning defaults to "Requires review" on Fri 2 Oct if no setting is chosen.

Patterns worth tracking

Fleet governance keeps expanding. 283 (deniedModels, exact matching) → 284 (gateway startup warnings) → 285 (allowedProviders). Model and provider are now both lockable from managed settings.
Fail-closed, sixth build running — with one deliberate exception: an OS-denied managed settings read now fails open with a warning.
