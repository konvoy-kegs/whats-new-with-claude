v2.1.296 — managed-hook enforcement, gateway code policy, subagent controls newest · aligned

hooks & permissions Fixed managed-settings PreToolUse hooks denying with "continue": false, and managed prompt hooks that block, refusing the call but not ending the turn. Fixed managed PostToolUse hooks not applying updatedMCPToolOutput in some sessions. Fixed Bash permission checks auto-approving commands that assign and then use BASH_ARGV0 (now prompt). Fixed Esc during a UserPromptSubmit hook letting the unchecked prompt through. Fixed cloud sessions skipping auto mode's checks on Claude in Chrome actions. Windows: rm -rf /c/Users/<name> in Git Bash now asks even in bypass mode.
secrets & MCP Fixed secret redaction in shared transcripts and debug logs missing some values (including JSON inside a shell string). Fixed headless sessions starting a folder's .mcp.json or plugin MCP server that was switched off for that folder, after changing directory or reloading plugins. Fixed hook output being altered when it contained text resembling a plugin hint tag. Fixed a plugin secret named constructor/prototype being deleted on save.
Claude apps gateway & Desktop Added a code key to managed.policies[]: the same settings as cli, also applied in Claude Desktop's Code tab; beside desktop, it turns on Desktop's gateway mode. Code tab now shows the reason as a reply when a gateway session can't start. Fixed a gateway serving allowedProviders with "gateway" locking out laptops that name it in user settings, and a saved gateway sign-in being ignored under forceLoginMethod: gateway with no URL (regression in 2.1.295).
new settings autoCompactWindow in subagent frontmatter and --agents, so a subagent compacts earlier than the main conversation. CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL pins every workflow agent to one model. CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS caps 529 backoff. Read tool allow_large option for whole large files. MCP tool descriptions and server instructions sent up front now capped at 4,096 chars (was 2,048). /cost and --max-budget-usd now price Sonnet 5.5 cache reads at $0.10/Mtok (was $0.20).
Windows, runners & reliability PowerShell commands up to 32 KB now honour allow rules and read-only detection (was ~1 KB). Stdio MCP servers get a graceful stdin close before kill at shutdown. claude plugin install retries GitHub sources over HTTPS when there's no SSH key. Edit/NotebookEdit now refuse non-UTF-8 files rather than mangling non-ASCII characters. Self-hosted runners: clearer registration errors, git fetch/push fix with --capacity above 1, per-session queue positions. VS Code: Claude in Chrome now asks before browser actions in every session. Claude Tag: admins can manage workspace/channel memory files.

v2.1.295 — fail-closed hooks, gateway controls, MCP reliability Thu 8 Oct UTC · bundled in Desktop

hooks & guards Added onFailure: "block" for command and HTTP hooks (fail closed instead of open). Fixed a Claude in Chrome site deny rule written with port 80 not applying to plain http:// pages. Fixed Bash permission checks for for-loops over glob patterns. Gateway: per-upstream models lists, timeouts.upstream_ttfb_ms for Bedrock/Vertex/Foundry, upstream_request_id in audit events, background requests routed to Haiku 4.5. On Amazon Bedrock, token counts use AWS CountTokens — grant bedrock:CountTokens. Fixed every request failing on a [1m] model when a gateway or cloud provider refuses the context-1m beta (now resent without it). claude.ai connectors negotiate MCP protocol 2026-07-28 by default. Program Status Protocol (OSC 7501) lets supporting terminals show whether Claude is working, waiting or done.

v2.1.294 — hook judgement fixes Thu 8 Oct UTC

hooks Fixed prompt and agent hooks written as instructions (such as "Block commands that...") allowing what they should block. Improved judging of instruction-style Stop/SubagentStop prompt hooks so Claude is less likely to stop early.

v2.1.293 — Claude Haiku 5.5 Wed 7 Oct UTC

model Added Claude Haiku 5.5 (claude-haiku-5-5), now the default Haiku on the Anthropic API — 1M context, $0.10/$0.50 per Mtok ($0.50/$2.50 over 100K). agentType added to the subagentStatusLine payload. Fixed sandboxed /ultrareview uploads wrongly refusing nested checkouts. claude.ai skill syncing now checks every ~40 minutes while idle (was 10).

Security & evals

Desktop v2.37337.1 · breaking managed-config changes

Today's actionable items

  • Desktop managed config (breaking) v2.37337.1 removes the former key names isDxtEnabled, isDxtSignatureRequired, isDxtDirectoryEnabled, enduserAttribution, trustBootstrapLocalExec and inferenceGatewayHeaders. A profile still using one now treats it as an unrecognized key: unsigned extensions load and the extension directory shows; end-user attribution turns on; a managed bootstrapUrl is trusted without asking; custom inference headers stop being sent. A macOS profile or Windows user policy holding only old names is no longer read as managed config at all (device becomes unmanaged); a Windows machine policy or Linux settings file holding only old names is a configuration error. Migrate to isDesktopExtensionEnabled, isDesktopExtensionSignatureRequired, isDesktopExtensionDirectoryEnabled, endUserAttribution, trustBootstrapDelivery, inferenceCustomHeaders.
  • Windows signing cert The certificate signing the Windows app and installer was renewed (same publisher). Publisher-based allow rules are unaffected; rules that pin the certificate itself need the new one added beside the old.
  • OAuth MCP connectors After updating, OAuth-protected MCP connectors ask you to sign in again once, and again whenever a connector's URL changes. Expect a wave of re-auth prompts across the team today.
  • egress allowlist Your inference provider's, gateway's and OTLP collector's hosts and api.anthropic.com are no longer auto-added to coworkEgressAllowedHosts. List them explicitly if agent shell commands, web fetches or HTTP hooks call them.
  • Windows SSH SSH sessions on Windows now run only an ssh.exe found on PATH; a .bat/.cmd/.ps1 wrapper named ssh is no longer executed. New developerModeEnabled key lets admins turn off Developer Mode and block installing extensions from a folder.
  • Desktop Code tab v2.37337.1 still bundles 2.1.295, not 2.1.296 — the Code tab lacks the managed-hook enforcement fix. Run /status in a Code-tab session to see which CLI it's on; terminal claude and the Code tab update independently. Same build fixes the "Strict sandbox mode" switch and /status Sandbox row showing strict mode off when your org already enforces it.
  • fleet CLI target remains 2.1.296. It carries the 2.1.292–2.1.295 hardening plus the managed-hook, BASH_ARGV0 and Windows bypass-mode fixes. If you deny tools via managed PreToolUse hooks with "continue": false, or rewrite MCP output with updatedMCPToolOutput, retest on 2.1.296.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

Desktop is now where the breaking changes land. The CLI has been quiet for five days; v2.37337.1 is the first Desktop build to hard-remove deprecated managed-config names (the 7 Oct cutoff for older spellings is also now enforced as plain invalid values). If you manage Desktop via MDM or registry policy, diff your profile against the v1.40609.0 replacements list before this build reaches the fleet.
Five releases of guardrail hardening, now paused. 2.1.292 through 2.1.296 all closed gaps where hooks, auto mode, tool lists or Bash parsing could be bypassed. Treat hooks as part of your security boundary and test them on each upgrade.
Desktop bundles trail the CLI by a release or two. Desktop v2.26454.x shipped 2.1.289 then 2.1.293; v2.31226.0 shipped 2.1.293; v2.31226.1 and v2.37337.1 ship 2.1.295. Expect 2.1.296 on the next Desktop bump.
stable still lags. v2.1.287, nine releases behind latest, missing all five hardening releases. Pin to latest-track versions on managed machines.

Claude Cowork

GA · macOS, Windows & Linux · web & mobile · cloud by default on Pro/Max

What's new

scheduled tasks · Desktop v2.37337.1 (13 Oct) Two more scheduled-task fixes. Scheduled tasks on your computer that couldn't be edited after their first run ("Failed to update scheduled task") now can be. Scheduled tasks that never started on a computer where Claude's workspace fails to start now start without the workspace after about ten minutes — commands that need the workspace fail in those runs rather than the whole task silently not running. Relevant to anyone running digests like this one.
artifacts & reliability · v2.37337.1 Charts, tables and diagrams in artifacts no longer stay blank offline or when the network blocks their CDN — Chart.js, Grid.js and Mermaid now ship with the app. Fixed Cowork tasks on a computer whose admin turned off the local VM trying to start locally instead of in the cloud. Fixed messages that couldn't be sent sometimes showing as sent with no error, and the first message of a new task being lost if the app reloaded while the task was starting. Improved the "workspace disk full" prompt so cleanup frees enough space. Fixed Cowork not starting when the org's model list hadn't loaded (it now waits briefly, then starts or explains).
carry-over · v2.31226.0 (8 Oct) Four earlier scheduled-task fixes (prompt overwrite on same-name tasks, folder re-approval stalls, "ask" policy prompts being skipped, failed-to-start notifications). Computer-use fixes on macOS; back-to-back plugin install/marketplace refreshes no longer fail; a skill switched off in Customize is no longer offered or run.
cloud sessions · Claude Code 2.1.296 New status filter on the Sessions and Runners lists in admin settings; each session waiting on a self-hosted runner shows its own queue position; a message sent mid-reply no longer jumps above the reply. Fixed auto mode occasionally refusing an update to your own artifact. Fixed skills synced from claude.ai never finishing install when sessions share a config directory.
carry-over Cloud by default (since 6 Oct) on Pro and Max. New tasks run in the cloud; "Only on your computer" was removed. Local folder access still needs the desktop app open. See Use Claude Cowork on web, desktop, and mobile and Claude Cowork and chat are one Claude.
