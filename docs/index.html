Code tab on a device whose only configuration is a local file: with coworkEgressAllowedHosts unset, shell commands can reach the network (an empty list still blocks). NODE_EXTRA_CA_CERTS and other env entries in managed-settings.json now take effect in Chat and Cowork sessions — review that file before the rollout rather than after. v2.1.317 — email-exfiltration check, fail-closed SDK hooks, gateway cost report and OTel plan attributes, AWS/TLS/proxy fixes, the Desktop MCP-disconnect fix Tue 03 Nov AEDT · 87 bullets · latest · bundled in Desktop v4.16336.0

data handling & permission modes Added a check that asks before a web or shell tool call sends your account email address to the network. The first explicit exfiltration guard on a specific identifier: a tool call whose URL, header or payload contains the signed-in account's email now stops for approval instead of going out. Expect it to fire on legitimate things (a curl to an API that wants a contact address, a git config step) — that is the point, and worth a line to the team. Added a warning to /schedule when a new cloud scheduled task gets connectors you did not ask for, with how to remove them — a cloud task inheriting the account's full connector set was easy to miss. Added onFailure: "block" for Agent SDK hook callbacks, so a callback that fails blocks the action instead of letting it run: SDK hooks were fail-open until now, which for a policy hook is the wrong default; set it on every hook that exists to deny something. Three permission-mode fixes in the same release: Remote Control and SDK hosts no longer offer "don't ask again" on a mod's tool calls; agent team teammates in tmux or iTerm2 panes no longer start in auto mode when the lead session was in manual mode; and a background session no longer loses a just-made change of permission mode when it is upgraded or retired. Auto mode in cloud sessions also stops stopping for approval when the Artifact tool uploads, writes to a database or saves a file through the outputs folder.
Claude apps gateway · cost report, identity, telemetry Added a cost report to the Claude apps gateway admin API, GET /v1/organizations/analytics/cost, for reading past spend over a date range in total, per developer, per day or per IdP group — the first spend read-out that isn't a per-seat limit, and the natural feed for a Grafana panel. It groups by a new daily record of each developer's IdP groups on gateways with admin: set, kept for admin.identity_retention_days (an identity-retention setting to decide on before turning it on). Added anthropic.plan, anthropic.seat_type, anthropic.provider and anthropic.custom_base_url to OTel metrics, events and spans — usage can now be split by plan and by gateway in the existing exporter without a lookup table. Fixes: auto mode no longer fails every turn when an LLM gateway set as the base URL answers 403 or 422 to its server-side safety check (a 403 with an apiKeyHelper is unchanged); the gateway no longer hides Amazon Bedrock's "Input is too long." error, which left sessions failing every turn with "upstream rejected the request" instead of compacting; the status line and /usage no longer show a developer's own spend limit as 100% used after their group's pooled budget ran out; and the startup error when a required gateway can't be reached now points to the network instead of a sign-in, and says when the gateway's TLS certificate can't be verified. Neither the cost report nor pooled_budget nor oidc.user_id_claim is in the gateway docs yet.
Desktop sessions, MCP, AWS, TLS & proxies Fixed project and local MCP servers disconnecting after the first turn in some Claude desktop sessions — the fix Desktop v4.16336.0 ships by bundling this build, and the likely cause of "the MCP server was there, then wasn't" reports from the Code tab over the past fortnight. Fixed a project's effortLevel setting being ignored by sessions an app starts ahead of time and then opens in the project, such as new Code-tab sessions. Fixed stdio MCP servers receiving an empty AWS_BEARER_TOKEN_BEDROCK when their env config sets it to empty; the variable is now unset, so the server can use the machine's own AWS credentials — relevant to any MCP server that talks to AWS from a runner with an instance role. Fixed API requests failing with "unable to get local issuer certificate" behind some TLS-inspecting proxies after a root certificate renewal (the third corporate-CA fix in a week, after v2.1.314's cross-signed root and v2.1.316's looped cross-certificate handling). Three OpenTelemetry-behind-proxy fixes: exports to an https:// endpoint through a proxy never being sent when they started while another export was in progress; a flood of connection attempts to a proxy that blocks (403) exports to an http:// endpoint; and exports hanging indefinitely behind a proxy that never answers — they now time out after 10 seconds, or OTEL_EXPORTER_OTLP_TIMEOUT up to 30 seconds. A region or network block (HTTP 403) is no longer shown as a sign-in failure. claude auth status no longer exits before a slow token refresh is saved, which could sign you out on the next run.
headless, runners & CI Fixed claude -p exiting 0 when a full disk or quota lost its transcript or ~/.claude.json writes; it now prints an error and, in text and json output, exits 1 (full NFS exports may be missed) — the second exit-code correction in a week after v2.1.314's startup-failure fix; pipelines that were green on a full disk will go red. Added CLAUDE_CODE_DISABLE_NESTED_SESSION_ID: set it to 1 on a self-hosted runner to have claude -p run inside a session use that session's ID and transcript, as in earlier versions — because the default changed: a nested claude -p inside a cloud or runner session no longer shares that session's ID (it wrote into the session's transcript, and a restart could resume the wrong conversation) and no longer generates a title of its own and sends it to the parent. Self-hosted runners and runner sessions now open new connections after a 5xx other than 501 or 529, and after a heartbeat gets no answer, instead of reusing the failed one; runner sessions no longer lose recent turns or the whole conversation when restarted while a plan waited for approval; an MCP server switched off no longer comes back on after a session moves to a new machine; and the interrupted tool call is seen when a session moves to a new runner past CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS. Fixed high memory use and slow startup in headless sessions with many plugins that register commands. Fixed old transcripts not being cleaned up on machines where some runs skip cleanup, such as runs using --setting-sources. Fixed edits to settings files made in the first second or so after launch not taking effect until a settings file changed again. Fixed stored scheduled tasks being impossible to list or delete after scheduled tasks were turned off.
context, compaction, search & subagents Fixed very long conversations losing their earlier summary when compaction had to shorten its own request, and "Prompt is too long" after automatic compaction in sessions whose very large CLAUDE.md changed since it was last sent. Fixed DISABLE_PROMPT_CACHING_OPUS and DISABLE_PROMPT_CACHING_SONNET having no effect on [1m], other-region and undated spellings of the default model. Fixed Claude treating partial Grep and Glob results as complete when a search hit its time limit. Removed the Read tool's "file unchanged since your last Read" stub: reading an unchanged file again returns its content. Fixed a PDF's own metadata being able to make Read and @-mentions under-count its pages. Changed SendMessage so a message to a running background agent arrives earlier: its running command moves to the background, without being stopped. Changed subagents and teammates on a different model from the main conversation to use that model's saved effort level or its default, instead of the session's effort level — pairs with v2.1.316's CLAUDE_CODE_SUBAGENT_EFFORT. Fixed resumed sessions telling Claude again about a file change it already knew about, and Claude sometimes not using a built-in tool in a resumed session after an earlier call failed because the tool was switched off. Fixed deleted agent team inboxes being re-created by a teammate's late message, and a re-created teammate being removed from its team by an earlier shutdown approval. Fixed Ctrl+C stopping all running background agents when pressed to clear typed text at the prompt. Fixed child processes of a stopped shell command sometimes being sent SIGTERM twice.
Windows, VS Code, cloud sessions & Claude Tag [Windows] Fixed every tool call being refused on some volumes where the native path lookup fails; the working-directory check now compares the folder's identity instead. Fixed the session scratchpad and other temporary paths growing with the project's path length in sessions not started by Claude Desktop, which made repositories cloned into them hit the 260-character path limit. [VSCode] Fixed forked conversations dropping messages (only one of Claude's parallel tool calls was kept, and the last messages a compaction kept were lost); fixed a message being lost when Claude did not finish starting in time (the extension now starts Claude once more); the sign-in screen no longer opens when a request is blocked for its region; file links open in another editor group; ultrathink raises effort with telemetry off. [Cloud sessions] Added a link card, so you can open or decline a link an MCP server asks you to visit instead of the request going unseen (the companion to v2.1.316's form card); the Add secret form now refuses a network secret for a host that already has one instead of silently replacing it; new scheduled tasks no longer ignore the organisation's default environment; the organisation environment dialog in admin settings uses the short layout. [Remote Control] Fixed the next message to an idle session going unanswered after restarting claude remote-control within a minute of the previous message. [Claude Tag] Newly pasted artifact links in Slack show a simpler card with an Open button. Also: skills synced from claude.ai no longer lost or re-downloaded every ten minutes when they can't be written to disk; /remote-control now says Remote Control is turned off by disableRemoteControl instead of "Unknown command"; /design-sync says up front when the design system has moved to Claude; the exit hint repeats the flags you launched with ahead of --resume; the built-in plugin-authoring skill offers once to help share a mod.

Today's actionable items

  • upgrade · pin v2.1.317 Move runners, auto-mode pipelines and headless claude -p jobs from the 2.1.316 pin to 2.1.317. It is documented, released on GitHub, on latest, and the build Desktop v4.16336.0 bundles — the first time latest, the Code tab and local Cowork sessions have all run the same code since this page started. It carries the email-exfiltration check, onFailure: "block", the AWS credential fix for stdio MCP servers, the TLS-inspecting-proxy fix and the OTel proxy fixes.   • Desktop · Windows managed-settings.json path (v4.16336.0) The fallback that read Claude Code's managed-settings.json from C:\ProgramData\ClaudeCode is removed. Keep the file in C:\Program Files\ClaudeCode, the only folder Claude Code itself reads. Patterns worth tracking

Desktop caught up in one jump — and stable didn't follow. Six documented CLI releases (v2.1.310 through v2.1.317) arrived in the Code tab at once with v4.16336.0, after five days without a Desktop build. stable moved too, but only to v2.1.311, so yesterday's "stable tracks the Desktop build" reading lasted exactly one day. The better model: stable moves a few versions at a time on its own schedule, Desktop bundles whatever latest was at its build cut, and neither is a reliable floor for the other. Pin latest's documented version and treat the rest as noise.
The week's change-control load is in the Desktop 3P list, not the CLI changelog. Five of the morning's actionable items — the Windows managed-settings path, OpenSSH transport, strict autoMode lists, the AppArmor fallback and local-config egress — come from one Desktop release, and three of them loosen rather than tighten (fallbacks to unsandboxed, to network-reachable, to "ignore the deprecated key"). Read the 3P section of every Desktop changelog with the same care as a CLI security entry; this one would have been missed by a changelog grep for "Fixed".
Data-handling guards are arriving at the client. In one week: a check before a tool call sends the account email to the network (v2.1.317), a warning when a cloud scheduled task inherits connectors (v2.1.317), claude.ai removed from cookie import and the Chrome shortcut tools removed (Desktop), Send to Anthropic removed from the diagnostic report (Desktop), Reset App Data deleting Cowork tasks server-side (Desktop), and a refusal to silently replace a network secret (v2.1.317).
