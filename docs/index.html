What matters this morning. Two releases, 174 bullets, and six things that land on us directly. (1) Opus 4.8 fast mode is deprecated as of 30 October and removed on 30 November — after removal a fast-mode request on Opus 4.8 returns an error and does not fall back to standard Opus 4.8; anything still on it migrates to Opus 5.5. (2) Server-managed settings for Team and Enterprise logins now apply without an approval prompt, and a stored copy that doesn't verify is refused — developers stop seeing the consent dialog, and a tampered local copy of org policy is thrown away rather than used. (3) permissions.blockWritesOutsideWorkingDirectories (v2.1.314) makes Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode, including bypass — the write-side twin of blockReadsOutsideWorkingDirectories, and the obvious managed setting for runners. (4) claude -p now exits 1 and prints the error when startup fails, where it used to exit 0 with no output — CI jobs that have been passing on an empty result will start failing honestly. (5) The gateway grew a layer of finance and policy controls: pooled monthly budgets a group shares on top of per-member caps, layered policy merging, per-upstream IdP group routing, Bedrock guardrail tracing and input tagging, and a 400 for any request that names a model outside availableModels / deniedModels / models (it used to check only the first). (6) Windows: PowerShell hooks that begin with a type cast, param, using or an attribute now block on exit code 2 (they fell open before), and Grep/Glob no longer hang forever when the search process is killed at the timeout but doesn't exit. None of this reaches the Desktop Code tab or local Cowork sessions yet — Desktop is still on 2.1.309. Dates: Plugins page GA 9 Nov, Unified Claude 10 Nov (eight days), and three things on 30 Nov — the Skills-off-blocks-plugins rule, Enterprise Plugins page, and Opus 4.8 fast-mode removal.

v2.1.316 — Opus 4.8 fast-mode deprecation, silent managed settings, gateway pooled budgets and layered policy, subagent effort, a --restricted upload fix Sat 31 Oct AEDT · 55 bullets · newest on npm

models · deprecation with a date Deprecated fast mode for Opus 4.8 as of October 30, 2026; it will be removed on November 30, 2026. After removal, fast mode requests on Opus 4.8 return an error and do not fall back to standard Opus 4.8. Migrate to Opus 5.5 to keep the speedup. This is the first dated removal in the changelog since the Opus 4/4.1 retirement in January, and it is a hard stop rather than a downgrade: a pipeline that still sends fast-mode requests to claude-opus-4-8 on 1 December gets errors, not slow answers. Search settings files, ANTHROPIC_DEFAULT_OPUS_MODEL overrides and gateway models[] maps for Opus 4.8 this week; anything found moves to claude-opus-5-5. Also in this release for models: CLAUDE_CODE_SUBAGENT_EFFORT sets the effort subagents run at when nothing else names one, instead of inheriting the session's (a cheap way to keep xhigh parent sessions from spawning xhigh fan-outs); CLAUDE_CODE_DISABLE_ULTRATHINK turns the keyword off; and sonnet, opus and haiku on Vertex AI and Amazon Bedrock now switch to an older model mid-session instead of erroring when the newest isn't yet available to the account or region.
managed settings · behaviour change Changed server-managed settings for Team and Enterprise logins: settings fetched from Anthropic's API now apply without an approval prompt, and a stored copy that doesn't verify is refused. Two consequences. Developers who sign in with a Team or Enterprise account no longer see the "apply your organisation's settings?" dialog — policy lands silently, which is what an admin wants and what a developer may ask about on Monday. And the on-disk copy of those settings is now integrity-checked: one that fails verification is discarded, not loaded, so editing the local cache is no longer a way to loosen policy (v2.1.314 separately makes Claude's own file tools ask before editing that copy). Pair with v2.1.314's fix for forceRemoteSettingsRefresh, which had stopped applying once the stored copy expired and let sessions start with no policy while the server was unreachable.
Claude apps gateway · budgets, policy, guardrails, model allow-lists Added pooled group budgets: one monthly budget that a group's members share, on top of each member's own limit, set with pooled_budget on the spend limits admin API. Until now every group cap was a per-seat default each member inherited; this is the first shared pool, which is how most teams actually think about a monthly allowance. Added managed.policy_mode: layered: every policy that matches a developer applies, each merged over the ones listed below it, instead of first-match-wins — a base policy plus a contractors overlay plus a team overlay becomes expressible without duplicating blocks. Added guardrail.input_tagging on Bedrock upstreams, which wraps prompts in the input tags an Amazon Bedrock guardrail's prompt-attacks filter needs; all_messages_and_system also tags the system prompt. Fixed the gateway not checking every model a request names against availableModels, deniedModels and models; a request that names a blocked model now gets a 400 naming the field. That one is a permission-bypass fix: a request could name an allowed primary model and a denied model elsewhere (a subagent or fallback field) and only the first was checked. Also: claude auth login now shows the gateway sign-in in a terminal where managed settings require a gateway, instead of refusing to run. None of the three new keys is in the configuration reference yet.
permissions, sandbox & auto mode Fixed --restricted sessions uploading files from outside the working directories when a Read allow rule covered them. A Read allow rule for, say, ~/.aws/** was enough for a restricted session to attach those files to a cloud session or Remote Control upload; it now isn't. Fixed a managed autoMode.allow list without "$defaults" getting the built-in exceptions back from a host app's --settings, a first rule added in /permissions, or /auto-mode-setup — an admin who deliberately dropped the defaults was having them silently restored. The mirror-image change: an autoMode.allow list without "$defaults" no longer removes the built-in rule on scheduled-task prompts, and cloud sessions and cloud scheduled tasks are now marked failed when auto mode stops a turn because the server returned no safety verdict (they used to look like they finished). claude -p text output now says why auto mode stopped a turn even when a background agent was still running, and CLAUDE_CODE_AUTO_MODE_SERVER=1 is honoured in sessions started by a host application such as Claude Desktop behind a proxy or gateway with experimental betas off.
shell, network & TLS Fixed shell commands being left running on macOS and Linux when Claude Code exits by itself, for example when credentials are refused or a cloud session is archived — orphaned npm run dev and friends on runners after a session died. Fixed bash scripts started from the Bash tool stopping after their first command when SHELLOPTS is exported, and bash aliases with line breaks or dash-prefixed function names being garbled in the tool's shell (Windows: aliases and functions lost in Git Bash when the rc file sets errexit/pipefail). Fixed some network requests hanging when a compressed response was cut off or corrupted. Added CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP to keep system cross-certificates that certify each other in a loop, for servers whose private CA needs one — the companion to v2.1.314's fix for UNABLE_TO_GET_ISSUER_CERT on renewed roots cross-signed with their predecessor. SSL certificate errors now name the likely causes (a server that leaves out an intermediate among them) and the fix for each.
Windows, subagents, resume & UI Fixed PowerShell hooks not blocking on exit code 2 when the command begins with a type cast, param, using or an attribute — the second PowerShell/Git Bash hook fail-open fix in three weeks (v2.1.310 covered quoted-string commands when Git Bash is missing). Fixed Grep and Glob never returning when the search process is killed at the timeout but does not exit, seen on Windows. Fixed sub-agents that inherited a parent sub-agent's model moving to the main model when a background job or message woke them. Fixed /model <id> not warning when the model isn't recognised by this version and auto-compact will assume a 200K context window. Fixed plugin MCP headersHelper scripts receiving a corrupted CLAUDE_PLUGIN_ROOT and server URL when a credential-named environment variable was set to a switch value such as 1. Fixed a rare case where resuming a conversation did not restore its plan. Fixed prompts containing invisible characters needing a second Enter to send. Fixed the SDK register_repo_root control request not loading the CLAUDE.md of a directory outside the working directory. Improved /diff on large repositories (one fewer full-repository git command per refresh, spaced out when git is slow).
VS Code, cloud sessions, Claude Tag & Code Review [VSCode] Added sign-in to a Claude apps gateway from the chat panel, with no terminal needed; ultrathink runs its turn at xhigh effort and shows in a rainbow, as in the terminal; the missing Effort slider, Ultracode switch and model name with an opus[1m]-style setting are back. [Cloud sessions] Added a form card, so you can fill in or decline a form an MCP server asks for instead of the request being cancelled without you seeing it; a "Catching up…" line while a cloud or Remote Control session you switch back to is still syncing; Enterprise members can now add and delete network secrets on their own cloud environments instead of only viewing them; the Changes pane's note about what the list leaves out is now a badge beside the branch name. [Claude Tag] A channel's "Respond automatically" switch becomes a "How Claude participates" choice on the channel's Configure page and in admin settings; a cloud scheduled task's live status checklist in Slack no longer stays half-done; untagged replies in Slack Connect threads where both organisations installed Claude are answered; canvases shared to a second channel can be edited again from the channel that made them. [Code Review] A findings-by-severity card on the analytics page — total findings, a daily chart stacked by severity, and each severity's count; /code-review from the Desktop Code tab now shows the findings card in cloud and claude remote-control sessions.

v2.1.314 — blockWritesOutsideWorkingDirectories, gateway upstream groups and guardrail tracing, idle compaction, claude -p exit codes, a long managed-settings and sandbox fix list Fri 30 Oct AEDT · 119 bullets · v2.1.313 skipped

permissions · new setting Added permissions.blockWritesOutsideWorkingDirectories: Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode. The read-side setting has existed since the sandbox work in September; this closes the write side, and "every permission mode" includes bypass and auto mode. It only covers Claude's file tools — a Bash cp is the sandbox's job — but for self-hosted runners and claude -p pipelines it is the setting that stops an agent "helpfully" editing ~/.gitconfig or a sibling checkout. Candidate for the managed settings file this week. Alongside it: Fixed sandbox protections not applying to a worktree entered by claude -p --resume or --continue; Fixed hooks matching Bash not running on shell commands started by the Monitor tool (such hooks can block or ask, but not approve or rewrite those commands; hook if conditions like Monitor(tail *) now match the way Bash(tail *) does); Fixed a settings file excluded with --setting-sources still supplying some settings, such as auto mode rules and saved permission consents; Changed Claude's file tools to ask before editing the local copy of your organisation's server-managed settings; and /permissions Recently blocked now refuses to approve a call you can't read in full, including one the terminal is too short to show.
managed settings, policy & TLS Fixed an administrator's TLS trust settings in managed settings not being applied in Claude Desktop sessions — a Desktop Code-tab session behind a corporate CA was ignoring the admin's trust configuration (it reaches Desktop only when Desktop bundles 2.1.314). Fixed forceRemoteSettingsRefresh set only in remote managed settings no longer applying once the stored copy had expired, which let sessions start without policy when the server could not be reached. Fixed TLS connections failing with UNABLE_TO_GET_ISSUER_CERT when the system certificate store holds a renewed root certificate that is cross-signed with its predecessor — the exact shape of a corporate root rotation. Fixed model switching being refused on machines with managed plugin settings when one of your own --plugin-dir or --plugin-url plugins had a broken manifest. Fixed the Bedrock and Vertex model upgrade offer returning at every start when managed settings pin the model. Fixed "Continue automatically at usage limit" continuing more than three times without a prompt when a task restarted itself between waits (a /goal check-in, a background or scheduled task). Fixed background and cloud sessions started with Ultracode turning it back on at their next start after it had been switched off. Fixed model IDs spelled with a dot behind an LLM gateway, such as claude-opus-4.8, being treated as an older model with the wrong context window, output limit, effort, thinking mode and cost.
Claude apps gateway · routing and tracing Added an optional groups list to gateway upstreams: only developers in the listed IdP groups are sent to that upstream, on failover too. Group-based routing at the upstream level — contractors to one Bedrock account and employees to another, from one gateway — which previously needed separate gateways or a policy-level models trick. Added guardrail_trace to Bedrock upstreams, to log which Amazon Bedrock guardrail filter fired on a request, without the matched text. Fixed a Vertex upstream hanging for minutes when a Google token endpoint accepts the connection and never answers. Fixed repeated refused requests behind a gateway that doesn't accept tool search's tool_reference blocks (the request is resent once without tool search and the session remembers), and requests failing when a gateway or cloud provider refuses one of Claude Code's beta headers by name (resent without it). Fixed Microsoft Foundry sessions failing when the resource has no deployment for the default Sonnet, Opus or Haiku model (falls back to an older model of that family). Fixed Bedrock sessions with many images failing every turn with "400 Input is too long" instead of removing older images and compacting.
headless, CI & effort Fixed claude -p exiting with code 0 and no output when startup failed; it now prints the error and exits 1. Any pipeline step that has been green on an empty stdout (expired credentials, a refused managed-settings fetch, a broken plugin) will now go red. That is the correct outcome, but it will look like a regression the first time it fires. Fixed sessions failing turn after turn with "Invalid effort level" when an organisation's admin caps a model's effort: Claude Code now lowers the effort, retries, and says which level it uses. Added idle compaction to VS Code and Claude Desktop's Code tab: a 200K+ token conversation left idle is summarised, and the summary is used on your next message if the prompt cache has expired; it also runs for subscribers with telemetry off, and on Bedrock, Vertex, Foundry and LLM gateways once the one-hour prompt cache is on. Fixed claude ultrareview and claude remote-control asking the workspace-trust question in a CI job that has a terminal (with CI set they refuse an untrusted folder at once). Fixed a PreCompact hook with very large output making compaction fail or repeat (output now cut at 10,000 characters). Improved memory use in long headless and SDK turns that run many subagents (the parent no longer keeps each subagent's tool results until the turn ends). Changed FORCE_HYPERLINK=false (also no and off) to turn hyperlinks off instead of on. Changed the Bash tool's shell to clear any inherited which alias or function.
cloud sessions, scheduled tasks & Cowork [Cloud sessions] Improved scheduled tasks: runs in Anthropic's cloud now load the plugins enabled on your claude.ai account — until now a cloud-run task could not use the plugins an interactive session had. Changed cloud sessions from the web, desktop and mobile apps to start even when a setup script exits with an error, instead of failing to start (watch for sessions that now run on a half-built environment). Changed auto mode in Cowork cloud sessions: a hook's allow of an MCP tool call now counts as no answer, so the classifier or a permission prompt decides. Fixed WebFetch in Cowork cloud sessions silently dropping a PDF's text past 100,000 characters (it now says how much was unread). Fixed Claude being told only that a command was declined after you stopped it with Esc or Stop in a cloud session or the IDE (it now also hears the command may have run). Added an Include completed button to the Scheduled tasks page; fixed recently used self-hosted environments never appearing among recent environments on the new session card; improved Test connection for GitHub Enterprise in admin settings to also connect the way cloud sessions do. [Remote Control] The permission mode button now shows the real mode on open.
terminal, skills & housekeeping Fixed ~/.claude/skills/.trash and ~/.claude/plugins/.trash growing without limit (now about 1024 entries each), and the skill file watcher checking every removed skill kept there. Fixed background diff refreshes briefly taking the repository's index lock, which could make a concurrent git command fail with "Unable to create '.git/index.lock'". Fixed the Bash edit diff listing a whole file as changed when a CRLF file under git's line-ending conversion was re-saved. Fixed MCP servers that also work without sign-in showing "needs authentication" after their stored sign-in stopped working, and claude mcp logout reporting success when the sign-in was not removed (for example with the macOS keychain locked over SSH). Improved /context speed in sessions with ten thousand or more MCP tools, --resume speed on damaged transcripts, and session auto-titles for sessions that start with a skill or prompt-based command. Current lineup and what changed

  • Haiku 5.5 claude-haiku-5-5 — default Haiku on the Anthropic API since 2.1.293 (7 Oct); 1M context.
  • Sonnet 5.5 claude-sonnet-5-5 — default Sonnet in Claude Code (28 Sep).
  • Opus 5.5 claude-opus-5-5 — default Opus (22 Sep). Also the model behind Claude Duet, and now the named migration target for Opus 4.8 fast mode.
  • Fable 5.1 claude-fable-5-1 — top tier (1 Sep); 1M context in Claude Code. fable/best aliases retry once on the previous Fable model when the newest isn't enabled for your org (since 2.1.301).
  • Opus 4.8 fast mode · deprecated (v2.1.316) Deprecated as of 30 October 2026; removed 30 November 2026. After removal, fast-mode requests on Opus 4.8 return an error and do not fall back to standard Opus 4.8. Opus 4.8 itself (28 May) is not being removed — only its fast mode. Anything on it moves to Opus 5.5 before 30 Nov. Check ANTHROPIC_DEFAULT_OPUS_MODEL, settings model keys, gateway models[] maps and any SDK code that sets a fast-mode option on claude-opus-4-8.
  • subagent effort · CLAUDE_CODE_SUBAGENT_EFFORT (v2.1.316) Sets the effort level subagents run at when nothing else names one, instead of inheriting the session's. Combine with CLAUDE_CODE_SUBAGENT_MODEL for a cheap, fast fan-out under an xhigh parent. Also: CLAUDE_CODE_DISABLE_ULTRATHINK turns the keyword off; in VS Code ultrathink now runs at xhigh as it does in the terminal.
  • admin effort caps (v2.1.314) Sessions no longer fail turn after turn with "Invalid effort level" when an organisation's admin caps a model's effort: Claude Code lowers the effort, retries, and says which level it uses. Relevant to the Enterprise model-entitlements beta (effort ceilings per role).
  • model names behind gateways (v2.1.314) Model IDs spelled with a dot behind an LLM gateway, such as claude-opus-4.8, were treated as an older model with the wrong context window, output limit, effort, thinking mode and cost. Fixed. If your gateway rewrites IDs with dots, sessions were being mis-costed and mis-sized until Friday.
  • cloud-provider aliases (v2.1.316) sonnet, opus and haiku on Vertex AI and Amazon Bedrock switch to an older model mid-session instead of erroring when the newest is not yet available to the account or region; Foundry falls back to an older model of the family when there is no deployment for the default (v2.1.314). Flagged requests retry on another model, not a refusal, when ANTHROPIC_DEFAULT_OPUS_MODEL, availableModels or deniedModels leaves only an older Opus model, or none (v2.1.314).
  • gateway model allow-lists (v2.1.316) The Claude apps gateway now checks every model a request names against availableModels, deniedModels and models, and returns a 400 naming the field for a blocked one; it used to check only the first.
  • provider API keys encrypted (Desktop v4.4212.0, 29 Oct) Provider API keys saved in Setup are encrypted where the computer has secure storage; versions below 4.29 cannot read them — a rollback or a data move means re-entering the key.
