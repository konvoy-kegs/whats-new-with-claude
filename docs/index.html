v2.1.312 — gateway user_id_claim, Bedrock behaviour changes for custom model names, managed-settings fix, hook concurrency cap, safety_event withdrawn Wed 28 Oct AEDT · 39 bullets · newest on npm · second day as current

Claude apps gateway · identity Added oidc.user_id_claim to the Claude apps gateway, to identify people by an id_token claim other than sub, such as Microsoft Entra ID's oid. Until now the gateway keyed its per-user identity (the x-claude-gateway-user-id header, user-scoped spend limits and the user.id attribute in monitoring exports) on sub; Entra tenants that already track people by oid elsewhere can line the two up. The gateway configuration reference, re-checked this morning, still documents only email_claim and groups_claim under oidc, so treat the changelog line as the spec until the docs catch up — and note that changing the claim changes the user ID that existing spend-limit rules and monitoring dashboards match on.
Bedrock, Vertex, Foundry & Mantle · custom model names Changed Bedrock, Vertex, Foundry and Mantle to use the shorter system prompt for model names Claude Code doesn't recognise, such as custom deployment names and inference profile ARNs, even when they front Sonnet or Haiku; set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 to keep the full prompt. Any Bedrock session that points at an inference profile ARN or an application inference profile rather than a bare model ID now runs on the shorter prompt, so outputs can drift without any config change on our side. Changed automatic model switches after a flagged message to also cover model names Claude Code doesn't recognise, such as custom deployment names; set CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 to turn them off. Until now an ARN-addressed session stayed on its model after a refusal; it can now switch models mid-session, which matters wherever the ARN was chosen for region, cost or compliance reasons. Desktop v4.29.0's new behavesAs key (3P) is the app-side answer to the same problem: it names the Claude model behind a gateway alias so the alias gets that model's effort levels and limits.
managed settings & policy files Fixed managed settings and organization policy not being fetched for the rest of the session after signing in from the VS Code extension. A developer who signed in through the VS Code panel ran that session without the organisation's managed settings — permission rules, hooks policy, allowed MCP servers — until the next launch. Fixed Claude overwriting a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start; Write now asks Claude to read it all or edit in place. A long rules file edited by Claude could have been truncated to the part it had read. Fixed per-directory and paths: skills not being found after a Bash cd deeper into a git repository — a skill scoped to infra/ silently disappeared once Claude cd-ed into it. Fixed a command with an invalid name stopping all commands from loading, which could leave claude -p with no output.
hooks & OpenTelemetry Changed prompt and agent hooks to run at most 24 at a time per session, sub-agents included, plus at most 12 that have waited longer than their event's timeout; a timeout under 1 second now counts as 1 second. Hooks that fan out per subagent will now queue rather than spawn unbounded; hooks with sub-second timeouts get a full second. Changed Claude Code to stop sending the claude_code.safety_event OpenTelemetry event — added in v2.1.307 on 21 Oct, withdrawn six days later; the tool_decision event with its classifier fields (v2.1.300/301) remains the signal for blocked and prompted tool calls. Changed OpenTelemetry mcp_server.name to report the real name of fixed-URL remote MCP servers declared by plugins from the official Anthropic marketplace, instead of custom. Fixed the spinner, OTel effort values and transcripts naming a newly picked effort level before the model applied it; they now show the level in force. Changed a subagent's autoCompactWindow to lower the window set by CLAUDE_CODE_AUTO_COMPACT_WINDOW, where it had no effect before; it still never raises it.
sessions, resume & UI Fixed a rare case where the first reply after resuming a session in the terminal could be missing the next time the session was resumed. Fixed the Read tool sometimes failing on PDF pages with "pdftoppm failed" when old-session clean-up ran at the same time. Fixed some sessions showing as waiting on you when the last message only mentioned items waiting on you mid-sentence. Added click to send: in fullscreen, clicking the "to send now" hint under a queued message sends it right away. Changed usage-limit messages to call the 5-hour window the "5-hour limit" instead of the "session limit"; VS Code shows the reset as a clock time. Changed cloud sessions started from the CLI to get their names and branch names from the server. Improved WebFetch errors in cloud sessions: a host that does not resolve is now explained as possibly outside the allowed network domains, so Claude names the host to allow. Fixed /verify showing its long model-facing description in /help; vim-mode d/c/y with an oversized gj/gk count now only moves the cursor; agent view no longer restores input cleared with Ctrl+C or reopens in shell mode after Ctrl+D.
VS Code, cloud sessions, Claude Tag & Code Review [VSCode] Sessions no longer end on a bare exit code when the organisation's settings couldn't be loaded or were refused at startup; the tab says why and offers Retry or Sign in again. [Cloud sessions] Added an effort level to the model picker when you create or edit a routine that runs in the cloud; added a Bash editor with colours, line numbers and Copy to the setup-script box in cloud environment settings; the step shown when Claude adds a repository now shows a short table instead of raw JSON; fixed resending an unchanged message after a failed send sometimes running it twice; fixed a failed environment creation showing its error only as a toast. [Remote Control] An unarchived session no longer shows as working until a computer reconnects. [Claude Tag] The retry notice in Slack names the model in use or says rate limits were hit; a channel's on/off switch and agent settings no longer fall back to workspace defaults when an older private channel goes public and gets a new ID; Claude now replies in channels whose environment has network access set to None; files no longer land in the wrong thread. [Code Review] Fixed Code Review reviewing an outdated commit, or none at all, when GitHub delivered a push event late; it now reviews the pull request's current commit.

v2.1.311 — ultrathink at xhigh effort, signed model catalog on cloud providers, runner idle hold, a long unattended-session fix list Tue 27 Oct AEDT · 92 bullets · not on stable or Desktop

effort & models ultrathink in the interactive terminal runs its turn at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 through Anthropic's API; typed mid-turn it raises the rest of that turn. Model names drop the [1m] suffix where it has no effect (still accepted). Standard-context sessions no longer stop with "Usage credits required for 1M context" past 200K tokens; Claude Code compacts and continues.
Bedrock, Vertex, Foundry & sandbox Claude Code on Bedrock, Mantle, Vertex and Foundry loads model settings from a signed file on downloads.claude.ai; CLAUDE_CODE_MODEL_CATALOG=off turns it off — a new outbound dependency for runners with tight egress allowlists. Long hidden thinking no longer cut off as idle on Vertex, Foundry and Claude Platform on AWS. Linux: sandboxed Bash no longer fails with bwrap: Can't create file when a --plugin-dir folder is also an added directory under permissions.blockReadsOutsideWorkingDirectories.
runner & unattended sessions --hold-idle-file and --max-hold-min on self-hosted-runner keep an idle session while the host reports processes it left running. SubagentStop hooks no longer fire about twice a minute per running subagent; subagents can use MCP tools from servers that connect after they start; a subagent's worktree is no longer removed while a background subagent is still in it; claude -p/SDK transcripts are saved in order; requests the API marked not-to-retry are no longer retried (which could hold a turn for minutes, or indefinitely under CLAUDE_CODE_RETRY_WATCHDOG); Claude no longer sees stale CLAUDE.md/MEMORY.md right after compaction. DISABLE_COMPACT from settings files is now one-way (off only). Cowork cloud sessions: WebFetch/WebSearch fail after 300 s instead of hanging; connectors are no longer lost after a restart when a plugin or settings named an agent; a finished /code-review no longer runs twice on restart.

Current lineup

  • Haiku 5.5 claude-haiku-5-5 — default Haiku on the Anthropic API since 2.1.293 (7 Oct); 1M context.
  • Sonnet 5.5 claude-sonnet-5-5 — default Sonnet in Claude Code (28 Sep).
  • Opus 5.5 claude-opus-5-5 — default Opus (22 Sep). Also the model behind the Claude Duet app.
  • Fable 5.1 claude-fable-5-1 — top tier (1 Sep); 1M context in Claude Code. The fable/best aliases retry once on the previous Fable model when the newest isn't enabled for your org (since 2.1.301).
  • gateway aliases in Desktop (v4.29.0, 27 Oct) New 3P key behavesAs on inferenceModels entries names the Claude model behind a gateway alias or other Model ID that Claude Desktop can't identify, so the ID gets that model's effort levels and limits. Once any entry sets it, sessions ignore modelPicker in people's own Claude Code settings. This is the Desktop-side counterpart to v2.1.312's CLI change for unrecognised model names; the two are set in different places (Desktop managed config vs. CLI env), so a gateway fleet needs both decided.
  • unrecognised model names on cloud providers (CLI v2.1.312) On Bedrock, Vertex, Foundry and Mantle, a model name Claude Code doesn't recognise — a custom deployment name or an inference profile ARN — now gets the shorter system prompt even when it fronts Sonnet or Haiku (CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 restores the full prompt), and is covered by the automatic model switch after a flagged message (CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 turns that off). Fleets that address Bedrock by ARN should set both deliberately rather than inherit the new defaults; a bare model ID is unaffected.
  • Desktop SSH/WSL sessions and provider env vars (v4.29.0) SSH and WSL Code sessions now take most settings, on/off values and numbers from the computer's CLAUDE_*, ANTHROPIC_* and DISABLE_* environment, but most other text, such as a cloud provider's key or base URL, goes only if saved under Environment variables. A Bedrock or gateway session over SSH that relied on ANTHROPIC_BEDROCK_BASE_URL or an API key exported in the local shell will stop picking it up.
  • token-window warning in Desktop (v4.29.0) Cowork, Chat and Code warn once a person has used 75% of the limit set with inferenceMaxTokensPerWindow and inferenceTokenWindowHours; inferenceTokenWarningPercent (1–100) changes the threshold. At the limit it reads "Token limit reached" and cannot be closed.
  • ultrathink = xhigh effort (v2.1.311) In the interactive terminal, ultrathink runs the turn at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 through Anthropic's API, and typed mid-turn raises the rest of that turn. Anthropic API only.
  • signed model catalog on cloud providers (v2.1.311) Claude Code on Bedrock, Mantle, Vertex and Foundry loads model settings from a signed file on downloads.claude.ai; CLAUDE_CODE_MODEL_CATALOG=off disables it. "Mantle" still has no docs page.
  • effort indicator (v2.1.312) The spinner, OTel effort values and transcripts show the effort level actually in force rather than a newly picked level the model hasn't applied yet.
  • Monitor tool on Bedrock, Vertex & Foundry (v2.1.310) Third-party-provider parity keeps arriving a few releases behind the Anthropic API: /auto-mode-setup (2.1.304), Monitor (2.1.310), model catalog (2.1.311), prompt and refusal-fallback handling for custom names (2.1.312), behavesAs in Desktop (v4.29.0).
  • gateway effort beta (v2.1.310) Behind a gateway that rejects the effort-2025-11-24 beta or mid-conversation system messages, Claude Code retries without them; /effort and ultrathink do nothing on that route until the gateway allows the beta.
  • API version 2026-10-21 (v2.1.307) /claude-api api-version moves your code to it. Check the Claude API release notes before switching production services.
  • Claude Duet (21 Oct) Research preview of a proactive-agent app built around Opus 5.5, included in Pro and Max plans with shared usage limits; waitlist only. Still the newest entry on the Claude apps release notes (re-checked this morning).
  • plans Max and Team plans include monthly API credits for the Claude Platform (7 Oct).

Security & evals

Desktop v4.29.0: Windows folder-delete escape, SSH password lockout, provider env vars over SSH/WSL, PowerShell hooks fail closed, GitHub PR reviews always ask · CLI stable a week stale · Unified Claude on 10 Nov

Today's actionable items

  • decision due · stable It is Thursday and stable has not moved off v2.1.308 in a week. Yesterday's trigger fires: switch fleet policy for runners, auto-mode pipelines and headless claude -p jobs from the stable dist-tag to an explicitly pinned version that this digest tracks — today that is 2.1.312. stable currently has none of the v2.1.309 sandbox fixes, the v2.1.310 Windows hooks fix, the v2.1.311 hook/subagent/retry fixes or the v2.1.312 managed-settings and CLAUDE.md fixes. Re-evaluate when stable next moves.
  • upgrade · Desktop v4.29.0 Roll Desktop v4.29.0 (27 Oct) out; it fixes two things worth not waiting on. (1) Deleting a folder on Windows could also delete files outside it, through a junction or a mounted volume inside it — the second Windows delete-escape fix in a week after v3.6556.1's Reset App Data fix. (2) The app resent an SSH password after the server had refused it and disconnected, which could lock the account — relevant to any SSH Code session into a bastion with lockout policy. Also: session starts no longer wait a minute each for a hanging local MCP server; the HIPAA-configuration local cleanup no longer deletes work on an out-of-date retention period. The bundled CLI moves to 2.1.309, which brings the sandbox and permission-check hardening to the Code tab.
  • provider credentials over SSH/WSL · Desktop v4.29.0 SSH and WSL Code sessions no longer take most text values from the computer's CLAUDE_*/ANTHROPIC_*/DISABLE_* environment — settings, on/off values and numbers still pass; a cloud provider's key or base URL goes only if saved under Environment variables. Good hygiene (keys stop leaking into remote sessions by accident), but any engineer whose SSH session to an EC2 host was finding Bedrock via a locally exported ANTHROPIC_BEDROCK_BASE_URL or AWS_* passthrough will see that session fall back to defaults after the update. Move those values into the environment's saved Environment variables.
  • PowerShell hooks fail closed · Desktop v4.29.0 A failed PreToolUse or PermissionRequest hook with "shell": "powershell" now blocks the call on PCs without Git for Windows unless it sets args or "onFailure": "continue". If the hook was written for Bash: remove shell, add "onFailure": "block" to keep blocking, install Git, reopen Claude. This closes, on the Desktop side, the same fail-open class that CLI v2.1.309/v2.1.310 closed — but a Windows laptop with a policy hook and no Git for Windows now gets every tool call blocked rather than every tool call allowed, so expect tickets.
  • GitHub connector · Desktop v4.29.0 Built-in GitHub connector updated to github-mcp-server v2.0.2. pull_request_review_write asks before every call, comment-only reviews and thread resolves included, even when toolPolicy allows it; where no prompt can be shown, the call is refused. New change-making tools ask by default: update_issue_comment, and in off-by-default toolsets create_repository_ruleset, custom_properties_write, assign_copilot_to_issue_with_intent. Unattended Cowork tasks cannot submit PR reviews through the connector at all now; this digest's own push still uses git over HTTPS.
  • scheduled-task web fetch · Desktop v4.29.0 Web fetch in scheduled Cowork tasks, outside Auto and Skip-all-approvals modes, now needs a URL named in the task's instructions or found by search or an earlier fetch. A scheduled task that fetches a hard-coded page it never names in its prompt will start failing quietly. (This digest hit exactly that this morning on the Desktop changelog and had to search for the URL first; the task prompt should name the URLs it fetches.)
  • Unified Claude on 10 November · Desktop v4.29.0 An unset desktopHome opens Unified Claude at launches after 12:00 PM PT on 10 November 2026, and with Cowork on also turns on Chat and Advanced file analysis even if chatTabEnabled or chatAdvancedFileAnalysisEnabled is false. Where coworkTabEnabled is false, nothing changes. Set desktopHome deliberately in managed config before then if the current view is wanted. Also: Skip all approvals in Cowork now follows the organisation's Cowork setting instead of its Claude Code settings; when an admin turns it or Auto off, tasks in that mode drop lower at their next start.
  • connectors & MCP · Desktop v4.29.0 defaultState: off on remote managedMcpServers provides a connector that stays out of sessions until a person turns it on — and adding off to a connector in use turns it off for everyone who hasn't opted in. toolTimeoutSec (5–3,600) per server; platformOverrides for per-OS command/args/env (an invalid value under any one drops the server on every device); oauth.omitResource for Entra's AADSTS9010010. Chat, Cowork and Code sessions no longer start while the provider connection settings are missing, invalid or not yet fetched. The Microsoft 365 connector keeps each sign-in per tenant/client/cloud/CAE — connected users sign in again once after this update. Fixed Cowork and Chat flagging an org connector as failed when managed-mcp.json on the device lists a server of the same name.
  • carry-over (CLI v2.1.312) Managed settings not fetched after VS Code sign-in; large CLAUDE.md/rules-file truncation on write; scoped skills missing after cd; refusal fallback and shorter system prompt on ARN-addressed Bedrock models (CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1, CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0); claude_code.safety_event withdrawn (keep tool_decision as the load-bearing signal); hook concurrency cap 24 (+12 overdue), sub-second timeouts round up to 1 s; oidc.user_id_claim on the gateway changes the identity spend limits key on — still undocumented in the configuration reference; Code Review reviewed stale commits on late push events.
  • carry-over (v2.1.311 / v2.1.310 / v2.1.309) New downloads.claude.ai dependency on Bedrock/Vertex/Foundry/Mantle (CLAUDE_CODE_MODEL_CATALOG=off); SubagentStop hooks fired ~2×/minute per subagent; not-to-retry requests were retried; DISABLE_COMPACT one-way from settings; Windows hooks failed open without Git Bash; gateways that reject the effort beta silently drop /effort; sandboxed Bash ran shell startup files outside the sandbox; --mcp-config was writable from sandboxed commands; five permission-check bypasses closed; bypass-mode rm/rmdir hard deny; sed -i no longer restored by /rewind; claude ultrareview needs --trust-workspace in scripts.

Desktop just changed its version scheme and caught up one step. v3.6556.2 (22 Oct) to v4.29.0 (27 Oct) is a new major number and the first build in five days; it bundles 2.1.309, so Desktop went from four CLI releases behind to three. The 3P section is the largest in weeks (six new keys), which is the signal that Desktop's managed-config surface is now moving as fast as the CLI's. The configuration changelog still tops out at 19 Oct and does not yet list v4.29.0's keys.
Fail-open hooks are being closed on every surface. CLI v2.1.309 (PowerShell hooks), v2.1.310 (Windows hooks without Git Bash) and now Desktop v4.29.0 (PowerShell PreToolUse/PermissionRequest without Git for Windows) all turn "hook couldn't run, so the call went through" into "hook couldn't run, so the call is blocked". That is the right default, and it means a policy hook that was silently inert on some Windows machines will now be loudly blocking on them. Audit which Windows devices have Git installed before the Desktop update lands.
Credentials are being pulled out of implicit paths. v2.1.311's signed model catalog, v2.1.312's gateway identity claim, and today's Desktop change that stops provider keys and base URLs riding into SSH/WSL sessions from the local environment all push configuration into declared, managed places. Runner images and SSH environments that relied on an exported shell variable need the value written into the environment's saved variables instead.
Third-party providers keep getting their own behaviour, now from two directions. The CLI changes the system prompt and refusal fallback for unrecognised model names (v2.1.312); Desktop adds behavesAs so an alias gets the right effort levels and limits (v4.29.0). A Bedrock session addressed by inference-profile ARN now behaves differently from one addressed by model ID in four separate ways, configured in two different places. Keep the ARN-vs-model-ID decision written down per runner image and per Desktop managed config.
OpenTelemetry surfaces are churning week to week. claude_code.safety_event arrived in v2.1.307 and is gone in v2.1.312; mcp_server.name changed meaning; effort values now report the level in force. Don't alert on a Claude Code OTel event until it has survived two weeks of releases; keep tool_decision as the one load-bearing safety signal.
Unified Claude has a date. 10 November, 12:00 PM PT, for any device with desktopHome unset. That is twelve days away and it also switches on Chat and Advanced file analysis where Cowork is on. Decide the home view in managed config this week rather than discover it on the day.

What's new

Desktop v4.29.0 · 27 Oct · scheduled tasks & approvals Changed web fetch in scheduled tasks, outside Auto and Skip all approvals modes, to need a URL named in the task's instructions or found by search or an earlier fetch (not in third-party deployments). Scheduled tasks that fetch pages they never name will start coming back empty; name the URLs in the task prompt, or have the task search first. Changed Skip all approvals to follow your organisation's Cowork setting instead of its Claude Code settings. A device's own Claude Code managed settings still apply; when an admin turns Skip all approvals or Auto off, tasks in that mode drop lower at their next start or message. Fixed shell commands continuing to run, or starting, after you pressed Stop. Fixed a task that could stay stuck on "working" after a follow-up message's attachment failed to upload, or after Stop during an upload. Changed deleting a task or a Dispatch chat so a failed deletion is kept with an error and can be retried; deleting a Dispatch chat also removes earlier local copies.
Desktop v4.29.0 · computer use & connectors Fixed computer use working in the background on Mac replacing all the text in a field when the app was slow to respond, leaving a field you were typing in selected so one key press wiped it, sending clicks aimed outside a window to its edge, and getting stuck at Finder's Go to Folder. New managed-config keys for connectors in Cowork: defaultState: off (a connector people opt into), toolTimeoutSec per server, platformOverrides per OS, oauth.omitResource for Entra. The GitHub connector's pull_request_review_write asks before every call and is refused where no prompt can be shown — so an unattended task cannot submit a PR review through it. Microsoft 365 users sign in again once. Memory can now be paused when Cowork is off (Settings > General). Local Cowork sessions now run on the bundled Claude Code 2.1.309, picking up the v2.1.309 sandbox hardening and bypass-mode rm hard deny.

Added a Bash editor with colours, line numbers and a Copy button to the setup-script box in cloud environment settings. The step shown when Claude adds a repository to a cloud session now shows a short table instead of raw JSON. Fixed resending an unchanged message after a failed send in a cloud session sometimes running it twice. A failed cloud environment creation now shows its error inside the dialog; Edit in a routine's menu opens the edit dialog. Improved WebFetch errors in cloud sessions: a host that does not resolve is now explained as possibly outside the allowed network domains, so Claude names the host to allow. from Claude Code v2.1.312 · Claude Tag (Slack) & Code Review Claude Tag's retry notice in Slack now names the model in use, or says rate limits were hit. Fixed a Claude Tag channel's on/off switch and agent settings falling back to workspace defaults when an older private Slack channel goes public and gets a new ID. Fixed Claude in Slack not replying in channels whose environment has network access set to None, and sometimes posting a file in the wrong thread. Code Review now reviews the pull request's current commit when GitHub delivers a push event late.
