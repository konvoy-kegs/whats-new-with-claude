v2.1.278 — server-side auto-mode classifier by default, and it is free newest · aligned · 3 days stable

Changed auto mode for Claude API and Enterprise users, and on Bedrock, Vertex, Foundry and gateways, to default to the server-side classifier, which does not charge for classifier overhead. Until now every auto-mode action — each shell command, each network request — cost a separate classifier call billed as tokens. From v2.1.278 the server performs those checks as part of the session's own model requests and does not bill them. CLAUDE_CODE_AUTO_MODE_SERVER=0 opts out on Bedrock, Vertex, Foundry and gateways (the variable is ignored on a direct Anthropic API connection, and is documented as temporary). Where the server's checks cannot reach a session, Claude Code warns once, names the gateway if it can identify one, and falls back to its own billed classifier for the rest of the session — nothing breaks. Pro, Max and Team plans never see the notice. On Bedrock, Vertex, Foundry and signed-in gateway sessions, auto mode itself still requires Sonnet 5, Opus 4.7 or later, or a Fable model.
Added an Auto mode server row to /status showing whether this session's auto mode classifier runs on the server. Enabled means the server's checks are deciding the session's actions; Disabled means it has fallen back to local, billed classification. This is the one-line check for whether our gateway is passing the safeguards request field and the safeguard_results response field through untouched — and it is the single thing worth running as part of today's roll-out. In headless -p runs the fallback notice goes to stderr; in stream-json it is a system warning the SDK can read; in VS Code it is an in-conversation notice with nothing to acknowledge.

v2.1.277 — the substance of this roll-out 87 entries · Sat

AGENTS.md support: in a project with no CLAUDE.md, Claude Code reads AGENTS.md instead; change it under “Project instructions” in /config (not yet on Bedrock, Vertex or Foundry). AGENTS.md is the cross-vendor convention several other coding agents already read, so a repo that carries one for another tool now steers Claude Code too — with exactly the trust a CLAUDE.md gets. Governance note: an omitClaudeMd-style exclusion or a repo review that only looked for CLAUDE.md now has a second file to check. Our Bedrock fleet is exempt until the platform catches up.
Three prompt-injection defences. (1) Subagent results now reach the main agent under a header marking them as subagent output, with the result indented, so text in a subagent's result cannot pass as the session's own instructions. (2) Invisible Unicode formatting and tag characters in a prompt are removed, and the cleaned prompt is shown for review before it is sent — the zero-width and tag-character smuggling trick is closed at the input. (3) On Bedrock, Vertex and Foundry, workflow scripts' computed agent() prompts reach the subagent framed as script-authored text, so the safety classifier does not read them as the user.
Containment: sandbox.excludedCommands globs exempted an entire compound Bash command when only one part matched; every part must now match. A pattern meant to let git status run unsandboxed was also letting git status && curl … run unsandboxed. Fifth consecutive documented release with a containment fix (271, 273, 274, 275, 277). Related: $TMPDIR expanded empty in Bash commands running outside the sandbox while sandboxing was enabled; the dangerous-rm prompt now names the flagged command and suggests a ${VAR:?} guard.
Two fail-open bugs closed. One malformed strictKnownMarketplaces or blockedMarketplaces entry silently disabled the whole enterprise marketplace policy — a typo in one line meant no marketplace restriction at all. And in Claude Code on the web, a cloud environment saved with Custom network access and no domains silently reverted to Trusted; the dialog now demands at least one domain. Same shape as the managed-mcp.json and device-managed MCP key bugs a fortnight ago.
Claude apps gateway. CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1 for gateways whose only egress is a forward proxy — every outbound request hands the proxy the hostname instead of resolving it locally, so a gateway in a no-DNS subnet works. An optional headers: map on gateway upstreams sends static headers to a proxy you run in front of a provider, which is how a Bedrock-fronting proxy gets an auth header without code.
Headless and CI. claude -p and Agent SDK sessions that could hang forever with no result after an internal error now report the error and exit with code 1 — the CI job fails instead of timing out. Conversations failing every request with “text content blocks must be non-empty” after a resume are fixed, as is being unexpectedly logged out when an older Claude Code build (an IDE extension's bundled CLI) runs on the same machine. Removed: the deprecated TaskOutput tool; taskOutputMaxChars and TASK_MAX_OUTPUT_LENGTH no longer have any effect.

Patterns worth tracking

The lag rule earned its keep, and today it pays out. v2.1.275 was fully documented, aligned across all five sources and looked like the cleanest build of the week; it broke every gateway session for five hours until v2.1.276. Metadata alignment says nothing about correctness. The rule — pin a number, wait a day, test one gateway session — kept us off it, and v2.1.278 has now cleared the same bar with three days and no follow-up.
The release cadence has broken step. Five builds landed Tue 15 Sep to Sat 19 Sep; Sunday and Monday were both quiet. A pause is not a signal on its own, but it does mean today's roll-out is moving onto a version that has had the longest soak of any build this month.
Auto mode is being made cheaper to say yes to. v2.1.271 added per-command allowed_domains; v2.1.273 made Bedrock default to the local classifier; v2.1.278 flips the default to server-side and stops billing it. Anthropic wants auto mode on by default and is removing the cost and the sandbox gaps that argued against it. Our position holds — auto mode with sandboxing and per-command domain allowlists is the containment; the classifier is defence in depth — but the cost objection is gone.
Fail-open is the recurring bug class. managed-mcp.json unreadable (271), device-managed MCP keys ignored (273), Write(path) rules never matching (275), one bad marketplace entry disabling the whole policy (277), Custom network access with no domains reverting to Trusted (277). Five in two weeks, each a control that admitted everything on imperfect input. Treat every managed control as unverified until you have watched it deny something, and use managed_settings_resolved (274) to watch it load.
Trust boundaries are being drawn explicitly. Subagent results framed as subagent output; workflow-script prompts framed as script-authored; invisible Unicode stripped; Bash sandbox instructions reworded as “the boundary of what the task was given”. All v2.1.277. The model is being told, at each hand-off, who is speaking. That is the right fix for prompt injection and it is arriving release by release.

Claude Cowork

GA · macOS & Windows · Linux beta

What's new

No new Cowork announcement in the last seven days either. The support-centre release notes stop at Salesforce in Claude (15 Sep), a Cowork plugin with 37 sales skills for Salesforce-approved orgs on paid plans. Everything below is from the CLI releases this roll-out delivers.
WebFetch and WebSearch in Cowork cloud sessions now tell Claude why a request was refused — a used-up fetch budget or an admin policy — instead of failing silently (v2.1.277). Before this, a routine that hit an admin domain block or exhausted its fetch budget just came back with nothing and Claude guessed. Now a scheduled task's output will name the block rather than produce a thin report. Related: rate-limited artifact publishes no longer tell Claude to stop retrying; it is told nothing was published and when to send the same publish again.
Cloud environments on Team and Enterprise get Personal and Organization sections in the environment picker (v2.1.277). Admins can share a personal environment with the organisation; organisation environments open read-only from the Code tab and are edited under Admin settings → Cloud environments. Fixed alongside: a cloud environment saved with Custom network access and no domains was silently reverting to Trusted — the dialog now requires at least one domain. If we saved a restricted environment with an empty list, it was not restricted — re-check ours as part of today's roll-out. Also: an environment with a very long allowed-domains list now fails to save up front instead of failing every session start (v2.1.275). The admin setting labelled “Web” is now “Cloud sessions”.
Artifact tool: permission prompts and link handling tidied. Prompts use shorter sentences, name pages and artifacts by title or file name, and list links after the text (v2.1.277). Claude now reads a claude.ai artifact link with the Artifact tool instead of WebFetch when that tool is available. Carried from v2.1.275: scheduled and Run-now routine runs can republish an artifact you can edit without asking — the change that lets the routine building this page refresh its own artifact unattended; updates no longer fail with “File not found” after a scratchpad clear; a publish built on an older version is stopped before it is sent.
Routines and Claude Tag. Routines created in a Slack channel on an Enterprise Grid org-wide install failing to read other public channels in their workspace — fixed (v2.1.277). Pylon's credential preset can point at the EU host; Google Cloud credential forms now say why a key file was refused and keep a pasted key on a rejected rotation; the network events log shows response status for AWS-signed, client-certificate and custom-CA connections — the audit trail for our AWS access bundles was missing status codes until now. From v2.1.275: CloudWatch, CloudWatch Logs, SNS, Google Cloud Monitoring and Cloud Logging presets; Datadog US3/AP1/AP2/US1-FED limited to read/query routes. Also fixed (v2.1.273): saved scheduled tasks running in the wrong session after .claude/scheduled_tasks.json was copied into another folder such as a new worktree.
Plugins. claude plugin install no longer breaks an installed copy a running session is using; official-marketplace plugins are now recorded with their commit in installed_plugins.json; a malformed entry in strictKnownMarketplaces or blockedMarketplaces no longer disables the whole enterprise marketplace policy; /plugin Installed shows which plugin an MCP server belongs to and strips control characters from error text (v2.1.277). From v2.1.275: npm-sourced plugins fetched with --ignore-scripts and integrity-verified; /plugin install <plugin> --marketplace <source> offers to add the marketplace first; account skills and plugins sync into terminal sessions, so what is enabled in the Cowork Customize panel is what a developer gets in the CLI.
Standing context — merged experience, Salesforce, smart reports, scanning. In the merged Chat-and-Cowork experience (Pro/Max first; see Claude Cowork and chat are one Claude) existing tasks, projects, connectors, skills, artifacts and files carry over; local-only features (trusted folders, built-in browser, computer use) still need Desktop open. Smart reports (beta, 10 Sep) tells Enterprise admins which repeated patterns are worth packaging as skills; claude plugin eval (v2.1.269) measures them. Artifacts created on or after 19 Aug are shareable and openable from the web. Enterprise skill and plugin security scanning (6 Aug) remains the control that matters most now that account plugins sync to terminals.
