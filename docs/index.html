Claude Code

CLI · v2.1.331 on latest and next · stable on v2.1.325
All sources aligned on v2.1.331. Newest on npm, the latest and next dist-tags, the changelog's top entry and the newest GitHub release (v2.1.331) all agree. Published 2026-11-23 18:36 UTC (Tue 24 Nov 05:36 AEDT). The stable dist-tag moved from v2.1.323 to v2.1.325 (published 13 Nov UTC).
What matters this morning. (1) Managed marketplaces will auto-update (announced in 2.1.331). In a future release, on or after 30 November 2026, plugin marketplaces in managed extraKnownMarketplaces auto-update by default — set "autoUpdate": false on an entry to opt it out. (2) Data-safety and hang fixes (2.1.331). A rewind no longer deletes files after a restore had failed; MCP tool calls no longer hang for up to 30 minutes on some malformed replies; turns that go silent while Claude is thinking are retried once instead of failing in cloud sessions. (3) Code Mode on cloud providers (2.1.331). Terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS now support Code Mode. (4) Telemetry (2.1.331). claude_code.llm_request trace spans gain gen_ai.usage.*, gen_ai.response.model and gen_ai.operation.name; note gen_ai.usage.input_tokens includes prompt cache tokens. (5) Still current from 2.1.330. More rm commands ask for approval and are refused where nobody can answer; deniedMcpServers name entries hide only the named claude.ai connector.

v2.1.331 — Code Mode on cloud providers, marketplace auto-update notice, rewind fix Tue 24 Nov AEDT · 135 bullets · latest

security · permissions & policy Announced for a future release, on or after 30 November 2026: plugin marketplaces in managed extraKnownMarketplaces will auto-update by default. To opt one out, set "autoUpdate": false on its entry. Fixed PermissionRequest hooks not saving Skill(name:*) allow rules outside local settings. Fixed a permission rule on a subagent's model, such as Agent(model:*), blocking Claude's follow-up message to a subagent started with no model named. Fixed auto mode sometimes refusing Claude's call to stop a /loop, which left the next wake-up to fire. A PermissionDenied hook's retry: true now tells Claude to make the refused call again only if you asked for that call. Fixed sandboxed Bash commands sometimes failing to start on a full temp disk. VS Code: fixed a chat left in bypass-permissions mode reopening in Auto mode instead of your initial permission mode when settings disable bypass; fixed an edited command on the permission prompt running without the line breaks typed into it; logging out now warns, with a link to the revoke page, when revoking the claude.ai login isn't confirmed.
behaviour changes Windows: an HKLM registry policy outranks managed-settings.json and a broken value can stop start-up — check registry-managed settings before upgrading (the non-ASCII registry start-up failure is fixed). Yes/No questions for stopping auto-connect in /ide and for /clear, /compact or /rewind in a subagent's view now list Yes first; they still start on No, so Down then Enter now answers No. VS Code permission cards show only Yes and No when allowManagedPermissionRulesOnly is set and the card would offer an allow rule; key 2 now answers No.
features Code Mode in terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS. claude doctor gains an API connectivity section (HTTP status or error, or why it wasn't tested). claude_code.llm_request trace spans add gen_ai.usage.*, gen_ai.response.model and gen_ai.operation.name. Plugin manifests accept optionalDependencies: plugins that install with the plugin listing them and can be disabled or uninstalled on their own. CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION asks for uncompressed model responses behind a proxy that cuts compressed ones off (not advised yet for self-hosted runners or Remote Control). Claude apps gateway: oidc.groups_jsonpath and CLAUDE_GATEWAY_IDP_CONNECT_BY_HOSTNAME=1. A notice now shows when tap-mode voice dictation stops by itself. VS Code: "Fix with Claude Code" quick fix for errors, warnings and failed tests; "Add Cell to Chat" for notebook cells; "Add to Chat" for changed files in Source Control; "Resolve Merge Conflicts" in the editor title; a notice before sending a very large selection.
reliability Fixed a rewind deleting files after a restore had failed; MCP tool calls hanging for up to 30 minutes on some malformed replies from a local or WebSocket server; turns and subagents failing in cloud sessions, or timing out on long replies elsewhere, when a reply went silent while Claude was still thinking (the request is now tried once more); /compact and auto-compact sometimes losing part of the summary; an interrupted plugin update leaving a partial plugin folder; a Workflow agent's background shells and MCP servers left running after its report; Esc and Stop waiting a minute or more on a stalled cloud or network file read; claude plugin install and marketplace add hanging silently when managed settings needed an approval that could not be asked for; a crash when a custom API endpoint returned a tool call with no tool name; @file#10-12 mentions attaching the whole file; PushNotification misreporting terminal activity to headless runs such as scheduled ones. Code Mode: long script output no longer loses its middle, and --resume in another permission mode keeps thinking and the prompt cache. Faster start-up for sessions started soon after another and outside git repositories; Windows: faster first Bash command.

v2.1.330 — rm guard, MCP deny-list change, Enterprise sign-in Sat 21 Nov AEDT · 142 bullets

security · permissions & policy More rm commands aimed at the root, home, a top-level folder or the working folder now ask for approval; where nobody can answer, they are refused. deniedMcpServers name entries now hide only the named claude.ai connector, not others at its URL — to block them all, deny its exact URL. Fixed background sessions sometimes waking in their previous permission mode after approving a plan. Fixed Code Mode ignoring an MCP tool's request to end the turn in auto and bypass-permissions modes. Fixed startup under forceLoginOrgUUID being refused after one temporary server error. The built-in chart tool stays blocked when an MCP allowlist or denylist excludes it (the repeated start-up warning is gone).
behaviour changes Reverted 2.1.329's removal of the automatic retry when max_tokens exceeds a model's or gateway's limit. Recurring scheduled tasks and /loop now run up to 30 days instead of 7 while their session keeps running (tasks made before this release still end at 7 days). claude --teleport in some setups prints the git commands for switching branch instead of running them; with -p it exits 1 until you switch. Skills with a model setting (other than context: fork) leave subagents, forks, compaction and /recap on the session's model. Unrecognized model names containing "sonnet" or "haiku" use the shorter system prompt (CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 for the full one). Prompt hooks accept model aliases in their model field.
features Sign-in to organizations managed in Anthropic's Enterprise Admin Console: after claude auth login, Claude Code applies the organization's settings and uses its cloud provider or gateway. easel, a built-in mod that draws charts when asked and under MCP metrics results (Pro, Max and, where available, Team and Enterprise on macOS and Linux; turn automatic charts off in /config). CLAUDE_CODE_FULL_SIGN_IN_LINK=1 prints the full sign-in link; the default link is now much shorter. claude plugin install --json adds commandPrinted and commandFailed. VS Code: /fork, /workflows, and settings claudeCode.escapeStopsClaude, claudeCode.pinPrompt, claudeCode.contextUsageThreshold.
self-hosted runner --start-dir / SELF_HOSTED_RUNNER_START_DIR starts work in a folder of a repository. New /metrics: claude_code_self_hosted_runner_order_to_registered_seconds and ..._order_to_first_session_seconds. spawn-runner hooks now start while earlier ones still run, up to --hook-concurrency (4 by default; set 1 if yours can't run side by side). A checkout hook exiting 108 stops a session's start at once. Bash commands skip the file diff when nothing needs it (bashEditDiffEnabled: true in managed settings restores every diff). A 403 such as an IP allowlist's is no longer logged as a bad secret or token — update log alerts that match the old words. Runners that start on a full disk now wait for room instead of taking and failing sessions. Fixed pkill -f ending its own shell or the runner on Linux.
reliability Fixed ExitWorktree and the worktree exit dialog deleting a worktree another running session was working in; user settings lost when several processes saved at once; freezing for minutes after compacting a very long conversation; WebFetch freezing the session on some pages; --continue/--resume opening an empty session on an invalid timestamp; the first prompt after sleep waiting three minutes on a dead connection (Linux, WSL); "JSON schema is invalid" turn failures with many MCP tools; claude -p exiting 0 with no message on a full disk (now exits 1); Bedrock (Mantle) sessions ignoring a pinned Opus model; SessionStart-hook environment variables lost with claude -p --continue; claude.ai connectors sharing a server URL being dropped. Windows: faster Grep and Glob, and Bash no longer slow for the rest of a session after a slow Git Bash start.

v2.1.329 – v2.1.326 — previous releases Tue 17 – Fri 20 Nov AEDT

2.1.329 · hooks visibility, config durability Trust dialog warns where a folder's hooks are declared; non-interactive hosts warn when managed-settings hooks fail to load; most scheduled tasks saved by earlier versions need scheduling again in new signed-in sessions; fixed ~/.claude.json being reset to defaults on a network stall or file lock; fixed repeated macOS sign-outs when the Keychain was readable but not writable.
2.1.328 · auto mode on cloud providers Auto mode for Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and the Claude apps gateway; "onFailure": "block" for mcp_tool hooks; fixed self-hosted runners deleting a kept clone's objects/refs after a temporary disk error.
2.1.327 · data-loss fixes Remote Control worktree stop no longer deletes git-ignored files (.env); runner git-proxy no longer deletes GIT_CONFIG_GLOBAL; claude mcp add-json <name> - reads JSON from stdin.
2.1.326 · bypass-mode tightening Some bypass-mode tool calls now ask or are denied; file tools refuse writes to .credentials.json; OTEL_RESOURCE_INCLUDE_HOST.

  • upgrade · v2.1.331 Move self-hosted runners, Remote Control hosts and headless claude -p jobs to 2.1.331 — adds the rewind file-deletion fix, the 30-minute MCP tool-call hang fix, the retry for replies that go silent in cloud sessions, and the clean-up of a Workflow agent's leftover shells and MCP servers, on top of 2.1.327–2.1.330's data-loss fixes.

If a marketplace must stay pinned or change only under review, set "autoUpdate": false on its entry now. /status has a "Marketplace auto-update" row (2.1.329) that names managed marketplaces getting no automatic updates.
  • telemetry dashboards claude_code.llm_request spans now carry gen_ai.usage.*; gen_ai.usage.input_tokens includes prompt cache tokens — account for that in any panel or alert that adds cache tokens separately.
  • Windows managed settings An HKLM policy outranks managed-settings.json, and a broken registry value can stop Claude Code from starting — check registry-managed settings before upgrading Windows machines.
  • hooks PermissionDenied hooks returning retry: true now tell Claude to retry only a call you asked for. PermissionRequest hooks now save Skill(name:*) allow rules outside local settings — review where those rules land.
  • carried from 2.1.330 Unattended jobs have rm aimed at the root, home, a top-level folder or the working folder refused. deniedMcpServers name entries hide only the named claude.ai connector — deny the exact URL to block the server.

Claude can see a user's screen and work in the desktop apps they allow; it works in the new Claude experience in Claude Desktop, and from web and mobile where Computer access is on (setup guide, release notes).

Claude Cowork

Computer use beta reaches Team/Enterprise · Plugins page for Enterprise 30 Nov

What's new

computer use · 20 Nov Computer use (beta) for Team and Enterprise covers the unified Claude experience that Cowork is now part of — tasks can work in the desktop apps a user allows once the organization has it (setup guide).
upcoming · 30 Nov The Plugins page (replacing the separate Skills, Connectors and Plugins tabs) reaches Enterprise, and organizations with Skills turned off will find plugins stop working in Cowork and the Code tab. From Claude Code 2.1.331's notes: managed plugin marketplaces auto-update by default on or after the same date unless an entry sets "autoUpdate": false.
via Claude Code 2.1.331 Plugin manifests accept optionalDependencies, and the plugin auto-update notice names plugins newly installed as dependencies separately from updated ones. Fixed an interrupted plugin update leaving a partial plugin folder that later loaded with skills missing. Fixed PushNotification telling a headless run, such as a scheduled one, that the terminal was active in its first minute.
