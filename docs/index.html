v2.1.327 — runner data-loss fixes, secrets hygiene, config diagnostics Wed 18 Nov AEDT · 173 bullets · latest

security · data loss Fixed Remote Control in worktree mode deleting a running session's git-ignored files (e.g. .env) on server stop. Fixed self-hosted runners with --use-anthropic-git-proxy deleting a non-empty GIT_CONFIG_GLOBAL directory at startup (now kept, ignored and warned). Fixed claude mcp add/remove (project scope) deleting other top-level keys from .mcp.json. Fixed an allowed command still running after Stop in cloud and self-hosted runner sessions. /export now asks before overwriting.
security · secrets & permissions claude mcp add-json <name> - reads JSON from stdin so tokens stay out of shell history; Claude is told not to commit files that likely contain secrets; confirmation before /install-github-app changes a repo; WebFetch refuses URLs over 2,000 characters before any prompt; fixed --disallowedTools rules with parentheses and wildcard PowerShell allow rules in auto mode; nested claude processes no longer inherit CLAUDE_CODE_OAUTH_SCOPES.
behaviour change Shell start-up files may run before a session's first Bash command is approved, even if it's refused, to speed up the first command. Set CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1 where rc files must not run unapproved.
features & admin /status now lists broken agent/skill/command files, keybinding errors, an unavailable sandbox, ignored permission settings and hook matchers that never match; /config notes when other settings override a row; attributionProject names a session's billing group on Claude apps gateways; x-claude-code-managed-settings-checksum gateway hint header; /tui classic.
reliability Remote MCP servers reached over https are retried in the background for ~a day after an outage (e.g. VPN drop); Claude Code starts when HTTPS_PROXY is a bare host:port in the desktop app, SDK and cron; claude -p no longer hangs on a stalled model-settings fetch (10 s timeout); many resume/compaction message-loss fixes; artifact publishes fixed in cloud scheduled tasks for orgs requiring approval.

v2.1.326 – v2.1.323 — previous releases Fri 13 – Tue 17 Nov AEDT

2.1.326 · bypass-mode tightening Some tool calls in bypass-permissions mode now ask or are denied when nobody can answer; PowerShell asks about more commands; file tools refuse writes to .credentials.json; sandboxed commands no longer write to some sensitive home folders (sandbox.filesystem.allowWrite); OTEL_RESOURCE_INCLUDE_HOST.
2.1.325 · sandbox prompts by default Sandboxed Bash follows the normal permission flow (sandbox.autoAllowBashIfSandboxed: true to keep auto-allow); zstd response-decoding security fix; pluginDigests deprecated.
2.1.323 · Code Mode, plugin pinning Experimental opt-in Code Mode; engines["claude-code"] in plugin.json; ~30 permission and sandbox fixes.
