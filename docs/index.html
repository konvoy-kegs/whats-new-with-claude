Still undocumented at this morning's check: pooled_budget on the spend-limits page, oidc.user_id_claim, and the GET /v1/organizations/analytics/cost report.
What matters this morning. (1) v2.1.318 is a reliability release, and three of its fixes are ours. Of 84 bullets, 47 start with "Fixed" and 15 with "Improved"; there is no new model, no pricing change and no CVE. But it carries a regression fix for --continue sometimes losing the earlier conversation after a malformed tool call's retries ran out (regression in 2.1.314) — anything on 2.1.314 through 2.1.317 that resumes with --continue is exposed; a fix for version cleanup deleting the binary of a still-running process, which made claude remote-control hosts, the background daemon and self-hosted runners fail to start new sessions with spawn ENOENT after an update (and a running process owned by another user, such as one left by sudo claude, being treated as dead and losing its binary); and fifteen or so fixes for shared network home directories: /logout, claude auth logout and claude mcp remove reporting success while the change was silently dropped, jobs exiting Not logged in when another terminal or host signs in to the same account on the same home, claude mcp add/remove writing the config without its lock, the stored login replaced by an empty file when the home has no room left for data, and ~/.claude.json, settings files and the login "less often deleted, briefly emptied or replaced by a near-empty or older copy". If any dev box or runner mounts a shared home, this is the release that was written for it. (2) Credential expiry is now observable from CI. claude auth status reports loginExpiresAt, claude -p JSON results carry credential_expires_at, and text output gets a one-line stderr warning starting 10 days before a stored claude.ai sign-in ends; the failure itself now says so and names claude auth login and claude setup-token instead of a generic sign-in error. Put the JSON field on a dashboard and the 10-day warning in the job log grep. (3) Three permission-adjacent changes. Permission prompts were being answered by keys typed just after sending a message, or before a slow prompt appeared — a keystroke race that could approve a tool call nobody read; fixed. deniedMcpServers URL entries now also block Anthropic-provided servers whose upstream URL matches, and connectors in cloud sessions and on self-hosted runners (where the session is given the connector's own URL); otherwise deny a connector by name — a deny list that was quietly narrower than it looked. And /claude-api managed-agents-onboard now gives a new agent's built-in tools, and a quickstart template's MCP tools, the auto permission policy ("Judge risky actions") by default, matching the Console; say "run without asking" to opt out. Also fixed: a shell command approved after a self-hosted runner or cloud session restart running in the session's start folder rather than the folder it was asked in (now refused if that folder can't be entered), and sessions refused at startup by an allowedProviders list another login on the same machine had stored. (4) Gateway and AWS. assume_role on mantle upstreams of the Claude apps gateway, for a role in another AWS account and for per-developer AWS cost attribution — documented the same day, with the usual warning that an older gateway refuses to start on the key, so upgrade gateways before adding it. A log warning when a Google federation (external_account) access token is about to expire; clearer listen.trusted_proxies hints (list only a proxy that adds the connecting address to X-Forwarded-For itself); and the Bedrock CountTokens warning now says Claude Code, not the gateway, counts after the 501. NODE_EXTRA_CA_CERTS that is empty, not PEM or starts with a damaged certificate no longer fails every connection: readable certificates are used, with a warning on stderr — a loosening worth knowing about, since a broken bundle used to be loud. (5) Runner operators: log lines changed. The orchestrator's ok session=… line now prints at every log level on stdout (was debug only, on stderr) with reason=… after jti=…, and nack session=… ends with reason=… after retryable=… — update any parser or alert that keys on those. CLAUDE_RUNNER_SPAWN_REASON (runner_lost, resumed, …) reaches the spawn-runner hook environment. (6) Pin. Move the runner pin from 2.1.317 to 2.1.318: documented, released, on latest, and it carries the --continue regression fix and the version-cleanup fix that specifically hits runners. Desktop stays on 2.1.317 until its next build. (7) Dates. Plugins page GA 9 Nov (four days), Unified Claude 10 Nov 12:00 PM PT (five days), Desktop deprecation warnings from 17 Nov (12 days), 30 Nov (25 days) for Skills-off-blocks-plugins, the Enterprise Plugins page and Opus 4.8 fast-mode removal, 17 Dec (42 days) for the deprecated Desktop keys and sessionRetentionHold.

v2.1.318 — the --continue regression, version cleanup killing runners, shared-home survival, credential expiry in auth status and -p, gateway assume_role Wed 04 Nov AEDT · 84 bullets · latest · 11 Added, 47 Fixed, 15 Improved, 10 Changed, 1 Removed

regressions, runners & the daemon Fixed --continue sometimes losing the earlier conversation after a malformed tool call's retries ran out (regression in 2.1.314). Four documented releases carried it; any wrapper script that chains claude -p --continue after a tool error was the exact trigger. Fixed claude remote-control hosts, the background daemon and self-hosted runners failing to start new sessions (spawn ENOENT) after an update or version cleanup removed the binary of a still-running process — the mechanism behind "runner was fine until the auto-update, then every new session failed". Fixed a running Claude Code process owned by another user (for example one left by sudo claude) being treated as dead by version cleanup, which could delete its binary. Both are now in the Remote Control troubleshooting docs: a missing working folder now names the folder instead of a misleading program-file message, and "before v2.1.318, new sessions failed this way even with a newer version installed". Fixed /remote-control showing a session as available after a failed connection, and /design revoke reporting success on a 404. Fixed a shell command approved after a self-hosted runner or cloud session restart running in the session's start folder, not the folder it was asked in; if that folder can't be entered, it is not run. Fixed macOS sessions with many running Bash commands stalling while memory grew. Fixed workflows re-running finished agents when resumed after a usage limit. Self-hosted runner: CLAUDE_RUNNER_SPAWN_REASON in the orchestrator's spawn-runner hook environment (why Anthropic sent the request, e.g. runner_lost, resumed; unset when none was sent); a startup warning when --release-idle-session-min is the last argument with no value or has a value of only spaces; and the orchestrator's log lines changed — ok session=… at every log level on stdout with reason=…, nack session=… ending in reason=… — so log parsers need a look.
shared network homes, config survival & sign-in The largest group in the release. Fixed /logout, claude auth logout and claude mcp remove reporting success, and changes to trust, consent or MCP settings being dropped with no word, when the config file could not be updated on a shared network home directory. Fixed jobs exiting with Not logged in when another terminal or host signs in again to the same account and organization on the same home. Fixed claude mcp add and remove writing the config without its lock: they now wait for it or exit 1 (another job's save can still replace a saved server). Fixed claude plugin commands exiting before a slow token refresh was saved, which could sign you out on the next run (the claude auth status version of this was in v2.1.317). Fixed sessions being refused at startup by an allowedProviders list that another login on the same machine had stored. Fixed the stored login being replaced by an empty file when a network home has no room left for data but still takes new files. Fixed retention cleanup leaving a home that only runs claude -p with no ~/.claude.json backup (it now takes a fresh backup before deleting the last good one). Fixed non-interactive launches replacing a ~/.claude.json that isn't valid JSON with defaults; the start now fails, says how to restore the file, and leaves it as is (anthropics/claude-code#87551) — an empty file with no backup is treated as missing, not corrupted, and the printed restore command no longer names an empty or cut-off backup. Fixed tokens from setup-token being refused at start on machines with forceLoginOrgUUID when the token belongs to a permitted organization. Improved how ~/.claude.json, settings files and the stored login survive saves on shared network home directories, and sessions on network file systems look again when the configuration file is wrongly reported as missing, so fewer start without MCP servers and trusted folders. Unattended runs (claude -p, SDK apps) stop rewriting ~/.claude.json on every run when nothing changed. Added the date a stored claude.ai sign-in ends to claude auth status (loginExpiresAt) and to claude -p JSON results (credential_expires_at), and a one-line stderr warning to claude -p text output starting 10 days before it ends; the sign-in failure when the login reaches its limit now says so and, in -p, names claude auth login and claude setup-token.
permissions, MCP deny lists & managed agents Fixed permission prompts being answered by keys typed just after sending a message, or before a slow prompt appeared. Changed deniedMcpServers URL entries to also block Anthropic-provided servers whose upstream URL matches, and connectors in cloud sessions and on self-hosted runners, where the session is given the connector's own URL; otherwise deny a connector by name. Re-read any URL-based deny list with that in mind: it now reaches further than it did on Tuesday. Changed /claude-api managed-agents-onboard to give a new agent's built-in tools, and a quickstart template's MCP tools, the auto permission policy ("Judge risky actions") by default, matching the Claude Console; say "run without asking" to opt out. Changed subagents to stop instead of switching models when "Switch models when a message is flagged" is set to "Ask each time". Changed the /permissions rule details, built-in rules and delete confirmation views to use the standard dialog (Ctrl+C twice goes back or cancels instead of quitting). Fixed Claude not being told when an approved connector tool was unavailable after a cloud session restart, and /mcp in cloud sessions counting tools the model can't use. Fixed stdio MCP servers that exit on the version probe being re-probed on every start (a server that dies in under 3s for its own reason is pinned to the legacy handshake for 7 days). Improved MCP tool errors: a call made before the tool is loaded now returns its input schema. Added a record of your answer when Claude Code asks to turn on the mods it writes in a session. Changed what a mod attaches at prompt.submit to stay in the user's turn rather than go out as a system message. Fixed a mod's turn.step hook making a stopped reply finish as a success in headless runs, and claude -p/SDK sessions reporting success when an API error cut off a reply while a mod hooked turn.step.
Claude apps gateway, AWS & TLS Added assume_role on mantle upstreams of the Claude apps gateway, for a role in another AWS account and for per-developer AWS cost attribution — the same keys as on a bedrock upstream, including session_name; documented the same day on the gateway configuration page, with the warning that an earlier gateway exits at startup on the key, so upgrade every gateway before adding it. Gateway: added a log warning when the Google access token from a federation (external_account) credentials file is about to expire; improved the listen.trusted_proxies hints (list only a proxy that adds the connecting address to X-Forwarded-For itself); and the warning when AWS CountTokens fails on Amazon Bedrock now says Claude Code counts after the 501 and points at IAM only when AWS denies access. Fixed every connection failing when the NODE_EXTRA_CA_CERTS file is empty, not PEM, or starts with a damaged certificate: readable certificates are now used, with a warning on stderr. Note the direction: a broken bundle used to fail loudly; now it half-works with a stderr line, so a proxy CA that silently fails to load will show up as TLS errors on some hosts rather than all. The fourth corporate-CA change in eight days, after v2.1.314's cross-signed root, v2.1.316's looped cross-certificates and v2.1.317's TLS-inspecting-proxy fix.
headless, subagents, compaction & the IDE Fixed custom slash commands that fail, or that only Claude can invoke, printing nothing in claude -p and SDK sessions. Fixed a message sent right after a model change still running after Stop in headless sessions (Stop now cancels or stops it as it would a queued message). Fixed a deleted session transcript being re-created with its last prompt when an idle non-interactive session exited. Fixed a restarted session re-sending a message that failed with an API error ahead of the newer message waiting behind it, and dropping its interrupted turn when the restart came right after a large image read or a retried tool call. Fixed idle compaction replacing a conversation with a reply that was not a summary. Fixed the "Now using usage credits" notice reappearing every 30 seconds while a background subagent runs. Added an effort option to a mod's $.model.fork, so a quick side job can run at low whatever effort the session uses. Changed background subagents to move a shell command to the background after 3 minutes on all providers, so the prompt cache doesn't expire while it runs; on Bedrock, Vertex, Foundry or with telemetry off, a subagent progress summary on a cold prompt cache can now wait up to 5 minutes. Improved the reliability of git commits and pull request creation when the Bash tool runs macOS's built-in /bin/bash. Improved auto-update to retry right away after a brief network failure while verifying a release. Changed Claude Code to no longer install or update the IDE extension when started in an IDE terminal; use /ide from an outside terminal or your editor's extensions view. Removed the 2.1.288 fix that kept the model's earlier thinking when resuming a conversation started on 2.1.286 or earlier; that thinking can now be dropped. [VSCode] Fixed a window whose sign-in the organization's settings refuse starting a new Claude Code process in the background every minute; the sign-in screen now shows what Claude Code printed when its status check fails.
cloud sessions, Remote Control, Claude Tag & Code Review [Cloud sessions] Added a No repository option: a cloud session on an Anthropic-hosted environment can now start without picking a repository. Added the usual Chrome names, so tools other than Playwright can find the built-in Chromium through google-chrome and CHROME_PATH. Added a New session button to the card shown when a cloud session's environment was deleted. Fixed reading GitHub Actions logs in cloud sessions: gh run view --log and gh api log requests now get the log in most environments, not an unreachable redirect. Improved most Create PR failure messages in cloud and Remote Control sessions to give the reason or a GitHub link instead of "Try again". Changed connector search results to tell Claude that the search covers only part of the connector directory. Fixed cloud sessions being stopped mid-turn when the service refuses uploads for several minutes; variables a Setup hook writes to CLAUDE_ENV_FILE not reaching the Bash tool in some cloud sessions; and the iPhone app showing a cloud session's turn as finished while it kept running. Improved how fast remote sessions reconnect after a pause or sleep. [Remote Control] Fixed side-by-side checkouts of one repository looking identical in the environment menu (each now shows its own folder name); a fork of a terminal fork is titled "Name (fork 2)". [Claude Tag] Fixed keyboard focus and screen reader announcements in admin setup. [Code Review] The analytics page retries once after a server or network failure, then shows a Try again banner instead of empty cards.

Current lineup and what changed

  • Haiku 5.5 claude-haiku-5-5 — default Haiku on the Anthropic API since 2.1.293 (7 Oct); 1M context.
  • Sonnet 5.5 claude-sonnet-5-5 — default Sonnet in Claude Code (28 Sep).
  • Opus 5.5 claude-opus-5-5 — default Opus (22 Sep). Also the model behind Claude Duet, and the named migration target for Opus 4.8 fast mode.
  • Fable 5.1 claude-fable-5-1 — top tier (1 Sep); 1M context in Claude Code. fable/best aliases retry once on the previous Fable model when the newest isn't enabled for your org (since 2.1.301).
  • Opus 4.8 fast mode · deprecated (v2.1.316, Desktop v4.16336.0) Deprecated as of 30 October 2026; removed 30 November 2026. After removal, fast-mode requests on Opus 4.8 return an error and do not fall back to standard Opus 4.8. The Desktop changelog carries the same line, so Code-tab and Cowork sessions are covered by the same date. Opus 4.8 itself (28 May) is not being removed. Check ANTHROPIC_DEFAULT_OPUS_MODEL, settings model keys, gateway models[] maps and SDK code that sets a fast-mode option on claude-opus-4-8. 25 days.
  • subagents and model switching (v2.1.318) Subagents now stop instead of switching models when "Switch models when a message is flagged" is set to "Ask each time" — a fan-out can no longer quietly land on a different model because a subagent's message was flagged and nobody was there to answer. Background subagents move a shell command to the background after 3 minutes on all providers so the prompt cache doesn't expire; on Bedrock, Vertex, Foundry, or with telemetry off, a subagent progress summary on a cold prompt cache can wait up to 5 minutes. A mod's $.model.fork takes an effort option, so a side job can run at low whatever the session uses; the result reports the effort sent.
  • telemetry by plan and provider (v2.1.317) anthropic.plan, anthropic.seat_type, anthropic.provider and anthropic.custom_base_url on OTel metrics, events and spans. Cost per plan tier and per gateway becomes a group-by rather than a join. The gateway's GET /v1/organizations/analytics/cost report gives the same split per developer, per day and per IdP group from the server side; with v2.1.318's assume_role on mantle upstreams, per-developer attribution now reaches the AWS bill as well.
  • subagent effort (v2.1.316 / v2.1.317) CLAUDE_CODE_SUBAGENT_EFFORT sets the effort subagents run at when nothing else names one; subagents and teammates on a different model from the main conversation use that model's saved effort level or its default instead of the session's. CLAUDE_CODE_DISABLE_ULTRATHINK turns the keyword off.
  • per-session cost in Desktop (v4.16336.0) With inferenceModelPricingEnabled on, each session's estimated cost shows above the message box in Cowork, Chat and Code, not only on the Usage page; where sessionStatusLine is set, its program's line shows there instead. inferenceGatewayAutoModeServerChecks (temporary, off by default) lets the provider behind your gateway check risky Auto mode actions — it sends session details such as folder paths and a user name to that provider.

Patterns worth tracking

The burst-then-silent pattern did not repeat. v2.1.318 was next-only with no notes at yesterday's check, two hours after its publish; by 11:01 AEDT it had a GitHub release and the changelog entry, and latest moved. Last week's v2.1.315 never got any of that and was replaced in three and a half hours. The useful rule for the pin: a build that is still notes-less at the next morning's check is a v2.1.315; one that gets its release within a few hours is a latest. Two hours of silence is not a signal either way.
stable is a trailing marker, not a floor. Seven npm versions and six documented releases behind latest, one behind the Desktop-bundled build, and it moved once in nine days (v2.1.309 → v2.1.311 on Tuesday). Nothing on this page should be pinned to it; its only use is as the lower bound of what an engineer might plausibly be running.
v2.1.318 is the shared-home release. Around fifteen of its 47 fixes are about configuration files, stored logins and MCP settings on network home directories, profile containers and full disks — logouts that didn't log out, MCP removals that didn't remove, sign-ins that bounced because another host signed in. That is a map of where support load has been. If the team runs Claude Code on anything with an NFS or FSLogix home, treat Tuesday-to-Thursday settings changes as unverified and re-check them after the upgrade.
Credential lifetimes are now a first-class signal. Two weeks ago a stored claude.ai login that reached its limit looked like a generic sign-in error in a job log. Now it is a date in auth status and in every -p JSON result, a 10-day stderr warning, and a failure message that names the two commands that fix it. Combined with v2.1.317's credential_expires_at-adjacent exit-code fixes and OTel plan attributes, the headless story is converging on "observable before it breaks". Instrument it.
Permission surfaces keep getting corrected at the edges. This week: stray keystrokes approving a prompt (fixed), URL deny lists that didn't reach Anthropic-hosted servers or connectors (widened), an approved command running in the wrong folder after a restart (refused), SDK hooks that failed open (onFailure: "block"), autoMode lists that didn't apply strictly in Desktop (now strict), managed agents defaulting to "run without asking" (now auto). None is a CVE; each is a place where "approved" meant less than it read. The direction is consistently toward stricter, and three of the six are in the client rather than the server, so the pin matters as much as the policy.
Docs: same-day for the CLI changelog and the new gateway key, still behind on three older ones. code.claude.com served v2.1.318 and the assume_role reference within the day. pooled_budget (v2.1.316), oidc.user_id_claim (v2.1.312) and the cost report (v2.1.317) are still changelog-only, and the spend-limits page still contradicts the changelog on pooled group caps. The newer the key, the faster it gets documented; the backlog is the older keys.
Dates: five in the next six weeks. Plugins page GA (9 Nov) and Unified Claude (10 Nov) are this coming week; deprecation warnings from 17 Nov; three removals on 30 Nov (Skills-off blocks plugins, Enterprise Plugins page, Opus 4.8 fast mode); the deprecated Desktop keys and sessionRetentionHold on 17 Dec. One change-control ticket per date; the 10 Nov one should also set coworkSessionRetentionDays.
