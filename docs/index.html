v2.1.287 — Claude Mods, 1M context on clouds, MCP elicitation newest · aligned

extensibility Claude Mods. Plugins can now modify deeper Claude Code behaviour. First built-in mod: "You should know", a side agent that watches the session and flags things you or Claude might miss. Enable with /plugin enable cc-plugin-you-should-know@builtin (first-party sessions with telemetry on).
models 1M context by default on Bedrock, Vertex, Foundry and the Claude apps gateway. Opus 4.7+ and Fable no longer need the [1m] suffix. Set CLAUDE_CODE_DISABLE_1M_CONTEXT=1 to keep 200K — worth checking against cloud spend budgets.
MCP URL prompts (elicitation) from MCP servers on the 2025-11-25 protocol, e.g. for sign-in. If a server stops connecting after updating, add "bareElicitationCapability": true to its MCP config entry. Also: alwaysLoad: false now defers all of a server's tools behind tool search.
observability OpenTelemetry user_prompt event gains prompt_text (a copy of prompt). If you drop or mask prompt in your OTel pipeline, do the same for prompt_text.
fleet Fixes worth knowing. Bedrock/Vertex startup checks now honour an enforced availableModels list; Bedrock Guardrails blocks mid-response show the guardrail message instead of an API error; claude remote-control registers behind HTTP proxies; Remote Control gives up on a stuck reconnect after 30s; Windows Bash tool is faster; self-hosted runners get a built-in gh api (REST) when the GitHub CLI isn't installed.

v2.1.286 — retries, fallbacks, scripting and plugin hardening Thu 1 Oct

One retry budget per model call (max 14 requests by default); same-tier fallback when the API refuses your default model; --bare connects only named MCP servers; plugin installs refuse git/folder npm sources; MCP error path that could print a credential value fixed.

v2.1.285 — provider lockdown, Desktop handoff, headless plugins Wed 30 Sep · now stable

allowedProviders managed setting pins which API providers a machine may use; claude --desktop hands a session to the Desktop app; claude plugin configure / install --config for scripted plugin setup; ANTHROPIC_AUTH_TOKEN sessions now load org policy.

Security & evals

rm safeguard bypass fixed · scanning default changes today

Today's actionable items

  • permissions A dangerous rm (e.g. on / or home) could lose its always-ask safeguard when the same command also redirected output to a ~ or wildcard path. Fixed in 2.1.287 — good reason to move canaries forward.
  • permissions Whole-tool Bash allow rules and allowing hooks now prompt (not run) shell writes to files the file tools refuse outright, such as the host credentials file. Shell writes through repo-committed symlinks to sensitive files or out of tree now name the destination and wait for a person.
  • policy Org per-tool permission ceilings were silently dropped for an MCP tool named __proto__ — fixed.
  • sandbox Sandboxed Bash on Linux no longer inherits an open handle on the Claude Code executable.
  • telemetry New OTel field prompt_text duplicates prompt — update masking/redaction rules before rolling 2.1.287 to the fleet.
  • privacy /feedback and /bug no longer pre-fill recent error messages into the public GitHub issue.
  • deadline Enterprise skill/plugin scanning defaults to "Requires review" today, Fri 2 Oct, if no setting is chosen.
  • deadline Cowork on Pro/Max goes cloud-by-default on Tue 6 Oct.

Patterns worth tracking

Fleet governance keeps expanding. 283 (deniedModels) → 285 (allowedProviders) → 286 (policy kills live Remote Control sessions) → 287 (enforced availableModels honoured in Bedrock/Vertex startup checks).
Plugins are getting more power. Claude Mods let plugins change deeper behaviour, right as plugin scanning defaults tighten for Enterprise. Review what your org allows before enabling mods broadly.
