Claude Fable 5

model · access restored

Access restored after export controls lifted headline

Source: Redeploying Claude Fable 5 · anthropic.com · posted 30 Jun, restored 1 Jul 2026

Fable 5 and Mythos 5 are back. On 30 Jun the US government lifted the export controls that had suspended both models since 12 Jun. Fable 5 returned on 1 Jul to users globally on the Claude Platform, Claude.ai, Claude Code, and Claude Cowork. Anthropic is re-enabling access on AWS, Google Cloud, and Microsoft Foundry “as quickly as possible” — those cloud paths may not be live yet. Mythos 5 has been restored for a set of US organisations (government approval on 26 Jun), with Glasswing access expanding from there. Access to all other models — Opus 4.8, Sonnet 5, Haiku — was never affected.
What this means for us: workflows pinned to claude-fable-5 on Claude Code and the API should work again. But Bedrock/AWS access is still being re-enabled — keep CI agents and Bedrock calls on claude-opus-4-8 until Fable 5 is confirmed live on AWS. Also note the new safety classifier (below) blocks more borderline requests during routine coding/debugging; any blocked request to Fable 5 is auto-routed to Opus 4.8, so callers should expect an occasional silent model switch on security-adjacent prompts.
  • status Export controls lifted 30 Jun; Fable 5 available again globally from 1 Jul across Claude Platform, Claude.ai, Claude Code, and Cowork. Cloud provider (AWS / Google Cloud / Microsoft Foundry) re-enablement is in progress, not confirmed complete.
  • safeguards Anthropic shipped an improved cybersecurity classifier that blocks the specific Amazon-reported bypass in >99% of cases; blocked requests are flagged and re-routed to Opus 4.8. It flags benign requests more often during routine coding/debugging — expect more false positives. US Commerce CAISI tested both the prior and new safeguards and rated them extraordinarily strong.
  • access & pricing The included Fable 5 allowance for Pro, Max, Team, and select (premium) Enterprise plans (up to 50% of weekly usage limits) ran through 7 Jul; that window has now closed, so continued access is via usage credits. Standard Enterprise seats have no included allowance — access is credits-only.
  • industry Anthropic, with Amazon, Microsoft, Google and other Glasswing partners, is drafting a consensus framework for scoring AI jailbreak severity, and has opened a HackerOne program for cyber-jailbreak submissions against Fable 5.
  • background Fable 5 launched 9 Jun as a Mythos-class model made safe for general use; Mythos 5 is the same model with fewer safeguards, restricted to Project Glasswing partners for defensive cybersecurity.

v2.1.211 — Bedrock/Vertex prompt-caching billing fix, permission-preview hardening, subagent text forwarding newest documented

Published 15 Jul 2026 at 19:24 UTC · CHANGELOG · a billing-relevant caching fix for cloud providers, permission-UI security hardening, and a wide reliability sweep

Prompt-caching regression fixed on Bedrock, Vertex, Mantle, and Foundry. A regression was billing the trailing system context block as fresh input tokens on every request instead of reading it from cache. Directly relevant to our Bedrock agents’ token spend — worth updating CI/agent images promptly and watching whether input-token costs drop after the upgrade.
Permission previews hardened against Unicode spoofing. Tool-input previews relayed to chat channels now neutralize bidirectional-override, zero-width, and look-alike quote characters, so a crafted tool input can no longer visually alter the approval message you’re being asked to approve. Related: in auto mode, a PreToolUse hook’s ask decision now floors unsandboxed Bash at a prompt instead of being overridden.
New --forward-subagent-text flag (and CLAUDE_CODE_FORWARD_SUBAGENT_TEXT env var) includes subagent text and thinking in stream-json output — useful for observability on headless/SDK pipelines.
  • security File-upload validation hardened: filenames ending in a DOS device suffix (.prn) or trailing dot are accepted, files with multiple hard links are refused; Claude in Chrome file-upload path validation hardened.
  • behaviour change “Always allow” permission rules now save at the repository root, so approvals granted in a git worktree persist across sessions and worktrees; /usage-credits now asks for confirmation before sending a request to organization admins.
  • aws Fixed Claude Code on Vertex and Bedrock attempting the default Opus model at startup and printing a spurious fallback notice when a model is explicitly configured.
  • auth Fixed parallel Claude Code sessions all logging out simultaneously after wake-from-sleep when many sessions share one credential store; background jobs on LLM gateway auth (ANTHROPIC_AUTH_TOKEN + ANTHROPIC_BASE_URL) no longer come back “Not logged in” after the daemon respawns them.
  • reliability Plugin MCP servers now reconnect after an idle web session wakes; subagents spawned with an explicit model override no longer revert to the parent’s model on resume; /clear now resets the session cost counter; /loop no longer hides the session from /resume; background agents killed by the user no longer auto-respawn and re-run stale prompts.
  • quality Improved background agent result reporting — Claude now waits for real completion instead of fabricating results for still-running agents; integer env vars (timeouts, token budgets) now accept 1e6 and 64_000 spellings; terminal layout and rendering performance improved.

v2.1.210 — worktree isolation fix, prompt-injection hardening, auto-mode classifier on Sonnet 5 now documented

Published 14 Jul 2026 at 19:39 UTC · CHANGELOG · yesterday’s undocumented npm release now has notes: two security fixes and a background-agent reliability sweep

Worktree isolation fix. isolation: 'worktree' subagents could previously run git-mutating commands against the main repo checkout instead of their own isolated worktree. If you rely on worktree isolation for parallel agents, this is the reason to be on ≥2.1.210.
Agent tool hardened against indirect prompt injection via content a subagent read. Also: the ultracode keyword opt-in no longer fires on non-human-originated input such as webhook payloads and relayed PR comments, and late-appearing .claude/* symlinks are now reconciled into the sandbox deny-write list.
  • feat Live elapsed-time counter on the collapsed tool summary line, so long-running tool calls visibly tick; startup warning for Write(path), NotebookEdit(path), and Glob(path) permission rules — use Edit(path) or Read(path) instead.
  • auto mode The permission classifier now defaults to Sonnet 5 for external sessions, validated on the session’s first request and pinned for the session.
  • unattended A hook callback timeout is no longer misreported to the model as a user rejection, which made unattended sessions stop and wait — relevant to scheduled/CI runs.
  • fix claude attach no longer fails with “job not found” during session transitions; plan approvals without edits are no longer labeled “(edited by user)” and no longer overwrite the plan file with a stale snapshot; unmatched $1/$2 placeholders in skills and commands are preserved verbatim instead of silently stripped; killed background sessions no longer leave a permanent git worktree lock behind.
  • status Fable temporarily shows as unavailable in the advisor picker while a server-side issue causing Fable advisor failures is fixed.

v2.1.208 — screen reader mode, corporate process wrapper, big performance & memory sweep

Published 13 Jul 2026 at 21:31 UTC · CHANGELOG · accessibility and enterprise-launcher features, a permissions guardrail, and a ~40-item fix and performance sweep

Screen reader mode. Opt-in plain-text rendering for screen reader users: run claude --ax-screen-reader, set CLAUDE_AX_SCREEN_READER=1, or add "axScreenReader": true to settings. Also new: vimInsertModeRemaps (map two-key insert-mode sequences like jj to Escape in vim mode) and mouse-click support for multi-select menus in fullscreen mode.
CLAUDE_CODE_PROCESS_WRAPPER — corporate launcher support. Agent view and the background service now honor a required wrapper executable for every Claude Code self-spawn. Worth a look if we ever standardise a wrapped launcher on managed engineering machines.
  • permissions Catastrophic removals (e.g. rm -rf ~) in commands containing $(…)/backticks/<(…) now prompt even in --dangerously-skip-permissions and auto mode, matching the plain form.
  • performance Memory-leak sweep: MCP stdio stderr no longer accumulates up to 64 MB per server, LSP documents now LRU-capped at 50, the file-edit read cache is bounded to 16 MB; session transcripts up to 79x smaller in edit-heavy sessions; up to 7x faster tool rounds at high MCP tool counts; permission-rule matchers compiled once and cached (fixes multi-second per-turn slowdowns with many deny/ask rules).
  • aws Fixed Bedrock auth failing with “Session token not found or invalid” for AWS SSO profiles whose sso_region differs from the Bedrock region (a 2.1.207 regression — relevant to our SSO setup); Bedrock streaming errors behind a transforming gateway now name the content-type and point at the proxy instead of a misleading “Truncated event message received.”
  • reliability Context window (and auto-compact indicator) no longer falsely resets to 200k after the CLI auto-updates; background-session attach no longer fails permanently after an update replaced the running binary; fixed truncated stream-json/JSON output when piping large responses from claude -p; stream-json input no longer kills the session on blank CRLF lines from Windows-style SDK hosts.
  • fix /release-notes no longer injects the entire changelog into the model’s context; apiKeyHelper script failures are surfaced within 3 attempts instead of hidden behind a generic 401; env vars like CLAUDE_CODE_MAX_OUTPUT_TOKENS no longer parse 1e6 as 1; the Edit tool no longer fails on files modified after reading when the target text still matches uniquely.
  • agents Replies typed to a background agent are no longer lost when delivery fails; completed background agents stay listed in /tasks until cleanup; attaching to a stopped agent shows its transcript immediately; agent-view Ctrl+X never destroys unpushed commits; fast mode now restores automatically when switching back to a model that supports it.

v2.1.207 — auto mode default-on for Bedrock/Vertex/Foundry, Opus 4.8 cloud default, plugin shell-injection fix

Published 10 Jul 2026 at 22:25 UTC · CHANGELOG · cloud-provider default changes, a security sweep, and a large streaming/terminal and AWS-credential fix sweep

Auto mode is now available without the CLAUDE_CODE_ENABLE_AUTO_MODE opt-in on Bedrock, Vertex AI, and Foundry — and those providers now default to Claude Opus 4.8. Directly relevant to our Bedrock agents: sessions that haven’t pinned a model move to Opus 4.8 on upgrade, and auto mode no longer needs the env flag (disable org-wide via disableAutoMode in settings). Also a behaviour change: auto mode no longer reads autoMode from repo-resident .claude/settings.local.json — use ~/.claude/settings.json instead.
Plugin shell-injection fix. ${user_config.*} in shell-form plugin hook/monitor/headersHelper commands is now rejected. Hooks should use exec form (args array) or $CLAUDE_PLUGIN_OPTION_<KEY>; monitors and headersHelper should read the value inside the script. Plugin option values (pluginConfigs) are also no longer read from project-level .claude/settings.json — audit any plugins we maintain.
  • consent Fixed remote managed settings from a non-interactive run (claude -p, the SDK) being permanently recorded as consented without ever showing the security consent dialog; /usage-credits malformed amounts are now rejected with an error, and amounts over $1,000 require a typed confirmation.
  • performance Fixed the terminal freezing and keystrokes lagging while streaming responses containing very long lists, tables, paragraphs, or code blocks; the transcript no longer jumps above the start of the answer when a response finishes streaming.
  • aws Bedrock no longer repeatedly requests fresh AWS SSO credentials from IAM Identity Center on every API request; fixed an indefinite hang on Windows when AWS credential resolution stalls (e.g. a stuck credential_process) — the 60-second stall guard now fires. Both relevant to our AWS setup.
  • fix The auto-updater no longer overwrites a custom launcher script or symlink at ~/.local/bin/claude on every release (/doctor now reports an externally managed launcher); fixed spurious prompt-injection warnings from benign system-generated conversation updates; fixed extensions.worktreeConfig being left in .git/config (breaking go-git tools like tea) after the last sparse worktree was removed.
  • agents Fixed a crash loop in agent teams from a malformed teammate mailbox message; Remote Control task status updates no longer lost when the connection recovers; desktop-hosted Remote Control sessions now show background agent and workflow progress on mobile and web; Deep research Fetch-phase chips now show the source hostname instead of “unknown.”
