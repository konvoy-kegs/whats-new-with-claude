All sources aligned on v2.1.301. npm newest, the latest and next dist-tags, the changelog top and the newest GitHub release all read v2.1.301. npm publish 2026-10-15 14:34 UTC (Fri 16 Oct 01:34 AEDT); GitHub release 2026-10-15 19:22 UTC (06:22 AEDT). That makes three releases in two UTC days: v2.1.299 (14 Oct 00:23), v2.1.300 (14 Oct 14:27) and v2.1.301 (15 Oct 14:34). v2.1.301 has a full changelog entry (51 bullets). stable stays on v2.1.292, now seven releases behind latest.
What matters in v2.1.301. A smaller, cleanup-flavoured release after the two big ones. For infra: the fable/best alias now falls back to the previous Fable model instead of erroring when the newest one isn't enabled for your org; unattended retry mode gets a cap on how long it waits for a usage-limit reset; auto-mode classifier decisions are now distinguishable in OpenTelemetry tool_decision events; and two cost leaks are closed (a model switch that silently paid for a summary, and endless re-compaction behind a gateway that renames the model). Also fixed: Grep/Glob reporting "no matches" when the search program crashed, skills vanishing after /rewind, and quitting deleting a hook-created worktree with unpushed commits. Desktop v2.42304.0 (15 Oct) now bundles 2.1.299, so the Code tab finally has the sandbox and gateway-key fixes — but not 2.1.300 or 2.1.301.

v2.1.301 — Fable alias fallback, retry-watchdog cap, classifier telemetry, cost fixes newest · aligned · 51 bullets

models Fixed the fable (and best) model alias erroring on the Anthropic API when the newest Fable model is not available to your organization: Claude Code now retries once on the previous Fable model. Fixed switching to a model whose name contains application-inference-profile running your awsAuthRefresh command and delaying model-switch hooks when the provider is not Bedrock. Improved switching to a model with a smaller context window: a conversation too long for the new model is now summarized by the previous model first — and fixed a case where that switch could spend usage credits on the summary without asking.
unattended runs & observability Added CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS so unattended retry mode (CLAUDE_CODE_RETRY_WATCHDOG) ends a request at a usage limit that resets too far away instead of waiting. Added classifier_verdict and permission_mode to OpenTelemetry tool_decision events, so auto-mode classifier decisions can be told apart from permission rules; with OTEL_LOG_TOOL_DETAILS=1, classifier_category names the built-in rule a classifier block matched. Added OpenTelemetry tracing guidance to the claude-api skill, including setting up trace destinations with the ant CLI. Fixed the /claude-api skill saying CMEK external-key endpoints aren't available on Claude Platform on AWS.
permissions, auth & hooks Fixed sign-in refresh timeouts and unexpected sign-outs after a short command such as claude auth status or claude plugin list exited in the middle of a token refresh. Fixed the permission prompt for a plugin or skill hook's ask decision not showing which plugin or skill the hook comes from. Fixed a tool call cut off by a message sent mid-turn during its permission check being reported to the model as rejected by the user. Fixed workflow scripts asking for permission or being refused when read, edited or re-run after a Bash cd. Fixed workflow agents sometimes skipping their step, and the run still reporting success, after reading the harness note that their task text carries no user authority. Fixed artifact updates being refused where a PreToolUse hook covers Edit or Write; Claude now edits the file and republishes instead. Fixed a misleading "Please run /login" error when a full disk keeps the login from being refreshed; it now names the disk. Self-hosted runner: fixed sessions started from Slack being unable to find or attach a repository when managed settings restrict MCP servers (use deniedMcpServers to keep those tools off); fixed sessions wrongly reported as having a deleted source branch and not retried; fixed the log promising a retry for a session that is ending.
reliability & cost Fixed conversations being compacted over and over, on a model you didn't pick, behind an LLM gateway whose responses name a different model than the one requested. Fixed quitting removing a worktree made by a WorktreeCreate hook without asking when it may hold unpushed commits. Fixed Grep and Glob reporting no matches when the search program failed before returning results; they now return an error saying the search failed. Fixed the Read tool reading binary files such as .xlsm, .parquet, .epub and .heic as text. Fixed skills no longer being listed to the model after /rewind. Fixed skills, commands and hooks with very many or very long argument names stalling for seconds or using very large amounts of memory (only the first 64 names, each up to 64 characters, are now filled in). Fixed the compaction row in a resumed session offering ctrl+o for history that is not loaded. Windows: fixed stopped background PowerShell commands missing the closing [killed] line in their output file. Improved rendering performance while a long-running subagent works (progress trail updates incrementally).
terminal, mods & VS Code Added the % motion to vim mode (matching bracket, alone or with d/c/y); fixed vim mode sometimes staying in INSERT after Escape on a busy machine, and Esc discarding a typed AskUserQuestion answer. Added rows to a mod's Input for multi-line text fields; a tree above the question dialog can now hold Markdown and up to 48 rows in VS Code and the desktop and mobile apps. Changed a mod hook's .catch to run only when the hook throws or times out; $.env.set now resolves with {} or { deny }. Fixed stray >0q/>4m characters on VTE terminals older than 0.53 (MATE Terminal on RHEL 8) and stray GOK text in iTerm2. Fullscreen: /compact no longer freezes the UI while the transcript is rebuilt. VS Code: LaTeX math rendering in responses; a "Get more usage" link on the usage-limit banner for Pro and Max; fixed a crashing conversation reopening on every reload; fixed the panel slowing down during long thinking; fixed diagnostics showing "[object Object]" instead of the rule code.

v2.1.300 — /advisor on AWS, OTel GenAI spans, hook input validation, gzip Thu 15 Oct AEDT · 88 bullets

Claude Platform on AWS & observability Added /advisor on Claude Platform on AWS. No advisor runs until you pick one with /advisor, advisorModel or --advisor; CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1 turns it off outright. Added OpenTelemetry GenAI semantic-convention attributes to trace spans (gen_ai.provider.name, gen_ai.conversation.id, gen_ai.tool.name, error.type) and cache_creation_5m_tokens/cache_creation_1h_tokens on api_request. Large requests to api.anthropic.com now use gzip even with telemetry off (CLAUDE_CODE_GZIP_REQUEST_BODIES=0 to opt out). Local session transcripts now also record each API request's system prompt, tools and parameters — mind what you share.
hooks, auth & permissions updatedInput from PreToolUse and PermissionRequest hooks is now validated like Claude's own input — unknown keys are dropped, and input the tool rejects denies the call. Agent hooks no longer ignore their model; an unavailable model falls back to the caller's instead of allowing the action. Fixed a login refused by forceLoginOrgUUID leaving the refused organization's token stored. CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST sessions ignore CA-bundle, tool-proxy, git TLS and git config variables in settings. PermissionRequest hooks in Cowork cloud sessions: a setMode update in an allow is ignored. Removed --sandbox/--no-sandbox from claude remote-control; passing either now exits with an error — set sandbox.enabled in settings. Claude Tag: Slack Connect channel support (off by default), a private Allow once / Deny card for connector approvals, Slack voice clips.

v2.1.299 — sandbox and gateway hardening, MCP rule semantics, idle compaction Wed 14 Oct AEDT · 190 bullets · bundled in Desktop v2.42304.0

sandbox, gateways & credentials Fixed a sandboxed shell command being able to write into a --plugin-dir folder, whose code Claude Code reloads and runs outside the sandbox. Fixed macOS sandbox symlink bypasses of denied paths, glob parsing mismatches between settings checks and the sandbox, and WSL2 bwrap failures. Fixed feature flag, startup, fast mode, profile and feedback requests carrying the API key configured for a third-party gateway (ANTHROPIC_BASE_URL) to Anthropic endpoints. Fixed MCP OAuth not sending configured headers/headersHelper. Requests to claude.ai's connector proxy and Anthropic-hosted MCP servers no longer follow HTTP redirects.
permission rules & hooks (behaviour change) mcp__a now allows only the server named a — not a__b or a_; write mcp__<server>__* with the whole normalized name, and agent tools: lists follow the same rule. Plugin hooks fail closed: actions a hook can block are refused when the hook cannot be handed them or cannot answer. Cowork cloud auto mode: a PermissionRequest hook can no longer approve shell commands or subagents. UserPromptSubmit hooks now run before a skill or slash command expands. Skills and commands whose file names contain hidden or direction-changing characters are no longer offered until renamed.
context & cost Idle compaction in the terminal: a 200K+ token conversation left idle ~54 minutes is compacted before its one-hour prompt cache expires. CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS changes the floor; "idleCompaction": false turns it off. Added CLAUDE_CODE_DISABLE_FILE_MENTIONS, /usage warnings for max effort, workflows, always-on context and large tool results, /effort and /fast in agent view, --shutdown-drain-sec for the self-hosted runner orchestrator, and --disallow-tools for claude plugin eval.

2.1.296 Managed-settings PreToolUse hooks denying with "continue": false now end the turn; managed PostToolUse hooks apply updatedMCPToolOutput. Bash permission checks no longer auto-approve commands that assign and use BASH_ARGV0. Windows: rm -rf /c/Users/<name> in Git Bash asks even in bypass mode. Added the gateway code policy key for Desktop's Code tab, per-subagent autoCompactWindow, CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL, Read allow_large, and corrected Sonnet 5.5 cache-read pricing to $0.10/Mtok.
2.1.295 onFailure: "block" for command and HTTP hooks (fail closed). Gateway per-upstream models lists and timeouts.upstream_ttfb_ms; on Amazon Bedrock token counts use AWS CountTokens (grant bedrock:CountTokens).
2.1.294 Instruction-style prompt/agent hooks ("Block commands that…") could allow what they should block. Two bullets only.

Security & evals

v2.1.301 CLI · Desktop v2.42304.0 · new signing cert, managed-import auto-install

Today's actionable items

  • upgrade Fleet CLI target moves to 2.1.301. Nothing in 2.1.301 is a bypass fix on its own, but it sits on top of 2.1.299's sandbox write escape (--plugin-dir), macOS symlink bypasses and gateway-key leakage, and 2.1.300's updatedInput validation. It also stops unexpected sign-outs after short commands like claude auth status mid-refresh, which were showing up as flaky CI auth. Run claude update on every machine on latest.
  • Desktop signing cert (Windows) v2.42304.0 changed the certificate that signs the bundled Claude Code helper (claude.exe) to the renewed one the app and installer have used since v2.37337.1. Rules that hold the certificate itself — a Microsoft Defender certificate indicator, AppLocker/WDAC publisher rules — need the new certificate added beside the old one or the Code tab's helper will be blocked after the update.
  • Desktop managed import now auto-installs Where device management turned the import from Claude (third-party) on, v2.42304.0 now adds local MCP servers and starts those that were on, installs the desktop extensions and uploaded plugins your org allows, and uploads skills that grant tools or declare hooks — without asking the user to confirm. claudeAiImport.automatic3pImport also reinstalls optional plugins from any allowedPluginMarketplaces entry (GitHub, git or URL) with the same source in the old and new org, including on computers that moved orgs before this version. Review what your marketplace allowlist contains before the fleet updates.
  • Desktop mcpPersistentAlwaysAllowEnabled Now also applies to Code sessions on the device, in WSL and over SSH: with it false, MCP tool prompts offer "Allow for this session" instead of "Always allow", and scheduled tasks get no lasting approval unless mcpScheduledTaskApprovalLifetimeDays is one day or more. If you set it for Cowork only, Code-tab users will notice.
  • Desktop chat sandbox egress Chat's file-analysis sandbox (chatAdvancedFileAnalysisEnabled) can now reach the hosts in coworkEgressAllowedHosts, e.g. to install packages, with no approval prompt. Before, it had no network access by default. With no list, or an empty one, it still has none — check that list is what you intend for chat too, not just Cowork.
  • Desktop Git operations skip hooks The commit/stash around a branch switch, the in-folder branch switch, and the push behind "Continue in cloud" no longer run repository Git hooks. Pre-push checks you rely on in those paths won't fire; push Git LFS objects from a terminal before continuing in the cloud.
  • Desktop Code tab now on 2.1.299 v2.42304.0 bundles 2.1.299, so the Code tab has the sandbox and gateway-key fixes and the narrowed mcp__ rule matching. It still lacks 2.1.300's updatedInput validation and 2.1.301. /status shows which CLI a session is on.
  • session export scope Desktop session export (Settings > Import & export) now covers everything by default instead of the last 30 days. Combined with 2.1.300's transcripts recording system prompts and tool parameters, an export is now a complete record — review before sharing.
  • MCP permission rules (carry-over) Since 2.1.299, mcp__a matches only the server named a. Audit permissions.allow/deny and agent tools: lists for servers with double underscores and rewrite them as mcp__<whole name>__*. Now live in the Desktop Code tab too.
  • gateway users (carry-over) If you run Claude Code through an ANTHROPIC_BASE_URL gateway with its own API key, that key was being sent to Anthropic's background endpoints before 2.1.299. Upgrade first; consider rotating the gateway key. 2.1.301 adds a fix for a gateway that renames the model causing endless re-compaction.
  • hooks & auto mode (carry-over) Plugin hooks fail closed (2.1.299); updatedInput a tool rejects denies the call (2.1.300); a PermissionRequest hook can't approve shell or subagents in Cowork cloud auto mode. 2.1.301 adds the plugin/skill name to hook ask prompts, so users can finally see which hook is asking.
  • stable dist-tag Still v2.1.292; seven releases behind. Anyone pinned to stable has none of the sandbox, gateway-key, hook or MCP-rule fixes from 2.1.294 onward.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

Eight consecutive hardening releases, then a breather. 2.1.292 through 2.1.300 each closed a hook, sandbox, permission-rule or credential path. 2.1.301 is mostly cleanup and observability — the first release in two weeks with no bypass fix in it. Don't read that as "done"; 2.1.299's changes are only now reaching Desktop users.
Desktop managed-config is shifting from "ask" to "apply". v2.42304.0's managed import installs MCP servers, plugins and skills without confirmation, and automatic3pImport reinstalls optional plugins across org moves. That's convenient for onboarding and a wider blast radius if a marketplace allowlist is too broad. Treat allowedPluginMarketplaces as a security control.
Telemetry is catching up with auto mode. 2.1.300 added GenAI span attributes; 2.1.301 adds classifier_verdict, permission_mode and classifier_category on tool_decision. You can now build a Grafana panel that separates "classifier blocked it" from "a rule blocked it" — worth wiring up before widening auto mode.
Desktop bundles trail the CLI by one to two releases. v2.42304.0 ships 2.1.299 two days after it landed on npm; the CLI is already two ahead. Expect 2.1.301 or later on the next Desktop bump.
