All sources aligned on v2.1.251. npm's newest publish, the latest dist-tag, the next dist-tag, the changelog and the GitHub release tag all agree — no divergence to reason about today. It published Sat 29 Aug 01:34 local over the weekend, tagged on GitHub at 04:19 local the same day, so this is the first weekday digest to cover it. A plain claude update installs v2.1.251. v2.1.251 is the largest release in weeks — 71 changelog entries — and it is overwhelmingly a security release. Five separate permission-bypass fixes land at once: a symlink swapped inside the working directory after the permission check let file tools read or write outside the approved location; Grep and Glob ignored Read(...) deny rules through symlinked search paths; plugin marketplace entries could point commands outside the plugin directory; the Workflow tool read a scriptPath before the permission check ran; and Bash auto-approved commands assigning arithmetic expressions to shell variables. Alongside them, four classes of settings that could previously weaken your sandbox or exfiltrate credentials now require explicit approval. If you run Claude Code anywhere near untrusted code, this is a same-day upgrade.

v2.1.251 — five permission bypasses, four settings-escalation classes, and a prompt-cache line in /cost today's headline

71 entries · published Sat 29 Aug 01:34 local · on latest and next · source: CHANGELOG.md

Permission bypass — a symlink swapped after the check let file tools read and write outside the approved directory. “Fixed file tools (Read, Write, Edit) following a symlink swapped inside the working directory after the permission check, which could read or write outside the approved location.” This is a classic time-of-check/time-of-use race, and the working directory is exactly where an attacker-controlled repository can plant one. The path is validated, approval is granted for that path, and then the link is repointed before the write lands. Paired with it in the same release: “Fixed Grep and Glob not applying Read(...) deny rules to files reached through a symlinked search path” — so a deny rule you wrote to keep Claude out of a directory did not survive a symlink into it. If you rely on Read(...) deny rules as a control rather than a convenience, they were softer than advertised until this release.
Permission bypass — plugin marketplace entries could point outside the plugin directory. “Fixed plugin commands declared in a marketplace entry being able to point outside the plugin directory; such paths are now rejected with a path-traversal error.” Directly relevant to us: a private marketplace is backed by a GitHub repository, so write access to that repo was write access to a path-traversal primitive on every machine that installed from it. This is the third consecutive week with marketplace hardening (v2.1.247 closed terminal-escape injection, v2.1.246 fixed cache-directory collisions). The access list on any repo backing a marketplace deserves a review this week, not next quarter.
Permission bypass — Bash auto-approved arithmetic variable assignments. “Fixed Bash permission checks auto-approving commands that assign an arithmetic expression to an integer shell variable (e.g. OPTIND=1/0, RANDOM=2+2); these now prompt for approval.” Arithmetic evaluation in bash is not inert — it expands variables and can be driven to side effects — and the classifier was treating these as trivially safe. Also fixed: the Workflow tool was reading (and quoting in error messages) a scriptPath outside what the session may read, before the permission check ran — a read primitive that leaked its results through the error text.
Settings escalation — four categories that could previously weaken the sandbox or move credentials now require approval. This is the structural change in the release, and it is worth reading as one item rather than four. (1) Server-managed settings that terminate sandbox TLS, route sandbox traffic through your own proxy, inject credentials, or weaken sandbox isolation now require approval before they apply. (2) ANTHROPIC_CUSTOM_HEADERS from managed or project settings now requires approval when it sets a credential, org/tenant, routing or API-behaviour header — Authorization, Host and friends. (3) Project-level .claude/settings.json env can no longer set CLAUDE_CONFIG_DIR, CLAUDE_CODE_TMPDIR, or TMPDIR/TMP/TEMP — a repo could previously relocate the config directory Claude Code reads its own settings from. (4) Project settings can no longer enable detailed beta tracing or raw API body logging, and a lower-scope tracing endpoint can no longer bypass an OTLP collector pinned by managed settings or a host app. Taken together: a checked-out repository can no longer reconfigure the security posture of the tool inspecting it. Expect a one-off approval prompt after upgrading if your managed settings touch any of these.
Claude in Chrome now goes through Claude Code's permission checks. “Changed Claude in Chrome so browser actions always go through Claude Code's permission checks, including in sessions with telemetry disabled, which previously used the Chrome extension's own prompts.” Two permission systems for one action is one too many — browser actions were being approved by the extension's prompts rather than the rules in your settings, so an org that had carefully constrained Claude Code had not constrained what it could do in a browser. Also hardened this release: how Bash command output files are created and read back in the sandbox, so a sandboxed command cannot redirect or replace them.
Cost visibility — a real prompt-cache breakdown in /cost, and a spend-limit bar in /usage. “Added a per-session prompt-cache line to /cost (hit ratio, misses, tokens re-cached, warm/cold) and a matching prompt_cache object for status line scripts.” After a fortnight of releases fixing invisible cache misses, this is the instrumentation that lets you see them yourself — and the prompt_cache object means a status line or a dashboard can track hit ratio across a team rather than one person noticing a bill. Alongside it: a Spend limit bar in /usage and a rate_limits.spend_limit status line field for anyone behind a Claude apps gateway with spend limits, and SessionStart resume hooks now receive session staleness and the estimated re-cache cost, so a hook can decide whether resuming is worth the re-cache.
New — PreModelSwitch and PostModelSwitch hooks. These can block, confirm or annotate a model switch. The obvious governance use is preventing a switch to a model we do not have contracted rates for, which until now was only achievable by curating the /model list with modelPicker — a suggestion rather than a control. A hook can refuse. Related model-selection changes in the same release: CLAUDE_CODE_SUBAGENT_MODEL now sets the default subagent model rather than overriding everything, so an agent definition's model: and an explicit per-spawn model take precedence; /effort now saves your default effort level per model; and the default model for seat-based Enterprise subscriptions is now Opus 5, matching other premium plans.
Agents and background sessions — four silent-failure fixes. A backgrounded session could not edit files inside a git worktree it had created itself with git worktree add. Background sessions occasionally started with no plugin skills at all, and stayed that way, when another Claude Code process was refreshing the marketplace at that moment. In agent teams, a teammate's final answer was not reaching the team lead — it now arrives in the idle notification instead of a content-free “available” notice. And background subagents could not reply to a message from an unnamed sibling or parent. Also: SDK and cloud sessions no longer hang indefinitely when an SDK MCP server's handshake acknowledgment is lost — the wait times out after 70 seconds and marks only that server failed. Plus a TUI fix for lag with many parallel subagents, where per-second progress ticks were piling up in the transcript rather than replacing each other.
Operational fixes worth knowing about. Conversations were getting stuck on “text content blocks must be non-empty” after a turn where the model produced only thinking. Opus 5 requests were failing outright with “effort … is not supported when thinking is disabled” when effort was xhigh/max and thinking was off; effort is now sent as high in that case. Backgrounded sessions were losing a Vertex/Bedrock gateway exported in the shell, so every request failed. Session transcripts were being silently overwritten when a directory change relocated a session onto an existing same-ID transcript. The self-hosted runner was leaving Bash processes running after a force-stop. And an additionalDirectories entry containing a null byte crashed startup — it is now skipped. On size: the native binary is about 5 MB smaller, and dropping syntax highlighting for six rarely-used languages took another 2.5 MB off.

Still worth actioning from last week carry forward

v2.1.248 — rotate credentials that lived in uncommitted *.tfvars or prod.env files. /ultrareview and locally seeded cloud sessions were uploading uncommitted edits to those files, and to editor swap/temp/backup copies of credential files (key.pem.tmp, id_rsa.swo). The fix is forward-looking only — an upload that already happened is not undone by upgrading. See the Security tab.
v2.1.248 — --restricted is still the mode to reach for on untrusted code. It removes the tools that run commands or code plus WebFetch, keeps file tools inside the working directory, refuses bypassPermissions, and ignores user, project and local settings files. Today's settings-escalation fixes narrow what a repo can do in normal mode; --restricted is still the stronger answer for reviewing a dependency or a read-only CI runner.
v2.1.246 — rotate any third-party LLM gateway API key. Telemetry and metrics requests to Anthropic were carrying the API key configured for a gateway via ANTHROPIC_BASE_URL. A credential minted for our gateway was sent to a host that is not our gateway. On latest for nearly a week now; there is no reason to still be exposed.
v2.1.246 — audit Bash allow rules with a wildcard before the subcommand. Bash(git * main) also matches options inserted before the subcommand (git -c …, git --exec-path=…), which changes what the command does. Reinforced by today's arithmetic-assignment fix: the Bash permission matcher has now been corrected twice in a week, so treat the rule set as worth re-reading rather than assuming it means what it looks like.

Sandboxing and isolation notes

The theme across four releases is now unmistakable: the repository you point Claude Code at is untrusted input, and until this week it had more authority than that. It could inject terminal escapes through marketplace text (v2.1.247), reach network paths through markdown links (v2.1.247), widen the sandbox through its own settings files (v2.1.248's --restricted), send working-tree secrets to cloud containers (v2.1.248), and — as of today's fixes — relocate the config directory Claude Code reads its settings from, enable raw API body logging, escape the plugin directory through a marketplace entry, and defeat path-based permission checks with a swapped symlink. v2.1.251 is the release where the trust boundary finally sits where the mental model always assumed it did.
Two permission systems became one. Claude in Chrome browser actions now route through Claude Code's permission checks rather than the extension's own prompts, including with telemetry disabled. Any org that constrained Claude Code but not the browser extension had a gap it probably did not know about — worth checking whether your rule set actually covers browser actions now that it governs them.
Fail-closed continues to replace silent-permissive. Marketplace paths outside the plugin directory are rejected with an explicit path-traversal error rather than followed; arithmetic Bash assignments prompt rather than auto-approve; a null byte in additionalDirectories is skipped rather than crashing startup; and a lost MCP handshake fails that one server after 70 seconds rather than hanging the session. The pattern from the last fortnight — refuse loudly instead of proceeding quietly — held again this release.

Claude Desktop

macOS · Windows · Linux (beta)

What's new

Sources: support.claude.com release notes (newest entry 25 Aug — unchanged for six days), platform release notes, Claude Desktop help. Checked Mon 31 Aug 2026. Today's Desktop news again comes from the Claude Code changelog rather than the support site.

New — replying to a cross-session message delivered by Claude Desktop now works. v2.1.251: “Fixed replying to a message Claude Desktop delivered from another session: SendMessage to that session id now delivers through Claude Desktop instead of failing with ‘not reachable’.” Cross-session messaging was one-way through the desktop app — you could receive but the reply bounced. Relevant to anyone running a CLI session and a Desktop session against the same work.
New — Bedrock sessions launched by Claude Desktop no longer stall on inference-profile discovery. Under CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST (which is how Claude Desktop launches sessions), a session given a Bedrock model ID or ARN directly no longer waits for discovery it does not need. Straight latency win at session start for anyone on Bedrock through the desktop app.
Carried forward — the 30-day session deletion fix. v2.1.248 stopped the CLI's transcript cleanup reaping desktop-written sessions the app still considered live. Anything already reaped before that release is gone and upgrading does not recover it. The desktopSessionCleanupPeriodDays setting caps the exemption; org-managed retention policy still takes precedence.
Standing context — memory, the Customize panel, and Cowork GA. Everything Claude remembers is listed under Topics in Settings > Memory and can be edited or deleted. Memory is on by default for Free, Pro and Max, and off by default for Team and Enterprise — on our plan nothing is retained unless somebody turned it on. Sensitive categories stay out unless Include sensitive topics in memory is switched on. Also live: Claude Cowork generally available on macOS and Windows, Linux in beta, on all paid plans; a Customize section grouping skills, plugins and connectors in one place; the monthly recap at Settings > Reflect; break reminders and quiet hours at Settings > Time and focus.

Claude Cowork

Generally available · cloud sessions in beta

What's new

Sources: Release notes — 25 Aug entry, Get started with Claude Cowork, Use plugins in Claude, Use Claude Cowork safely. Checked Mon 31 Aug 2026.

New — background sessions could start with no plugin skills at all, silently. v2.1.251: “Fixed background sessions occasionally starting without any plugin skills (and staying that way) when another Claude Code process was refreshing the plugin marketplace at the same moment.” This is the most consequential Cowork item today, because a scheduled task that starts with no skills does not fail — it runs and produces something worse. If a recurring task has produced an oddly generic result at some point in the last few weeks, this is a plausible explanation. Same release also fixes a background session being unable to edit files inside a git worktree it created itself.
New — /schedule now explains that Claude Code MCP servers cannot attach to cloud routines. Previously it returned a bare “No MCP connectors” message. This is the local-vs-cloud boundary showing up in the UI at last — a scheduled task running on Anthropic's servers cannot reach MCP servers configured in your local Claude Code, and the old message made that look like a configuration error rather than a design boundary.
New — the auto-mode default offer no longer appears in unattended sessions. The one-time “make auto mode your default” prompt was appearing in unattended contexts such as agent-team teammate panes, where a stray keypress could accept it unread. A related change makes plugin/LSP install suggestions and that offer wait until you have sent or cleared what you are typing, so the Enter that sends your prompt cannot answer them. Prompts that can be answered accidentally are a permissions problem, not a UX one.
Carried forward — the unattended-run reliability fixes have stacked up substantially. A lost SDK MCP handshake now times out after 70 seconds and fails only that server rather than hanging the session (v2.1.251); a stalled background session names the hook and schema error that broke it (v2.1.248); cloud sessions whose container restarts mid-turn report the lost work rather than going silent (v2.1.247); MCP failures are reported to Claude rather than looking like missing tools (v2.1.247); interrupted MCP calls are reported as interrupted rather than “completed with no output” (v2.1.246). Six ways an unattended run could silently degrade have been closed in four releases.
The operational rule that keeps catching people: scheduled tasks run with no device online. They execute on Anthropic's servers rather than a laptop, so they no longer need the machine awake or the app open. The corollary is the trap: a scheduled task cannot reach local files, or local MCP servers, unless the desktop app happens to be open on that machine — and as of v2.1.251 /schedule at least says so out loud.
Standing context — plugin and skill governance for Team and Enterprise. Each plugin bundles skills, connectors and sub-agents into one package; hooks and sub-agents run only in Cowork, so they appear greyed out in chat. Admins can create private plugin marketplaces from a GitHub repository — and today's path-traversal fix is the third reason in three weeks to take that repo's write access seriously. Org-wide skill management publishes a skill to everyone under Customize > Skills; Enterprise skill and plugin security scanning checks third-party content on upload or edit; plugin OpenTelemetry distinguishes admin-install so “what did we push versus what did people add themselves” is answerable from telemetry. Ten financial services agent templates are also available for Cowork and Claude Code.
