CLI · v2.1.295 on latest and next
All sources aligned on v2.1.295. npm newest, the latest and next dist-tags, the changelog top and the newest GitHub release all read v2.1.295. npm publish 2026-10-08 18:22 UTC (Fri 9 Oct 05:22 AEDT); GitHub release 2026-10-08 19:48 UTC. Two releases since yesterday's digest (2.1.294 and 2.1.295). stable moved from 2.1.285 to v2.1.286, still nine releases behind.
v2.1.295 headline: fail-closed hooks. Command and HTTP hooks can now set onFailure: "block" — a hook that can't start, times out, or exits unexpectedly blocks the action instead of letting it through. Paired with 2.1.294's fix for instruction-style prompt/agent hooks that allowed what they should block, this is a good day to review your guard hooks. Also: a large batch of Claude apps gateway features for Bedrock/Vertex/Foundry, MCP reliability fixes, and ~140 changelog lines overall.

v2.1.295 — fail-closed hooks, gateway controls, MCP reliability newest · aligned

hooks & guards Added onFailure: "block" for command and HTTP hooks (fail closed instead of open). Fixed --tools and --restricted not applying to built-in tools that register after launch. Fixed a mod's hook receiving deeply nested tool input cut short with no error (a guard could pass content it never saw), and calls made during a mod reload slipping past another mod's guard hook. Fixed a tampered server-managed-settings cache making a personal plugin count as org-managed. Fixed Bash permission checks for for-loops over glob patterns. Fixed Claude in Chrome not applying a host:80 deny rule to plain http:// pages.
Claude apps gateway Optional per-upstream models list (wildcards allowed; honoured on failover); timeouts.upstream_ttfb_ms now applies to Bedrock, Vertex, Foundry and other cloud upstreams; upstream_request_id in the inference audit event and a request-id response header that matches Claude Code telemetry; forceLoginMethod: "gateway" in user settings on unmanaged machines. On Amazon Bedrock, token counts now use AWS's CountTokens API — grant bedrock:CountTokens. Background requests now use Haiku 4.5 where the gateway serves it. Unknown desktop policy keys now start with a warning instead of failing.
MCP & reliability Fixed every request failing on a [1m] model when a gateway, Bedrock, Vertex or Foundry refuses the context-1m beta (now resent without it). Remote MCP servers in headless/SDK sessions now reconnect after long outages, with backoff up to 30 s. Fixed MCP pagination loops, CSS/JS/XML MCP results saved as .bin, and a terminal freeze on very long responses. claude -p no longer drops earlier responses when background work starts another turn.
changes claude.ai connectors now negotiate MCP protocol 2026-07-28 by default (MCP_PROTOCOL_NEGOTIATION=legacy opts out). MCP tool descriptions loaded through tool search are cut at 16,384 chars (was 2,048). Subagents preload at most 32 skills. WebSocket MCP messages over 16 MiB close the connection. New: Program Status Protocol (OSC 7501) terminal status, CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS, $.ui.notify for mods.
IDE, cloud & Slack VS Code: a chat row for files Claude sends you; fixed project-scope plugins not loading on Windows due to drive-letter casing. Cloud sessions: fixed some older routines starting without their saved prompt. Claude Tag (Slack): settings confirmation cards stay open 30 min; fixed other bots' @Claude going unanswered in busy channels. Code Review: re-reviews now report how many earlier findings remain open.

v2.1.294 — hook judgement fixes Thu 8 Oct UTC

hooks Fixed prompt and agent hooks written as instructions (such as "Block commands that...") allowing what they should block. Improved how prompt hooks on Stop and SubagentStop written as instructions are judged, so Claude is less likely to stop early.

v2.1.293 — Claude Haiku 5.5, compaction & MCP fixes Wed 7 Oct UTC

model Added Claude Haiku 5.5 (claude-haiku-5-5), now the default Haiku on the Anthropic API — 1M context, $0.10/$0.50 per Mtok ($0.50/$2.50 over 100K). Fixed post-compaction retracting/redoing finished work, and an HTTP MCP connection memory leak.

v2.1.292 — security sweep, plugin install shortcut Tue 6 Oct UTC

permissions PreToolUse hook approvals and auto mode could bypass the prompt for UNC-path file reads; tampered managed-settings cache could unseat the policy plugin; sandboxed commands could read staged /ultrareview uploads — all fixed. Plus claude plugin install --marketplace, Agent tool effort, NO_PROXY honoured.

v2.1.291 — two regression fixes Tue 6 Oct UTC

regressions Cloud sessions could drop answers to permission prompts (from 2.1.290); the last messages of a session could be lost when quitting (from 2.1.288).

Security & evals

hook guardrails: review today

Today's actionable items

  • fleet Move to 2.1.295. It carries 2.1.292's security fixes, 2.1.294's hook fixes, and today's --tools/--restricted and guard-hook bypass fixes.
  • hooks Add onFailure: "block" to command/HTTP hooks that act as security guards, so a crashed or slow hook fails closed. Re-test any prompt/agent hooks phrased as instructions ("Block commands that…") — before 2.1.294 they could allow what they should block.
  • AWS / gateway If you run the Claude apps gateway on Bedrock, grant bedrock:CountTokens to its role. Consider per-upstream models lists and timeouts.upstream_ttfb_ms for failover.
  • MCP protocol claude.ai connectors now join stdio servers in negotiating 2026-07-28 by default. MCP_PROTOCOL_NEGOTIATION=legacy is the escape hatch.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs that hadn't set it, since 2 Oct (doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

Guardrails are getting stricter defaults. Three releases in a row (2.1.292–2.1.295) close gaps where hooks, auto mode or tool lists could be bypassed. Treat hooks as part of your security boundary and test them on each upgrade.
stable still lags. It moved to 2.1.286 but remains nine releases behind latest, missing four permission-hardening releases. Pin to latest-track versions on managed machines.

Claude Desktop

v2.26454.2 · 7 Oct · bundles Claude Code 2.1.293

What's new

No new Desktop release since 7 Oct. v2.26454.2 still bundles Claude Code 2.1.293, so today's 2.1.295 fixes reach the Code tab on the next Desktop bundle bump.
Desktop-relevant fixes in Claude Code 2.1.295. Desktop and SDK sessions now switch back to auto mode without a restart after disableAutoMode is removed; status for a session waiting on a permission prompt names the MCP tool by server and readable name; macOS sessions started in the home folder no longer trigger the "access data from other apps" prompt. The gateway now serves unknown desktop policy keys with a warning, so new Desktop settings need no gateway upgrade.
Recent (6 Oct, v2.26454.0). Claude Desktop for Debian/Ubuntu (.deb, x64 & arm64); a failing reply or tool step no longer takes down the whole chat; fixed installed plugins disappearing. Older managed-config key spellings stopped being accepted on 7 Oct — confirm managed configs use current keys.

Claude Cowork

GA · macOS, Windows & Linux · web & mobile · cloud by default on Pro/Max

What's new

Routines and scheduled tasks (Claude Code 2.1.295). Fixed some older routines starting without their saved prompt (they now run it again); fixed a message after unarchiving a cloud session getting no reply; a background /loop whose wakeup came due while the process was down now says so; scheduled tasks survive rewind and compaction correctly. Scheduled and Run-now routines in telemetry-disabled installs now publish private artifacts without asking.
Plugins & marketplaces. Marketplaces in repos with large git submodules now add and refresh (only plugin submodules are fetched); claude plugin marketplace add refuses a marketplace name nothing can install under; /plugin's Errors tab now asks before removing a failed marketplace. Enterprise skill/plugin scanning on by default since 2 Oct.
Cloud by default (since 6 Oct) on Pro and Max. New tasks run in the cloud; "Only on your computer" was removed. Local folder access still needs the desktop app open. See Use Claude Cowork on web, desktop, and mobile and Claude Cowork and chat are one Claude.
