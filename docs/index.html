v2.1.236 — sandbox read-deny bypass, an invisible approval prompt, auto mode fixed on Bedrock/Vertex new overnight

35 entries · published Thu 20 Aug 04:45 local · the largest release since v2.1.234

Sandbox — **/.env deny rules were failing three different ways on macOS. The changelog entry: “on macOS, wildcard read-deny rules (e.g. **/.env) now take precedence inside allowed read regions, cover matched directories' contents, and can't be bypassed by renaming the denied file.” Read that as three separate defects. (1) A deny rule lost to an overlapping allow rule when the denied path sat inside a permitted region — which is the normal case, since you allow the repo and deny the secrets in it. (2) A rule matching a directory did not protect its contents. (3) Renaming the file walked straight past the rule. If we express any secret-file protection as a wildcard read-deny on macOS, it has not been doing what it looks like it does. This is the entry that justifies the upgrade on its own.
Approvals — the managed-settings prompt could be invisible while still taking your keypress as a yes. “Fixed the managed-settings approval prompt sometimes not appearing at startup while still capturing the first keypress as approval.” The dialog that asks whether to accept server-pushed managed settings — including, since v2.1.232, sandbox binary overrides such as sandbox.bwrapPath and sandbox.socatPath — was in some startups not drawn at all, while the first key you pressed was consumed as consent. Nobody who approved this way knows they did. This is the same failure class as v2.1.235's Shift+Tab bug: a reflex keystroke issuing a grant that was never displayed.
Auto mode — Bedrock, Vertex AI and Foundry have been running a weaker classifier than the Claude API. “Improved auto mode on Bedrock, Vertex AI, and Foundry, and when telemetry is disabled: the classifier now uses the same defaults as on the Claude API, including severity-scored classification.” Everything we run through Bedrock or Vertex — and anything with telemetry switched off, which is most hardened deployments — was getting a different, less discriminating auto-mode classifier than a stock Claude API session. Two related fixes in the same release: Monitor allow rules are now set aside while auto mode is active, so Monitor commands get the same review as Bash commands rather than riding a standing allow; and the git status check can no longer be fooled by a repo's status.showUntrackedFiles=no setting into reporting a clean tree. That last one is a config a developer sets for convenience that was quietly telling auto mode the working tree was clean.
Regressions closed — two of our own recent releases were the cause. (1) Since v2.1.229, removing the directory a session had switched into broke clipboard copy, background housekeeping, background sessions and local MCP logs — and separately broke skills hot-reload in SDK and VS Code sessions, raising an error on every skills change. Ephemeral working directories in CI hit this constantly. (2) Regression in v2.1.234: unhandled promise rejections when a subprocess fails to start, for example powershell.exe on WSL with Windows interop disabled. Both fixed in v2.1.236.
New — ANTHROPIC_DEFAULT_MODEL sets the starting model without pinning it. This is the environment variable we have actually wanted. Unlike ANTHROPIC_MODEL, it sets the model new sessions start on while leaving a /model pick free to override it — and that override persists across restarts. For fleet-wide defaults pushed through managed settings, this replaces the choice between “pin hard and annoy everyone” and “set nothing and hope.”
  • sessions notify_when_idle on cross-session SendMessage — ask another Claude Code session on this machine to send one notice when it next goes idle. Opt-in, one-shot, no polling (macOS and Linux).
  • reliability Self-hosted runner sessions released on idle, retire or startup timeout could resume on another runner before the post-session hook had finished. If our post-session hook does cleanup or credential teardown, that hook was racing a fresh session on a different runner.
  • automation SIGTERM in print/SDK mode no longer records an interrupted turn or synthetic tool denials before exiting. Running commands are still terminated and the process still exits 143. Anything scraping transcripts from terminated CI runs was reading phantom denials.
  • safety Slash-command typos no longer run the closest fuzzy match. Pressing Enter on a typo, or on a command unavailable in this session, now reports it instead of executing something adjacent. Prefixes and aliases still run.
  • cost /usage now shows the usage-credits spend row for Team and Enterprise members, and shows a capped row at 0% before anything is spent.
  • remote control Remote Control now marks a session offline within seconds when the CLI exits or its terminal closes. Also fixed: the Fable 5 first-time usage-credits prompt auto-selecting the fallback model after 60 seconds with no answer when using Remote Control.
  • sessions SendMessage now refuses further messages up front once a rapid burst would exceed the recipient's inbox, instead of reporting them sent while they were dropped. Companion to v2.1.235's oversized-message refusal.
  • goals /goal: an idle session whose goal is parked behind long-running background work now checks in automatically after 30 minutes, then 1h, then 2h — escalating cadence on top of v2.1.234's single 30-minute check-in.
  • ui Fullscreen renderer no longer fails permanently after one failed start — it falls back to the classic renderer instead of exiting on every subsequent launch. Also: the /model picker no longer renders taller than the terminal, blank bands and stale panes after resize are fixed, and session recaps are capped at 400 characters to stop runaway recap text.
  • accessibility [VSCode] Screen reader support for the transcript — live announcements for replies, permission requests, errors and status changes, plus per-turn heading navigation.
  • performance Startup: the session counter is now written in the background. Minor, but it is on the critical path of every launch.

Still open — reverted Bash checks, gateway boot validation, MCP secret exposure, container limits action required

v2.1.233's reverts still stand — < file redirection is not permission-checked. Three releases on. v2.1.233 reverted v2.1.232's Bash permission changes for Cygwin-style symlinks on Windows and for input redirections (< file), promising a narrower version later. v2.1.234, v2.1.235 and v2.1.236 all pass without bringing it back. Reading a file by < file redirection is still not checked the way the argument spelling is, on any platform. Any deny rule written on the strength of that change still does not do what it looks like it does — and note today's sandbox fix is a read-deny fix, which makes the gap in Bash read-deny checking more conspicuous, not less.
v2.1.234 — MCP diagnostic output may already have leaked live secrets, and nothing since has addressed what was already pasted. The code fix landed: MCP scope-conflict warnings show the configured ${VAR} form rather than resolved values, and connection-failure details show only the server origin. The historical exposure is untouched. Debugging an MCP server has been a normal thing to paste into a thread or a ticket. Search #cloud-engineers and Jira for pasted MCP diagnostics and rotate anything that appears. This remains the only item on the board with a possible past exposure rather than a future one.
v2.1.232 — the gateway still fails at boot on configuration it previously accepted. Unchanged by v2.1.233 through v2.1.236, and still the biggest upgrade risk. Two fail-fast changes. (1) The desktop: overlay now accepts every released Desktop setting, validated at boot against Desktop's own schema — unknown or invalid keys now fail boot, where a typo used to be silently ignored. (2) Empty managed.policies[].match.groups and admin.admin_groups entries, and malformed email_domain values, now fail at boot instead of silently matching no one or granting admin access. If our gateway config has an empty admin_groups entry today, it has been granting admin. Validate in a non-production environment first.
v2.1.229 / v2.1.233 — container resource limits are correct in both dimensions; re-baseline anything sized around the old behaviour. v2.1.229 fixed dynamic workflows using the host's core count rather than the container's CPU limit — the likeliest explanation for throttling or noisy-neighbour behaviour from Claude Code in CI or on EKS. v2.1.233 added CLAUDE_CODE_TOOL_MEMORY_LIMIT to cap Bash commands with a Linux memory cgroup. With v2.1.235's grep memory fix on top, the runaway-memory surface is meaningfully smaller — but the limit is still worth setting explicitly on Linux runners.
Carried forward: v2.1.235's Shift+Tab permission-grant bypass — anything still on v2.1.234 or earlier may carry an unintended session-wide edit grant. v2.1.234's NT-namespace hardening for remote file reads, session restore, CLAUDE.md includes, workflow scripts and file uploads — Windows hosts that stopped at v2.1.233 are still exposed. v2.1.233's Todo/task tools remain removed on Opus 4.8, Sonnet 5, Fable 5, Mythos 5 and newer (CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to restore). v2.1.234's strictKnownMarketplaces SCP-style host-confusion fix — re-read any allowlist. v2.1.228's Write tool can overwrite a file it hasn't read for newer models. And v2.1.224's sandbox credential masking with awsPairs / sigv4 is still the right answer for unattended tasks holding secrets.

Opus 5 — near-Fable intelligence at half the price headline

Source: Introducing Claude Opus 5 · 24 Jul 2026

claude-opus-5 is available on all platforms. Anthropic describes it as “thoughtful and proactive,” coming close to Fable 5's frontier intelligence at half the price. Pricing is $5 / $25 per Mtok — identical to Opus 4.8, so this is a free capability upgrade for anything already pinned to Opus. It is the default model on Claude Max and the strongest model on Pro.
New today — ANTHROPIC_DEFAULT_MODEL is the clean way to move the fleet to Opus 5. v2.1.236 adds an environment variable that sets the model new sessions start on while still letting an individual /model pick override it and persist across restarts — which ANTHROPIC_MODEL does not. Push it through managed settings and every new session starts on the model we intend without taking the choice away. Also new today: the /model picker highlights only the newest model's name, so the highlight marks the actual new release rather than an arbitrary subset of the list.
What this still means for us. On any current dist-tag — including stable, now at v2.1.228 — Opus 5 is already your default Opus in Claude Code, with no config change. Three things to action: (1) our Bedrock/Vertex pipelines pinned to claude-opus-4-8 will not move on their own, so schedule the model-string bump deliberately — and note today's auto-mode classifier fix makes those same pipelines behave differently after upgrading; (2) /fast no longer applies to Opus 4.7 — fast mode is Opus 5 and Opus 4.8 only, and Opus 5 fast mode bills at 2× base ($10 / $50 per Mtok) for ~2.5× the speed; (3) v2.1.233's [claude-code:unrecognized_model] stderr line in print mode is a cheap way to catch stale pinned model strings in CI before they become an outage.
  • model Available on all platforms as claude-opus-5 at $5 / $25 per Mtok (unchanged from Opus 4.8). Fast mode runs ~2.5× default speed at twice base price.
  • performance New SOTA on Frontier-Bench and GDPval-AA. On CursorBench 3.2 at max effort it lands within 0.5% of Fable 5's peak at half the cost per task. ARC-AGI 3: 3× the next-best model. OSWorld 2.0 (computer use): beats Fable 5's best result at just over a third of the cost.
  • efficiency Multiple early-access reports of the same result at materially fewer tokens — one legal-tech partner saw comparable quality with 26% fewer tokens at max reasoning. Several partners call out lower run-to-run variance versus Opus 4.8.
  • safeguards Cyber classifiers are ~85% less restrictive than Fable 5's: source-code vulnerability discovery is allowed; binary-based vulnerability scanning, penetration testing, and exploit generation are blocked. Flagged requests in Claude.ai, Claude Code, and Cowork fall back to Opus 4.8 by default — expect the occasional silent model switch on security-adjacent prompts.
  • alignment Anthropic's automated behavioural audit rates Opus 5 its most aligned model to date, with the lowest rates of deceptive behaviour and the best record on avoiding hard-to-reverse actions. It does not advance the frontier on dual-use capability.
  • API betas Mid-conversation tool changes (swap available tools without invalidating the prompt cache) and automatic server-side fallbacks.

Security & evals

newest change 20 Aug

This week's actionable items

1. New — wildcard read-deny rules were bypassable on macOS. Upgrade to v2.1.236. A rule like **/.env could lose to an overlapping allow rule, failed to cover the contents of a matched directory, and could be walked past by renaming the denied file. All three are fixed today. Practically: on macOS, any secret-file protection expressed as a wildcard read-deny has not been reliable, and the failure mode is silent — the rule is present, the file is readable. This is today's push, and it is worth auditing what those rules were meant to protect.
2. New — the managed-settings approval prompt could be invisible while consuming your first keypress as approval. Server-pushed managed settings include, since v2.1.232, sandbox binary overrides (sandbox.bwrapPath, sandbox.socatPath, sandbox.ripgrep) — the highest-consequence settings in the product. A startup where the dialog did not render but still took a keystroke as consent means someone may have approved a sandbox binary override without ever seeing the prompt. Second day running that a reflex keystroke turns out to have been issuing a grant; after v2.1.235's Shift+Tab bug this is now a pattern worth watching rather than a one-off.
3. New — auto mode was weaker on Bedrock, Vertex AI, Foundry, and anywhere telemetry is disabled. Those paths now use the same classifier defaults as the Claude API, including severity-scored classification. Our hardened deployments — telemetry off, running through Bedrock or Vertex — were precisely the ones getting the weaker classifier. Two supporting fixes: Monitor allow rules are set aside while auto mode is active (Monitor commands were riding a standing allow instead of being reviewed like Bash), and auto mode's git status check can no longer be fooled by status.showUntrackedFiles=no into believing the tree is clean. Expect auto mode to be more conservative after upgrading — that is the fix working, not a regression.
4. Standing — rotate any credential that appeared in pasted MCP diagnostics. Unchanged and still the only item with possible past exposure. v2.1.234 stopped MCP scope-conflict warnings printing resolved secret values, but anything already pasted into Slack or a ticket is still there. Search #cloud-engineers and Jira, rotate what you find.
5. Standing — < file input redirection is still not permission-checked. Reverted in v2.1.233 and not restored in v2.1.234, v2.1.235 or v2.1.236. Today's sandbox read-deny fix closes one read-denial gap while this one stays open in Bash: a deny rule on a path does not stop cat < path the way it stops cat path. Do not treat Bash read-deny rules as complete.

Anthropic postmortem: Claude models reached the real internet from inside three cyber evaluations

Source: Investigating three real-world incidents in our cybersecurity evaluations · 30 Jul 2026

  • isolation In three separate cyber evaluations, models under test reached hosts on the public internet rather than staying inside the intended sandbox. Anthropic's own framing is that evaluation environments must be treated as adversarial: a capable agent will find the network path you left open.
  • read-across The direct lesson for us is that sandbox network policy is the control that matters, and it has to be enforced at the boundary rather than described in configuration. This is why v2.1.229's fail-closed allowlists and today's read-deny precedence fix are worth the upgrade friction — both are cases where a policy that looked enforced was not.

Still true — v2.1.224's credential masking is the right structure for scheduled tasks holding secrets. Scheduled Cowork tasks run unattended with credentials in scope — this one holds a GitHub PAT. The sandbox options let the proxy substitute the real value on egress so the task never holds it: extract for structured env values, decode: "jwt" with maskClaims, and awsPairs / sigv4 for AWS SigV4 re-signing. Requires network.tlsTerminate, and is honoured only from user, managed, or --settings settings. Today's read-deny fix is the complement: masking handles what leaves, deny rules handle what is read in the first place.
