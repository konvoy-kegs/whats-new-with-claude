Claude Code

CLI · v2.1.263 on latest and next
All sources aligned on v2.1.263. The newest npm publish, the latest dist-tag, the next dist-tag, the changelog top entry and the newest GitHub release all say v2.1.263 (published Sun 06 Sep 12:07 local, GitHub release tagged 12:54). claude update installs v2.1.263 this morning. The canary/promotion split we flagged on Friday has closed: next and latest are the same build again.
But v2.1.263 is documented in name only. Its entire changelog entry, and its entire GitHub release body, is one line: “Bug fixes and reliability improvements.” There is no v2.1.262 on npm — the number was skipped. So the newest build with a substantive changelog is v2.1.261, and the two releases below (v2.1.261 and v2.1.260) are both new since Friday's digest. v2.1.260 was undocumented on Friday; its 66 entries have since landed and include four permission-enforcement fixes that matter to us.
Three things changed over the weekend that we should act on before a broad rollout. (1) v2.1.260 fixed Edit/Write/Read permission rules whose path contains parentheses being silently dropped — “read-only” folders were writable. (2) v2.1.260 reverted the v2.1.259 change that applied Read() deny rules to Bash arguments, because it denied npm run build under a Read(./**/build/**) rule. (3) v2.1.261 changed machines pinned to forceLoginMethod: "gateway" to ignore a leftover API key or claude.ai login and demand /login. Details under Security below.

v2.1.261 — skill pruning, bigger inline output, and gateway login enforcement newest documented

Added /skill-doctor to show which loaded skills go unused and what they cost in context. Every skill we provision is a fixed context tax on every turn whether or not it fires. This is the first tool that tells us which ones are dead weight — run it across a few representative sessions before the next skills review.
Added bashOutputMaxChars and taskOutputMaxChars settings to raise how much command and background-task output Claude receives inline before it is spilled to a file, up to 128K characters. Relevant to anyone whose kubectl, terraform plan or aws output was being truncated into a file the model then had to re-read. Pair with --append-subagent-system-prompt-file, also new, for subagent prompts too large for the command line.
Changed machines whose managed settings pin forceLoginMethod: "gateway" to ignore a leftover API key or claude.ai login and ask for /login. Bedrock, Vertex AI and Foundry sessions are unaffected. If we set forceLoginMethod and someone still had an old ANTHROPIC_API_KEY in their shell, that key was winning. After this release it stops working, and the person sees a login prompt. Expect a handful of “Claude Code is asking me to log in again” tickets; they are the policy working.
Fixed the Bedrock setup wizard hanging when AWS or an AWS credential helper never responds — it now times out with a clear error — and its model checks failing behind a TLS-inspecting proxy. Also new: an “Organization policy” line in /status and claude doctor that says why the org policy could not be loaded (for example a proxy not passing the endpoint through). Both directly relevant to our AWS SSO and proxy setup.
Changed auto mode to treat a link that packs content into a public diagram renderer's URL as an upload to that site. No longer auto-approved unless you asked for it. A Mermaid or PlantUML live-editor URL carries the whole diagram source in the query string; auto mode was happily “opening” those. Correct fix. Also: the dangerous-rm safety prompt now catches rm -rf on positional parameters and inside double-quoted sh -c scripts.
Fixed resuming a session losing hook output and other context around parallel tool calls, which changed the resumed request. Also fixed: cloud sessions discarding a plugin synced from claude.ai when managed settings force-enable it in enabledPlugins, then falling back to a marketplace clone that could fail; and claude.ai connectors staying absent for a whole session when the startup connector fetch timed out (the CLI now retries in the background).
A dozen Remote Control fixes — stale permission mode on attach, stuck spinner after stopping from a phone, inbound event stream failing behind TLS-inspecting proxies on native Windows, /teleport sessions uploading into the connected session, and SDK/cloud sessions ignoring a Stop sent before the first turn started. If anyone steers local sessions from the claude.ai app, upgrade.
Also worth knowing: a Claude apps gateway 403 on managed-settings load now says Claude Code may not be enabled for the organization instead of advising a new sign-in; /context uses a local token estimate when the counting API is unavailable; prompt word-editing keys now match Bash (Ctrl+W, Alt+F, Alt+D) and keybindingFlavor no longer has any effect; feature flags gated to a newer version no longer occasionally apply to an older build on the same machine. [VSCode] MCP servers can now be added and removed from a dialog without leaving the IDE, and the model picker is one flat list.

v2.1.260 — the diff panel, prompt-cache diagnosis, and four enforcement fixes documented since Friday

Added a diff panel that opens beside the conversation in fullscreen mode and shows your uncommitted changes as Claude edits; toggle it with /diff. The most-requested UI change in months. You no longer have to leave the session to see what has actually been touched.
Added a likely cause for prompt-cache misses to /cost and the status line's prompt_cache field — tool definitions or system prompt changed, idle past the TTL, and so on. Cache misses are our largest controllable cost line; this is the first time the CLI says why one happened. Paired with fixes for prompt caching on Fable 5.1 not covering context attached after tool results (re-sent uncached on every tool-call turn) and /effort changes mid-session invalidating the cache.
Fixed Edit/Write/Read permission rules whose path contains parentheses being dropped as invalid or ignored by the Bash sandbox, which left “read-only” folders writable. And: one file permission rule with an uncompilable pattern (an unclosed [, say) made every file edit fail; such a deny rule now guards the literal path it spells. Audit any rule with (, ) or [ in it — on Windows, Edit(C:\dir\(name)\**) was being read as an escaped parenthesis. The settings error now suggests an unambiguous spelling.
Reverted the v2.1.259 change applying Read() deny rules to Bash arguments. It denied npm run build under a Read(./**/build/**) rule in every mode and made cd … && grep prompt even in auto mode. Friday's digest told you deny rules now covered option values and cd DIR && cat FILE compounds. As of v2.1.260 they do not. The lesson stands: deny rules are a mistake-catcher, not a boundary.
Fixed Bash permission checks auto-approving zsh commands that hide a command substitution in a REPORTTIME, REPORTMEMORY or DIRSTACKSIZE assignment. Another shell-parsing bypass in auto mode; these now prompt. Also fixed: permissions.blockReadsOutsideWorkingDirectories on macOS hiding the user's git config from sandboxed git and hiding a worktree-isolated sub-agent's own checkout.
Fixed managed settings not loading for claude.ai Enterprise/Team users who also had a leftover API key from an earlier /login. Fourth consecutive release with a fix for policy silently not applying. /status now marks which of a signed-in account and a configured API key is actually in effect. Also fixed: managed skillOverrides keyed on a bundled skill's alias not applying, and Skill(name) deny rules not covering a nested <dir>:name skill.
AWS-specific: Bedrock model discovery, token counting and SSO/STS credential calls no longer fail with “unable to get local issuer certificate” when the corporate root CA is only in the OS certificate store. The Claude apps gateway on Bedrock now counts input tokens for an aborted request with the free CountTokens API — grant bedrock:CountTokens in the gateway's IAM policy or aborted requests fall back to a one-token billable call. Vertex startup no longer spawns extra gcloud processes when GOOGLE_APPLICATION_CREDENTIALS is set.
Fable 5.1 is now selectable in /model for organisations that can use it (previously only accepted as typed /model claude-fable-5-1), model: fable agents honour the [1m] tag on ANTHROPIC_DEFAULT_FABLE_MODEL, and auto-compact on Opus and Fable now runs shortly before the 1M limit instead of timing out on very large contexts.
Also worth knowing: /rewind no longer reports success when checkpoint backups were missing and nothing was restored; the one-hour limit on subagent background commands is removed; the ! bash-mode prompt now runs outside the sandbox even under strict sandbox mode, like typing into your own terminal (deliberate — note it); Claude in Chrome now follows the organisation's admin setting and is unavailable when an admin turns it off; a managed CLAUDE.md no longer triggers the security approval dialog; GitLab nested subgroups and owner/repo#123 links on GitLab are fixed. [VSCode] effort level shown in the footer model pill; Open/Closed filters in the session list.

Models

Fable 5.1 now in the picker
No new model since Fable 5.1 (announced 1 Sep, shipped in v2.1.257). What changed over the weekend is access: v2.1.260 fixed the /model picker not showing Fable 5.1 for organisations entitled to it, fixed prompt caching on Fable 5.1 skipping context attached after tool results, and stopped /effort changes from invalidating the cache. If Fable 5.1 looked expensive last week, part of that was the caching bug. Behind a Claude apps gateway, fable and best still resolve to Fable 5 until the gateway is configured for 5.1.

Security & evals

action required

This week's actionable items

  • roll out v2.1.263 is safe to standardise on. Friday's hold on v2.1.260 is lifted: it is documented, promoted, and superseded. v2.1.263 itself adds only “bug fixes and reliability improvements”, so the review surface is v2.1.260 + v2.1.261, both below.
  • audit Every file permission rule with parentheses or brackets in its path. v2.1.260: rules with (/) were silently dropped, leaving “read-only” folders writable; an unclosed [ broke every edit. On Windows, \( reads as an escape. Rules that looked configured were not in force.
  • re-read The Read()-on-Bash coverage from v2.1.259 is reverted in v2.1.260. If you widened deny rules last week expecting them to cover --file=.env or cd DIR && cat, they no longer do. Sandboxing and permissions.blockReadsOutsideWorkingDirectories remain the controls that hold.
  • expect tickets forceLoginMethod: "gateway" now rejects leftover API keys and claude.ai logins (v2.1.261). Anyone who has been quietly running on a personal key under a gateway-pinned policy will be asked to /login. That is the control finally working — but tell support before the tickets arrive.
  • IAM Grant bedrock:CountTokens to the Claude apps gateway role (v2.1.260). Aborted requests are now counted with the free CountTokens API instead of a billable one-token call; without the permission the count fails.
  • note The ! bash-mode prompt now runs outside the sandbox even under sandbox.allowUnsandboxedCommands: false (v2.1.260). Intentional — it is you typing, not the model — but if the sandbox was part of a compliance story for interactive use, the story has a footnote.
  • check first allowedMcpServers no longer filters managed MCP servers (v2.1.259, still in force). A managed-mcp.json server the allowlist used to suppress loads on upgrade; move it to deniedMcpServers before rollout.
  • validate Validate the managed-settings payload before deploy. Unparseable managed settings refuse to start the CLI (v2.1.259), and the Claude apps gateway now also refuses to start when a desktop policy misspells a field in a nested managedMcpServers or orgPluginSettings entry (v2.1.260). Fail-closed, org-wide.
  • enable --permission-prompts none on unattended runners (v2.1.259) replaces bypassPermissions as the headless posture. permissions.blockReadsOutsideWorkingDirectories (v2.1.257) is the read boundary; v2.1.260 fixed it hiding git config on macOS, so it is now usable without breaking git.
  • verify Containment Escape rule on EC2/EKS runners (v2.1.257): metadata-credential fetches now stop and ask in auto mode. v2.1.261 adds a similar rule for diagram-renderer URLs that carry content.
  • audit Write access to any GitHub repo backing a private plugin marketplace — sixth consecutive week. claude plugin validate --json (v2.1.259) makes the CI gate easy. v2.1.261 fixed plugin install hints from background CLIs leaking raw <claude-code-hint> tags into the conversation.
  • unpin Move anything pinned to the stable dist-tag. stable is v2.1.236 from 20 Aug — twenty releases and every fix on this list behind.

Patterns worth tracking

Channels have reconverged, and the digest can go back to reading “newest on npm” as “what claude update gives you”. Friday's split (v2.1.260 on next, v2.1.259 on latest) lasted under a day. Worth remembering that it can happen; not worth restructuring around.
Permission enforcement fixes are now a weekly certainty, and the direction is “the rule you wrote was not the rule in force”. Parenthesised paths dropped, uncompilable patterns breaking everything, zsh variable-assignment substitutions auto-approved, leftover API keys overriding both managed settings (v2.1.260) and forceLoginMethod (v2.1.261). Every one of these is a case where configuration and enforcement diverged silently. Treat “we set the policy” and “we verified the policy applies on a real machine” as separate tickets.
A change shipped and reverted inside two releases. The Read()-deny-on-Bash-arguments widening in v2.1.259 broke npm run build and was pulled in v2.1.260. We advised acting on it on Friday. Guidance in this digest about a control that is less than a week old should be read as provisional.
Cost visibility is improving faster than cost control. /cost now names the likely cause of a cache miss, /skill-doctor names the skills that cost context and never fire, and three Fable 5.1 caching bugs were fixed in one release. Run both tools across a sample of sessions this week and bring the numbers to the next spend review.

Claude Desktop

macOS · Windows · Linux (beta)

What's new

Fable 5.1 is the Desktop-visible change of the week. The support-centre release note dated 1 Sep announces Claude Fable 5.1 and Mythos 5.1 for chat and Cowork; no other Desktop release-note entry has appeared since. Fable 5.1 — 1M context, $10/$50 per Mtok — is the default Fable model in the picker where the organisation is entitled to it. Enterprise admins control which models and effort levels users see under Manage model access (beta since 1 Jul).
From v2.1.260/261 — the Claude apps gateway now speaks Desktop's newer policy keys. desktop policy blocks accept userPluginMarketplacesEnabled and userPluginUploadsEnabled, orgPluginSettings is sent in the list form read by Claude Desktop 1.15200.0 and later (older desktops ignore it), and a misspelt field in a nested policy entry now stops the gateway starting rather than being silently dropped. If we govern Desktop through the gateway, check the Desktop version floor and re-validate the policy file.
From v2.1.261 — Desktop's OpenTelemetry export was being told to use JSON while the terminal CLI uses protobuf, so protobuf-only collectors rejected Desktop's data. Fixed. If Desktop-hosted Claude Code sessions have been missing from the collector while terminal sessions appear, this is why — and it stacks on the v2.1.259 fix for cloud-session telemetry missing user.email, organization.id and user.account_uuid. Expect a step change in attributed Desktop usage after upgrade.
From v2.1.261 — Desktop and web no longer show a session as busy while it is only watching an artifact for updates. Small, but it was making idle sessions look stuck. Also from v2.1.260: /reload-plugins and a text form of /advisor now appear in the Desktop command list; SDK-provided MCP servers (Desktop connectors) no longer go missing from the first turn; -p --resume as used by Desktop no longer fails on every retry once a worktree loses its git metadata.
Standing context — memory, the Customize panel, and Cowork GA. Memory (25 Aug) works across chat and Cowork in the cloud; everything remembered is listed under Settings > Memory > Topics and can be edited or deleted. On by default for Free, Pro and Max; off by default for Team and Enterprise — on our plan nothing is retained unless somebody turned it on. Also live: a Customize section grouping skills, plugins and connectors; the monthly recap at Settings > Reflect; break reminders and quiet hours at Settings > Time and focus.

Claude Cowork

GA · macOS & Windows · Linux beta

What's new

No new Cowork release-note entry since 25 Aug (memory in Cowork). Everything below comes from the CLI changelog, which is where Cowork's runtime fixes actually land.
From v2.1.261 — Claude in Chrome file_upload was failing with “paths: expected array, received undefined” in local Cowork sessions run from the Desktop app. Fixed. Also from v2.1.260: the Artifact tool's first call failing with “Invalid tool parameters” in some Cowork sessions, and Claude in Chrome tools dropping to “Not connected” mid-task in cloud-hosted sessions when a connector was added or removed. Two of the three integrations this digest depends on had a first-call failure mode until this weekend.
From v2.1.261 — cloud sessions were discarding a plugin synced from claude.ai when managed settings force-enable it in enabledPlugins, then falling back to a marketplace clone that could fail. If we force-enable an org plugin, cloud Cowork sessions were sometimes running without it or failing to start it. Paired with a fix for claude.ai connectors staying absent all session when the startup fetch timed out; the CLI now retries in the background.
From v2.1.260 — plugins from a URL marketplace failed to install with “marketplace entry path does not stay inside the marketplace directory” when a host app such as Claude Desktop stores it as a directory. Fixed. Also: an extra browser tab no longer opens when an artifact is published from a session driven via claude.ai, Desktop or mobile.
From v2.1.261 — /skill-doctor applies to Cowork too. Every plugin we install adds skills that load into every session; /skill-doctor is the first way to see which ones never fire. Run it in a Cowork session before the next plugin review.
Carried forward — scheduled-session fixes from v2.1.257–259 are all in v2.1.263. Remote and scheduled sessions doing nothing after a connector permission was approved while paused; failing with “user messages must have non-empty content”; /schedule routines saved without a message role. If a scheduled task silently produced nothing on a recent day, upgrade and re-run before debugging the task. Reading an artifact that is not yours still always asks first, even in auto mode (v2.1.257).
Standing context — plugins, skills, artifacts and scheduled tasks. Plugins bundle skills, connectors and sub-agents into one installable package; hooks and sub-agents run only in Cowork. Customize in the upper right tailors an installed plugin to how you work. Artifacts created on or after 19 Aug are shareable, connected, versioned and openable from the web. Cowork sessions run remotely in the cloud (beta) so scheduled tasks fire with no device online. Enterprise plans can turn on skill and plugin security scanning (6 Aug) — still worth enabling given six consecutive weeks of marketplace and plugin path fixes in the CLI.
