What matters this morning. (1) Hooks visibility (2.1.329). The trust dialog now says where a folder's hooks are declared, and Desktop/headless hosts warn in-conversation when hooks in managed settings fail to load — worth checking managed hook rollouts. (2) Scheduled tasks change (2.1.329). Most scheduled tasks saved by earlier versions need scheduling again in new signed-in sessions; "Exit and stop tasks" now ends them for good. (3) Runner safety (2.1.328). Fixed self-hosted runners deleting a kept clone's objects/refs (and commits only there) after a temporary disk error, and a scheduled task being deleted when the tasks file had a typo. (4) Config durability (2.1.329). Fixed ~/.claude.json sometimes being reset to defaults during a network stall or file lock.

v2.1.329 — hooks visibility, scheduled-task changes, config durability Fri 20 Nov AEDT · 130 bullets · latest

security · hooks & auth Trust dialog now warns where a folder's hooks are declared. Warning in Claude Desktop and other non-interactive hosts when hooks in managed settings fail to load. Fixed repeated macOS sign-outs when the Keychain was readable but not writable (session now stops at expiry and says why). Fixed an MCP server being re-authenticated after you cleared its auth during a token refresh. /sandbox on Linux now says allowUnixSockets entries aren't actually opened. Computer use on macOS updated to newer safety rules.
behaviour changes Saved scheduled tasks: most saved by earlier versions need scheduling again in new signed-in sessions (--resume of their own session still runs them). "Exit and stop tasks" now ends scheduled tasks so they don't run on resume. /code-review with no target reviews the whole branch against the default branch; /code-review <pr> now reads the PR via gh pr diff or stops. Removed 2.1.326's automatic retry on max_tokens errors — behind a gateway with a lower output cap, set CLAUDE_CODE_MAX_OUTPUT_TOKENS. Code Mode: an erroring PreToolUse hook no longer refuses a tool call — set "onFailure": "block" where it must. Gateway now warns at every start while access_control.allow_cidrs is empty.
features /tasks now lists scheduled tasks, /loop wakeups, goals and forks; /mcp shows a remote HTTP server's JSON-RPC refusal message; /status names managed marketplaces that don't auto-update; Code Mode works with OpenTelemetry events and metrics on.
reliability Fixed ~/.claude.json being reset to defaults on a network stall or file lock; HTTP MCP servers on older protocol versions reconnect by themselves; MCP-sent PDFs/images typed application/octet-stream no longer saved as .bin; self-hosted runner fixes for Git LFS, SSH host aliases and remote MCP timeouts; many Code Mode memory and runaway-loop fixes.

v2.1.328 — auto mode on cloud providers, MCP hook blocking Thu 19 Nov AEDT · 144 bullets

auto mode Auto mode added for Claude Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and the Claude apps gateway; interactive sessions with no permission mode start in it.
security · hooks & runners "onFailure": "block" now available for mcp_tool hooks; warning when a message from a permission-skipping session may be dropped by a cloud session; CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME; fixed self-hosted runners deleting a kept clone's objects/refs after a temporary disk error; fixed runners stopping when the token expired on a host with a slow clock; fixed a scheduled task being deleted when the tasks file had a typo.
observability /status and claude doctor flag an OpenTelemetry exporter with no endpoint; gateway warns on an invalid maxEffortLevel.

v2.1.327 – v2.1.326 — previous releases Tue 17 – Wed 18 Nov AEDT

2.1.327 · data-loss fixes Remote Control worktree stop no longer deletes git-ignored files (.env); runner git-proxy no longer deletes GIT_CONFIG_GLOBAL; claude mcp add-json <name> - reads JSON from stdin; shell rc files may run before the first Bash approval (CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1 to opt out).
2.1.326 · bypass-mode tightening Some bypass-mode tool calls now ask or are denied; file tools refuse writes to .credentials.json; OTEL_RESOURCE_INCLUDE_HOST.

Security & evals

Move runners to 2.1.329 · re-check scheduled tasks and managed hooks

Today's actionable items

  • upgrade · v2.1.329 Move self-hosted runners, Remote Control hosts and headless claude -p jobs to 2.1.329 — picks up 2.1.328's kept-clone deletion fix and 2.1.329's ~/.claude.json reset fix on top of 2.1.327's data-loss fixes.
  • scheduled tasks After upgrading, check Claude Code scheduled tasks still exist (/tasks now lists them) — most saved by earlier versions need scheduling again.
  • managed hooks Watch for the new "hooks in managed settings failed to load" warning in Desktop/headless sessions; for hooks that must enforce, set "onFailure": "block" (now also on mcp_tool hooks).
  • gateway If running the Claude apps gateway, make sure access_control.allow_cidrs is set — never expose it to the public internet. Gateways with lower output caps should set CLAUDE_CODE_MAX_OUTPUT_TOKENS.
  • dates 30 Nov: Opus 4.8 fast mode removed; Plugins page reaches Enterprise and turning off Skills also blocks plugins in Cowork. 17 Dec 12:00 PT: remove deprecated Desktop keys coworkTabEnabled, chatTabEnabled, chatAdvancedFileAnalysisEnabled.
