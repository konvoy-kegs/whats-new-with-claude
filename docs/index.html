What matters this morning in v2.1.311. No new models, no pricing changes, but two model-adjacent behaviour changes: ultrathink now runs its turn at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 through Anthropic's API (typed mid-turn it raises the rest of that turn), and model names drop the [1m] suffix where it has no effect. For the Bedrock-backed sessions the big one is a new outbound dependency: Claude Code on Bedrock, Mantle, Vertex and Foundry now loads model settings from a signed file on downloads.claude.ai (CLAUDE_CODE_MODEL_CATALOG=off turns it off) — check egress allowlists before rolling out. Self-hosted runner gains --hold-idle-file and --max-hold-min to keep an idle session alive while the host reports processes it left running. A long list of reliability fixes for unattended work: SubagentStop hooks were firing about twice a minute per subagent instead of once; subagents couldn't use MCP tools from servers that connected after they started; a subagent's isolated worktree could be removed while a background subagent was still in it; claude -p/SDK transcripts were saved out of order; Claude Code was retrying requests the API marked not-to-retry (holding a turn for minutes, or indefinitely under CLAUDE_CODE_RETRY_WATCHDOG); and standard-context sessions stopped with "Usage credits required for 1M context" past 200K tokens instead of compacting. Cowork cloud sessions: WebFetch/WebSearch no longer hang on a stalled response (300 s cap), and connectors are no longer lost after a restart when a plugin or settings named an agent.

Security & evals

v2.1.311 CLI: new downloads.claude.ai dependency on Bedrock/Vertex/Foundry, SubagentStop hooks over-firing, not-to-retry requests retried, stale CLAUDE.md after compaction · stable three behind

Today's actionable items

  • upgrade Fleet CLI target moves to v2.1.311. stable is now three releases behind on v2.1.308 and has none of the v2.1.309 sandbox fixes, the v2.1.310 Windows hooks fix, or today's hook, subagent and retry fixes. For runners, auto-mode pipelines and headless claude -p jobs, pin latest or an explicit 2.1.311 rather than waiting for stable.
  • egress: downloads.claude.ai on Bedrock, Vertex & Foundry Claude Code on Bedrock, Mantle, Vertex and Foundry now loads model settings from a signed file on downloads.claude.ai. Sessions that used to talk only to the cloud provider's endpoint now make a call to an Anthropic host at startup. If the Bedrock runner images or VPC egress rules allow only bedrock-runtime.*.amazonaws.com, that call will fail (and the fallback behaviour isn't described in the changelog) — either allow the host or set CLAUDE_CODE_MODEL_CATALOG=off in managed settings before rolling v2.1.311 to those machines. The file is signed, which is the right design, but it is still a remote-controlled model list; decide deliberately whether to take it.
  • SubagentStop hooks fired ~2×/minute per subagent Until v2.1.311, a SubagentStop hook ran about twice a minute for every running subagent instead of once when it finished. Any hook that posts to Slack, writes an audit row or triggers a downstream job on that event has been producing duplicates since subagents went mainstream; de-duplicate what it wrote, and check the hook isn't rate-limited or billed per call.
  • retry watchdog: not-to-retry requests were retried Claude Code was retrying requests the API marked not to retry, which could hold a turn for minutes or, under CLAUDE_CODE_RETRY_WATCHDOG, indefinitely. Any unattended pipeline that occasionally "hung for no reason" on an API error has a plausible cause; fixed in v2.1.311. Keep job-level timeouts anyway.
  • stale CLAUDE.md / MEMORY.md after compaction Right after automatic compaction, Claude saw the old content of CLAUDE.md and MEMORY.md if they had been edited earlier in the session. A policy change made mid-session (a new "never touch X" rule, say) silently reverted for the rest of a long run. Fixed in v2.1.311; until fleets are on it, restart sessions after editing policy files rather than relying on compaction to pick them up.
  • transcript integrity for claude -p / SDK Transcript messages could be saved out of order, and messages that were taken back could be kept. If transcripts are part of the audit trail for automated runs, those from before v2.1.311 may not reflect the order the model actually saw. Also fixed: subagents unable to use MCP tools from late-connecting servers (a subagent that "didn't have the GitHub tool" probably just started before the server finished connecting), and a subagent's isolated worktree being removed while a background subagent was still working in it.
  • Linux sandbox: --plugin-dir + blockReadsOutsideWorkingDirectories Sandboxed Bash commands failed with bwrap: Can't create file when a --plugin-dir folder was also an added directory and permissions.blockReadsOutsideWorkingDirectories was on. That combination is exactly how a locked-down runner with a local plugin folder is set up; if sandboxing was turned off to work around it, turn it back on at v2.1.311.
  • DISABLE_COMPACT is now one-way from settings DISABLE_COMPACT in settings files and in a mod's $.env.set can only turn compaction off, not back on. A managed-settings file that disables compaction (to keep full transcripts) can no longer be undone by a project or user file. Agent teammates also stop compacting under it.
  • Cowork cloud sessions & connectors Cowork cloud sessions lost their connectors and most tools after a restart when a plugin or settings named an agent; they now ignore that setting. WebFetch and WebSearch in Cowork cloud sessions fail after 300 seconds instead of hanging. A finished /code-review (or any skill that runs in a sub-agent) no longer runs a second time when a cloud or background session restarts — one fewer way for an unattended run to double-post or double-commit. The Slack connector now reads a channel's topic for posting rules before messaging a channel you didn't name explicitly.
  • VS Code telemetry follows the editor The extension now starts Claude Code sessions with DISABLE_TELEMETRY set while VS Code's telemetry setting is off, so those sessions send no usage metrics or error reports and fetch no feature flags. If the OTel pipeline relies on Claude Code's own telemetry from VS Code sessions, an editor-level telemetry opt-out now silences it too; use the Claude Code setting, not the VS Code one, to control what the fleet reports.
  • Remote Control & mobile Messages Claude sent to a cloud or Remote Control session appeared as the user's own message in the Claude mobile apps — worth knowing for anyone reading a mobile transcript as evidence of who said what. Patterns worth tracking

stable is three releases behind and counting. It has sat on the one-line v2.1.308 since Thursday while v2.1.309 (79 bullets), v2.1.310 (26) and v2.1.311 (92) shipped on latest. Whatever promotion cadence Anthropic uses, stable is currently a snapshot of the week's least-documented build; fleets that pin it for predictability are running without the sandbox, hooks and retry fixes that matter most. If stable hasn't moved by Thursday, it is worth switching the fleet policy to an explicitly pinned latest version that this digest tracks.
Third-party providers are picking up remote-controlled surfaces. v2.1.310 brought the Monitor tool to Bedrock, Vertex and Foundry; v2.1.311 adds a signed model catalog fetched from downloads.claude.ai on the same providers (plus "Mantle"). Each is sensible on its own, but the net effect is that a "Bedrock-only" deployment now has two Anthropic-hosted dependencies (feature flags were already one). Keep a written list of what each version adds to the egress allowlist; this page will keep tracking it.
Hooks are the recurring reliability theme. v2.1.309 and v2.1.310 fixed Windows hooks failing open; v2.1.311 fixes SubagentStop hooks over-firing and adds a VS Code spinner for slow UserPromptSubmit hooks. The pattern is that hook semantics are still settling under subagents and non-POSIX shells. Any hook that is load-bearing for policy (deny) or for audit (log once per event) deserves a regression test per release, not a one-time check.
Unattended sessions got a lot of attention this release. Not-to-retry requests retried, background sessions not restarted after a crash, /code-review double-running on restart, transcripts out of order, Cowork cloud connectors lost after restart, WebFetch hanging forever. Taken together these read like Anthropic working through a backlog from their own routines and Claude Tag deployments; the upside is that scheduled Cowork tasks (this one included) and claude -p pipelines get noticeably more predictable at v2.1.311.
Desktop is now three CLI releases behind. v3.6556.2 (22 Oct) is still the newest Desktop build and bundles Claude Code 2.1.308, so the Code tab and local Cowork sessions are missing the v2.1.309 hardening, the v2.1.310 Windows hooks fix and everything above. Desktop bumps have been landing roughly weekly; the next one is the one to watch.
