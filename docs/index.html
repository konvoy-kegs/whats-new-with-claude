What matters this morning in v2.1.304. /auto-mode-setup — a guided setup that reads your project and recent sessions to teach auto mode about your environment — now works on Bedrock, Vertex, Foundry, the Claude apps gateway and telemetry-disabled sessions. /claude-api managed-agents-secure compares a Managed Agents agent's settings against Anthropic's published security guide without changing anything. Behaviour change for gateway users: tool search is now on by default behind a custom ANTHROPIC_BASE_URL (a 400/422 from the gateway is retried without it). Two fixes worth knowing about for automation: a plugin could keep a headless run going past --max-turns, Stop or ended input by spawning subagents or re-running a finished one; and claude --worktree could remove the worktree and its branch without asking at exit when HEAD was detached or on another branch, which could lose commits. Also: scheduled Cowork cloud sessions no longer wait five minutes per subagent whose WebFetch needed a URL approval nobody was there to give. Code Review gets Quick / Standard / Deep review levels per org and per repo, and an "every repository in the GitHub organisation, including ones added later" option.

v2.1.304 — auto-mode setup everywhere, Managed Agents security check, settings ceilings, headless & worktree fixes, Code Review levels newest · aligned · 76 bullets

auto mode, Managed Agents & mods Added /auto-mode-setup: a guided setup that reads your project and recent sessions to teach auto mode about your environment, now also available on Bedrock, Vertex, Foundry, the Claude apps gateway and telemetry-disabled sessions. Added /claude-api managed-agents-secure, which compares a Managed Agents agent's settings with Anthropic's published security guide, without changing anything. Added decider: "person" to a mod's tool.check answer: only the permission dialog or a host's callback can approve the ask, and it is refused with the mod's reason where nobody can be asked. Added e.isReadOnly to a mod's tool.check event. Added a transcript line when a plugin that runs first skips one of your mod's hooks, naming the event and the plugin. Improved session file size in auto mode: the safety classifier's context is no longer stored with every request. Updated the /claude-api skill to use the ant CLI on Claude Platform on AWS instead of falling back to the SDK or curl. Removed the "(research preview)" label from the /fast dialog on Opus 5.5.
managed settings, policy & sandbox Changed mods' settings.read hooks to receive each settings layer and rewrite the merged settings, so a managed mod can make an organisation's setting a ceiling, including the cleanupPeriodDays the retention sweep uses. Fixed the organisation policy not refreshing until the hourly check after approving an ANTHROPIC_API_KEY at startup or switching "Use custom API key" in /config. Fixed OpenTelemetry settings delivered through server-managed settings being ignored for the whole session after signing in during first-run setup or the first start after /logout. Fixed sandboxed commands failing to start on Linux when a sandbox.filesystem.denyRead glob contains brackets that are not a character class, such as a [user-id] route folder. Fixed rm -r of a mounted drive or a top-level folder (/Volumes, /media, WSL's /mnt/c) not getting the safety prompt that rm -rf /Applications gets. Changed skills under a policy that allows hooks from plugins only: a skill whose hooks are kept out no longer gets its allowed-tools. Changed skill hooks: the skills of one source can register at most 1,024 hooks and 16,384 matcher characters per session. Fixed a skill's once hook also removing another skill's identical hook after it ran. Fixed a PreToolUse hook's deny reason being replaced by a timeout error when an Agent SDK callback hook on the same tool call timed out.
headless, CI & worktrees Fixed a plugin keeping a headless run going past --max-turns, Stop, or ended input by spawning subagents or re-running a finished one. Fixed claude --worktree removing the worktree and its branch without asking at exit when HEAD was detached or on another branch, which could lose commits. Fixed Bash and PowerShell deleting a large command's output file when it could not be copied to the session's tool-results folder. Fixed CLAUDE_CODE_TRANSCRIPT_LOCAL_GC dropping messages from the saved transcript when the disk filled up while the file was being trimmed. Fixed CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k silently setting a 100K window; the variable now accepts k and M suffixes and warns when a value is out of range. Improved the claude -p invalid-settings warning: a file that did not load lists only what stopped it. Improved resume of large compacted sessions in SDK and headless mode. Fixed claude --help text for --tools, --resume, --debug, --json-schema, --disable-slash-commands, --system-prompt-snapshot and claude update to match actual behaviour. Windows: git commands now start via Git for Windows' git.exe directly instead of its cmd launcher. Self-hosted runner: the "not found" git-host error now names the repository and whom to ask.
gateways, models & cost Changed tool search to be on by default behind a custom ANTHROPIC_BASE_URL; a 400 or 422 from the gateway is retried without it. Fixed context_management: Extra inputs are not permitted errors behind LLM gateways; Claude Code now resends without that field. Fixed /effort status, /effort ultracode and the prompt's effort indicator showing a guessed level when CLAUDE_CODE_EFFORT_LEVEL is auto or unset. Added a warning on Pro and Max plans when resuming an inactive conversation would use a noticeable share of your 5-hour usage limit. Fixed self-paced /loop wakeups scheduled at the 1-hour maximum firing just after the 1-hour prompt cache expired (those wakeups no longer re-read the conversation uncached). Fixed model switches, messages and interrupts waiting behind a context usage check in SDK and desktop sessions. Changed compaction to send Claude the skill list again afterwards; /reload-skills now sends only new or changed skills. Fixed resumed and cloud sessions sending the whole skill list again each time plugins reloaded at startup. Improved /usage to say when a rate limit on usage data ends. Improved responsiveness and throughput when many subagents run at once, and memory use in long or resumed conversations.
Code Review, Claude Tag, VS Code & cloud sessions Code Review: added review levels — Owners choose Quick, Standard (default) or Deep for the organisation and can give individual repositories their own level; added an option to review every repository in a GitHub organisation, including ones added later; fixed PRs opened within a minute or two of turning Code Review on being silently skipped (now retried). Claude Tag (Slack): fixed Claude going silent when its channel becomes shared across Enterprise Grid workspaces mid-task; @Claude !fork outside a thread now gets a private note. VS Code: mod drawing in the chat panel on Bedrock, Vertex, Foundry, gateways and telemetry-off; SessionStart hook time no longer counts toward the 60-second startup limit (up to 10 minutes); background sub-agents show as one status line under their Agent card. Cloud sessions: a new conversation's first turn no longer waits for plugins' local stdio MCP servers synced from claude.ai (unless alwaysLoad: true); fixed scheduled Cowork cloud sessions waiting five minutes per subagent on an unattended WebFetch URL approval; fixed claude.ai Directory plugin skills not running as commands from the "/" menu; fixed the composer's @ list showing folders with no name. Remote Control: fixed history being withheld when a different account was signed in to the terminal, and failing to start from Desktop with DISABLE_TELEMETRY/DO_NOT_TRACK set on a paid plan.

v2.1.302 — headless permission default, fork subagents on by default, auto-mode model Sat 17 Oct AEDT · 63 bullets · still the behaviour change that matters

behaviour changes for automation claude -p and Agent SDK sessions with no permission mode start in default mode on third-party providers, with telemetry off or on a fresh install; --permission-mode auto keeps auto. A CI job on Bedrock or Vertex that never set a mode will stop at its first permission prompt — set the mode explicitly. Fork subagents (subagent_type: "fork") are on by default in claude -p, the Agent SDK, the desktop app and VS Code; CLAUDE_CODE_FORK_SUBAGENT=0 turns them off. The desktop app and VS Code always run the main conversation's subagents in the background. At most 12 prompt/agent hooks of one event run at a time.
auto mode, limits & plugins CLAUDE_CODE_AUTO_MODE_MODEL chooses the client-side auto-mode classifier model. Auto mode with the server-side classifier compacts a too-long conversation instead of denying every checked tool call. Idle compaction row in /config. The Read tool refuses image sources over 128 MB instead of loading them whole into memory. MCP servers negotiating protocol 2026-07-28 without resultType/ttlMs/cacheScope work again. claude plugin no longer exits before a queued settings write lands. Plugin marketplaces no longer re-clone every refresh under git's reftable format. Standalone Claude Design (claude.ai/design) closes by 14 December 2026. Cloud sessions: a routine that failed partway is no longer re-run from the start an hour later.

Security & evals

v2.1.304 CLI (documented) · stable promoted · Desktop v2.42304.2

Today's actionable items

  • upgrade Fleet CLI target moves to v2.1.304, and this one you can cite for change control. Two fixes justify it on their own: a plugin could keep a headless run going past --max-turns/Stop (unbounded spend or runtime in CI), and claude --worktree could delete a worktree and its branch without asking on a detached HEAD, losing commits. Run claude update on every machine on latest.
  • stable is no longer a lagging channel The stable dist-tag jumped from v2.1.292 to v2.1.304 overnight. Anything installed with npm i -g @anthropic-ai/claude-code@stable or pinned to the stable channel picks up twelve releases in one update, including 2.1.302's headless permission-mode default and fork-subagents-on default. If you used stable as a brake, you no longer have one; pin an exact version in your image or installer if you need a controlled rollout.
  • managed settings as ceilings v2.1.304 lets a managed mod's settings.read hook see each settings layer and rewrite the merged result, so an org setting can be enforced as a ceiling rather than a default that users override — the example in the changelog is cleanupPeriodDays for transcript retention. This is the first mechanism for enforcing a maximum, not just a value. Worth a look if retention or sandbox settings need to be non-negotiable.
  • policy refresh Before v2.1.304, approving an ANTHROPIC_API_KEY at startup or toggling "Use custom API key" in /config left the organisation policy stale until the hourly check. OTel settings delivered through server-managed settings could also be ignored for a whole session after a first-run sign-in. Both are fixed; if telemetry had gaps on fresh installs, this is why.
  • gateway users: tool search default v2.1.304 turns tool search on by default behind a custom ANTHROPIC_BASE_URL. A gateway that rejects the field returns 400/422 and Claude Code retries without it, so it should degrade cleanly — but watch gateway error rates for a day after rolling out.
  • sandbox Sandboxed commands failed to start on Linux when a sandbox.filesystem.denyRead glob contained non-class brackets (e.g. a Next.js [user-id] route folder). rm -r of /Volumes, /media or WSL's /mnt/c now gets the same safety prompt as rm -rf /Applications.
  • Managed Agents /claude-api managed-agents-secure diffs a Managed Agents agent's settings against Anthropic's published security guide, read-only. Cheap to run against anything we have deployed.
  • Code Review (GitHub) Review levels (Quick / Standard / Deep) per org and per repo, and an "all repositories, including future ones" switch. If Code Review is on for the konvoy-kegs org, decide whether new repos should be auto-enrolled and at which level. PRs opened within minutes of enabling were being silently skipped; fixed.
  • headless permission mode (carry-over, 2.1.302) claude -p and Agent SDK sessions with no permission mode start in default mode on Bedrock, Vertex, LLM gateways, with telemetry off, or on a fresh install. Pass --permission-mode explicitly in every pipeline. Fork subagents are default-on; set CLAUDE_CODE_FORK_SUBAGENT=0 in managed env if your token budget or threat model assumed otherwise.
  • Desktop v2.42304.2 Shipped 19 Oct with "no user-facing changes" in every section and still bundles Claude Code 2.1.299. The Windows signing-certificate change from v2.42304.0 still stands: Defender certificate indicators and AppLocker/WDAC publisher rules need the renewed certificate added beside the old one. The Desktop Code tab still lacks 2.1.300's updatedInput validation, 2.1.302's permission-mode default and everything in v2.1.304.
  • MCP permission rules (carry-over) Since 2.1.299, mcp__a matches only the server named a. Audit permissions.allow/deny and agent tools: lists for servers with double underscores and rewrite them as mcp__<whole name>__*.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks). See skill and plugin scanning.

Patterns worth tracking

The undocumented patch lasted a day. v2.1.303 shipped Sunday night with a one-line changelog; v2.1.304 followed within 24 hours with 76 bullets and the same list in its GitHub release. The pattern to expect: a thin "reliability" patch followed quickly by the documented release it was clearing the way for. Cite v2.1.304, not v2.1.303.
stable caught up in one jump. After 17 days parked on v2.1.292, stable moved straight to v2.1.304, skipping every intermediate release. Anthropic's docs describe stable as lagging latest by about a week, but in practice it moves in bursts. Treat it as "eventually everything", not as a long-term support line.
Enforcement is moving into mods. 2.1.299–2.1.296 hardened hooks (fail closed, managed hooks end the turn); v2.1.304 adds decider: "person" so a mod can insist a human approves, and settings.read layers so a managed mod can cap a setting. Together these make a managed mod the place to express org policy that users can't lower.
Desktop trails the CLI by five releases. v2.42304.2 (19 Oct) is a no-change rebuild still on 2.1.299; the CLI is on v2.1.304. The next real Desktop bump will land 2.1.300–2.1.304 at once, including the headless permission-mode and fork-subagent defaults, in the Code tab.
