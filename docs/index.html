v2.1.332 — MCP skills, skill shell-command hook, cloud model alias changes Wed 25 Nov AEDT · 150 bullets · latest · newest documented

security · permissions & policy New PreSkillShellCommand hook event can refuse a skill or command's inline shell commands as it loads (on 2.1.331 and older, a settings file naming it opens a dialog at start). Terminal and VS Code sessions moved to Sonnet 5 or 5.5 on Bedrock Mantle, Agent Platform and Foundry now start in auto mode if no mode is set; set disableAutoMode to "disable" to stop it. Self-hosted runner: the CLAUDE_CODE_OAUTH_TOKEN prefix can now end in oat02- as well as oat01- — update proxy rules and log scrubbers that match oat01-, and mask the whole value. /permissions now refuses a rule that would be skipped at the next start, such as rm -rf with no tool name, and shows the reason. Plan mode in the desktop app's Code tab and VS Code asks for approval instead of refusing when no auto mode safety check can judge a command (for plans entered from Manual or Accept edits). Computer use on macOS follows newer safety rules, so some actions are refused and typing can be slower; Esc now stops it between actions. Fixed claude auth login reporting Login successful. when a claude.ai login could not be saved (it now exits 1). Fixed a PreToolUse hook's reason for asking not showing on terminal Read, Grep, Glob, Edit and Write prompts. Fixed a freeze when a permission rule or hook condition with several wildcards was checked against a long command. The startup header shows your Cyber Verification Program access tier where it applies.
behaviour changes sonnet on Google Cloud's Agent Platform and Microsoft Foundry is now Sonnet 5.5, and Foundry's opus is Opus 5.5; sonnet on Amazon Bedrock stays at Sonnet 4.5. Foundry's default model is Sonnet 5.5 — deploy claude-sonnet-5-5 or set ANTHROPIC_DEFAULT_SONNET_MODEL. Agent Platform reads VERTEX_REGION_CLAUDE_5_5_SONNET for sonnet and background requests; with only the 4_5 variable set they go to CLOUD_ML_REGION or us-east5. --model default and a Default pick now move to an older model when theirs isn't available instead of stopping with an error. SDK and claude -p mid-turn messages count as the user's where feature flags aren't fetched (clouds, telemetry off), from Opus 4.8 on — mark relayed text isSynthetic: true. computer-use is a reserved skill name on Macs with computer use on; your own skill of that name stops loading. awsCredentialExport times out after 10 minutes instead of waiting forever. /schedule, permission prompts and /loop's cloud offer say "cloud scheduled task" instead of "routine" (/routines still works). PgUp and Home go to No on destructive questions.
features Skills from MCP servers (beta) — they show as server:skill in the / menu; other skills keep their names. "Always deliver" on the prompt for held messages from other sessions. A footer line that stays while a flagged message has your session on a different model, until you pick one with /model. VS Code and Desktop's Code tab warn when part of a session couldn't be saved (and how to save it with /compact) and note when a resumed session's earlier messages weren't loaded. Tap-mode voice dictation keeps the microphone on until 60 seconds without new words or 10 minutes (up from 15 seconds and 2 minutes). Computer use takes less context until Claude uses it, and its Screen Recording permission prompt can restart Claude Code and resume the chat. VS Code (30 bullets): installed version in Manage plugins rows, a warning when /rewind stops a self-paced /loop, more notifications when closing a proposed diff leaves an edit unapplied, plus many fixes.
telemetry New OpenTelemetry assistant_response event for text Claude sends through SendUserMessage or Cowork's message tool, when response logging is on. tool_input now shows only the length of that text unless OTEL_LOG_ASSISTANT_RESPONSES=1. Desktop Code tab sessions default service.name to claude-code-desktop — update filters keyed on claude-code, or set OTEL_SERVICE_NAME to keep the old name. Fixed a failed mcp_server_connection event at each start for a built-in server that isn't turned on for the account.
self-hosted runner Fixed sessions failing their first clone under Anthropic-managed git when the machine's git config has an includeIf "gitdir:" or (git 2.44 to 2.46) "onbranch:" section. Fixed --configure-git sometimes reporting a hung git --version as a git that isn't on PATH. claude self-hosted-runner setup with no arguments on macOS and Linux now asks for the environment key in the terminal before Claude starts, and hides it as you paste.
reliability Fixed Read, @-mentions and compaction hanging on a named pipe that nothing writes to, such as a .env mounted by a locked secrets manager (the read now fails after 20 seconds); turns ending in "Prompt is too long" after repeated auto-compaction failures; compaction failing when a summary ran past the output limit; freezes and runaway memory while a hook prints output without end, or a local MCP server floods its standard output; SSE MCP servers hanging or refusing every tool call after their event stream was cut; CLAUDE.md and rules files being sent a second time after a session moves into a worktree; ~/.claude.json being reported as corrupted while another session was saving it; a resumed conversation missing its last messages after a crash or kill on Bedrock, Agent Platform, Foundry and other third-party providers; headless and cloud sessions reporting a foreground fork's Agent call as finished the moment it started; web searches failing with an API error when the allowed or blocked domain list was empty or had duplicates; a usage limit reported as reached to Remote Control, IDE and SDK clients after it had reset; task ids being reused and deleted tasks coming back; several Code Mode stalls and skipped tool calls. Better recovery behind a proxy or gateway with a request size limit (413) or one that damages compressed responses. Windows: better stability on some company PCs and faster Glob in large folders. Lower memory use on resume, at start-up with many MCP tools, and in claude -p.

v2.1.331 — Code Mode on cloud providers, marketplace auto-update notice, rewind fix Tue 24 Nov AEDT · 135 bullets

security · permissions & policy Announced for a future release, on or after 30 November 2026: plugin marketplaces in managed extraKnownMarketplaces will auto-update by default. To opt one out, set "autoUpdate": false on its entry. Fixed PermissionRequest hooks not saving Skill(name:*) allow rules outside local settings. Fixed auto mode sometimes refusing Claude's call to stop a /loop. A PermissionDenied hook's retry: true now tells Claude to make the refused call again only if you asked for that call. Windows: an HKLM registry policy outranks managed-settings.json and a broken value can stop start-up.
features Code Mode in terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS. claude doctor gains an API connectivity section. claude_code.llm_request trace spans add gen_ai.usage.*, gen_ai.response.model and gen_ai.operation.name. Plugin manifests accept optionalDependencies. VS Code: "Fix with Claude Code" quick fix, "Add Cell to Chat", "Add to Chat" in Source Control, "Resolve Merge Conflicts".
reliability Fixed a rewind deleting files after a restore had failed; MCP tool calls hanging for up to 30 minutes on some malformed replies; turns that went silent while Claude was thinking failing in cloud sessions (now retried once); /compact and auto-compact sometimes losing part of the summary; an interrupted plugin update leaving a partial plugin folder; a Workflow agent's background shells and MCP servers left running after its report.

v2.1.330 – v2.1.326 — previous releases Tue 17 – Sat 21 Nov AEDT

2.1.330 · rm guard, MCP deny-list change More rm commands aimed at the root, home, a top-level folder or the working folder ask for approval, and are refused where nobody can answer. deniedMcpServers name entries hide only the named claude.ai connector — deny the exact URL to block the server. Sign-in to organizations managed in the Enterprise Admin Console; easel chart mod; recurring scheduled tasks and /loop run up to 30 days; fixed ExitWorktree deleting a worktree another session was using.
2.1.329 · hooks visibility, config durability Trust dialog warns where a folder's hooks are declared; fixed ~/.claude.json being reset to defaults on a network stall or file lock; fixed repeated macOS sign-outs when the Keychain was readable but not writable.
2.1.328 · auto mode on cloud providers Auto mode for Opus 4.6 and Sonnet 4.6 on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and the Claude apps gateway; "onFailure": "block" for mcp_tool hooks.
2.1.327 · data-loss fixes Remote Control worktree stop no longer deletes git-ignored files (.env); runner git-proxy no longer deletes GIT_CONFIG_GLOBAL.
2.1.326 · bypass-mode tightening · now stable Some bypass-mode tool calls now ask or are denied; file tools refuse writes to .credentials.json; OTEL_RESOURCE_INCLUDE_HOST.

Models

No new models this week · alias and default changes on cloud providers in 2.1.332 · Opus 4.8 fast mode removed 30 Nov (3 days; no fallback)

Current lineup and what changed

  • Fable 5.2 claude-fable-5-2 — launched 9 Nov; 1M context; $8/$40 per Mtok, $0.20/Mtok cache reads. Needs Claude Code 2.1.321+ (the stable dist-tag, v2.1.326, qualifies).
  • launch offer · ended Fable on Pro / standard Team seats needs usage credits (details).
  • Opus 5.5 claude-opus-5-5 — default Opus and the recommended daily driver.
  • Sonnet 5.5 claude-sonnet-5-5 — default Sonnet.
  • Haiku 5.5 claude-haiku-5-5 — default Haiku; 1M context.
  • 2.1.332 · aliases on cloud providers sonnet is Sonnet 5.5 on Google Cloud's Agent Platform and Microsoft Foundry; Foundry's opus is Opus 5.5 and its default model is Sonnet 5.5. On Amazon Bedrock sonnet stays at Sonnet 4.5. On Bedrock Mantle sonnet had been resolving to Haiku 4.5; it now means Sonnet 5 (not 5.5), and an account without Sonnet 5 gets an error — enable it first. Foundry: Sonnet 4, Opus 4 and Opus 4.1 count as retired. The Claude apps gateway's built-in list swaps Sonnet 4.5 for Sonnet 5.5 as its second model.
  • 2.1.332 · model fallback --model default steps down to an older model when its own isn't available (in auto mode, only to a model auto mode accepts). opus behind a gateway that refuses a model in its own words steps down to an older model that answers. Bedrock sub-agents use the model's own profile when the account lists none in the parent's region — which can be outside that region. A family name such as sonnet in --fallback-model is no longer dropped when availableModels allows only an older version.
  • Opus 4.8 fast mode · removed 30 Nov Fast-mode requests on Opus 4.8 error after 30 Nov with no fallback to standard speed — migrate to Opus 5.5 to keep the speedup.

Security & evals

v2.1.332 documented — runners can move · check auto-mode default, token prefix and telemetry filters first

Today's actionable items

  • upgrade · v2.1.332 v2.1.332 is unchanged since yesterday and has a changelog entry and GitHub release. Move self-hosted runners, Remote Control hosts and headless claude -p jobs to 2.1.332 after the checks below. It adds the named-pipe read hang fix, compaction recovery, hook and MCP flood freezes, and the SSE MCP reconnect fix on top of 2.1.331's rewind and MCP-hang fixes.
  • auto mode default · Bedrock Mantle, Agent Platform, Foundry Terminal and VS Code sessions moved to Sonnet 5 or 5.5 on those providers start in auto mode if no mode is set. If that is not wanted, set disableAutoMode to "disable" in managed settings before rolling out 2.1.332.
  • Bedrock model resolution sonnet on Amazon Bedrock is unchanged (Sonnet 4.5). On Bedrock Mantle it now needs Sonnet 5 enabled on the account. Bedrock sub-agents may now use a model profile outside the parent's region when none is listed in it — relevant where data must stay in one region.
  • runner token prefix CLAUDE_CODE_OAUTH_TOKEN can start oat02- as well as oat01-. Update proxy rules, secret scanners and log scrubbers that match oat01-, and mask the whole value.
  • telemetry dashboards Desktop Code tab sessions now report service.name as claude-code-desktop — panels and alerts filtered on claude-code stop counting them unless OTEL_SERVICE_NAME is set. tool_input carries only the length of text sent through SendUserMessage or Cowork's message tool unless OTEL_LOG_ASSISTANT_RESPONSES=1; with it on, a new assistant_response event carries the text.
  • new hook · PreSkillShellCommand Lets policy refuse a skill or command's inline shell commands as it loads. On 2.1.331 and older, a settings file that names it opens a dialog at start — upgrade every machine and runner before adding it to shared or managed settings.
  • skills from MCP servers (beta) MCP servers can now supply skills, shown as server:skill in the / menu. Review which connected servers are trusted to do that.
  • managed marketplaces · 30 Nov On or after 30 November, plugin marketplaces listed in managed extraKnownMarketplaces auto-update by default. If a marketplace must stay pinned or change only under review, set "autoUpdate": false on its entry now.
  • artifacts as apps · file transfers with connectors Claude Desktop (6.28899.0+) can install an artifact as a Mac or Windows app that may ask for full access to the computer; Team has it on by default with full access off, Enterprise has it off until an owner turns it on (article, admin guide). New on 24 Nov: Claude can send files to connected apps and save files from them (beta) — on Team and Enterprise only when an owner turns it on (article).
  • computer use · Team/Enterprise Computer use (beta) has been rolling out to Team and Enterprise organizations since 20 Nov — decide the organization's setting before it reaches us (admin setup). In Claude Code 2.1.332, computer-use is a reserved skill name on Macs with computer use on.
  • dates 30 Nov: Opus 4.8 fast mode removed; managed marketplace auto-update default (on or after); with Skills off, plugins stop working in Claude Desktop (Cowork and the Code tab) on Team and Enterprise; the Plugins page starts rolling out to Team, with Enterprise in the following weeks. 17 Dec 12:00 PT: remove deprecated Desktop keys coworkTabEnabled, chatTabEnabled, chatAdvancedFileAnalysisEnabled.

Claude Desktop

File transfers with connectors (beta) and artifacts as apps (beta) from 24 Nov · computer use (beta) rolling out to Team and Enterprise

What's new

file transfers with connectors · 24 Nov Claude can send a file to an app you've connected, or save a file that the app offers (beta). Rolling out gradually on Pro, Max and Ultra plans, and on Team and Enterprise plans when an owner turns it on (how it works). Also on 24 Nov: the monthly recap (Reflect, in Settings) is out of beta for Free, Pro, Max and Ultra plans, and can now draw on Claude Code sessions and Claude Cowork tasks in the cloud (article).
artifacts as apps · 24 Nov · computer use · 20 Nov Install an artifact as a Mac or Windows app (beta); needs Claude Desktop 6.28899.0 or later. The app gets its own window and icon and can ask for notifications, shortcuts, floating windows, a menu bar or tray item, or full access to the computer. Team: on by default, full access off until an admin enables it. Enterprise: off until an owner turns it on (how it works, admin guide). Computer use (beta) is rolling out to Team and Enterprise organizations gradually (setup guide).
Code tab · Claude Code 2.1.332 The Code tab now warns when part of a session couldn't be saved and notes when a resumed session's earlier messages weren't loaded. Its OpenTelemetry service.name defaults to claude-code-desktop. On Anthropic's API beside a gateway address, it ignores model ids in your own settings that don't start with claude, and a CLAUDE_CODE_AUTO_COMPACT_WINDOW under 200K (use /autocompact). Plan mode asks for approval instead of refusing when no auto mode safety check can judge a command. Fixed a session sometimes losing its "needs input" status after a background task's report. Still pending: remove coworkTabEnabled, chatTabEnabled and chatAdvancedFileAnalysisEnabled before 17 Dec.

Claude Cowork

Plugins page timing revised: Team from 30 Nov, Enterprise in the following weeks · Skills-off rule still 30 Nov

What's new

Plugins page · timing revised 25 Nov Anthropic revised the Plugins page article on 25 Nov, and it was edited again this week with the same dates: the single Plugins page (replacing the separate Skills, Connectors and Plugins tabs; Customize becomes Plugins) now starts rolling out gradually to Team plans on 30 November and reaches Enterprise plans in the following weeks; Free, Pro, Max and Ultra have it now. On Enterprise it will be on by default. Unchanged: from 30 November, Team and Enterprise organizations with Skills turned off find plugins stop working in Claude Cowork and the Code tab — an owner must turn Skills on beforehand (Organization settings > Library > Policy) to keep them.
file transfers · monthly recap · 24 Nov Claude can send files to connected apps and save files from them (beta; Team and Enterprise when an owner turns it on — article). The monthly recap, now out of beta on Free, Pro, Max and Ultra, can draw on Claude Cowork tasks in the cloud. Live artifacts from Claude Cowork still cannot be installed as apps.
via Claude Code 2.1.332 Skills can now come from MCP servers (beta), shown as server:skill. Text Claude sends through Cowork's message tool gets its own OpenTelemetry assistant_response event when response logging is on, and tool_input otherwise shows only its length. /schedule and permission prompts say "cloud scheduled task" instead of "routine". Fixed temp_* folders piling up in ~/.claude/plugins/cache when a downloaded plugin couldn't be copied into place, and the plugin "not cached" error pointing to /plugin instead of /reload-plugins. Managed plugin marketplaces auto-update by default on or after 30 November unless an entry sets "autoUpdate": false.
