v2.1.312 — gateway user_id_claim, Bedrock behaviour changes for custom model names, managed-settings fix, hook concurrency cap, safety_event withdrawn Wed 28 Oct AEDT · 39 bullets · newest on npm · third day as current

Claude apps gateway · identity Added oidc.user_id_claim to the Claude apps gateway, to identify people by an id_token claim other than sub, such as Microsoft Entra ID's oid. Until now the gateway keyed its per-user identity (the x-claude-gateway-user-id header, user-scoped spend limits and the user.id attribute in monitoring exports) on sub; Entra tenants that already track people by oid elsewhere can line the two up. The gateway configuration reference, re-checked this morning for the third day, still documents only email_claim and groups_claim under oidc, so treat the changelog line as the spec — and note that changing the claim changes the user ID that existing spend-limit rules and monitoring dashboards match on.
Bedrock, Vertex, Foundry & Mantle · custom model names Changed Bedrock, Vertex, Foundry and Mantle to use the shorter system prompt for model names Claude Code doesn't recognise, such as custom deployment names and inference profile ARNs, even when they front Sonnet or Haiku; set CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 to keep the full prompt. Any Bedrock session that points at an inference profile ARN or an application inference profile rather than a bare model ID now runs on the shorter prompt, so outputs can drift without any config change on our side. Changed automatic model switches after a flagged message to also cover model names Claude Code doesn't recognise; set CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 to turn them off. An ARN-addressed session can now switch models mid-session, which matters wherever the ARN was chosen for region, cost or compliance reasons. Desktop's behavesAs key (v4.29.0) is the app-side answer to the same problem.
managed settings & policy files Fixed managed settings and organization policy not being fetched for the rest of the session after signing in from the VS Code extension. A developer who signed in through the VS Code panel ran that session without the organisation's managed settings — permission rules, hooks policy, allowed MCP servers — until the next launch. Fixed Claude overwriting a very large CLAUDE.md, rules file or @-included file in a subdirectory after seeing only its start; Write now asks Claude to read it all or edit in place. Fixed per-directory and paths: skills not being found after a Bash cd deeper into a git repository. Fixed a command with an invalid name stopping all commands from loading, which could leave claude -p with no output.
hooks & OpenTelemetry Changed prompt and agent hooks to run at most 24 at a time per session, sub-agents included, plus at most 12 that have waited longer than their event's timeout; a timeout under 1 second now counts as 1 second. Changed Claude Code to stop sending the claude_code.safety_event OpenTelemetry event — added in v2.1.307 on 21 Oct, withdrawn six days later; the tool_decision event with its classifier fields (v2.1.300/301) remains the signal for blocked and prompted tool calls. Changed OpenTelemetry mcp_server.name to report the real name of fixed-URL remote MCP servers declared by plugins from the official Anthropic marketplace, instead of custom. Fixed the spinner, OTel effort values and transcripts naming a newly picked effort level before the model applied it; they now show the level in force. Changed a subagent's autoCompactWindow to lower the window set by CLAUDE_CODE_AUTO_COMPACT_WINDOW; it still never raises it.
sessions, resume & UI Fixed a rare case where the first reply after resuming a session in the terminal could be missing the next time the session was resumed. Fixed the Read tool sometimes failing on PDF pages with "pdftoppm failed" when old-session clean-up ran at the same time. Fixed some sessions showing as waiting on you when the last message only mentioned items waiting on you mid-sentence. Added click to send: in fullscreen, clicking the "to send now" hint under a queued message sends it right away. Changed usage-limit messages to call the 5-hour window the "5-hour limit" instead of the "session limit"; VS Code shows the reset as a clock time. Changed cloud sessions started from the CLI to get their names and branch names from the server. Improved WebFetch errors in cloud sessions: a host that does not resolve is now explained as possibly outside the allowed network domains, so Claude names the host to allow. Fixed /verify showing its long model-facing description in /help; vim-mode d/c/y with an oversized gj/gk count now only moves the cursor; agent view no longer restores input cleared with Ctrl+C or reopens in shell mode after Ctrl+D.
VS Code, cloud sessions, Claude Tag & Code Review [VSCode] Sessions no longer end on a bare exit code when the organisation's settings couldn't be loaded or were refused at startup; the tab says why and offers Retry or Sign in again. [Cloud sessions] Added an effort level to the model picker when you create or edit a routine that runs in the cloud; added a Bash editor with colours, line numbers and Copy to the setup-script box in cloud environment settings; the step shown when Claude adds a repository now shows a short table instead of raw JSON; fixed resending an unchanged message after a failed send sometimes running it twice; fixed a failed environment creation showing its error only as a toast. [Remote Control] An unarchived session no longer shows as working until a computer reconnects. [Claude Tag] The retry notice in Slack names the model in use or says rate limits were hit; a channel's on/off switch and agent settings no longer fall back to workspace defaults when an older private channel goes public and gets a new ID; Claude now replies in channels whose environment has network access set to None; files no longer land in the wrong thread. [Code Review] Fixed Code Review reviewing an outdated commit, or none at all, when GitHub delivered a push event late; it now reviews the pull request's current commit.

  • provider API keys encrypted (Desktop v4.4212.0, 29 Oct) Provider API keys saved in Setup are now encrypted where the computer has secure storage; keys saved earlier are encrypted at the next launch. Versions below 4.29 cannot read them — after a rollback below 4.29, or a move of the app's data to another computer or account, the key has to be entered again. Any Bedrock or gateway deployment that relied on copying app data between machines to pre-seed a key loses that path.
  • token limits now count the app's own requests (Desktop v4.4212.0) Settings > Usage and the limit set with inferenceMaxTokensPerWindow no longer leave out requests the app makes itself, such as naming a session. They now count toward the limit, and once it is reached the app stops making them, except its connection check. Expect per-user usage numbers to tick up slightly with no change in behaviour, and the 75% warning (inferenceTokenWarningPercent, v4.29.0) to fire a little earlier.
  • HTTP 402 from a provider or gateway (Desktop v4.4212.0) Cowork now shows "Billing issue", with no Try again button, instead of "Something went wrong" when the inference provider or gateway refuses a request with 402. A gateway that returns 402 for a per-user spend cap now surfaces as a billing message in the app, so spend-limit wording on the gateway side should match.
  • gateway aliases in Desktop (v4.29.0, 27 Oct) behavesAs on inferenceModels entries names the Claude model behind a gateway alias or other Model ID that Claude Desktop can't identify, so the ID gets that model's effort levels and limits. Once any entry sets it, sessions ignore modelPicker in people's own Claude Code settings. Now documented in the configuration changelog.
  • unrecognised model names on cloud providers (CLI v2.1.312) On Bedrock, Vertex, Foundry and Mantle, a model name Claude Code doesn't recognise — a custom deployment name or an inference profile ARN — now gets the shorter system prompt even when it fronts Sonnet or Haiku (CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 restores the full prompt), and is covered by the automatic model switch after a flagged message (CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1 turns that off). Fleets that address Bedrock by ARN should set both deliberately rather than inherit the new defaults.
  • Desktop SSH/WSL sessions and provider env vars (v4.29.0) SSH and WSL Code sessions take most settings, on/off values and numbers from the computer's CLAUDE_*, ANTHROPIC_* and DISABLE_* environment, but most other text, such as a cloud provider's key or base URL, goes only if saved under Environment variables.
  • ultrathink = xhigh effort (v2.1.311) In the interactive terminal, ultrathink runs the turn at xhigh effort on Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 through Anthropic's API, and typed mid-turn raises the rest of that turn. Anthropic API only.
  • signed model catalog on cloud providers (v2.1.311) Claude Code on Bedrock, Mantle, Vertex and Foundry loads model settings from a signed file on downloads.claude.ai; CLAUDE_CODE_MODEL_CATALOG=off disables it. "Mantle" still has no docs page.

  • gateway effort beta (v2.1.310) Behind a gateway that rejects the effort-2025-11-24 beta or mid-conversation system messages, Claude Code retries without them; /effort and ultrathink do nothing on that route until the gateway allows the beta.
  • API version 2026-10-21 (v2.1.307) /claude-api api-version moves your code to it. Check the Claude API release notes before switching production services.

Desktop v4.4212.0: device managed settings beat the admin console for three keys, encrypted provider keys, skill scanning in Desktop, sshClientPath under %LOCALAPPDATA%, dev-server approval · Plugins page: Skills-off blocks plugins from 30 Nov · CLI stable eight days stale · Unified Claude on 10 Nov

Today's actionable items

  • decision stands · stable stable is still on v2.1.308, eight days on. Yesterday's call — move runners, auto-mode pipelines and headless claude -p jobs from the stable dist-tag to an explicitly pinned version — stands; the pin is still 2.1.312, which has now had two days with no follow-up patch, which is as good a sign of a settled build as this release cadence gives. Re-evaluate when stable next moves.
  • upgrade · Desktop v4.4212.0 Roll Desktop v4.4212.0 (29 Oct) out after v4.29.0, and know what it changes in precedence first. Three device-level Claude Code managed settings — disableBrowserExternalNavigation, browserExternalPageTools and remoteControlAtStartup: false (from managed-settings.json, MDM or HKLM policy) — now apply even when the claude.ai admin console also has managed settings. Until now a console-side managed-settings object could silently override a device policy for these; after the update the device wins. If any of the three is set in one place and not the other, decide which is meant to win before the build lands. Also in this build: the first message after an SSH session starts or reconnects no longer sometimes runs without your MCP servers; SSH set-up no longer fails outright when Anthropic's download server is busy; Rewind on the first message of a very large session no longer clears the whole conversation.
  • provider keys · Desktop v4.4212.0 Provider API keys saved in Setup are encrypted where the computer has secure storage; versions below 4.29 cannot read them. A rollback below 4.29, or moving the app's data to another computer or account, means entering the key again. Any imaging or profile-copy process that carries a Bedrock or gateway key between machines inside the app's data folder stops working; use managed config or the saved Environment variables instead.
  • skill scanning in Desktop · skillScanningEnabled (beta) New 3P key: run a security scan on each skill a user creates or uploads before it can be used; skills that fail are blocked. This is the Desktop-side counterpart of the Enterprise skill and plugin scanning that has been on by default since 2 Oct (which still doesn't cover MCP servers or hooks). Worth turning on for the Cowork fleet now, before the Plugins page consolidation makes skills and plugins one thing on 9 Nov / 30 Nov.
  • Plugins page · Skills-off rule on 30 Nov From 30 November, if Skills are disabled for the organisation, plugins are also blocked in the Claude Desktop app — Cowork and the Code tab included. Free/Pro/Max/Team see the new Plugins page from 29 Oct (GA 9 Nov); Enterprise gets it on by default 30 Nov. Keeping plugins needs an owner to turn on Cloud code execution and file creation and Skills under Organization settings > Library > Policy (Skills is renamed Plugins on 30 Nov). Removing a plugin that packages a connector does not disconnect the connector — it has to be disconnected separately. HIPAA configurations: the BAA still doesn't cover connectors, plugins or skills. The new projectsEnabled key (false hides projects in Chat and Cowork without deleting them) lands in the same build.
  • sshClientPath under %LOCALAPPDATA% · Desktop v4.4212.0 On Windows, sshClientPath (beta) may now begin with %LOCALAPPDATA%\ — only when HKLM policy sets it as a plain REG_SZ, with sshTransport: system-openssh, and only while Claude does not run as administrator; a configuration server in use must repeat both values or the device's are ignored. The documented caveat is the point: whoever can replace a program in that folder can see SSH passwords and get around sshHostAllowlist. Do not use it on shared or non-admin-locked devices; Program Files remains the safe location.
  • dev servers in Auto / Bypass · Desktop v4.4212.0 Code sessions now ask for approval before starting a dev server from launch.json in Auto and Bypass permissions modes, where Claude Code's sandbox (the default on macOS, Linux and WSL) or deny/ask rules in managed settings limit shell commands. A small new prompt in otherwise unattended sessions; scripted flows that relied on Bypass starting a server silently will now wait on it.
  • built-in browser · Local network access New per-site "Local network access" setting in the built-in browser's menu (builtinBrowserEnabled), with a question the first time an https site tries to reach an app on this computer or a device on the network — the case is sign-in pages that check a desktop agent such as Okta Verify. builtinBrowserBlockedDomains can block devices but not local apps. Where the browser is on for Cowork, expect this prompt on IdP sign-ins.
  • Unified Claude on 10 November · tightened in v4.4212.0 An unset desktopHome reads as standard at launches after 12:00 PM PT (20:00 UTC) on 10 November: Unified Claude opens with Cowork on, even where coworkTabEnabled is false. In v4.29.0 this applied only where Cowork was on; the configuration changelog marks the v4.4212.0 version as breaking. chatTabEnabled and chatAdvancedFileAnalysisEnabled have no effect under standard. Eleven days away — set desktopHome deliberately in managed config this week. (A deployment with Cowork on that sets chatSessionRetentionDays without a matching coworkSessionRetentionDays keeps its current view, per the v4.29.0 note.)
  • carry-over · Desktop v4.29.0 (27 Oct) Windows folder-delete escape through junctions/mounted volumes fixed; SSH password no longer resent after refusal (account lockout); SSH/WSL sessions no longer take provider keys or base URLs from the local environment; PowerShell PreToolUse/PermissionRequest hooks fail closed without Git for Windows; GitHub connector's pull_request_review_write asks before every call and is refused where no prompt can be shown; web fetch in scheduled Cowork tasks needs a URL named in the task or found by search; defaultState: off, toolTimeoutSec, platformOverrides, oauth.omitResource on managedMcpServers; Microsoft 365 users sign in again once. All now listed in the configuration changelog.
  • carry-over · CLI v2.1.312 / v2.1.311 / v2.1.310 / v2.1.309 Managed settings not fetched after VS Code sign-in; large CLAUDE.md/rules-file truncation on write; scoped skills missing after cd; refusal fallback and shorter system prompt on ARN-addressed Bedrock models (CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1, CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0); claude_code.safety_event withdrawn (keep tool_decision as the load-bearing signal); hook concurrency cap 24 (+12 overdue); oidc.user_id_claim on the gateway still undocumented; new downloads.claude.ai dependency on Bedrock/Vertex/Foundry/Mantle (CLAUDE_CODE_MODEL_CATALOG=off); not-to-retry requests were retried; Windows hooks failed open without Git Bash; sandboxed Bash ran shell startup files outside the sandbox; five permission-check bypasses closed; bypass-mode rm/rmdir hard deny; claude ultrareview needs --trust-workspace in scripts.

Patterns worth tracking

Device policy is being made to beat the admin console, key by key. v4.4212.0 names three Claude Code managed settings that a device's managed-settings.json, MDM or HKLM policy now enforces even when the claude.ai admin console also carries managed settings. That is the right direction for anyone running MDM, but it is being done one key at a time, so the precedence rule is now different for these three than for everything else. Keep a short list of which keys are device-wins and check it against each Desktop build.
Desktop is shipping twice a week and the CLI it bundles isn't moving. v4.29.0 (27 Oct) and v4.4212.0 (29 Oct) both bundle 2.1.309, while latest sits on 2.1.312. The gap between what a terminal gets from claude update and what the Code tab runs is three releases and holding. The v4.x version scheme has also gone back to a build-number middle segment (4.29.0 to 4.4212.0), which looks like a return to the v3.6556.x style rather than semver.
stable is a snapshot, not a channel. Eight days on v2.1.308 while 236 bullets shipped across v2.1.309 – v2.1.312 on latest, and now latest itself has paused for two days. The pinned-latest policy is in place; the thing to watch is whether stable jumps to v2.1.312 or to something newer when it moves.
Skills and plugins are converging on one control, with a hard date. The Plugins page folds Skills, Connectors and Plugins into one surface (29 Oct onwards), skillScanningEnabled brings scanning to user-created skills in Desktop, and from 30 Nov the Skills switch is the plugins switch. An organisation that turned Skills off for caution a few months ago will lose plugins in Cowork and the Code tab on that date without any further change on its side.
Credentials keep moving into declared, managed places. v2.1.311's signed model catalog, v2.1.312's gateway identity claim, v4.29.0's stop on provider keys riding into SSH/WSL sessions, and now v4.4212.0's encrypted saved keys that older builds can't read. Each one breaks a convenience path (copying app data, exporting a shell variable) in favour of a managed one.
The configuration changelog caught up. Yesterday it topped out at 19 Oct with v4.29.0's keys missing; this morning it lists both v4.29.0 and v4.4212.0 in full, including the breaking desktopHome note. The Claude Code side has not: oidc.user_id_claim is still absent from the gateway configuration reference three days after the changelog named it.
Unified Claude has a date and it got firmer. 10 November, 12:00 PM PT (20:00 UTC), for any device with desktopHome unset — and v4.4212.0 removes the "only where Cowork was on" qualifier. Eleven days. Decide the home view in managed config this week rather than discover it on the day.
