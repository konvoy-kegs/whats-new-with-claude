v2.1.290 — permission & policy hardening newest · aligned

permissions Plan mode could let the auto mode classifier approve non-read-only connector tools that carry a server-pushed ask policy — fixed. Bash checks no longer auto-approve "read-only" commands (rg, git grep) whose args the shell expands as wildcards, or commands whose variable names zsh reads differently from bash; these now prompt. Permission rules now also apply after a PreToolUse hook rewrites a tool's input.
managed policy disableClaudeAiConnectors and allowedMcpServers URL rules weren't applied to some MCP entries in .mcp.json, plugins or agents — fixed. A user-installed mod could make an org guard skip its check or get an org plugin unloaded — now the mod is unloaded. New warnings when a managed settings file is a symlink outside the managed folder, and in /status/doctor when managed settings ignore user sandbox allowRead paths or allowed domains.
data boundaries Image reads and @-mentions could escape approved paths via a link swapped mid-read; symlinked CLAUDE.md/AGENTS.md loaded despite blockReadsOutsideWorkingDirectories; background workers honoured --allow-dangerously-skip-permissions without the disclaimer; background/daemon processes sent telemetry to Anthropic behind a Claude apps gateway; --restricted opened the cross-session socket. All fixed.
workflow claude attach <name> / claude logs <name> accept part of a session name; /claude-api managed-agents-onboard scaffolds Managed Agents as ant apply files; WebFetch now reports truncation past 100k chars and takes an offset; Deny button on the apps gateway sign-in approval page.
reliability Requests through proxies/gateways that reject a beta header with a non-400 status now work; scheduled tasks and /loop survive compaction and background hand-offs; long image-heavy sessions no longer stick on "unprocessable" errors; Cowork cloud replies no longer hang on container restart; slow startup under SDK hosts (VS Code, WSL) since 2.1.285 fixed.

v2.1.289 — deny/ask rules hold in more places Sat 3 Oct UTC

Bash deny/ask rules no longer slip under sandbox auto-allow with env-var prefixes; Read deny rules apply through IDE symlinks; user plugins can't rewrite org-managed MCP sign-in tool descriptions; VS Code claude auth status sign-out regression reverted.

v2.1.288 — rm bypass, MCP OAuth step-up Fri 2 Oct UTC

Dangerous rm in bash -c no longer runs unprompted; MCP OAuth scope step-up; mid-response API timeouts continue from partial output; CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS for gateways that reject structured outputs; Ctrl+C draft recovery.

Security & evals

third consecutive permission-hardening release

Today's actionable items

  • permissions Move canaries to 2.1.290: closes plan-mode auto-approval of non-read-only connector tools, wildcard-expanding "read-only" Bash commands, zsh variable parsing gaps, and PreToolUse-rewrite bypasses.
  • MCP policy If you enforce allowedMcpServers or disableClaudeAiConnectors, older clients didn't apply them to some .mcp.json/plugin/agent entries. Upgrade before relying on them.
  • managed settings Run /status or doctor on a managed machine after upgrading — new warnings flag symlinked managed settings files and ignored user sandbox paths/domains.
  • gateway / telemetry Behind a Claude apps gateway without forced gateway login, background commands and daemon workers were sending telemetry and a feature-flag request to Anthropic — fixed in 2.1.290.
  • supply chain User-installed mods can no longer make an org guard skip its check or unload an org plugin.
  • today Cowork on Pro/Max is cloud-by-default from today, Tue 6 Oct.

Patterns worth tracking

Permission edges keep closing. 2.1.288, 2.1.289 and 2.1.290 all fix cases where deny/ask rules or approval gates were skipped. Treat older clients as having weaker guardrails and keep the fleet current.
Org-vs-user precedence for mods. 2.1.289 and 2.1.290 both tighten how user-installed mods interact with organization plugins and guards — expect more of this as Claude Mods matures.

Claude Cowork

What's new

Today (Tue 6 Oct): cloud by default. New Cowork tasks on Pro and Max now run in the cloud, and "Only on your computer" in Settings > General is being removed. See Use Claude Cowork on web, desktop, and mobile.
