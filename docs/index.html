v2.1.248 — a secrets-upload fix, a restricted run mode, and 30-day session loss in Desktop and Cowork today's headline

49 entries · published Fri 28 Aug 06:35 local · on latest · source: CHANGELOG.md

Secrets — uncommitted .tfvars and prod.env files were being uploaded to cloud sessions. Rotate, do not just upgrade. “Fixed /ultrareview and locally seeded cloud sessions uploading uncommitted edits to prod.env-style and *.tfvars files, or to editor swap, temp, and backup copies of credential files (e.g. key.pem.tmp, id_rsa.swo); they now stay on your machine.” Cloud sessions seed themselves from your working tree, including uncommitted changes — which is precisely the set of files that .gitignore was protecting. Terraform variable files and environment files are where infrastructure credentials live, and editor swap files defeat the usual “we never commit the key” control because the swap copy has a different name. Action: if anyone has run /ultrareview or started a cloud session from a repo containing live *.tfvars, prod.env, or a .pem with a stray editor temp file, treat those credentials as disclosed and rotate them. Upgrading stops it recurring; it does not undo an upload that already happened.
New — --restricted, a genuine locked-down run mode. “Added --restricted (or CLAUDE_CODE_RESTRICTED=1): removes the built-in tools that run commands or code and WebFetch (unless named in --tools), keeps file tools inside the working directory, refuses bypassPermissions, and ignores user, project and local settings files.” The important half is the last clause. Every previous attempt at a safe mode could be widened by a settings file inside the repository being examined — so the thing you were sandboxing got a say in its own sandbox. --restricted ignores those files entirely and refuses bypassPermissions outright, which makes it the first mode that holds when pointed at untrusted code. The obvious uses here: reviewing a dependency or a third-party repo, and any CI runner that should read code but never execute it.
Data loss — Desktop and Cowork sessions were disappearing after 30 days. “Fixed Claude Desktop and Cowork sessions disappearing after 30 days: the transcript cleanup now keeps desktop-written sessions while they are in the app (unless org policy manages retention); the new desktopSessionCleanupPeriodDays setting caps the exemption.” The CLI's transcript cleanup was reaping sessions the desktop app still considered live — so a Cowork conversation you could still see in the sidebar had already had its transcript deleted underneath it. Anything older than 30 days is already gone and is not recoverable by upgrading. The new setting exists so the exemption does not become unbounded retention; org-managed retention policy still wins.
Cost — two prompt-cache misses that were quietly burning tokens, and a 4.7k-token prompt reduction. A cache miss was occurring roughly once an hour in long sessions because tool definitions were re-rendered after an OAuth token refresh, taking extended-thinking context with it. A second one hit the first turn of any --resume for accounts in usage overage, because the ScheduleWakeup tool definition changed between the original session and the resumed one. Both were invisible — you paid full input price on a cache you thought you had. Separately, the Workflow tool's description dropped from about 5.7k tokens to about 1k, with the reference material moved into a bundled workflow-authoring skill. That is a permanent saving on every session that loads it.
AWS — /usage-credits for organizations billed through AWS Marketplace. Enterprise organizations billed via AWS Marketplace, self-serve Enterprise and Enterprise trials can now have members request a higher usage limit from their admin in-session, rather than the request arriving out of band. Related fix in the same release: rate-limit and fast-mode messages no longer tell you to run /usage-credits when the command is not available to your org.
Cross-session messaging reaches Bedrock, Vertex and Foundry — and its failure modes got louder. SendMessage and ListAgents between sessions on the same machine now work on Bedrock, Vertex and Foundry, and with telemetry disabled. Two hardening items ride along: an invalid crossSessionInbound value is no longer silently ignored (it now warns and holds messages under user settings, or refuses them under managed settings), and root-equivalent trust for unmapped owners in Linux user namespaces is now limited to canonical system directories — relevant to anyone running Claude Code in rootless containers.
Operational fixes worth knowing about. Background sessions that stalled silently when a PermissionRequest or PreToolUse hook printed an invalid answer now name the hook and the schema error in the claude agents row. A hook printing a stdout object that is not valid JSON is now reported as a hook error instead of being treated as plain text. A backgrounded worktree session now holds its worktree lock while running, so cleanup and git worktree remove leave it alone. Agent view no longer resurrects a weeks-old background session after the machine has been off. And on Windows, claude agents no longer stops responding to the keyboard after detaching from a session.

Still worth actioning from earlier this week carry forward

v2.1.247 — plugin marketplace text can no longer inject terminal escapes. Marketplace-supplied text in /plugin output is now escape-safe and names containing control or invisible characters are rejected. Relevant to us specifically, because a private marketplace can be backed by a GitHub repository — write access to that repo is the trust boundary. Included in v2.1.248.
v2.1.247 — markdown hyperlinks to network and automounter paths now render as plain text. A UNC path behind a clickable link is the classic credential-leak shape on Windows. Included in v2.1.248.
v2.1.246 — rotate any LLM gateway API key. Telemetry and metrics requests to Anthropic were carrying the API key configured for a third-party gateway via ANTHROPIC_BASE_URL. A credential minted for our gateway was sent to a host that is not our gateway — the response to a disclosed credential is rotation. On latest since Wednesday; there is no reason to still be exposed.
v2.1.246 — audit Bash allow rules with a wildcard before the subcommand. Bash(git * main) also matches options inserted before the subcommand (git -c ..., git --exec-path=...), which changes what the command does. The release warns at startup but does not narrow the rules for you.
v2.1.243 — modelPricing, and a 4.5× smaller Linux binary. Contracted per-model rates drive /cost, the status line and telemetry instead of list price. zstd compression takes the Linux x64 binary from ~340 MB to ~75 MB with 40–70 MB less memory per session — which changes the economics of baking Claude Code into container images and CI runners.

Sandboxing and isolation notes

The pattern across the last three releases is untrusted input arriving with more authority than it should have. Marketplace text reaching the terminal as control sequences (v2.1.247), markdown links reaching network paths (v2.1.247), settings files inside an examined repo widening the sandbox (addressed by --restricted in v2.1.248), and working-tree secrets reaching cloud containers (v2.1.248). Treating “the repo we are pointing Claude at” as untrusted input is the correct mental model, and the tooling has only just caught up to it.
Rootless containers and user namespaces: v2.1.248 limits root-equivalent trust for unmapped owners to canonical system directories in the cross-session messaging path, and falls back to a private per-user /tmp when the default directory cannot be used. If you run Claude Code in rootless Podman or a user-namespaced K8s pod, this is the release that makes that path behave predictably.
Fail-closed improvements: malformed Bash commands with a dangling && or || now always require approval (v2.1.246), and an invalid crossSessionInbound value is refused rather than ignored under managed settings (v2.1.248). Both replace silent permissive defaults with explicit refusals.

Claude Desktop

macOS · Windows · Linux (beta)

What's new

Sources: support.claude.com release notes (newest entry 25 Aug — unchanged for three days), platform release notes, Claude Desktop help. Checked Fri 28 Aug 2026. Today's Desktop news comes from the Claude Code changelog rather than the support site.

New today — your Desktop sessions were being deleted after 30 days while still visible in the app. v2.1.248 fixes the CLI's transcript cleanup reaping desktop-written sessions that the app still considered live. This is the most consequential Desktop item in weeks, because it is silent data loss rather than a bug you would notice and report. A new desktopSessionCleanupPeriodDays setting caps how long the exemption lasts, and org-managed retention policy still takes precedence. Anything already reaped is gone — upgrading only stops it happening again.
New today — premature “Claude is waiting for your input” notifications, fixed. Self-hosted runner sessions were reporting running before Claude Code had actually started, which fired a desktop notification with nothing behind it. Notifications that arrive before there is anything to respond to are how people learn to ignore notifications — worth having if anyone here pairs self-hosted runners with the desktop app.
Memory spans chat and Cowork, and the default differs by plan (25 Aug). Everything Claude remembers is listed under Topics in Settings > Memory, where any item can be edited or deleted. Memory is on by default for Free, Pro and Max, and off by default for Team and Enterprise. On a Team or Enterprise plan nothing is retained unless somebody turned it on — a decision to make deliberately rather than a change that has already happened to us. Sensitive categories such as health and beliefs stay out unless Include sensitive topics in memory is switched on.
Standing context — the Customize panel, plugin governance and Cowork GA. Claude Cowork is generally available on macOS and Windows through the Claude Desktop app, with Linux in beta, on all paid plans. A Customize section groups skills, plugins and connectors in one place. Also live: the monthly recap at Settings > Reflect, break reminders and quiet hours at Settings > Time and focus, and a managed marker in /mcp and /plugins showing which connector credentials belong to the organization rather than the user.

Claude Cowork

Generally available · cloud sessions in beta

What's new

Sources: Release notes — 25 Aug entry, Get started with Claude Cowork, Use plugins in Claude, Use Claude Cowork safely. Checked Fri 28 Aug 2026.

New today — Cowork sessions were disappearing after 30 days, same bug as Desktop. v2.1.248's transcript cleanup fix covers Cowork sessions too. For a surface where the session transcript is the record of what an agent did to your files and connectors, silent 30-day deletion is an audit problem, not just an inconvenience. The new desktopSessionCleanupPeriodDays setting bounds the exemption; org retention policy overrides it.
New today — the secrets-upload fix applies to Cowork cloud sessions. Cloud sessions seed from the working tree including uncommitted changes, and were pulling in *.tfvars, prod.env-style files and editor temp copies of credential files. If you have run a Cowork cloud session against an infrastructure repository, this is the item to act on — see the Security tab.
New today — a stalled background session now tells you which hook broke it. A PermissionRequest or PreToolUse hook printing an invalid answer used to leave a background session waiting silently and indefinitely; the row now names the hook and the schema error. Alongside it, a hook printing a stdout object that is not valid JSON is reported as a hook error rather than silently treated as plain text. For scheduled tasks running unattended, “waits forever with no explanation” is the worst failure mode there is, and it has now been closed.
Carried forward — the run-reliability fixes have stacked up nicely. Cloud sessions whose container restarts mid-turn now report the lost work instead of going silent (v2.1.247); MCP failures are reported to Claude rather than looking like missing tools (v2.1.247); interrupted MCP calls are reported as interrupted rather than “completed with no output” (v2.1.246); and non-interactive sessions automatically continue a response cut off mid-stream (v2.1.246). Four of the ways an unattended run could silently degrade have been closed in three releases.
The operational rule that keeps catching people: scheduled tasks run with no device online. They execute on Anthropic's servers rather than a laptop, so they no longer need the machine awake or the app open. The corollary is the trap: a scheduled task cannot reach local files unless the desktop app happens to be open on that machine. Anything that must touch local state needs to be designed around that, not assumed.
Standing context — plugin and skill governance for Team and Enterprise. Each plugin bundles skills, connectors and sub-agents into one package; hooks and sub-agents run only in Cowork, so they appear greyed out in chat. Admins can create private plugin marketplaces from a GitHub repository — that repo's write access is the trust boundary, and yesterday's marketplace hardening is why that matters. Org-wide skill management publishes a skill to everyone under Customize > Skills, Enterprise skill and plugin security scanning checks third-party content on upload, and plugin OpenTelemetry distinguishes admin-install so “what did we push versus what did people add themselves” is answerable from telemetry. Ten financial services plugin templates are also available for Cowork and Claude Code.
