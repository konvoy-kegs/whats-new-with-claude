v2.1.307 — API version 2026-10-21, safety OTel event, MCP double-send fix, runner hook timeouts Thu 22 Oct AEDT · 43 bullets · newest on npm

Claude API version Added /claude-api api-version to move Claude API code to API version 2026-10-21. The changelog gives no detail on what the new version changes; run the skill against a branch of any service that pins an anthropic-version header and read the diff before merging. Also for API users: the prompt-caching-scope beta header is no longer sent behind custom ANTHROPIC_BASE_URL gateways and on Foundry, where it has no effect, and requests no longer fail with model-not-found when CLAUDE_CODE_DISABLE_1M_CONTEXT is set and the model is an alias with the [1m] suffix, such as opus[1m].
observability Added the claude_code.safety_event OpenTelemetry event for each tool call that a permission rule, auto mode, a safety check, a hook or the sandbox stopped, prompted or sent back. This is the per-block counterpart to the tool_decision event that gained classifier fields in v2.1.301 — worth a Grafana panel split by source. Also fixed: telemetry from Claude Desktop sessions behind a Claude apps gateway being rejected when OTEL_EXPORTER_OTLP_HEADERS is set; subagent transcripts recording placeholder token usage and an empty stop reason for streamed responses; CLAUDE_STREAM_FIRST_BYTE_TIMEOUT_MS being ignored in apps gateway sessions.
MCP reliability & permissions Fixed HTTP MCP tool calls being sent twice when the connection closed mid-call; only read-only or idempotent tools are now retried. If any internal HTTP MCP server performs side effects (creates, sends, deletes), earlier versions could have executed those twice on a dropped connection. Also: MCP servers no longer show "needs authentication" in claude -p on macOS while the login keychain is locked (they now say why, and reconnect after an unlock without a new sign-in); servers are no longer reported as timed out, and left failed in headless runs, when the machine slept while they were connecting; a turn no longer starts without an SDK MCP server's latest tools while a background task runs. /permissions > Recently denied now shows the denied shell command (approving a row names the command, not its description), and auto mode's local classifier no longer ignores an approval from there when it checks a retried command.
self-hosted runner Changed checkout hooks to be stopped after 30 minutes by default, failing the session's setup; raise --checkout-hook-timeout-min or set it to 0 if yours needs longer. Fixed sessions with --use-anthropic-git-proxy committing a .claude/settings.local.json left in the clone by an earlier session. Fixed archiving or requeueing a session, or stopping the runner, during its checkout hook leaving the hook's processes running and the runner's slot held. The certificate file built for Anthropic-managed git now filters its trusted certificates as the CLI does; a [runner:warn] line gives the number left out. Cloud sessions: the "Waiting for a runner" status on self-hosted environments now counts up from your last message and shows failed attempts.
sessions, compaction & subagents Fixed some "Autocompact is thrashing" errors in turns that read many PDF pages, images or other large tool results; /autocompact in cloud sessions going back to the default window after a restart; a conversation cleared with /clear coming back when a cloud or self-hosted runner session restarted. Model switches through the Agent SDK's setModel() are no longer refused when the API takes more than 5 seconds to confirm (now waits up to 15). Unparseable tool calls are retried up to twice before the turn ends with an error. Fork subagents launched together are each told which launch is their own, so they are much less likely to start each other's work. A background command stopped through a connected app (such as the desktop app archiving an idle session) is no longer reported as stopped by the user; the notice names its output file.
Cowork, Desktop, Code Review & VS Code WebFetch in Cowork cloud sessions now treats a 4xx status or a robots.txt refusal as a normal result instead of a tool error, as in local sessions. Write tools on a directly configured GitHub MCP server no longer show a form that closes without creating anything in the desktop app's Code tab. Artifact tool reads no longer fail with a connection reset on a closed reused connection. Web search errors in cloud and runner sessions show the 403 reason instead of "Authentication error", and the WebSearch-budget notice now tells Claude not to query search engines in a browser or through computer use. Code Review: @claude review stop (also off and pause) ends an @claude review always subscription on a pull request. VS Code: dictation behind a TLS-inspecting proxy now follows CLAUDE_CODE_CERT_STORE as well as NODE_EXTRA_CA_CERTS in ~/.claude/settings.json; the extension's own requests filter trusted certificates as the CLI does; a notice explains when voice dictation stops by itself. The axScreenReader setting and CLAUDE_AX_SCREEN_READER in a settings env block now apply only from user, managed or --settings settings (since 2.1.305).

v2.1.306 — two fixes for cloud sessions and MCP-heavy sessions Wed 21 Oct AEDT · 2 bullets · now stable

cloud & MCP Fixed claude -p inside cloud sessions reporting "Not logged in" when started without the session's environment variables. Fixed an API error being replaced by "prompt is too long", and an unneeded compaction, in sessions with many MCP tools. Nothing else; this is the build stable now points at.

v2.1.305 — gateway regression fix, MCP allowlist change, nested user namespaces Wed 21 Oct AEDT · 38 bullets

sandbox & managed MCP Added sandbox.allowNestedUserNamespaces so sandboxed commands on Linux can create user namespaces (Chromium, rootless podman); the changelog is explicit that this lets them get around the sandbox's file protections. Off by default. Changed allowedMcpServers to stop filtering managed-mcp.json stdio servers that use ${VAR} only in env: a server your allowlist left out now loads on upgrade; use deniedMcpServers to keep it off. Plugins that Claude Desktop mounts by path no longer keep their allowed-tools under allowManagedPermissionRulesOnly.
Bedrock, Vertex & gateways Fixed every request failing on Vertex, Bedrock and other providers when the endpoint or a gateway rejects tool search (a v2.1.304 regression); Claude Code now retries without it. /effort and /autocompact settings now apply when the model name differs from a modelOverrides value by letter case or a [1m] tag. An MCP server passed by a cloud session or the SDK's setMcpServers is no longer replaced mid-session by a same-named server from your own settings. /usage warnings are one-line fixes and f applies them. Self-hosted runner: repository access via a git credential helper or askpass reading GIT_CONFIG (broken since v2.1.296) fixed.

v2.1.304 — auto-mode setup everywhere, Managed Agents security check, settings ceilings, Code Review levels Tue 20 Oct AEDT · 76 bullets · bundled in Desktop

auto mode & Managed Agents /auto-mode-setup: a guided setup that reads your project and recent sessions to teach auto mode about your environment, now also on Bedrock, Vertex, Foundry and the Claude apps gateway. /claude-api managed-agents-secure compares a Managed Agents agent's settings with Anthropic's published security guide without changing anything. Pro/Max: a warning when resuming an inactive conversation would use a noticeable share of the 5-hour usage limit.
policy, sandbox, headless & Code Review Mods' settings.read hooks can make an organization's setting a ceiling. Organization policy refreshes right after approving an ANTHROPIC_API_KEY at startup. rm -r of a mounted drive or top-level folder gets the safety prompt. A plugin can no longer keep a headless run going past --max-turns by spawning subagents. claude --worktree no longer removes the worktree and branch without asking when HEAD was detached. Code Review gained review levels (Quick / Standard / Deep) per org and per repo, and org-wide enrolment. Tool search on by default behind a custom ANTHROPIC_BASE_URL (see the v2.1.305 fix).

Security & evals

v2.1.307 CLI (documented) · Desktop v3.1623.1 still on CLI 2.1.304 with the ten breaking managed-settings changes from v3.1623.0

Today's actionable items

  • upgrade Fleet CLI target moves to v2.1.307. It is a fix-and-plumbing release over v2.1.305/306 with no model changes; take it on the normal cadence. stable now points at v2.1.306, which carries the v2.1.305 gateway fix, so gateway fleets pinned to stable are finally past the v2.1.304 regression.
  • HTTP MCP double-send Before v2.1.307, an HTTP MCP tool call could be sent twice when the connection closed mid-call. Any internal MCP server with side-effecting tools (Konvoy Cloud writes, Slack sends, GitHub creates) could have run them twice on a dropped connection. Check logs for duplicate writes from Claude Code sessions, and make write tools idempotent regardless — only read-only or idempotent tools are retried now.
  • new OTel safety event claude_code.safety_event fires for every tool call stopped, prompted or sent back by a permission rule, auto mode, a safety check, a hook or the sandbox. Add it to the Grafana pipeline next to tool_decision; a rising count on one source is the earliest signal of a mis-scoped rule or a prompt-injection attempt.
  • self-hosted runner: 30-minute checkout hook cap Checkout hooks now fail the session's setup after 30 minutes by default. Any environment whose hook does a large monorepo clone or dependency install near that limit needs --checkout-hook-timeout-min raised (or 0) before upgrading runners.
  • self-hosted runner: stray settings.local.json Sessions using --use-anthropic-git-proxy were committing a .claude/settings.local.json left in the clone by an earlier session. Grep runner-authored branches and merged PRs for that file and remove any that landed; it can carry per-session permission allowlists.
  • certificate filtering Both the runner's Anthropic-managed git certificate file and the VS Code extension's own requests now filter trusted certificates as the CLI does. Behind a TLS-inspecting proxy, confirm NODE_EXTRA_CA_CERTS or CLAUDE_CODE_CERT_STORE is set in managed settings, and watch for a [runner:warn] line reporting certificates left out.
  • API version 2026-10-21 A new Claude API version; the migration skill is /claude-api api-version. Run it on a branch of each internal service that calls the Claude API directly, review the diff, and test in staging before changing the pinned anthropic-version header.
  • permissions UI /permissions > Recently denied now shows the actual denied shell command, and approving a row names the command rather than its description. Engineers who approved from that list before v2.1.307 were approving by description only.
  • Desktop v3.1623.1: no change, same enforcement The 21 Oct build has no user-facing changes and still bundles Claude Code 2.1.304. The ten (breaking) managed-settings changes from v3.1623.0 remain in force: a managed-settings file that fails to load blocks Code sessions on that computer; disableDesktopLocalSessions / disableSshSavedPasswords in the computer's own managed settings apply; sshHostAllowlist must list ProxyJump / ProxyCommand hosts and an empty or malformed list turns SSH off. Desktop Code-tab sessions do not yet have the v2.1.305 allowedMcpServers change or the v2.1.307 MCP and OTel fixes.
  • carry-over (v2.1.305) allowedMcpServers no longer filters managed-mcp.json stdio servers that use ${VAR} only in env — audit managed-mcp.json and add unwanted servers to deniedMcpServers. sandbox.allowNestedUserNamespaces is off by default; keep it out of managed settings unless a team needs Chromium or rootless podman inside sandboxed Bash.
  • carry-over (v2.1.302, v2.1.299) claude -p and Agent SDK sessions with no permission mode start in default mode on third-party providers or with telemetry off (CI needs --permission-mode auto). mcp__a permission rules match only the server named a.
  • Enterprise Skill and plugin security scanning is on by default for Enterprise orgs (since 2 Oct; doesn't cover MCP servers or hooks).

Patterns worth tracking

Three releases in 48 hours. v2.1.305 (Wed 06:29), v2.1.306 (Wed 13:28) and v2.1.307 (Thu 07:47 AEDT) followed the big v2.1.304. The middle one is a two-line fix release; the pattern is a large release, a next-day fix, a quick patch, then a full release again. Hold gateway fleets a day behind latest and let stable do the filtering.
stable skipped a version. It went v2.1.304 → v2.1.306 in one move, bypassing v2.1.305 even though v2.1.305 contained the regression fix. stable looks like it is promoted to the most recent small fix release rather than on a fixed lag.
Desktop is now three CLI releases behind. v3.1623.1 (21 Oct) bundles 2.1.304 while npm is on 2.1.307. Fixes that only matter in the desktop Code tab (GitHub MCP write-tool form, idle-session archiving notice, apps-gateway telemetry) shipped in the CLI first and wait on the next Desktop bump.
Observability of enforcement keeps growing. v2.1.301 added classifier fields to tool_decision; v2.1.307 adds safety_event per block from any source, including hooks and the sandbox. Managed settings and mods decide the policy; OTel is now where you see it being applied.

Claude Desktop

What's new

v3.1623.1 · 21 Oct A no-change rebuild. The changelog lists "No user-facing changes" for General, Code, Cowork and third-party deployments, and the bundled Claude Code stays at 2.1.304. If devices picked it up overnight, nothing new to roll out or validate; the v3.1623.0 managed-settings behaviour is unchanged.
Claude Duet · 21 Oct · research preview A new standalone app on iOS, Android and claude.ai where Claude works as a proactive agent: a short morning brief across connected apps, monitoring during the day with a message only when something needs you, tasks handed off that keep running when you step away, and a check-in before it acts on your behalf. Included in Pro and Max plans with shared usage limits; waitlist only. Built around Opus 5.5. Security notes Anthropic published: credentials handled as in Managed Agents (Claude never sees passwords or tokens), actions approved by the auto mode classifier, a new classifier and safety prompt that refuses to send the strictest tier of information (card numbers, government IDs) and sends health or finance details only on explicit instruction, external penetration testing and bug-bounty coverage. It is a separate app, not a Desktop or Cowork feature; worth knowing about before engineers ask whether they can point it at company mail.
waiting on the next Desktop bump · Claude Code v2.1.307 CLI fixes that apply to the Code tab once Desktop bundles 2.1.305 or later: write tools on a directly configured GitHub MCP server no longer show a form that closes without creating anything; a background command stopped by the desktop app archiving an idle session is no longer reported to Claude as stopped by the user; telemetry from Desktop sessions behind a Claude apps gateway is no longer rejected when OTEL_EXPORTER_OTLP_HEADERS is set; plugins mounted by path lose their allowed-tools under allowManagedPermissionRulesOnly (v2.1.305).
carry-over · v3.1623.0 · 20 Oct Storage in Settings (disk used by Claude; remove inactive Cowork tasks and Code sessions; /storage in Cowork and Code). Minimum Windows is 10 version 2004 (build 19041). The "Open external link" confirmation is gone for most links on consumer builds. Ten (breaking) Code-tab changes for managed devices: managed-settings file load failures block sessions; the computer's own disableDesktopLocalSessions and disableSshSavedPasswords apply; sshHostAllowlist covers jump hosts, an empty or malformed list turns SSH off; SSH sessions won't start desktop MCP servers on hosts governed by managed-mcp.json; Browser pane isolation in SSH sessions; "Download file" removed for .js/.bat/.ps1 shown as text in remote sessions. Third-party deployments gained the Code tab, releaseChannel: staggered, builtinToolPolicy for every built-in tool, and isLocalDevMcpEnabled: false covering plugin and managed-config local MCP servers.
