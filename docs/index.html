All sources aligned on v2.1.275. npm newest, latest dist-tag, next dist-tag, changelog top and newest GitHub release all read v2.1.275. It was published to npm at 2026-09-17 20:20 UTC (Fri 18 Sep 06:20 local), about three hours before this refresh, and — unlike every build this week — arrived with its 96-entry changelog and GitHub release already in place. claude update installs v2.1.275. This is the first morning since Mon 14 Sep that the newest npm build is fully documented and promoted, so v2.1.275 becomes the roll-out target; under the one-day lag rule, promote fleet and CI pins on Monday.
v2.1.275 is a supply-chain and hygiene release. (1) Plugins installed from an npm source are now fetched with npm pack --ignore-scripts and integrity-verified, so a package's install scripts no longer run — the plugin path can no longer execute arbitrary code at install time. (2) Skills and plugins enabled on a claude.ai account now sync into terminal sessions signed in with it; opt out with syncClaudeAiSkills: false / syncClaudeAiPlugins: false. (3) Tokens stored in git, ssh or marketplace URLs were being shown in plugin logs and claude plugin marketplace list — fixed, in both the CLI and the VS Code Manage plugins dialog. (4) Sandboxed Bash on Linux reported exit code 0 for failed commands when the shell is zsh — fixed. (5) /update-config was writing Write(path) permission rules that file permission checks never match; it now writes Edit(path). Also: gateway sign-in now names and confirms the account before saving the credential, and a failing otelHeadersHelper warns at startup instead of silently exporting nothing.
v2.1.274 — yesterday's undocumented build — is now documented, and it is a 108-entry release. The items this team should know: a new claude_code.managed_settings_resolved OTel event exposes which managed-settings sources resolved and the policy helper state (redacted settings and digests with OTEL_LOG_MANAGED_SETTINGS=1) — the first way to observe that a managed control actually applied; enduser.sub (the IdP subject) is now in the telemetry Desktop and Cowork send through a Claude apps gateway; two more Bash permission-checker gaps closed (loops and assignments over special shell variables now prompt; worktree-isolated sessions refuse certain nested shell expansions); MCP connection errors no longer show secrets resolved from ${VAR}; Bedrock, Vertex and Foundry installs move to the v2 MCP client and MCP 2026-07-28 negotiation by default; self-hosted runners recover from repeated 401s; the gateway drains in-flight streams for 25 s on SIGTERM instead of cutting them; and installed_plugins.json stops being rewritten on every start-up, which was making Claude Desktop reload every open session's plugins.

v2.1.275 — npm plugins without install scripts, account skill sync, secrets out of plugin logs newest · aligned

Changed plugins installed from an npm source to be fetched with npm pack --ignore-scripts and integrity-verified, so a package's install scripts no longer run. Until now an npm-sourced plugin could run preinstall/postinstall on a developer's machine at install time — the classic npm supply-chain vector. That door is closed, and the tarball is checked against the registry integrity hash. Pair with --accept-command <sha256> (v2.1.271) and Enterprise skill/plugin scanning (6 Aug) and the plugin install path is now reasonably defended. Related fix: claude plugin marketplace update was deleting a GitHub marketplace's local copy when the fetch failed and the marketplace was named after its repository.
Added syncing of the skills and plugins enabled on your claude.ai account to terminal sessions signed in with it; opt out with syncClaudeAiSkills: false or syncClaudeAiPlugins: false. This is the CLI half of the Chat-and-Cowork merge: whatever a developer has turned on in the Customize panel now shows up in their terminal. Governance question for us: it means anything enabled on a personal claude.ai account runs in the CLI too. If we want the org, not the individual, to decide what runs on developer machines, set both keys to false in managed settings. Write and Edit results in the synced account-skills folder now say the change is not saved to the account and how to save it; the ListPlugins tool description now makes clear it lists account plugins, not local /plugin installs.
Fixed plugin and marketplace messages, logs and claude plugin marketplace list showing a password or token stored in a git, ssh or marketplace URL, and the same in the VS Code Manage plugins dialog. Third secret-leak fix in eight days (v2.1.268: git source URL tokens in errors; v2.1.274: ${VAR} in MCP connection errors). If we have any private marketplace configured with a token in the URL, assume it has been visible in local logs and VS Code until today; rotate it.
Fixed sandboxed Bash commands on Linux reporting exit code 0 for failed commands when the shell is zsh. On a zsh-default Linux box with sandboxing on, a failing build or test was reported as success and Claude carried on as if it had passed. Anyone on Linux with zsh and sandboxing should treat green results from before v2.1.275 with suspicion. Also fixed: sandboxed Bash could not write to project directories named hooks/ or config/.
Fixed /update-config writing Write(path) permission rules, which file permission checks don't match, instead of Edit(path) rules. Any Write(…) allow or deny rule written through /update-config has been a no-op. Grep our settings files for Write( and rewrite as Edit(. Related: v2.1.274 fixed Bash permission checks for commands that loop over or assign certain special shell variables (they now ask), and worktree-isolated sessions now refuse Bash commands with certain nested shell expansions.
Claude apps gateway: the signed-in account is now confirmed before a credential is saved, and shows in /status; /logout also ends the session on gateways that advertise token revocation. Plus a startup warning when a configured otelHeadersHelper fails, so sessions that silently export no telemetry are noticed — the failure mode where the collector shows a quiet fleet and nobody knows why. From v2.1.274 on the gateway side: store.connect_timeout_seconds, three Postgres connect attempts at boot, a 25 s drain on SIGTERM (CLAUDE_GATEWAY_DRAIN_TIMEOUT_MS), a one-round-trip spend check, and a warning when a replica has more than 256 requests open.
Reliability: a cluster of resume and transcript fixes. --resume, the resume picker, resumed background agents and the transcript view no longer fail on a session whose saved history has a malformed task-reminder or @-file entry; sessions no longer fail to start on a malformed content block; a crash at launch on a malformed mcpNeedsAuthNoticed value is gone; Grep, Glob and @-file suggestions no longer hang or run out of memory past the 20 MB output cap; /rewind in a forked session no longer restores a zero-filled file when history backups could not be fully copied; a network gateway that rewrites API error responses no longer produces API Error: 400 on every turn. A restored memory file's age note no longer changes between requests after compaction (it was causing prompt-cache misses).
Ergonomics. A send-now key (ctrl+enter, or ctrl+x ctrl+s) interrupts the current turn and flushes every queued message at once; /plugin install <plugin> --marketplace <source> offers to add the marketplace first; pasted and attached images are saved where Claude can open them without a permission prompt, including in Desktop and VS Code. VS Code (29 entries): view, edit and delete saved memories in the Memory dialog; accept/reject buttons under each change in the proposed-change diff; send an attached image without text; a claudeCode.scrollToBottomOnSend setting; the agent map now counts running agents and turns red on failure. Claude Tag: Amazon CloudWatch, CloudWatch Logs, SNS, Google Cloud Monitoring and Cloud Logging presets on an access bundle's Credentials tab; Datadog presets for US3, AP1, AP2 and US1-FED with new connections limited to read/query routes; S3 uploads from recent AWS CLI/SDK versions no longer 502 through an AWS connection; access bundles can now attach in channels with guests or Slack Connect.

v2.1.274 — observability for managed settings, IdP subject in gateway telemetry, MCP v2 everywhere documented Thu

Added claude_code.managed_settings_resolved OTel event: managed-settings sources and policy helper state; redacted settings and digests with OTEL_LOG_MANAGED_SETTINGS=1. After two weeks of “managed control silently ignored” fixes, this is the tool we were missing: an event per session saying which sources (MDM file, server-managed, policy helper) resolved and a digest of what they contained. Turn it on in the collector and alert when a session's digest differs from the fleet's. Also new: effort on the claude_code.llm_request span, and OTEL_LOG_RAW_API_BODIES=file:<dir> now writes an index.jsonl linking each response to its request file and transcript message.
Added enduser.sub, the IdP subject, to the telemetry Claude Desktop and Cowork send through a Claude apps gateway. Per-user attribution of Desktop and Cowork spend and activity at the gateway, keyed on the SSO subject rather than a display name. Combined with OTEL_LOG_TOOL_DETAILS=1 carrying real plugin and MCP server names (v2.1.273) and OTEL_METRICS_INCLUDE_REPOSITORY (v2.1.269), per-user, per-repo, per-plugin cost is now derivable from the collector.
Changed Bedrock, Vertex, Foundry and telemetry-disabled installs to use the v2 MCP client and MCP 2026-07-28 negotiation with direct HTTP servers by default, as other installs already do. Opt out with MCP_SDK_GENERATION=v1 or MCP_PROTOCOL_NEGOTIATION=legacy. For our Bedrock fleet this is a behaviour change on the next upgrade; if any internal HTTP MCP server misbehaves, try the opt-out before debugging the server. Related MCP fixes: http servers that only speak legacy HTTP+SSE now connect when they answer with a 4xx; Streamable HTTP calls honour a per-server timeout longer than 5 minutes; a 403 insufficient_scope now names the missing permissions and points to /mcp instead of claiming the sign-in expired; CLAUDE_CODE_MCP_STARTUP_WAIT_MS bounds how long the first headless turn waits for connecting servers; "type": "sdk" MCP entries in config files are skipped with a warning.
Permission checker, again. Bash commands that loop over or assign certain special shell variables now ask for permission; worktree-isolated sessions refuse Bash commands with certain nested shell expansions; the Edit permission prompt preview could show a different location than the approved edit in files with multi-byte characters. Fourth consecutive documented release with a Bash-checker fix (271, 273, 274, 275).
Fleet and Desktop plumbing. installed_plugins.json was rewritten on nearly every start-up when plugin policy comes from remote managed settings, which made Claude Desktop reload every open session's plugins — fixed. The Bash tool re-sourced the shell profile (a multi-second stall) after every plugin reload; now only when plugins' bin/ directories changed. Self-hosted runners that failed every turn with 401 after a few failed token refreshes now keep retrying and fetch a new token. claude agents kept --model, --effort, --permission-mode and --agent across an auto-update relaunch. Subagents with model: "opus" on Bedrock, Vertex or Foundry no longer fall back to the session's model when the id has no recognisable family. Background commands are no longer stopped after 30 idle minutes under mild memory pressure — only when memory is critically low, with a visible warning.
[Claude Code on the web] a “Compare against” branch picker in the cloud session diff view; routines skip and retry for up to 72 hours when the owner's GitHub connection is missing instead of switching off; editing a routine no longer occasionally fires it twice or re-enables a paused one; commits no longer fail with a signing error for a few minutes after a credential refresh. [Claude Tag] Claude now answers when another Slack app or bot @mentions it; a follow-up sent minutes after its last message posts as a new notifying reply instead of a silent edit; single-channel search fixed; a Guests setting on Add channel / Add workspace. [Code Review] findings reworded as short sentences with who is affected, where, and the fix up front; transient GitHub failures at launch now wait and retry; a skipped review links the admin page that fixes the limit.

Patterns worth tracking

Alignment, finally. Every morning from Mon 14 Sep to Thu 17 Sep the newest npm build was ahead of the changelog, latest, or both. Today all five sources agree on v2.1.275, and the last two builds arrived with their changelog entries within hours, not a day. Keep the one-day lag rule regardless: the content of a release matters more than its metadata being tidy.
The Bash permission checker has been patched in four consecutive documented releases. v2.1.271: unrecognised options, wildcards in option values, declaration flags. v2.1.273: unanalysable commands, subshell-hidden rm. v2.1.274: special shell variables, nested expansions in worktrees. v2.1.275: Write(path) rules that never matched, zsh exit codes under sandbox. Each was a gap in a control we may have believed was in force. Sandboxing plus per-command allowed_domains is the containment; the checker is defence in depth.
From “fail closed” to “prove it applied”. Last week: three managed allowlists admitted everything when unreadable. This week: managed-mcp.json and three device-managed MCP keys were silently ignored (fixed 271, 273). Now v2.1.274 ships managed_settings_resolved, an event that says which sources resolved and what they contained. A managed control is a control once you have watched it deny something — and now you can also watch it load.
Secrets keep turning up in output. v2.1.268: tokens from git source URLs in plugin errors; ${VAR} in /mcp and claude mcp list. v2.1.274: ${VAR} in MCP connection errors and the login tool description. v2.1.275: tokens in marketplace URLs in logs, marketplace list and the VS Code dialog. Same lesson each time: never put a credential in a URL; use ${VAR} placeholders resolved from the environment, and rotate anything that ever lived in a URL.
Cost attribution is complete enough to build on. effort on the request span and enduser.sub at the gateway (v2.1.274), real plugin and MCP names on cost metrics (v2.1.273), vcs.* attributes (v2.1.269), gateway pricing on clients (v2.1.268), chargeback multiplier (v2.1.271). Claude Cowork

GA · macOS & Windows · Linux beta

What's new

Scheduled and “Run now” routine runs can now save data to, and republish the page of, an artifact you can edit without asking (v2.1.275); public artifacts, first publishes and deletes still ask. This is the change that lets an unattended routine — like the one that builds this page — refresh its own artifact without a human approving each run. Also: the startup notice that a one-off routine had run since your last session is gone.
Artifacts got sturdier for unattended use. Artifact updates no longer fail with “File not found” after a session resumes on another machine or its scratchpad is cleared — the last published version is restored (v2.1.275). A publish built on an older version is stopped before it is sent, with the newer page to merge (v2.1.274); a flaky fetch of that newer page is retried (v2.1.275). Publish and read results now say who can open the page and what the Share menu offers, and Claude updates a shared artifact in place when given edit access instead of publishing a copy. A first publish now asks for a one-word tab icon rather than an emoji favicon. In local sessions a version published elsewhere no longer starts a turn on its own (v2.1.274).
Cowork and claude.ai cloud sessions with network access on were treating reads of a teammate's artifact as if network access were off (fixed v2.1.274). Shared artifacts built on connector data should now load for everyone the artifact is shared with. Also fixed: /schedule saved a routine's prompt without its message role in one shape; hook-driven sessions such as an active /goal ended with “Prompt is too long” instead of compacting, and an active /goal was lost on --resume after compaction.
Claude Tag for the infra channel. Access bundles gain Amazon CloudWatch, CloudWatch Logs, SNS, Google Cloud Monitoring and Cloud Logging credential presets, plus Datadog US3/AP1/AP2/US1-FED with new connections limited to read and query routes (v2.1.275); S3 uploads from recent AWS CLI/SDK versions no longer fail with 502 through an AWS connection. Claude now answers when another Slack app or bot @mentions it, and a follow-up minutes after its last message posts as a new notifying reply rather than a silent edit (v2.1.274) — blockers surfaced late will now ping the thread. Bundles can attach in channels with guests or Slack Connect; a Guests setting on Add channel / Add workspace (v2.1.274).
Cloud routines are more forgiving. A routine whose owner's GitHub connection is missing now skips and retries for up to 72 hours instead of switching off at the first failed check; editing a routine no longer occasionally fires it twice or re-enables one just paused (v2.1.274); paused-subscription notices now tell you to turn the routine back on yourself (v2.1.275). A cloud environment with a very long allowed-domains list now fails to save up front, saying how much to trim, instead of failing every session start.
Plugins. npm-sourced plugins are fetched with --ignore-scripts and integrity-verified (v2.1.275); /plugin install <plugin> --marketplace <source> adds the marketplace on the way; Git LFS files in plugin clones are left as pointers (v2.1.274); a plugin directory without its own git repo no longer inherits a version from an enclosing one such as a git-managed ~/.claude. Account skills and plugins now sync into terminal sessions (v2.1.275), so what is enabled in the Cowork Customize panel is what a developer gets in the CLI.
Standing context — merged experience, Salesforce, smart reports, scanning. In the merged Chat-and-Cowork experience (Pro/Max first; see Claude Cowork and chat are one Claude) existing tasks, projects, connectors, skills, artifacts and files carry over; local-only features (trusted folders, built-in browser, computer use) still need Desktop open. Salesforce in Claude (beta, 15 Sep) is a Cowork plugin with 37 skills. Smart reports (beta, 10 Sep) tells Enterprise admins which repeated patterns are worth packaging as skills; claude plugin eval (v2.1.269) measures them. Artifacts created on or after 19 Aug are shareable and openable from the web. Enterprise skill and plugin security scanning (6 Aug) remains the control that matters most now that account plugins sync to terminals.
